# Актор-Критик — A2C и A3C

> REINFORCE шумный. Добавьте критика, который обучается `V̂(s)`, вычтите его из возврата — и вы получите преимущество (advantage) с тем же математическим ожиданием, но намного меньшей дисперсией. Это и есть actor-critic. A2C выполняет это синхронно; A3C — в нескольких потоках. Оба подхода — ментальная модель для каждого современного метода глубокого RL.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 9 · 04 (TD Learning), Phase 9 · 06 (REINFORCE)
**Time:** ~75 минут

## Проблема

Ванильный REINFORCE работает, но его дисперсия ужасна. Монте-карло возвраты `G_t` могут колебаться более чем в 10 раз между эпизодами. Умножение этого шума на `∇ log π` и усреднение дают оценку градиента, которой требуются тысячи эпизодов, чтобы сдвинуть политику на то же расстояние, которое можно пройти за гораздо меньшее число обновлений DQN.

Дисперсия возникает из-за использования «сырых» возвратов. Если вычесть базовую линию (baseline) `b(s_t)` — любую функцию состояния, включая обученное значение — математическое ожидание не изменится, а дисперсия упадёт. Лучшая практически достижимая базовая линия — `V̂(s_t)`. Теперь величина, умножающая `∇ log π`, называется *преимуществом* (advantage):

`A(s, a) = G - V̂(s)`

Действие хорошее, если оно дало возврат выше среднего; плохое — если ниже. REINFORCE с обученным критиком — это *actor-critic*. Критик даёт актору учителя с низкой дисперсией. Это основа каждого метода на основе глубокой политики после 2015 года (A2C, A3C, PPO, SAC, IMPALA).

## Концепция

![Actor-critic: policy net plus value net, TD residual as advantage](../assets/actor-critic.svg)

**Две сети, одна общая функция потерь:**

- **Актор** `π_θ(a | s)`: политика. Из неё производится выборка для действий. Обучается с помощью градиента политики.
- **Критик** `V_φ(s)`: оценивает ожидаемый возврат из состояния. Обучается минимизировать `(V_φ(s) - target)²`.

**Преимущество (advantage).** Две стандартные формы:

- *MC-преимущество:* `A_t = G_t - V_φ(s_t)`. Несмещённое, более высокая дисперсия.
- *TD-преимущество:* `A_t = r_{t+1} + γ V_φ(s_{t+1}) - V_φ(s_t)`. Смещённое (использует `V_φ`), намного ниже дисперсия. Также называется *TD-невязкой (TD residual)* `δ_t`.

**n-шаговое преимущество.** Интерполяция между двумя:

`A_t^{(n)} = r_{t+1} + γ r_{t+2} + … + γ^{n-1} r_{t+n} + γ^n V_φ(s_{t+n}) - V_φ(s_t)`

`n = 1` — чистый TD. `n = ∞` — MC. Большинство реализаций использует `n = 5` для Atari, `n = 2048` для PPO на MuJoCo.

**Обобщённая оценка преимущества (Generalized Advantage Estimation, GAE).** Schulman et al. (2016) предложили экспоненциально взвешенное усреднение по всем n-шаговым преимуществам:

`A_t^{GAE} = Σ_{l=0}^{∞} (γλ)^l δ_{t+l}`

где `λ ∈ [0, 1]`. `λ = 0` — это TD (низкая дисперсия, высокое смещение). `λ = 1` — это MC (высокая дисперсия, несмещённое). `λ = 0.95` — стандартное значение по умолчанию в 2026 году — настраивайте, пока регулятор смещение/дисперсия не окажется там, где нужно.

**A2C: синхронный advantage actor-critic.** Соберите `T` шагов по `N` параллельным окружениям. Вычислите преимущества для каждого шага. Обновите актора и критика на объединённом батче. Повторите. Более простой и лучше масштабируемый собрат A3C.

**A3C: асинхронный advantage actor-critic.** Mnih et al. (2016). Запустите `N` потоков-воркеров, каждый из которых исполняет своё окружение. Каждый воркер вычисляет градиенты локально на своём собственном прогоне (rollout), затем асинхронно применяет их к общему серверу параметров. Буфер воспроизведения (replay buffer) не нужен — воркеры декоррелируются за счёт исполнения разных траекторий. A3C доказал, что обучение возможно на CPU в большом масштабе. В 2026 году доминирует A2C на GPU (батчи параллельных окружений), потому что GPU требуют больших батчей.

**Объединённая функция потерь.**

`L(θ, φ) = -E[ A_t · log π_θ(a_t | s_t) ]  +  c_v · E[(V_φ(s_t) - G_t)²]  -  c_e · E[H(π_θ(·|s_t))]`

Три слагаемых: потеря градиента политики, регрессия значения, бонус за энтропию. `c_v ~ 0.5`, `c_e ~ 0.01` — канонические стартовые значения.

## Постройте это

### Шаг 1: критик

Линейный критик `V_φ(s) = w · features(s)`, обновляемый через MSE:

```python
def critic_update(w, x, target, lr):
    v_hat = dot(w, x)
    err = target - v_hat
    for j in range(len(w)):
        w[j] += lr * err * x[j]
    return v_hat
```

На табличном окружении критик сходится за несколько сотен эпизодов. На Atari замените линейный критик общим CNN-стволом с головой значения.

### Шаг 2: n-шаговое преимущество

Дан прогон длины `T` и бутстрапированное конечное `V(s_T)`:

```python
def compute_advantages(rewards, values, gamma=0.99, lam=0.95, last_value=0.0):
    advantages = [0.0] * len(rewards)
    gae = 0.0
    for t in reversed(range(len(rewards))):
        next_v = values[t + 1] if t + 1 < len(values) else last_value
        delta = rewards[t] + gamma * next_v - values[t]
        gae = delta + gamma * lam * gae
        advantages[t] = gae
    returns = [a + v for a, v in zip(advantages, values)]
    return advantages, returns
```

`returns` — целевое значение для критика. `advantages` — то, что умножает `∇ log π`.

### Шаг 3: объединённое обновление

```python
for step_i, (x, a, _r, probs) in enumerate(traj):
    adv = advantages[step_i]
    target_v = returns[step_i]

    # critic
    critic_update(w, x, target_v, lr_v)

    # actor
    for i in range(N_ACTIONS):
        grad_logpi = (1.0 if i == a else 0.0) - probs[i]
        for j in range(N_FEAT):
            theta[i][j] += lr_a * adv * grad_logpi * x[j]
```

On-policy, один прогон на обновление, отдельные скорости обучения для актора и критика.

### Шаг 4: параллелизация (A3C против A2C)

- **A3C:** запустите `N` потоков. Каждый исполняет своё окружение и свой прямой проход. Периодически отправляйте обновления градиентов в общий мастер. На мастере нет блокировок — гонки допустимы, они лишь добавляют шум.
- **A2C:** запустите `N` экземпляров окружения в одном процессе, соберите наблюдения в батч `[N, obs_dim]`, выполните батчевый прямой проход, батчевый обратный проход. Более высокая утилизация GPU, детерминированность, проще анализировать. Вариант по умолчанию в 2026 году.

Наш учебный код однопоточный для ясности; переписать на батчевый A2C — это три строки на numpy.

## Подводные камни

- **Смещение критика до градиента актора.** Если критик случаен, его базовая линия неинформативна, и вы тренируетесь на чистом шуме. Разогрейте критика в течение нескольких сотен шагов, прежде чем включать градиент политики, или используйте медленную скорость обучения актора.
- **Нормализация преимущества.** Нормализуйте преимущества к нулевому среднему/единичному стандартному отклонению на батч. Это значительно стабилизирует обучение практически без затрат.
- **Общий ствол.** Используйте общий экстрактор признаков для актора и критика на изображениях-входах. Отдельные головы. Общие признаки «бесплатно» используются обеими функциями потерь.
- **On-policy контракт.** A2C переиспользует данные ровно для одного обновления. Больше — и ваш градиент смещается (коррекция важностной выборки — это то, что добавляет PPO).
- **Коллапс энтропии.** Без `c_e > 0` политика становится почти детерминированной за несколько сотен обновлений и перестаёт исследовать.
- **Масштаб награды.** Величины преимущества зависят от масштаба награды. Нормализуйте награды (например, делением на скользящее стандартное отклонение) для согласованных величин градиента между задачами.

## Применение

A2C/A3C редко являются финальным выбором в 2026 году, но это та архитектура, которую впоследствии уточняет всё остальное:

| Метод | Отношение к A2C |
|--------|----------------|
| PPO | A2C + обрезанное отношение важностной выборки для многоэпоховых обновлений |
| IMPALA | A3C + V-trace коррекция off-policy |
| SAC (Phase 9 · 07) | Off-policy A2C с мягким (soft) value-критиком (следующий урок) |
| GRPO (Phase 9 · 12) | A2C без критика — групповое относительное преимущество |
| DPO | A2C, свёрнутый в функцию потерь предпочтительного ранжирования, без сэмплирования |
| AlphaStar / OpenAI Five | A2C с лиговым обучением (league training) + предобучением имитацией |

Если вы видите «advantage» в статье 2026 года — думайте actor-critic.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Актор (Actor) | «Сеть политики» | `π_θ(a\|s)`, обновляется градиентом политики. |
| Критик (Critic) | «Сеть значения» | `V_φ(s)`, обновляется регрессией MSE к возвратам / TD-целям. |
| Преимущество (Advantage) | «Насколько лучше среднего» | `A(s, a) = Q(s, a) - V(s)` или его оценщики. Множитель для `∇ log π`. |
| TD-невязка (TD residual) | «δ» | `δ_t = r + γ V(s') - V(s)`; одношаговая оценка преимущества. |
| GAE | «Регулятор интерполяции» | Экспоненциально взвешенная сумма n-шаговых преимуществ, параметризованная `λ`. |
| A2C | «Синхронный actor-critic» | Батчировано по окружениям; один шаг градиента на прогон. |
| A3C | «Асинхронный actor-critic» | Потоки-воркеры отправляют градиенты общему серверу параметров. Оригинальная статья; менее распространён в 2026 году. |
| Бутстрап (Bootstrap) | «Использовать V на горизонте» | Обрезать прогон, добавить `γ^n V(s_{t+n})`, чтобы замкнуть сумму. |
