# MDP: состояния, действия и награды

> Марковский процесс принятия решений — это пять вещей: состояния, действия, переходы, награды, дисконт. Всё в RL — Q-learning, PPO, DPO, GRPO — оптимизирует именно эту структуру. Выучите её один раз — и остальная часть обучения с подкреплением читается бесплатно.

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 1 · 06 (Вероятность и распределения), Phase 2 · 01 (Таксономия ML)
**Time:** ~45 минут

## Проблема

Вы пишете шахматного бота. Или планировщик запасов. Или торгового агента. Или цикл PPO, обучающий reasoning-модель. Четыре разные области — и один неожиданный факт: все четыре сводятся к одному и тому же математическому объекту.

Обучение с учителем даёт вам пары `(x, y)` и просит подогнать функцию. Обучение с подкреплением не даёт меток — только поток состояний, предпринятых вами действий и скалярной награды. Выиграл ли ход партию? Сэкономило ли решение о пополнении запасов деньги? Принесла ли сделка прибыль? Привёл ли только что сгенерированный LLM токен к более высокой награде от судьи?

Вы не сможете учиться на этом потоке, пока не формализуете его. «Что я увидел», «что я сделал», «что произошло дальше», «насколько это было хорошо» — каждое из этого должно стать объектом, над которым можно рассуждать. Эта формализация и есть марковский процесс принятия решений. Каждый алгоритм RL в этой фазе, включая циклы RLHF и GRPO в конце, оптимизирует именно эту структуру.

## Концепция

![Markov decision process: states, actions, transitions, rewards, discount](../assets/mdp.svg)

**Пять объектов.**

- **Состояния** `S`. Всё, что нужно агенту для принятия решения. В GridWorld — клетка. В шахматах — доска. В LLM — контекстное окно плюс любая память.
- **Действия** `A`. Варианты выбора. Движение вверх/вниз/влево/вправо. Ход в игре. Генерация токена.
- **Переходы** `P(s' | s, a)`. Для данного состояния `s` и действия `a` — распределение над следующим состоянием. Детерминированные в шахматах, стохастические в задачах запасов, почти детерминированные при декодировании LLM.
- **Награды** `R(s, a, s')`. Скалярный сигнал. Победа = +1, поражение = -1. Выручка минус затраты. Член отношения логарифмического правдоподобия в GRPO.
- **Дисконт** `γ ∈ [0, 1)`. Насколько будущая награда ценится по сравнению с текущей. `γ = 0.99` даёт горизонт около 100 шагов; `γ = 0.9` — около 10.

**Марковское свойство** `P(s_{t+1} | s_t, a_t) = P(s_{t+1} | s_0, a_0, …, s_t, a_t)`. Будущее зависит только от текущего состояния. Если это не так, представление состояния неполно — это недостаток не метода, а состояния.

**Политики и доходность.** Политика `π(a | s)` отображает состояния в распределения действий. Доходность (return) `G_t = r_t + γ r_{t+1} + γ² r_{t+2} + …` — это дисконтированная сумма будущих наград. Ценность (value) `V^π(s) = E[G_t | s_t = s]` — это ожидаемая доходность, начиная с `s` при политике `π`. Q-значение `Q^π(s, a) = E[G_t | s_t = s, a_t = a]` — это ожидаемая доходность, начиная с конкретного действия. Каждый алгоритм RL оценивает одну из этих двух величин, а затем улучшает `π` соответствующим образом.

**Уравнения Беллмана.** Уравнения неподвижной точки, которые использует всё в этой фазе:

`V^π(s) = Σ_a π(a|s) Σ_{s', r} P(s', r | s, a) [r + γ V^π(s')]`
`Q^π(s, a) = Σ_{s', r} P(s', r | s, a) [r + γ Σ_{a'} π(a'|s') Q^π(s', a')]`

Они разбивают ожидаемую доходность на «награду этого шага» плюс «дисконтированную ценность того, куда вы попадёте». Рекурсивно. Каждый алгоритм Фазы 9 либо итерирует это уравнение до сходимости (динамическое программирование), либо сэмплирует из него (метод Монте-Карло), либо «подтягивает» его на один шаг (временная разность).

## Реализация

### Шаг 1: крошечная детерминированная MDP

GridWorld 4×4. Агент стартует в верхнем левом углу, терминальное состояние — в нижнем правом, награда -1 за шаг, действия `{up, down, left, right}`. См. `code/main.py`.

```python
GRID = 4
TERMINAL = (3, 3)
ACTIONS = {"up": (-1, 0), "down": (1, 0), "left": (0, -1), "right": (0, 1)}

def step(state, action):
    if state == TERMINAL:
        return state, 0.0, True
    dr, dc = ACTIONS[action]
    r, c = state
    nr = min(max(r + dr, 0), GRID - 1)
    nc = min(max(c + dc, 0), GRID - 1)
    return (nr, nc), -1.0, (nr, nc) == TERMINAL
```

Пять строк. Это вся среда целиком. Детерминированные переходы, постоянный штраф за шаг, поглощающее терминальное состояние.

### Шаг 2: прогон политики

Политика — это функция из состояния в распределение действий. Простейшая: равномерно случайная.

```python
def uniform_policy(state):
    return {a: 0.25 for a in ACTIONS}

def rollout(policy, max_steps=200):
    s, total, steps = (0, 0), 0.0, 0
    for _ in range(max_steps):
        a = sample(policy(s))
        s, r, done = step(s, a)
        total += r
        steps += 1
        if done:
            break
    return total, steps
```

Запустите случайную политику 1000 раз. Средняя доходность для этой доски 4×4 составляет около -60...-80. Оптимальная доходность -6 (путь по прямой вниз-вправо). Сокращение этого разрыва — это и есть всё содержание Фазы 9.

### Шаг 3: точное вычисление `V^π` через уравнение Беллмана

Для небольших MDP уравнение Беллмана — это линейная система. Перечислите состояния, примените ожидание, итерируйте, пока значения не перестанут меняться.

```python
def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in all_states()}
    while True:
        delta = 0.0
        for s in all_states():
            if s == TERMINAL:
                continue
            v = 0.0
            for a, pi_a in policy(s).items():
                s_next, r, _ = step(s, a)
                v += pi_a * (r + gamma * V[s_next])
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V
```

Это итеративное оценивание политики. Это первый алгоритм у Саттона и Барто и теоретическая основа каждого последующего метода RL.

### Шаг 4: `γ` — гиперпараметр с физическим смыслом

Эффективный горизонт равен примерно `1 / (1 - γ)`. `γ = 0.9` → 10 шагов. `γ = 0.99` → 100 шагов. `γ = 0.999` → 1000 шагов.

Слишком низкий — агент действует близоруко. Слишком высокий — присвоение заслуг (credit assignment) становится шумным, потому что многие ранние шаги разделяют ответственность за далёкую будущую награду. В LLM RLHF обычно используют `γ = 1`, потому что эпизоды короткие и ограниченные. В задачах управления используют `0.95–0.99`. В стратегических играх с длинным горизонтом используют `0.999`.

## Подводные камни

- **Немарковское состояние.** Если для принятия решения вам нужны последние три наблюдения, «состояние» — это не только текущее наблюдение. Решение: стекинг кадров (DQN на Atari складывает 4 кадра) или рекуррентное состояние (LSTM/GRU поверх наблюдений).
- **Разреженные награды.** Награды только за победу делают обучение почти невозможным в больших пространствах состояний. Формируйте награду (промежуточный сигнал) или используйте имитационное обучение как отправную точку (Phase 9 · 09).
- **Взлом награды (reward hacking).** Оптимизация суррогатной награды часто приводит к патологическому поведению. Агент OpenAI в гонке на лодках бесконечно крутился по кругу, собирая бонусы, вместо того чтобы финишировать в гонке. Всегда определяйте награду исходя из целевого результата, а не суррогата.
- **Неправильная спецификация дисконта.** `γ = 1` на задаче с бесконечным горизонтом делает любую ценность бесконечной. Всегда ограничивайте либо конечным горизонтом, либо `γ < 1`.
- **Масштаб награды.** Награды {+100, -100} против {+1, -1} дают идентичные оптимальные политики, но совершенно разные масштабы градиентов. Нормализуйте примерно до `[-1, 1]` перед подачей в PPO/DQN.

## Применение

Стек 2026 года сводит каждый пайплайн RL к MDP ещё до написания кода:

| Ситуация | Состояние | Действие | Награда | γ |
|-----------|-------|--------|--------|---|
| Управление (локомоция, манипуляции) | Углы суставов + скорости | Непрерывные моменты силы | Специфичная для задачи сформированная награда | 0.99 |
| Игры (шахматы, го, покер) | Доска + история | Легальный ход | Победа=+1 / поражение=-1 | 1.0 (конечный) |
| Запасы / ценообразование | Запас + спрос | Объём заказа | Выручка - затраты | 0.95 |
| RLHF для LLM | Токены контекста | Следующий токен | Оценка reward-модели в конце | 1.0 (эпизод ~200 токенов) |
| GRPO для рассуждений | Промпт + частичный ответ | Следующий токен | Верификатор 0/1 в конце | 1.0 |

Напишите пять кортежей прежде, чем писать какой-либо обучающий цикл. Большинство багрепортов «RL не работает» в итоге сводятся к формулировке MDP, которая была сломана ещё на бумаге.

## Упражнения

1. **Лёгкое.** Реализуйте GridWorld 4×4 и прогон случайной политики в `code/main.py`. Запустите 10 000 эпизодов. Сообщите среднее значение и стандартное отклонение доходности. Сравните с оптимальной доходностью (-6).
2. **Среднее.** Запустите `policy_evaluation` с `γ ∈ {0.5, 0.9, 0.99}` для равномерно случайной политики. Выведите `V` в виде сетки 4×4 для каждого случая. Объясните, почему ценности состояний вблизи терминала растут быстрее при большем `γ`.
3. **Сложное.** Сделайте GridWorld стохастическим: каждое действие с вероятностью `p = 0.1` соскальзывает в соседнее направление. Заново оцените равномерную политику. Становится ли `V[start]` лучше или хуже? Почему?

## Ключевые термины

| Термин | Что обычно говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| MDP | «Постановка задачи обучения с подкреплением» | Кортеж `(S, A, P, R, γ)`, удовлетворяющий марковскому свойству. |
| Состояние | «Что видит агент» | Достаточная статистика для будущей динамики при выбранном классе политик. |
| Политика | «Поведение агента» | Условное распределение `π(a \| s)` или детерминированное отображение `s → a`. |
| Доходность (return) | «Суммарная награда» | Дисконтированная сумма `Σ γ^t r_t` начиная с текущего шага. |
| Ценность (value) | «Насколько хорошо состояние» | Ожидаемая доходность при `π`, начиная с `s`. |
| Q-значение | «Насколько хорошо действие» | Ожидаемая доходность при `π`, начиная с `s` с первым действием `a`. |
| Уравнение Беллмана | «Рекурсия динамического программирования» | Декомпозиция ценности/Q-значения в точке неподвижности на награду за один шаг плюс дисконтированную ценность следующего состояния. |
| Дисконт `γ` | «Будущее против настоящего» | Геометрический вес для далёкой будущей награды; эффективный горизонт `~1/(1-γ)`. |
