# Глубокие Q-сети (DQN)

> 2013: Мних обучил одну Q-сеть на сырых пикселях, превзойдя все классические RL-агенты на семи играх Atari. 2015: расширено до 49 игр, опубликовано в Nature, положило начало эре глубокого RL. DQN — это Q-обучение плюс три приёма, которые делают аппроксимацию функции устойчивой.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 3 · 03 (Backpropagation), Phase 9 · 04 (Q-learning, SARSA)
**Time:** ~75 минут

## Проблема

Табличному Q-обучению нужно отдельное Q-значение для каждой пары (состояние, действие). Шахматная доска имеет ~10⁴³ состояний. Кадр Atari — это 210×160×3 = 100 800 признаков. Табличный RL умирает уже на тысячах состояний, не говоря о миллиардах.

Решение очевидно задним числом: заменить Q-таблицу нейронной сетью, `Q(s, a; θ)`. Но «очевидное задним числом» заняло десятилетия. Наивная аппроксимация функции с Q-обучением расходится из-за «смертельной триады» — аппроксимация функции + бутстрэппинг + обучение вне политики. Мних и др. (2013, 2015) выделили три инженерных приёма, стабилизирующих обучение:

1. **Воспроизведение опыта (experience replay)** разрушает корреляцию переходов.
2. **Целевая сеть (target network)** замораживает бутстрэп-цель.
3. **Клиппинг наград (reward clipping)** нормализует величину градиентов.

DQN на Atari стал первым случаем, когда единая архитектура с единым набором гиперпараметров решала десятки задач управления по сырым пикселям. Всё «глубокое RL», построенное с тех пор — DDQN, Rainbow, Dueling, Distributional, R2D2, Agent57 — надстроено поверх этой базы из трёх приёмов.

## Концепция

![DQN training loop: env, replay buffer, online net, target net, Bellman TD loss](../assets/dqn.svg)

**Цель обучения.** DQN минимизирует одношаговую TD-потерю на нейронной Q-функции:

`L(θ) = E_{(s,a,r,s')~D} [ (r + γ max_{a'} Q(s', a'; θ^-) - Q(s, a; θ))² ]`

`θ` = онлайн-сеть, обновляемая на каждом шаге градиентным спуском. `θ^-` = целевая сеть, периодически копируемая из `θ` (каждые ~10 000 шагов). `D` = буфер воспроизведения прошлых переходов.

**Три приёма в порядке важности:**

**Воспроизведение опыта.** Кольцевой буфер из `~10⁶` переходов. На каждом шаге обучения из него случайно равномерно сэмплируется мини-батч. Это разрушает временную корреляцию (последовательные кадры почти идентичны), позволяет сети многократно учиться на редких вознаграждающих переходах и декоррелирует последовательные обновления градиента. Без этого TD-обучение на политике с нейросетью расходится на Atari.

**Целевая сеть.** Использование одной и той же сети `Q(·; θ)` по обе стороны уравнения Беллмана заставляет цель двигаться при каждом обновлении — «погоня за собственным хвостом». Решение: держать вторую сеть `Q(·; θ^-)` с замороженными весами. Каждые `C` шагов копировать `θ → θ^-`. Это стабилизирует цель регрессии на тысячи шагов градиента за раз. Мягкие обновления `θ^- ← τ θ + (1-τ) θ^-` (используемые в DDPG, SAC) — более плавный вариант.

**Клиппинг наград.** Величина наград в Atari варьируется от 1 до 1000+. Обрезка до `{-1, 0, +1}` не даёт одной игре доминировать над градиентом. Неверно, когда важна величина награды; подходит для Atari, где важен только знак.

**Double DQN.** Хасселт (2016) устраняет смещение максимизации: использовать онлайн-сеть для *выбора* действия, целевую сеть — для его *оценки*.

`target = r + γ Q(s', argmax_{a'} Q(s', a'; θ); θ^-)`

Прямая замена, стабильно лучше. Использовать по умолчанию.

**Другие улучшения (Rainbow, 2017):** приоритизированное воспроизведение (чаще сэмплировать переходы с высокой TD-ошибкой), дуэльная архитектура (отдельные головы `V(s)` и преимущества), зашумлённые сети (обученное исследование), n-шаговые возвраты, распределённое Q (C51/QR-DQN), многошаговый бутстрэппинг. Каждое добавляет несколько процентов; выигрыши примерно аддитивны.

## Реализация

Код здесь — только stdlib, без numpy: мы используем написанный вручную однослойный MLP на крошечном непрерывном GridWorld, так что каждый шаг обучения выполняется за микросекунды. Алгоритм идентичен DQN для Atari в масштабе.

### Шаг 1: буфер воспроизведения

```python
class ReplayBuffer:
    def __init__(self, capacity):
        self.buf = []
        self.capacity = capacity
    def push(self, s, a, r, s_next, done):
        if len(self.buf) == self.capacity:
            self.buf.pop(0)
        self.buf.append((s, a, r, s_next, done))
    def sample(self, batch, rng):
        return rng.sample(self.buf, batch)
```

~50 000 ёмкости для Atari; для нашей игрушечной среды хватает 5 000.

### Шаг 2: крошечная Q-сеть (ручной MLP)

```python
class QNet:
    def __init__(self, n_in, n_hidden, n_actions, rng):
        self.W1 = [[rng.gauss(0, 0.3) for _ in range(n_in)] for _ in range(n_hidden)]
        self.b1 = [0.0] * n_hidden
        self.W2 = [[rng.gauss(0, 0.3) for _ in range(n_hidden)] for _ in range(n_actions)]
        self.b2 = [0.0] * n_actions
    def forward(self, x):
        h = [max(0.0, sum(w * xi for w, xi in zip(row, x)) + b) for row, b in zip(self.W1, self.b1)]
        q = [sum(w * hi for w, hi in zip(row, h)) + b for row, b in zip(self.W2, self.b2)]
        return q, h
```

Прямой проход: линейный слой → ReLU → линейный слой. Это вся сеть.

### Шаг 3: обновление DQN

```python
def train_step(online, target, batch, gamma, lr):
    grads = zeros_like(online)
    for s, a, r, s_next, done in batch:
        q, h = online.forward(s)
        if done:
            y = r
        else:
            q_next, _ = target.forward(s_next)
            y = r + gamma * max(q_next)
        td_error = q[a] - y
        accumulate_grads(grads, online, s, h, a, td_error)
    apply_sgd(online, grads, lr / len(batch))
```

По форме это Q-обучение из урока 04 с двумя отличиями: (а) мы делаем обратное распространение через дифференцируемую `Q(·; θ)` вместо индексации таблицы, (б) цель использует `Q(·; θ^-)`.

### Шаг 4: внешний цикл

На каждом эпизоде действовать ε-жадно по `Q(·; θ)`, помещать переходы в буфер, сэмплировать мини-батч, делать шаг градиента, периодически синхронизировать `θ^- ← θ`. Шаблон:

```python
for episode in range(N):
    s = env.reset()
    while not done:
        a = epsilon_greedy(online, s, epsilon)
        s_next, r, done = env.step(s, a)
        buffer.push(s, a, r, s_next, done)
        if len(buffer) >= batch:
            train_step(online, target, buffer.sample(batch), gamma, lr)
        if steps % sync_every == 0:
            target = copy(online)
        s = s_next
```

На нашем крошечном GridWorld с 16-мерным one-hot состоянием агент обучается почти оптимальной политике за ~500 эпизодов. На Atari масштабируйте это до 200M кадров и добавьте извлечение признаков с помощью CNN.

## Подводные камни

- **Смертельная триада.** Аппроксимация функции + вне политики + бутстрэппинг может расходиться. DQN смягчает это целевой сетью + воспроизведением; не убирайте ни то, ни другое.
- **Исследование.** ε должно затухать, обычно от 1.0 до 0.01 за первые ~10% обучения. Без достаточного раннего исследования Q-сеть сходится в локальный бассейн.
- **Переоценка.** `max` по зашумлённому Q смещена вверх. Всегда используйте Double DQN в продакшене.
- **Масштаб наград.** Обрезайте или нормализуйте награды; величина градиента пропорциональна величине награды.
- **Холодный старт буфера воспроизведения.** Не обучайтесь, пока в буфере не накопится несколько тысяч переходов. Ранние градиенты на ~20 примерах переобучаются.
- **Частота синхронизации цели.** Слишком частая ≈ отсутствие целевой сети; слишком редкая ≈ устаревшие цели. DQN для Atari использует 10 000 шагов среды. Эмпирическое правило: синхронизируйте каждые ~1/100 горизонта обучения.
- **Предобработка наблюдений.** DQN для Atari стекирует 4 кадра, чтобы сделать состояние марковским. Любая среда с информацией о скорости требует стекирования кадров или рекуррентного состояния.

## Применение

В 2026 году DQN редко является передовым методом, но остаётся эталонным алгоритмом вне политики:

| Задача | Метод выбора | Почему не DQN? |
|------|------------------|--------------|
| Дискретные действия типа Atari | Rainbow DQN или Muesli | Тот же фреймворк, больше приёмов. |
| Непрерывное управление | SAC / TD3 (Phase 9 · 07) | У DQN нет сети политики. |
| На политике / высокая пропускная способность | PPO (Phase 9 · 08) | Нет буфера воспроизведения; легче масштабировать. |
| Офлайн RL | CQL / IQL / Decision Transformer | Консервативные Q-цели, без взрывов бутстрэппинга. |
| Большие дискретные пространства действий (рекомендации) | DQN с эмбеддингом действий или IMPALA | Подходит; детали важны. |
| RL для LLM | PPO / GRPO | Уровень последовательности, а не шага; другая функция потерь. |

Уроки всё ещё применимы. Воспроизведение и целевые сети встречаются в SAC, TD3, DDPG, SAC-X, буфере самоигры AlphaZero и в каждом методе офлайн RL. Клиппинг наград живёт в виде нормализации преимущества в PPO. Архитектура — это чертёж.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| DQN | «Глубокое Q-обучение» | Q-обучение с нейронной Q-функцией, буфером воспроизведения и целевой сетью. |
| Experience replay | «Перемешанные переходы» | Кольцевой буфер, сэмплируемый равномерно на каждом шаге градиента; декоррелирует данные. |
| Target network | «Замороженный бутстрэп» | Периодическая копия Q, используемая в цели Беллмана; стабилизирует обучение. |
| Deadly triad | «Почему RL расходится» | Аппроксимация функции + бутстрэппинг + вне политики = нет гарантии сходимости. |
| Double DQN | «Исправление смещения максимизации» | Онлайн-сеть выбирает действие, целевая сеть его оценивает. |
| Dueling DQN | «Головы V и A» | Разложение Q = V + A - mean(A); тот же выход, лучший поток градиента. |
| Rainbow | «Все приёмы сразу» | DDQN + PER + dueling + n-step + noisy + distributional в одном. |
| PER | «Приоритизированное воспроизведение» | Сэмплирование переходов пропорционально величине TD-ошибки. |
