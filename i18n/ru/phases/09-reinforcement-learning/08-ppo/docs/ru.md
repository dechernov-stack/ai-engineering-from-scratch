# Proксимальная оптимизация политики (PPO)

> A2C выбрасывает каждый rollout после одного обновления. PPO оборачивает градиент политики в усечённое отношение важности (importance ratio), что позволяет делать 10+ эпох на одних и тех же данных без «взрыва» политики. Schulman et al. (2017). По-прежнему алгоритм policy-gradient по умолчанию в 2026 году.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 9 · 06 (REINFORCE), Phase 9 · 07 (Actor-Critic)
**Time:** ~75 минут

## Проблема

A2C (Урок 07) — on-policy алгоритм: градиент `E_{π_θ}[A · ∇ log π_θ]` требует данных, сэмплированных из *текущей* `π_θ`. Сделайте одно обновление — и `π_θ` меняется; использованные вами данные становятся off-policy. Переиспользовать их — значит получить смещённый градиент.

Rollout'ы дороги. На Atari один rollout по 8 окружениям × 128 шагов = 1024 перехода и десяток секунд времени среды. Выбрасывать это после одного шага градиента расточительно.

Trust Region Policy Optimization (TRPO, Schulman 2015) стал первым решением: ограничить каждое обновление так, чтобы KL-дивергенция между старой и новой политикой оставалась ниже `δ`. Теоретически чисто, но требует решения методом сопряжённых градиентов на каждом обновлении. В 2026 году TRPO уже никто не использует.

PPO (Schulman et al. 2017) заменяет жёсткое ограничение trust region простой усечённой (clipped) целевой функцией. Одна дополнительная строка кода. Десять эпох на rollout. Никаких сопряжённых градиентов. Достаточно хорошие теоретические гарантии. Девять лет спустя это по-прежнему алгоритм policy-gradient по умолчанию — от MuJoCo до RLHF.

## Концепция

![PPO clipped surrogate objective: ratio clipping at 1 ± ε](../assets/ppo.svg)

**Отношение важности (importance ratio).**

`r_t(θ) = π_θ(a_t | s_t) / π_{θ_old}(a_t | s_t)`

Это отношение правдоподобия новой политики к политике, собравшей данные. `r_t = 1` означает отсутствие изменений. `r_t = 2` означает, что новая политика в два раза вероятнее выберет `a_t`, чем старая.

**Усечённая суррогатная функция (clipped surrogate).**

`L^{CLIP}(θ) = E_t [ min( r_t(θ) A_t, clip(r_t(θ), 1-ε, 1+ε) A_t ) ]`

Два слагаемых:

- Если преимущество `A_t > 0` и отношение пытается вырасти выше `1 + ε`, усечение выравнивает градиент — не продвигайте хорошее действие дальше, чем на `+ε` выше старой вероятности.
- Если преимущество `A_t < 0` и отношение пытается вырасти выше `1 - ε` (то есть мы бы сделали плохое действие более вероятным по сравнению с его усечённым уменьшением), усечение ограничивает градиент сверху — не продвигайте плохое действие ниже `-ε`.

`min` обрабатывает другое направление: если отношение сдвинулось в *выгодную* сторону, вы всё равно получаете градиент (усечения на стороне, которая могла бы навредить, нет).

Типичное значение `ε = 0.2`. Постройте график целевой функции как функции от `r_t`: кусочно-линейная функция с плоской «крышей» на «хорошей стороне» и плоским «полом» на «плохой стороне».

**Полная функция потерь PPO.**

`L(θ, φ) = L^{CLIP}(θ) - c_v · (V_φ(s_t) - V_t^{target})² + c_e · H(π_θ(·|s_t))`

Та же структура actor-critic, что и в A2C. Три коэффициента, обычно `c_v = 0.5`, `c_e = 0.01`, `ε = 0.2`.

**Цикл обучения.**

1. Соберите `N × T` переходов по `N` параллельным окружениям за `T` шагов каждое.
2. Вычислите преимущества (GAE), зафиксируйте их как константы.
3. Зафиксируйте `π_{θ_old}` как снимок текущей `π_θ`.
4. Для `K` эпох, для каждого минибатча `(s, a, A, V_target, log π_old(a|s))`:
   - Вычислите `r_t(θ) = exp(log π_θ(a|s) - log π_old(a|s))`.
   - Примените `L^{CLIP}` + value loss + энтропию.
   - Шаг градиента.
5. Отбросьте rollout. Вернитесь к шагу 1.

`K = 10` и минибатчи по 64 — стандартный набор гиперпараметров. PPO устойчив: точные значения редко имеют значение в пределах ±50%.

**Вариант с KL-штрафом.** В оригинальной статье предлагалась альтернатива с адаптивным KL-штрафом: `L = L^{PG} - β · KL(π_θ || π_old)` с `β`, регулируемым на основе наблюдаемого KL. Версия с усечением стала доминирующей; вариант с KL выживает в RLHF (где KL к референсной политике — отдельное ограничение, которое вам всё равно нужно).

## Реализация

### Шаг 1: зафиксировать `log π_old(a | s)` во время rollout

```python
for step in range(T):
    probs = softmax(logits(theta, state_features(s)))
    a = sample(probs, rng)
    s_next, r, done = env.step(s, a)
    buffer.append({
        "s": s, "a": a, "r": r, "done": done,
        "v_old": value(w, state_features(s)),
        "log_pi_old": log(probs[a] + 1e-12),
    })
    s = s_next
```

Снимок делается один раз, во время rollout. Он не меняется в течение эпох обновления.

### Шаг 2: вычислить преимущества GAE (Урок 07)

Так же, как в A2C. Нормализуйте по батчу.

### Шаг 3: обновление по усечённой суррогатной функции

```python
for _ in range(K_EPOCHS):
    for mb in minibatches(buffer, size=64):
        for rec in mb:
            x = state_features(rec["s"])
            probs = softmax(logits(theta, x))
            logp = log(probs[rec["a"]] + 1e-12)
            ratio = exp(logp - rec["log_pi_old"])
            adv = rec["advantage"]
            surrogate = min(
                ratio * adv,
                clamp(ratio, 1 - EPS, 1 + EPS) * adv,
            )
            # backprop -surrogate, add value loss, subtract entropy
            grad_logpi = onehot(rec["a"]) - probs
            if (adv > 0 and ratio >= 1 + EPS) or (adv < 0 and ratio <= 1 - EPS):
                pg_grad = 0.0  # clipped
            else:
                pg_grad = ratio * adv
            for i in range(N_ACTIONS):
                for j in range(N_FEAT):
                    theta[i][j] += LR * pg_grad * grad_logpi[i] * x[j]
```

Паттерн «усечено → нулевой градиент» — сердце PPO. Если новая политика уже слишком далеко сдвинулась в выгодную сторону, обновление останавливается.

### Шаг 4: value и энтропия

Добавьте стандартную MSE к целевому значению критика и бонус за энтропию к актору, как в A2C.

### Шаг 5: диагностика

Три вещи, за которыми нужно следить на каждом обновлении:

- **Средний KL** `E[log π_old - log π_θ]`. Должен оставаться в пределах `[0, 0.02]`. Если превышает `0.1`, уменьшите `K_EPOCHS` или `LR`.
- **Доля усечений (clip fraction)** — доля сэмплов, чьё отношение лежит вне `[1-ε, 1+ε]`. Должна быть `~0.1-0.3`. Если `~0`, усечение никогда не срабатывает → увеличьте `LR` или `K_EPOCHS`. Если `~0.5+`, вы переобучаетесь на rollout → уменьшите их.
- **Объяснённая дисперсия (explained variance)** `1 - Var(V_target - V_pred) / Var(V_target)`. Метрика качества критика. Должна расти к 1 по мере обучения критика.

## Подводные камни

- **Неверно подобранный коэффициент усечения.** `ε = 0.2` — де-факто стандарт. Переход к `0.1` делает обновления слишком осторожными; `0.3+` провоцирует нестабильность.
- **Слишком много эпох.** `K > 20` регулярно дестабилизирует обучение, потому что политика слишком далеко уходит от `π_old`. Ограничивайте число эпох, особенно для больших сетей.
- **Отсутствие нормализации наград.** Большие масштабы наград съедают диапазон усечения. Нормализуйте награды (скользящее стандартное отклонение) перед вычислением преимуществ.
- **Забытая нормализация преимуществ.** Нормализация по батчу (нулевое среднее/единичное стандартное отклонение) — стандарт. Пропуск этого шага ломает PPO на большинстве бенчмарков.
- **Не затухающий learning rate.** PPO выигрывает от линейного затухания LR до нуля. Постоянный LR часто хуже.
- **Ошибки в математике отношения важности.** Всегда `exp(log_new - log_old)` для численной стабильности, а не `new / old`.
- **Неверный знак градиента.** Максимизация суррогатной функции = *минимизация* `-L^{CLIP}`. Перевёрнутый знак — самая частая ошибка в PPO.

## Применение

PPO — алгоритм RL по умолчанию в 2026 году для удивительно большого числа областей:

| Сценарий использования | Вариант PPO |
|----------|-------------|
| MuJoCo / управление роботами | PPO с гауссовой политикой, GAE(0.95) |
| Atari / дискретные игры | PPO с категориальной политикой, скользящие rollout'ы по 128 шагов |
| RLHF для LLM | PPO с KL-штрафом к референсной модели, награда от RM в конце ответа |
| Крупномасштабные игровые агенты | IMPALA + PPO (AlphaStar, OpenAI Five) |
| LLM для рассуждений | GRPO (Урок 12) — вариант PPO без критика |
| Данные только с предпочтениями | DPO — замкнутое в аналитической форме схлопывание PPO+KL, без онлайн-сэмплирования |

*Форма* функции потерь PPO — усечённая суррогатная функция + value + энтропия — служит каркасом для DPO, GRPO и почти каждого пайплайна RLHF.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле значит |
|------|-----------------|-----------------------|
| Отношение важности (importance ratio) | "r_t(θ)" | `π_θ(a\|s) / π_old(a\|s)`; отклонение от политики, собравшей данные. |
| Усечённая суррогатная функция (clipped surrogate) | "Главный трюк PPO" | `min(r·A, clip(r, 1-ε, 1+ε)·A)`; плоский градиент за пределами усечения на выгодной стороне. |
| Trust region | "Замысел TRPO / PPO" | Ограничение KL каждого обновления для гарантии монотонного улучшения. |
| KL-штраф | "Мягкий trust region" | Альтернатива PPO: `L - β · KL(π_θ \|\| π_old)`. Адаптивный `β`. |
| Clip fraction | "Как часто срабатывает усечение" | Диагностика — должна быть 0.1-0.3; вне этого диапазона — неверная настройка. |
| Многоэпоховое обучение | "Повторное использование данных" | K эпох на каждом rollout; цена дисперсии обменивается на эффективность по данным. |
| Почти-on-policy | "В основном on-policy" | PPO номинально on-policy, но K>1 эпох безопасно использует слегка off-policy данные. |
| PPO-KL | "Другой PPO" | Вариант с KL-штрафом; используется в RLHF, где KL к референсной модели — уже существующее ограничение. |
