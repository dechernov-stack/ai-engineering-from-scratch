# RL для игр — AlphaZero, MuZero и эпоха LLM-рассуждений

> 1992: TD-Gammon обыграл чемпионов мира по нардам с помощью чистого TD. 2016: AlphaGo обыграл Ли Седоля. 2017: AlphaZero безраздельно освоил шахматы, сёги и го с нуля. 2024: DeepSeek-R1 доказал, что тот же рецепт — с GRPO вместо PPO — работает для рассуждений. Игры — это бенчмарк, который движет каждым прорывом на этом этапе.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 9 · 05 (DQN), Phase 9 · 08 (PPO), Phase 9 · 09 (RLHF), Phase 9 · 10 (MARL)
**Time:** ~120 минут

## Проблема

В играх есть всё, что нужно RL. Чистое вознаграждение (победа/поражение). Бесконечные эпизоды (self-play сбрасывается). Идеальная симуляция (сама игра *и есть* симулятор). Дискретные или небольшие непрерывные пространства действий. Мультиагентная структура, которая вынуждает к состязательной устойчивости.

И именно на играх тестировался каждый крупный прорыв RL. TD-Gammon (нарды, 1992). Atari-DQN (2013). AlphaGo (2016). AlphaZero (2017). OpenAI Five (Dota 2, 2019). AlphaStar (StarCraft II, 2019). MuZero (обучаемая модель, 2019). AlphaTensor (умножение матриц, 2022). AlphaDev (алгоритмы сортировки, 2023). DeepSeek-R1 (математические рассуждения, 2025) — последняя демонстрация того, что техники игрового RL работают и на тексте.

Этот капстоун рассматривает три знаковые архитектуры — AlphaZero, MuZero и GRPO — через единую объединяющую призму: **self-play + поиск + улучшение политики**. Каждая обобщает предыдущую; GRPO в частности — это рецепт AlphaZero, применённый к рассуждениям LLM, где токены выступают действиями, а математическая верификация — сигналом победы.

## Концепция

**Объединяющий цикл.**

```
while True:
    trajectory = self_play(current_policy, search)     # play game against self
    policy_target = search.improved_policy(trajectory) # search improves raw policy
    policy_net.update(policy_target, value_target)     # supervised on search output
```

**AlphaZero (2017).** Сильвер и др. Дана игра (шахматы, сёги, го) с известными правилами:

- Сеть политики-ценности: одна башня `f_θ(s) → (p, v)`. `p` — априорное распределение по допустимым ходам. `v` — ожидаемый исход игры.
- Monte Carlo Tree Search (MCTS): на каждом ходе разворачивается дерево возможных продолжений. `(p, v)` используется как априор + бутстрап. Узлы выбираются по UCB (PUCT): `a* = argmax Q(s, a) + c · p(a|s) · √N(s) / (1 + N(s, a))`.
- Self-play: игры агента против агента. На ходе `t` распределение посещений MCTS `π_t` становится целевым значением для обучения политики.
- Функция потерь: `L = (v - z)² - π · log p + c · ||θ||²`. `z` — исход игры (+1 / 0 / -1).

Никаких человеческих знаний. Никаких ручных эвристик. Единый рецепт, который освоил шахматы, сёги и го после нескольких десятков миллионов партий self-play для каждой игры.

**MuZero (2019).** Шриттвизер и др. Убирает требование знания правил.

- Вместо фиксированной среды обучается *латентная модель динамики* `(h, g, f)`:
  - `h(s)`: кодирует наблюдение в латентное состояние.
  - `g(s_latent, a)`: предсказывает следующее латентное состояние + вознаграждение.
  - `f(s_latent)`: предсказывает априор политики + ценность.
- MCTS выполняется в *обученном латентном пространстве*. Тот же поиск, тот же цикл обучения.
- Работает на го, шахматах, сёги *и* Atari — один алгоритм, без знания правил.

**Stochastic MuZero (2022).** Добавляет стохастическую динамику и узлы случайности; распространяется на игры класса нардов.

**Muesli, Gumbel MuZero (2022-2024).** Улучшения эффективности по выборкам и детерминированного поиска.

**GRPO (2024-2025).** Рецепт DeepSeek-R1. Тот же цикл в духе AlphaZero, применённый к рассуждениям языковых моделей:

- «Игра»: ответить на математическую / кодовую / логическую задачу. «Победа» = верификатор (тест-кейс проходит, числовой ответ совпадает) возвращает 1.
- Политика: LLM. Действия: токены. Состояние: промпт + ответ-на-данный-момент.
- Нет критика (V_φ в стиле PPO). Вместо этого для каждого промпта сэмплируются `G` завершений из политики. Для каждого вычисляется вознаграждение. **Групповое относительное преимущество** `A_i = (r_i - mean_r) / std_r` используется как сигнал для обновления в стиле REINFORCE.
- Штраф KL к референсной политике для предотвращения дрейфа (как в RLHF).
- Полная функция потерь:

  `L_GRPO(θ) = -E_{q, {o_i}} [ (1/G) Σ_i A_i · log π_θ(o_i | q) ] + β · KL(π_θ || π_ref)`

Нет модели вознаграждения, нет критика, нет MCTS. Групповой относительный базовый уровень заменяет все три компонента. По качеству на бенчмарках рассуждений соответствует PPO-RLHF или превосходит его, при этом требуя значительно меньше вычислений.

**Рецепт R1 целиком.** DeepSeek-R1 (DeepSeek 2025) — это две модели в одной статье:

- **R1-Zero.** Начало с базовой модели DeepSeek-V3. Без SFT. GRPO применяется напрямую с двумя компонентами вознаграждения: *вознаграждение за точность* (на основе правил — удалось ли распарсить финальный ответ в правильное число / прошёл ли код юнит-тесты) и *вознаграждение за формат* (обёрнута ли цепочка рассуждений в теги `<think>…</think>`). За тысячи шагов средняя длина ответа вырастает со ~100 до ~10 000 токенов, а результаты на математических бенчмарках приближаются к уровню o1-preview. Модель учится рассуждать с нуля. Недостаток: её цепочки рассуждений часто нечитабельны, смешивают языки и лишены стилистической отделки.
- **R1.** Исправляет проблемы читаемости R1-Zero с помощью четырёхэтапного конвейера:
  1. **Холодный старт SFT.** Собираются несколько тысяч демонстраций длинных CoT с чистым форматированием. Базовая модель дообучается на них с учителем. Это даёт читаемую отправную точку.
  2. **GRPO, ориентированное на рассуждения.** GRPO применяется с вознаграждениями за точность и формат плюс вознаграждение за *языковую согласованность*, чтобы предотвратить переключение между языками.
  3. **Отбор с отклонением + SFT раунд 2.** Из RL-чекпоинта сэмплируется ~600 тыс. траекторий рассуждений, сохраняются только те, у которых правильный финальный ответ и читаемый CoT, и они объединяются с ~200 тыс. примеров SFT без рассуждений (письмо, QA, самосознание). Базовая модель дообучается снова.
  4. **Полный спектр GRPO.** Ещё один раунд RL, охватывающий и рассуждения (вознаграждения на основе правил), и общее выравнивание (вознаграждения на основе предпочтений по полезности/безвредности).

Результат соответствует o1 на AIME и MATH-500 при открытых весах и достаточно компактен для дистилляции. Та же статья представляет шесть дистиллированных плотных моделей (от Qwen-1.5B до Llama-70B) путём SFT на траекториях рассуждений R1 — без RL у студента. Дистилляция сильного RL-учителя стабильно превосходит RL с нуля при том же масштабе студента.

**Почему GRPO вместо PPO для рассуждений.** Три причины из статьи DeepSeekMath (февраль 2024): (1) не нужно обучать сеть ценности, что вдвое снижает потребление памяти; (2) групповой базовый уровень естественным образом справляется с разреженным вознаграждением в конце траектории, которое характерно для задач на рассуждения; (3) нормализация на уровне промпта делает преимущества сравнимыми между задачами сильно разной сложности, чего единый критик PPO обеспечить не может.

**Поиск или его отсутствие.** В играх направления разошлись:

- *Игры с полной информацией и длинным горизонтом* (го, шахматы): по-прежнему на основе поиска. Доминируют AlphaZero / MuZero.
- *Рассуждения LLM*: пока без MCTS в продакшене; GRPO на полных развёртках, best-of-N для вычислений на этапе инференса. Модели процессного вознаграждения (PRM) намекают на возвращение поиска на уровне шагов.

## Соберите это

Код в `code/main.py` реализует **GRPO в миниатюре** — бандита с несколькими группами сэмплов. Алгоритм такой же, как в LLM; только политика и среда проще. Он показывает *функцию потерь* и *групповое относительное преимущество* — инновацию 2025 года.

### Шаг 1: крошечная среда с верификатором

```python
QUESTIONS = [
    {"prompt": "q1", "correct": 3},
    {"prompt": "q2", "correct": 1},
]

def verify(prompt_idx, answer_token):
    return 1.0 if answer_token == QUESTIONS[prompt_idx]["correct"] else 0.0
```

В настоящем GRPO верификатор запускает юнит-тесты или проверяет математическое равенство.

### Шаг 2: политика: softmax по K токенам-ответам на каждый промпт

```python
def policy_probs(theta, p_idx):
    return softmax(theta[p_idx])
```

Эквивалентно выходу финального слоя LLM, обусловленного промптом.

### Шаг 3: групповое сэмплирование и групповое относительное преимущество

```python
def grpo_step(theta, p_idx, G=8, beta=0.01, lr=0.1, rng=None):
    probs = policy_probs(theta, p_idx)
    samples = [sample(probs, rng) for _ in range(G)]
    rewards = [verify(p_idx, s) for s in samples]
    mean_r = sum(rewards) / G
    std_r = stddev(rewards) + 1e-8
    advs = [(r - mean_r) / std_r for r in rewards]

    for a, A in zip(samples, advs):
        grad = onehot(a) - probs
        for i in range(len(probs)):
            theta[p_idx][i] += lr * A * grad[i]
    # KL penalty: pull theta toward reference
    for i in range(len(probs)):
        theta[p_idx][i] -= beta * (theta[p_idx][i] - reference[p_idx][i])
```

Групповое относительное преимущество — трюк DeepSeek 2024 года. Критик не нужен. «Базовый уровень» — это среднее по группе, а нормализация использует стандартное отклонение по группе.

### Шаг 4: сравнение с базовым REINFORCE (без ценности)

Та же настройка, те же вычисления, обычный REINFORCE. GRPO сходится быстрее и стабильнее.

### Шаг 5: наблюдение за энтропией и KL

Та же диагностика, что и в RLHF: среднее KL к референсу, энтропия политики, вознаграждение во времени. Как только они стабилизируются, обучение завершено.

## Подводные камни

- **Взлом вознаграждения через обман верификатора.** GRPO наследует риск RLHF: если верификатор ошибочен или эксплуатируем, LLM найдёт эксплойт. Важны надёжные верификаторы (множественные тест-кейсы, формальные доказательства).
- **Слишком маленький размер группы.** Дисперсия группового базового уровня ведёт себя как `1/√G`. Ниже `G = 4` сигнал преимущества зашумлён; стандартный выбор — от `G = 8` до `64`.
- **Смещение по длине.** Завершения LLM разной длины имеют разные логарифмы вероятностей. Нормализуйте по количеству токенов, используйте логарифм вероятности на уровне последовательности или обрезайте до максимальной длины.
- **Циклы чистого self-play.** Обучение в стиле AlphaZero может застрять в циклах доминирования на играх общей суммы. Смягчается разнообразными пулами противников (лиговая игра, Урок 10).
- **Несоответствие политики и поиска.** AlphaZero обучает политику имитировать выход поиска. Если сеть политики слишком мала, чтобы представить распределение поиска, обучение застревает.
- **Потолок вычислений.** MuZero / AlphaZero требуют колоссальных вычислений. Одна абляция часто занимает сотни GPU-часов. Для обучения существуют миниатюрные демо (например, AlphaZero на «четыре в ряд»).
- **Покрытие верификатора.** Юнит-тесты, которые проходят для багнутого решения, закрепляют баг. Проектируйте верификаторы, которые ловят граничные случаи.

## Применение

Ландшафт игрового RL 2026 года по доменам:

| Домен | Доминирующий метод |
|--------|-----------------|
| Игры с нулевой суммой для двух игроков (го, шахматы, сёги) | AlphaZero / MuZero / KataGo |
| Карточные игры с неполной информацией (покер) | CFR + глубокое обучение (DeepStack, Libratus, Pluribus) |
| Игры Atari / пиксельные игры | Muesli / MuZero / IMPALA-PPO |
| Крупные многопользовательские стратегии (Dota, StarCraft) | PPO + self-play + лига (OpenAI Five, AlphaStar) |
| Математика/код LLM-рассуждений | GRPO (DeepSeek-R1, Qwen-RL, открытые репликации) |
| Выравнивание LLM | DPO / RLHF-PPO (не GRPO; верификатор — это предпочтение, а не проверяемая истина) |
| Робототехника | PPO + DR (не игровой RL, но использует те же инструменты градиента политики) |
| Комбинаторные задачи | Варианты AlphaZero (AlphaTensor, AlphaDev) |

Сам *рецепт* — self-play, улучшение с дополнением поиском, дистилляция политики — охватывает текст, пиксели и физическое управление. GRPO — самый молодой пример; будут и другие.

## Ключевые термины

| Термин | Что обычно говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| MCTS | «Поиск по дереву с обученной сетью» | Monte Carlo Tree Search; выбор по UCB1/PUCT с обученными априорами `(p, v)`. |
| AlphaZero | «Self-play + MCTS» | Сеть политики-ценности, обученная соответствовать посещениям MCTS и исходу игры. |
| MuZero | «AlphaZero с обученной моделью» | Тот же цикл, но в латентном пространстве через обученную динамику. |
| GRPO | «PPO без критика» | Group Relative Policy Optimization; REINFORCE с базовым уровнем — средним по группе — + KL. |
| PUCT | «UCB AlphaZero» | `Q + c · p · √N / (1 + N_a)` — балансирует оценку ценности с априором. |
| Self-play | «Агент против прошлой версии себя» | Стандарт для игр с нулевой суммой; симметричный сигнал обучения. |
| Лиговая игра | «Self-play на основе популяции» | Прошлые + текущие + «эксплуататоры» сэмплируются как противники. |
| Вознаграждение от верификатора | «Проверяемый RL» | Вознаграждение исходит от детерминированного проверяющего (тесты проходят, ответ совпадает). |
| Процессное вознаграждение | «PRM» | Оценивает каждый шаг рассуждения, а не только финальный ответ. |
