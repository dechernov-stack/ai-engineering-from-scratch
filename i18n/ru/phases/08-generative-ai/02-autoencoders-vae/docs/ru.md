# Автокодировщики и вариационные автокодировщики (VAE)

> Обычный автокодировщик сжимает, затем восстанавливает. Он запоминает. Он не генерирует. Добавьте один трюк — заставьте код выглядеть гауссовским — и вы получите генератор выборок. Именно этот трюк, репараметризация `z = μ + σ·ε`, объясняет, почему у каждой модели латентной диффузии и flow-matching для изображений, которую вы используете в 2026 году, на входе стоит VAE.

## Проблема

Сожмите 784-пиксельную цифру MNIST в 16-числовой код, затем восстановите. Обычный автокодировщик отлично справится с MSE реконструкции, но пространство кодов окажется ухабистой мешаниной. Возьмите случайную точку в пространстве кодов, декодируйте её — и получите шум. У него нет генератора выборок. Это модель сжатия, наряженная во что-то другое.

На самом деле вам нужно: (a) пространство кодов — это чистое, гладкое распределение, из которого можно сэмплировать — скажем, изотропное гауссово `N(0, I)`, (b) декодирование любого сэмпла даёт правдоподобную цифру, и (c) энкодер и декодер всё ещё хорошо сжимают. Три цели, одна архитектура, одна функция потерь.

VAE Кингмы 2013 года решает это, обучая энкодер выдавать *распределение* `q(z|x) = N(μ(x), σ(x)²)`, притягивая это распределение к априорному `N(0, I)` через штраф KL, а затем сэмплируя `z` из `q(z|x)` перед декодированием. На этапе вывода энкодер отбрасывается, сэмплируется `z ~ N(0, I)`, декодируется. Именно штраф KL заставляет пространство кодов быть структурированным.

В 2026 году VAE редко поставляются как самостоятельное решение — по качеству изображений их превзошла диффузия — но они остаются энкодером выбора для каждой модели латентной диффузии (SD 1/2/XL/3, Flux, AudioCraft). Изучите VAE — и вы изучите невидимый первый слой каждого пайплайна обработки изображений, которым вы пользуетесь.

## Концепция

![Autoencoder vs VAE: the reparameterization trick](../assets/vae.svg)

**Автокодировщик.** `z = encoder(x)`, `x̂ = decoder(z)`, потеря = `||x - x̂||²`. Пространство кодов неструктурировано.

**Энкодер VAE.** Выдаёт два вектора: `μ(x)` и `log σ²(x)`. Они определяют `q(z|x) = N(μ, diag(σ²))`.

**Трюк репараметризации.** Сэмплирование из `q(z|x)` недифференцируемо. Перепишем сэмпл как `z = μ + σ·ε`, где `ε ~ N(0, I)`. Теперь `z` — детерминированная функция от `(μ, σ)` плюс не-параметрический шум — градиенты текут через `μ` и `σ`.

**Функция потерь.** Evidence Lower BOund (ELBO), два слагаемых:

```
loss = reconstruction + β · KL[q(z|x) || N(0, I)]
     = ||x - x̂||²  + β · Σ_i ( σ_i² + μ_i² - log σ_i² - 1 ) / 2
```

Реконструкция подталкивает `x̂` к `x`. KL подталкивает `q(z|x)` к априорному распределению. Они находятся в компромиссе. Малое β (<1) = более резкие сэмплы, пространство кодов менее гауссово. Большое β (>1) = более чистое пространство кодов, более размытые сэмплы. β-VAE (Higgins 2017) сделал этот параметр знаменитым и дал старт исследованиям по разделению признаков (disentanglement).

**Сэмплирование.** На этапе вывода: берём `z ~ N(0, I)`, пропускаем через декодер. Один проход вперёд — без итеративного сэмплирования, как в диффузии.

## Соберите это

`code/main.py` реализует крошечный VAE без numpy или torch. Входные данные — 8-мерные синтетические данные, взятые из 2-компонентной гауссовой смеси в 8-мерном пространстве. Энкодер и декодер — MLP с одним скрытым слоем. Мы реализуем активацию tanh, прямой проход, функцию потерь и написанный вручную обратный проход. Это не продакшн — это педагогика.

### Шаг 1: прямой проход энкодера

```python
def encode(x, enc):
    h = tanh(add(matmul(enc["W1"], x), enc["b1"]))
    mu = add(matmul(enc["W_mu"], h), enc["b_mu"])
    log_sigma2 = add(matmul(enc["W_sig"], h), enc["b_sig"])
    return mu, log_sigma2
```

`log σ²` вместо `σ`, чтобы выход сети был неограниченным (softplus от σ — это ловушка: градиенты затухают при σ ≈ 0).

### Шаг 2: репараметризация и декодирование

```python
def reparameterize(mu, log_sigma2, rng):
    eps = [rng.gauss(0, 1) for _ in mu]
    sigma = [math.exp(0.5 * lv) for lv in log_sigma2]
    return [m + s * e for m, s, e in zip(mu, sigma, eps)]

def decode(z, dec):
    h = tanh(add(matmul(dec["W1"], z), dec["b1"]))
    return add(matmul(dec["W_out"], h), dec["b_out"])
```

### Шаг 3: ELBO

```python
def elbo(x, x_hat, mu, log_sigma2, beta=1.0):
    recon = sum((a - b) ** 2 for a, b in zip(x, x_hat))
    kl = 0.5 * sum(math.exp(lv) + m * m - lv - 1 for m, lv in zip(mu, log_sigma2))
    return recon + beta * kl, recon, kl
```

Точная замкнутая форма KL, поскольку оба распределения гауссовы. Не интегрируйте численно. Люди до сих пор в 2026 году поставляют код с оценками KL методом Монте-Карло — это в 3 раза медленнее без всякой причины.

### Шаг 4: генерация

```python
def sample(dec, z_dim, rng):
    z = [rng.gauss(0, 1) for _ in range(z_dim)]
    return decode(z, dec)
```

Вот и вся генеративная модель. Пять строк.

## Подводные камни

- **Коллапс апостериорного распределения (posterior collapse).** Слагаемое KL так агрессивно подталкивает `q(z|x) → N(0, I)`, что `z` не несёт никакой информации о `x`. Решение: β-аннелинг (начать с β=0, плавно довести до 1), free bits, или пропуск KL на неактивных измерениях.
- **Размытые сэмплы.** Гауссово правдоподобие декодера подразумевает реконструкцию по MSE, что байесовски оптимально для L2 (среднее значение) — среднее по набору правдоподобных цифр оказывается нечёткой цифрой. Решение: дискретный декодер (VQ-VAE, NVAE), либо использовать VAE только как энкодер и накладывать диффузию поверх латентов (именно это делает Stable Diffusion).
- **β слишком велико, слишком рано.** См. коллапс апостериорного распределения. Начните с β≈0.01 и плавно увеличивайте.
- **Слишком маленькая размерность латента.** 16-D работает для MNIST, 256-D — для ImageNet 256², 2048-D — для ImageNet 1024². VAE Stable Diffusion сжимает 512×512×3 → 64×64×4 (коэффициент понижения разрешения 32x по пространственной площади, 32x по каналам).

## Применение

Стек VAE 2026 года:

| Ситуация | Выбор |
|-----------|------|
| Энкодер латентов изображения для диффузии | VAE Stable Diffusion (`sd-vae-ft-ema`) или VAE Flux |
| Энкодер латентов аудио | Encodec (Meta), SoundStream, или DAC (Descript) |
| Видео-латенты | Пространственно-временные патчи Sora, Latte VAE, WAN VAE |
| Обучение разделённым представлениям | β-VAE, FactorVAE, TCVAE |
| Дискретные латенты (для моделирования трансформером) | VQ-VAE, RVQ (ResidualVQ) |
| Непрерывные латенты для генерации | Обычный VAE, затем кондиционирование flow/diffusion-модели в этом латентном пространстве |

Модель латентной диффузии — это VAE с диффузионной моделью, живущей между энкодером и декодером. VAE выполняет грубое сжатие, диффузионная модель делает основную работу. Та же схема для видео (VAE + видео-диффузионный DiT) и для аудио (Encodec + MusicGen трансформер).

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Автокодировщик | Сеть кодирование-декодирование | `x → z → x̂`, обучение на MSE. Не генеративная модель. |
| VAE | AE с генератором выборок | Энкодер выдаёт распределение, штраф KL формирует пространство кодов. |
| ELBO | Evidence lower bound | `log p(x) ≥ recon - KL[q(z\|x) \|\| p(z)]`; точна, когда `q = p(z\|x)`. |
| Репараметризация | `z = μ + σ·ε` | Переписывает стохастический узел как детерминированный + чистый шум. Позволяет обратное распространение через сэмплирование. |
| Приорное распределение | `p(z)` | Целевое распределение для латента, обычно `N(0, I)`. |
| Коллапс апостериорного распределения | «KL-слагаемое побеждает» | Энкодер игнорирует `x`, выдаёт априорное распределение; декодеру приходится галлюцинировать. |
| β-VAE | Настраиваемый вес KL | `loss = recon + β·KL`. Выше β = больше разделение признаков, но более размыто. |
| VQ-VAE | Дискретный латент | Замена непрерывного `z` ближайшим вектором кодовой книги; позволяет моделирование трансформером. |

## Заметка о продакшне: VAE — самый «горячий» участок в диффузионном сервере

В пайплайне Stable Diffusion / Flux / SD3 VAE вызывается дважды за запрос — один раз для кодирования (при img2img / inpainting) и один раз для декодирования. При разрешении 1024² проход декодера зачастую оказывается самым крупным пиком активационной памяти во всём пайплайне, поскольку он апсемплирует латенты `128×128×16` обратно до `1024×1024×3`. Отсюда два практических следствия:

- **Разбивайте декодирование на срезы или плитки.** `diffusers` предоставляет `pipe.vae.enable_slicing()` и `pipe.vae.enable_tiling()`. Тайлинг обменивает небольшой артефакт шва на `O(tile²)` памяти вместо `O(H·W)`. Это необходимо для 1024²+ на потребительских GPU.
- **bf16 декодер, fp32-арифметика для финального ресайза.** VAE SD 1.x был выпущен в fp32 и *молча выдаёт NaN* при приведении к fp16 на 1024²+. SDXL поставляется с `madebyollin/sdxl-vae-fp16-fix` — всегда предпочитайте вариант с исправлением для fp16 или используйте bf16.
