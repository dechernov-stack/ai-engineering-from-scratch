# Flow Matching и Rectified Flows

> Диффузионные модели требуют 20-50 шагов сэмплирования, потому что идут по искривлённому пути от шума к данным. Flow matching (Lipman et al., 2023) и rectified flow (Liu et al., 2022) обучали прямые пути. Чем прямее путь, тем меньше шагов и тем быстрее инференс. Stable Diffusion 3, Flux.1 и AudioCraft 2 — все перешли на flow matching в 2024 году.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 8 · 06 (DDPM), Phase 1 · Calculus
**Time:** ~45 minutes

## Проблема

Обратный процесс DDPM — это стохастическое блуждание на 1000 шагов от `N(0, I)` обратно к распределению данных. DDIM сжал это до 20-50 детерминированных шагов. Вы хотите меньше шагов — в идеале один. Препятствие в том, что ОДУ, решающее обратный процесс, жёсткое (stiff); путь искривлён.

Если бы вы могли обучить модель так, чтобы путь от шума к данным был *прямой линией*, один шаг Эйлера от `t=1` к `t=0` сработал бы. Flow matching строит это напрямую: определяется прямолинейная интерполяция от `x_1 ∼ N(0, I)` до `x_0 ∼ data`, обучается векторное поле `v_θ(x, t)`, согласующееся с её производной по времени, а при инференсе выполняется интегрирование.

Rectified flow (Liu 2022) идёт дальше: итеративно выпрямляет пути с помощью процедуры reflow, которая даёт постепенно всё более линейное ОДУ. После двух итераций reflow 2-шаговый сэмплер по качеству соответствует 50-шаговому DDPM.

## Концепция

![Flow matching: straight-line interpolation between noise and data](../assets/flow-matching.svg)

### Прямолинейный поток

Определим:

```
x_t = t · x_1 + (1 - t) · x_0,   t ∈ [0, 1]
```

где `x_0 ~ data` и `x_1 ~ N(0, I)`. Производная по времени вдоль этой прямой линии постоянна:

```
dx_t / dt = x_1 - x_0
```

Определим нейросетевое векторное поле `v_θ(x_t, t)` и обучим его согласовываться с этой производной:

```
L = E_{x_0, x_1, t} || v_θ(x_t, t) - (x_1 - x_0) ||²
```

Это функция потерь **conditional flow matching** (Lipman 2023). Обучение не требует симуляции: вы никогда не разворачиваете ОДУ. Просто сэмплируете `(x_0, x_1, t)` и выполняете регрессию.

### Сэмплирование

При инференсе интегрируем обученное векторное поле *назад* во времени:

```
x_{t-Δt} = x_t - Δt · v_θ(x_t, t)
```

Начинаем с `x_1 ~ N(0, I)`, делаем шаги Эйлера вниз до `t=0`.

### Rectified flow (Liu 2022)

Прямолинейный поток работает, но обученные пути *на самом деле не прямые* — они искривляются, потому что много `x_0` могут отображаться в одно и то же `x_1`. Шаг reflow в rectified flow:

1. Обучить модель потока v_1 со случайными парами.
2. Сэмплировать N пар `(x_1, x_0)`, интегрируя v_1 от `x_1` до точки приземления `x_0`.
3. Обучить v_2 на этих парных примерах. Поскольку пары теперь "сопоставлены через ОДУ" (ODE-matched), прямолинейный интерполянт между ними реально более плоский.
4. Повторить.

На практике 2 итерации reflow дают почти линейный путь, что позволяет выполнять инференс за 2-4 шага. SDXL-Turbo, SD3-Turbo, LCM — все эти модели дистиллированы из flow matching.

### Почему это победило в области изображений в 2024 году

Три причины:

1. **Обучение без симуляции** — нет разворачивания ОДУ во время обучения, тривиальная реализация.
2. **Лучшая геометрия потерь** — прямые пути имеют постоянное отношение сигнал/шум, тогда как ε-потеря DDPM имеет плохое SNR на краях расписания.
3. **Более быстрый инференс** — 4-8 шагов с качеством SDXL-Turbo; 1 шаг с consistency-дистилляцией.

## Flow matching vs DDPM — точная связь

Flow matching с гауссовым условным путём — это диффузия *с конкретным расписанием шума*. Выберите расписание `x_t = α(t) x_0 + σ(t) x_1`, и flow matching восстанавливает переформулированную по Стратоновичу диффузию с `v = α'·x_0 - σ'·x_1`. Эти два подхода алгебраически эквивалентны для гауссовых путей.

Что добавил flow matching: *ясность* цели (простая скорость), более чистую функцию потерь и возможность экспериментировать с негауссовыми интерполянтами.

## Реализуйте это

`code/main.py` реализует 1-мерный flow matching на смеси двух гауссиан. Векторное поле `v_θ(x, t)` — крошечный MLP, обученный с прямолинейной целью. При инференсе интегрируйте за 1, 2, 4 и 20 шагов Эйлера и сравните качество сэмплов.

### Шаг 1: функция потерь обучения

```python
def train_step(x0, net, rng, lr):
    x1 = rng.gauss(0, 1)
    t = rng.random()
    x_t = t * x1 + (1 - t) * x0
    target = x1 - x0
    pred = net_forward(x_t, t)
    loss = (pred - target) ** 2
    # backprop + update
```

### Шаг 2: многошаговый инференс

```python
def sample(net, num_steps):
    x = rng.gauss(0, 1)
    for i in range(num_steps):
        t = 1.0 - i / num_steps
        dt = 1.0 / num_steps
        x -= dt * net_forward(x, t)
    return x
```

### Шаг 3: сравните количество шагов

Ожидайте, что 4-шаговый сэмплер уже будет соответствовать качеству 20-шагового — это большое дело для латентности.

## Подводные камни

- **Параметризация времени.** Flow matching использует `t ∈ [0, 1]` с `t=0` на данных, `t=1` на шуме. DDPM использует `t ∈ [0, T]` с `t=0` на данных, `t=T` на шуме. Направление одно, масштаб разный. В статьях это постоянно путают.
- **Выбор расписания.** Прямая линия rectified flow — это "то самое" расписание flow matching, но можно использовать cosine или логит-нормальное сэмплирование t (так делает SD3) для лучшего покрытия масштабов.
- **Стоимость reflow.** Генерация парного датасета для reflow — это полный проход инференса на каждый сэмпл. Выполняйте reflow только когда вам действительно нужен инференс за 1-2 шага.
- **Classifier-free guidance всё ещё применим.** Просто замените ε на v в линейной комбинации: `v_cfg = (1+w) v_cond - w v_uncond`.

## Применение

| Сценарий использования | Стек 2026 |
|----------|-----------|
| Text-to-image, лучшее качество | Flow matching: SD3, Flux.1-dev |
| Text-to-image, 1-4 шага | Дистиллированный flow matching: Flux.1-schnell, SD3-Turbo, SDXL-Turbo |
| Инференс в реальном времени | Consistency-дистилляция из базы с flow matching (LCM, PCM) |
| Генерация аудио | Flow matching: Stable Audio 2.5, AudioCraft 2 |
| Генерация видео | Flow matching, смешанный с диффузией (Sora, Veo, Stable Video) |
| Наука / физика (траектории частиц, молекулы) | Flow matching + эквивариантное векторное поле |

Когда в статье в 2025-2026 годах написано "быстрее диффузии", почти всегда речь идёт о flow matching + дистилляции.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Flow matching | "Прямолинейная диффузия" | Обучение `v_θ(x, t)` согласовываться с `x_1 - x_0` вдоль интерполянта. |
| Rectified flow | "Reflow" | Итеративная процедура, выпрямляющая обученные потоки. |
| Velocity field (поле скоростей) | "v_θ" | Выход модели — направление движения `x_t`. |
| Прямолинейный интерполянт | "Путь" | `x_t = (1-t)·x_0 + t·x_1`; тривиальная целевая производная. |
| Euler-сэмплер | "ОДУ-решатель 1-го порядка" | Простейший интегратор; хорошо работает, когда пути прямые. |
| Логит-нормальное t | "Сэмплирование SD3" | Концентрация сэмплирования `t` вокруг средних значений, где градиенты сильнее всего. |
| Consistency-дистилляция | "1-шаговый сэмплер" | Обучение студента напрямую отображать любое `x_t` в `x_0`. |
| CFG со скоростью | "v-CFG" | `v_cfg = (1+w) v_cond - w v_uncond`; тот же трюк, новая переменная. |

## Заметка о продакшне: Flux.1-schnell — самый быстрый flow matching

Победа flow matching в продакшне — это Flux.1-schnell, flow-matched DiT, дистиллированный до 1-4 шагов инференса при сохранении качества уровня Flux-dev. Ноутбук Нильса "Run Flux on an 8GB machine" — эталонный рецепт развёртывания: кодирование T5 + CLIP, квантованный denoise MMDiT (за 4 шага для schnell против 50 для dev), декодирование VAE. Расчёт стоимости:

| Вариант | Шаги | Латентность при 1024² на L4 | Общие FLOPs (относительно) |
|---------|-------|------------------------|------------------------|
| Flux.1-dev (сырой) | 50 | ~15 с | 1.0× |
| Flux.1-schnell | 4 | ~1.2 с | 0.08× (в 12× быстрее) |
| SDXL-base | 30 | ~4 с | 0.25× |
| SDXL-Lightning 2-step | 2 | ~0.3 с | 0.03× |

Правило продакшна: **flow-matched база + дистилляция = стандарт 2026 года для быстрого text-to-image.** Каждый крупный поставщик выпускает эту комбинацию: SD3-Turbo (SD3 + flow + дистилляция), Flux-schnell (Flux-dev + выпрямление rectified-flow), CogView-4-Flash. Чисто диффузионные базы существуют только для legacy-чекпойнтов.
