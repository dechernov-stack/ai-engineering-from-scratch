# Генерация аудио

> Аудио — это одномерный сигнал с частотой дискретизации 16-48 кГц. Пятисекундный клип — это 80-240 тыс. сэмплов. Ни один трансформер не может обрабатывать такую последовательность напрямую через attention. Решение, используемое во всех промышленных аудиомоделях 2026 года, одно и то же: нейронный кодек (Encodec, SoundStream, DAC) сжимает аудио в дискретные токены с частотой 50-75 Гц, а трансформер или диффузионная модель генерирует эти токены.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 6 · 02 (Audio Features), Phase 6 · 04 (ASR), Phase 8 · 06 (DDPM)
**Time:** ~45 минут

## Проблема

Три задачи генерации аудио:

1. **Синтез речи (text-to-speech).** По тексту производится речь. Чистая речь узкополосна и обладает сильной фонетической структурой — хорошо решается с помощью трансформера над токенами. VALL-E (Microsoft), NaturalSpeech 3, ElevenLabs, OpenAI TTS.
2. **Генерация музыки.** По подсказке (текст, мелодия, аккордовая последовательность, жанр) производится музыка. Распределение гораздо шире. MusicGen (Meta), Stable Audio 2.5, Suno v4, Udio, Riffusion.
3. **Звуковые эффекты / саунд-дизайн.** По подсказке производится фоновый звук или шумовое оформление (Foley). AudioGen, AudioLDM 2, Stable Audio Open.

Все три задачи работают на одной и той же основе: нейронный аудиокодек + авторегрессионный генератор токенов или диффузионный генератор.

## Концепция

![Audio generation: codec tokens + transformer or diffusion](../assets/audio-generation.svg)

### Нейронные аудиокодеки

Encodec (Meta, 2022), SoundStream (Google, 2021), Descript Audio Codec (DAC, 2023). Сверточный энкодер сжимает волновую форму в вектор на каждый временной шаг; остаточная векторная квантизация (RVQ, residual vector quantization) преобразует каждый вектор в каскад из K индексов кодовой книги. Декодер выполняет обратное преобразование. 24 кГц аудио при 2 кбит/с с использованием 8 RVQ-кодовых книг с частотой 75 Гц = 600 токенов/сек.

```
waveform (16000 samples/sec)
    └─ encoder conv ─┐
                     ├─ RVQ layer 1 → indices at 75 Hz
                     ├─ RVQ layer 2 → indices at 75 Hz
                     ├─ ...
                     └─ RVQ layer 8
```

### Две генеративные парадигмы поверх кодека

**Токен-авторегрессия.** RVQ-токены выстраиваются в последовательность, и по ней запускается декодер-трансформер. MusicGen использует «отложенный параллелизм» (delayed parallel) для одновременной генерации K потоков кодовых книг со смещением по позиции для каждого потока. VALL-E генерирует речевые токены по текстовой подсказке + 3-секундному образцу голоса.

**Латентная диффузия.** Токены кодека упаковываются как непрерывные латенты либо моделируются с помощью категориальной диффузии. Stable Audio 2.5 использует flow matching на непрерывных аудиолатентах. AudioLDM 2 использует диффузию по цепочке текст-в-мел-спектрограмму-в-аудио.

Тенденция 2024-2026 годов: flow matching побеждает в генерации музыки (более быстрый инференс, более чистые сэмплы), в то время как токен-авторегрессия по-прежнему доминирует в речи, поскольку она естественно каузальна и хорошо работает в потоковом режиме.

## Реализация

`code/main.py` моделирует основную идею: обучение крошечного трансформера предсказания следующего токена на синтетических последовательностях «аудиотокенов», сгенерированных из двух различных «стилей» (чередующиеся низкие и высокие токены для стиля A, монотонное нарастание для стиля B). Обусловливание по стилю и сэмплирование.

### Шаг 1: синтетические аудиотокены

```python
def make_tokens(style, length, vocab_size, rng):
    if style == 0:  # "speech-like": alternating
        return [i % vocab_size for i in range(length)]
    # "music-like": ramp
    return [(i * 3) % vocab_size for i in range(length)]
```

### Шаг 2: обучение крошечного предсказателя токенов

Биграммный предсказатель, обусловленный стилем. Суть в самом паттерне: токены кодека → обучение с кросс-энтропией → авторегрессионное сэмплирование.

### Шаг 3: обусловленное сэмплирование

При заданном токене стиля и начальном токене сэмплируется следующий токен из предсказанного распределения. Продолжать на протяжении 20-40 токенов.

## Подводные камни

- **Качество кодека ограничивает качество вывода сверху.** Если кодек не может достоверно представить звук, никакое качество генератора не поможет. DAC сейчас — лучший открытый вариант.
- **Накопление ошибок RVQ.** Каждый слой RVQ моделирует остаток предыдущего. Ошибки первого слоя распространяются дальше. Сэмплирование с температурой 0 на более высоких слоях помогает.
- **Музыкальная структура.** 30 секунд токенов — это 20к+ токенов при 75 Гц. Тяжело для трансформеров. MusicGen использует скользящее окно + продолжение подсказки; Stable Audio использует более короткие клипы + кроссфейдинг.
- **Артефакты на границах.** Кроссфейдинг между сгенерированными клипами требует аккуратного перекрытия-сложения (overlap-add).
- **Аппетит к чистым данным.** Генераторам музыки нужны десятки тысяч часов лицензированной музыки. Иск RIAA против Suno / Udio (2024) вывел эту проблему на поверхность.
- **Этика клонирования голоса.** 3-секундного образца и текстовой подсказки достаточно для VALL-E / XTTS / ElevenLabs, чтобы клонировать голос. Каждая промышленная модель нуждается в обнаружении злоупотреблений + списках отказа.

## Упражнения

1. **Лёгкое.** Запустите `code/main.py` и явно задайте стиль. Убедитесь, что сгенерированные последовательности соответствуют паттерну стиля.
2. **Среднее.** Добавьте отложенное параллельное декодирование: смоделируйте 2 потока токенов, которые должны оставаться со смещением на 1 шаг. Обучите совместный предсказатель.
3. **Сложное.** Используйте HuggingFace transformers для локального запуска MusicGen-small. Сгенерируйте 10-секундный клип с тремя разными подсказками; проведите A/B-тест на соответствие стилю.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|-----------------|-----------------------|
| Codec | «Нейронное сжатие» | Энкодер / декодер для аудио; типичный вывод — токены с частотой 50-75 Гц. |
| RVQ | «Остаточный VQ» | Каскад из K квантизаторов; каждый моделирует остаток предыдущего. |
| Token | «Один символ кодека» | Дискретный индекс в кодовой книге; типично 1024 или 2048. |
| Delayed parallel | «Смещённые кодовые книги» | Генерация K потоков токенов со ступенчатым смещением для сокращения длины последовательности. |
| Flow matching | «Победа 2024 года для аудио» | Альтернатива диффузии с более прямым путём; более быстрое сэмплирование. |
| Voice prompt | «3-секундный образец» | Эмбеддинг диктора или префикс токенов, задающий клонируемый голос. |
| Mel spectrogram | «Визуализация» | Логарифмическая перцептивная спектрограмма амплитуды; используется во многих системах TTS. |
| Vocoder | «Из мела в волну» | Нейронный компонент, преобразующий мел-спектрограммы обратно в аудио. |

## Замечание о продакшне: аудио — это потоковая задача

Аудио — единственная выходная модальность, для которой пользователи ожидают, что она будет поступать *по мере генерации*, а не целиком сразу. В терминах продакшна это означает, что важен TPOT (Time Per Output Token, время на выходной токен), потому что целевая пропускная способность — это скорость прослушивания пользователем, а не скорость чтения. Для 16 кГц аудио, токенизированного с частотой ~75 токенов/секунду (Encodec), сервер должен генерировать ≥75 токенов/сек на пользователя, чтобы воспроизведение оставалось плавным.

Два архитектурных следствия:

- **Модели аудио на основе flow matching не могут нативно работать в потоковом режиме.** Stable Audio 2.5 и AudioCraft 2 рендерят клип фиксированной длины за один проход. Для потоковой передачи клип разбивается на части, а границы перекрываются — по сути, скользящая диффузия — добавляя 100-300мс накладных расходов по задержке по сравнению с AR-моделью на основе кодека.

Если продукт — «живой голосовой чат» или «продолжение музыки в реальном времени», выбирайте путь кодек + AR. Если это «отрендерить 30-секундный клип по запросу», flow matching выигрывает по качеству и общей задержке.
