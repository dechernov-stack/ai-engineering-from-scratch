# StyleGAN

> Большинство генераторов подмешивают `z` во все слои одновременно. StyleGAN разделил это на части: сначала отобразить `z` в промежуточное `w`, затем *инъецировать* `w` на каждом уровне разрешения через AdaIN. Это единственное изменение распутало латентное пространство и сделало фотореалистичные лица решённой задачей на семь лет вперёд.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 8 · 03 (GANs), Phase 4 · 08 (Normalization), Phase 3 · 07 (CNNs)
**Time:** ~45 минут

## Проблема

DCGAN отображает `z` в изображение через стек транспонированных свёрток. Проблема в том, что `z` управляет всем сразу — позой, освещением, идентичностью, фоном — всё это переплетено. Сдвиньтесь вдоль одной оси `z` — изменятся все четыре. Вы не можете попросить модель «тот же человек, другая поза», потому что представление не раскладывается таким образом.

Karras et al. (2019, NVIDIA) предложили: перестать подавать `z` напрямую в свёрточные слои. Подавать константный тензор `4×4×512` как вход сети. Обучить 8-слойный MLP, который отображает `z ∈ Z → w ∈ W`. Инъецировать `w` на каждом уровне разрешения через *adaptive instance normalization* (AdaIN): нормализовать каждую свёрточную карту признаков, затем масштабировать и сдвигать с помощью аффинных проекций `w`. Добавить пошаговый (per-layer) шум для стохастической детализации (поры кожи, пряди волос).

Результат: `W` имеет примерно ортогональные оси для «высокоуровневого стиля» (поза, идентичность) и «тонкого стиля» (освещение, цвет). Вы можете обменять стили между двумя изображениями, используя `w` изображения A для низкоразрешённых уровней и `w` изображения B — для высокоразрешённых. Это открыло путь к редактированию, кросс-доменной стилизации и целому направлению исследований «StyleGAN-инверсии».

## Концепция

![StyleGAN: mapping network + AdaIN + per-layer noise](../assets/stylegan.svg)

**Сеть отображения (mapping network).** `f: Z → W`, 8-слойный MLP. `Z = N(0, I)^512`. `W` не обязано быть гауссовым — оно обучается форме, адаптированной к данным.

**Сеть синтеза.** Начинается с обученной константы `4×4×512`. Каждый блок разрешения: `upsample → conv → AdaIN(w_i) → noise → conv → AdaIN(w_i) → noise`. Разрешения удваиваются: 4, 8, 16, 32, 64, 128, 256, 512, 1024.

**AdaIN.**

```
AdaIN(x, y) = y_scale · (x - mean(x)) / std(x) + y_bias
```

где `y_scale` и `y_bias` получаются из аффинных проекций `w`. Нормализуем каждую карту признаков, затем заново стилизуем. «Стиль» здесь — это статистики первого и второго порядка карты признаков.

**Пошаговый шум.** Одноканальный гауссов шум добавляется к каждой карте признаков, масштабируемый обученным коэффициентом на канал. Управляет стохастической детализацией, не влияя на глобальную структуру.

**Приём усечения (truncation trick).** На инференсе семплируется `z`, вычисляется `w = mapping(z)`, затем `w' = ŵ + ψ·(w - ŵ)`, где `ŵ` — среднее `w` по многим выборкам. `ψ < 1` обменивает разнообразие на качество. Почти каждая демонстрация StyleGAN использует `ψ ≈ 0.7`.

## StyleGAN 1 → 2 → 3

| Версия | Год | Инновация |
|---------|------|------------|
| StyleGAN | 2019 | Сеть отображения + AdaIN + шум + прогрессивное наращивание (progressive growing). |
| StyleGAN2 | 2020 | Демодуляция весов заменяет AdaIN (устраняет артефакты-капли); архитектура с пропусками/остаточными связями; регуляризация длины пути. |
| StyleGAN3 | 2021 | Свёртка без алиасинга + эквивариантные ядра; устраняет прилипание текстуры к пиксельной сетке. |
| StyleGAN-XL | 2022 | Условный по классам, 1024², ImageNet. |
| R3GAN | 2024 | Ребрендинг с усиленной регуляризацией; сокращает разрыв с диффузией на FFHQ-1024 при в 20 раз меньшем числе параметров. |

В 2026 году StyleGAN3 остаётся инструментом по умолчанию для (a) фотореализма узкой области при высоком FPS, (b) адаптации к домену на небольшом числе примеров (обучение на новом датасете из 100 изображений, с замороженной сетью отображения), (c) редактирования на основе инверсии (найти `w`, восстанавливающее реальную фотографию, затем редактировать это `w`). Для генерации изображений по тексту в открытом домене это не тот инструмент — там работает диффузия.

## Реализуйте это

`code/main.py` реализует игрушечный «style-GAN lite» в 1-D: MLP отображения, функцию синтеза, которая берёт обученный константный вектор и модулирует его масштабом/смещением, выведенными из `w`, и пошаговый шум. Это показывает, что инъекция `w` через аффинную модуляцию соответствует или превосходит конкатенацию `z` со входом генератора.

### Шаг 1: сеть отображения

```python
def mapping(z, M):
    h = z
    for i in range(num_layers):
        h = leaky_relu(add(matmul(M[f"W{i}"], h), M[f"b{i}"]))
    return h
```

### Шаг 2: адаптивная нормализация по экземплярам

```python
def adain(x, w_scale, w_bias):
    mu = mean(x)
    sd = std(x)
    x_norm = [(xi - mu) / (sd + 1e-8) for xi in x]
    return [w_scale * xi + w_bias for xi in x_norm]
```

Масштаб и смещение для каждой карты признаков получаются из `w` через линейную проекцию.

### Шаг 3: пошаговый шум

```python
def add_noise(x, sigma, rng):
    return [xi + sigma * rng.gauss(0, 1) for xi in x]
```

Sigma для каждого канала обучаема.

## Подводные камни

- **Артефакты-капли.** StyleGAN 1 производил бугристую каплю в картах признаков, потому что AdaIN обнулял среднее. Демодуляция весов в StyleGAN 2 исправляет это, масштабируя веса свёртки вместо активаций.
- **Прилипание текстуры.** Текстуры в StyleGAN 1 и 2 следовали пиксельным координатам, а не координатам объекта (заметно при интерполяции). Свёртки без алиасинга в StyleGAN 3 исправляют это с помощью оконных sinc-фильтров.
- **Покрытие мод.** Усечение `ψ < 0.7` выглядит чисто, но семплирует из узкого конуса; используйте `ψ = 1.0`, если нужно разнообразие.
- **Инверсия теряет информацию.** Инверсия реальной фотографии в `W` обычно выполняется через оптимизацию или энкодер (e4e, ReStyle, HyperStyle). Результаты дрейфуют при большом числе итераций.

## Применение

| Сценарий использования | Подход |
|----------|----------|
| Фотореалистичные человеческие лица (аниме, продукт, узкая область) | StyleGAN3 FFHQ / кастомная дообучка |
| Редактирование лица по фото | инверсия e4e + направления StyleSpace / InterFaceGAN |
| Замена лица / реэнактмент | StyleGAN + энкодер + блендинг |
| Пайплайны аватаров | StyleGAN3 с ADA для дообучки на малых данных |
| Адаптация к домену по нескольким изображениям | Заморозить сеть отображения, дообучить синтез |
| Мультимодальная или текстово-обусловленная генерация | Не используйте — используйте диффузию |

Для продуктовых демо, где ответом служит «фото лица человека», StyleGAN превосходит диффузию по стоимости инференса (один прямой проход, <10мс на 4090) и резкости при том же уровне качества.

## Ключевые термины

| Термин | Как говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Mapping network (сеть отображения) | «Этот MLP» | `f: Z → W`, 8 слоёв, разделяет геометрию латентного пространства и статистику данных. |
| W space (пространство W) | «Пространство стиля» | Выход сети отображения; примерно распутанное. |
| AdaIN | «Адаптивная инстанс-нормализация» | Нормализовать карту признаков, затем масштабировать + сдвинуть проекцией от `w`. |
| Truncation trick (приём усечения) | «Psi» | `w = mean + ψ·(w - mean)`, ψ<1 обменивает разнообразие на качество. |
| Path-length regularization (регуляризация длины пути) | «PL reg» | Штрафует большие изменения изображения на единицу изменения `w`; делает `W` более гладким. |
| Weight demodulation (демодуляция весов) | «Исправление из StyleGAN2» | Нормализовать веса свёртки вместо активаций; устраняет артефакты-капли. |
| Alias-free (без алиасинга) | «Приём StyleGAN3» | Оконные sinc-фильтры; устраняет прилипание текстуры к пиксельной сетке. |
| Inversion (инверсия) | «Найти w для реального изображения» | Оптимизировать или кодировать `x → w` так, чтобы `G(w) ≈ x`. |

## Заметка о продакшне: почему StyleGAN всё ещё используется в 2026 году

StyleGAN3 на 4090 генерирует лицо FFHQ 1024² менее чем за 10 мс — `num_steps = 1`, без декодирования VAE, без прохода cross-attention. В продакшн-терминах это минимальная возможная задержка для любого генератора изображений. Пайплайн SDXL + VAE-decode на 50 шагов при том же разрешении занимает ~3 секунды. Это разрыв в **300 раз**, и для продуктов в узкой области (сервисы аватаров, пайплайны ID-документов, генерация стоковых лиц) он выигрывает по совокупной стоимости владения (TCO).

Два эксплуатационных следствия:

- **Нет ни планировщика, ни батчера.** Статичный батч при целевой загрузке оптимален. Непрерывное батчирование (необходимое для LLM и диффузии) не даёт никакой выгоды, потому что каждый запрос требует одинакового количества FLOPs.
- **Усечение `ψ` — это регулятор безопасности.** `ψ < 0.7` семплирует из узкого конуса диапазона сети отображения. Это единственный рычаг, которым располагает слой обслуживания над разнообразием выборки. Понижайте `ψ` при пиковой нагрузке, повышайте для премиум-пользователей.
