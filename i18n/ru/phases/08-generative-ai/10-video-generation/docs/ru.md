# Генерация видео

> Изображение — это 2-мерный тензор. Видео — 3-мерный. Теория та же; вычисления сложнее в 10-100 раз. OpenAI Sora (февраль 2024) доказала, что это возможно. К 2026 году Veo 2, Kling 1.5, Runway Gen-3, Pika 2.0 и WAN 2.2 выпускают готовое к продакшену видео из текста в разрешении 1080p — а стек с открытыми весами (CogVideoX, HunyuanVideo, Mochi-1, WAN 2.2) отстаёт на 12 месяцев.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 8 · 07 (Latent Diffusion), Phase 7 · 09 (ViT), Phase 8 · 06 (DDPM)
**Time:** ~45 минут

## Проблема

10-секундное видео в 1080p при 24 кадрах/с — это 240 кадров по 1920×1080×3 пикселя. Это ~1,5 ГБ сырых данных на клип. Диффузия в пространстве пикселей невыполнима. Вам нужны:

1. **Пространственно-временное сжатие.** VAE, который кодирует не кадры, а видео — в последовательность пространственно-временных патчей.
2. **Временная согласованность.** Кадры должны сохранять содержание, освещение и идентичность объектов на протяжении секунд. Сеть должна моделировать движение.
3. **Вычислительный бюджет.** Обучение на видео в 10-100 раз дороже, чем на изображениях того же размера модели.
4. **Кондиционирование.** Текст, изображение (первый кадр), аудио или другое видео. Большинство продакшен-моделей принимают все четыре варианта.

Архитектура, решившая эту проблему, — **Diffusion Transformer (DiT)**, применённый к пространственно-временным патчам, обученный на огромных датасетах (промпт, подпись, видео). Та же функция потерь диффузии, что и в уроке 06.

## Концепция

![Video diffusion: patchify, DiT, decode](../assets/video-generation.svg)

### Patchify

Закодируйте видео с помощью 3D VAE (обученное пространственно-временное сжатие). Латент имеет форму `[T_latent, H_latent, W_latent, C_latent]`. Разбейте на патчи размера `[t_p, h_p, w_p]`. Для моделей в стиле Sora используется `t_p = 1` (патчи по кадрам) или `t_p = 2` (каждые два кадра). 10-секундное видео в 1080p сжимается до ~20 000-100 000 патчей.

### Пространственно-временной DiT

Трансформер обрабатывает плоскую последовательность патчей. Каждый патч имеет 3D позиционное вложение (время + y + x). Внимание обычно факторизовано:

- **Пространственное внимание** внутри патчей каждого кадра.
- **Временное внимание** между кадрами в одной и той же пространственной позиции.
- **Полное 3D-внимание** в 16-100 раз дороже; используется только при низком разрешении или в исследованиях.

### Текстовое кондиционирование

Cross-attention с большим текстовым энкодером (T5-XXL для Sora, CogVideoX-5B использует T5-XXL). Длинные промпты имеют значение — обучающий набор Sora содержал подробные повторные подписи, сгенерированные GPT, в среднем по 200 токенов на клип.

### Обучение

Стандартная функция потерь диффузии (предсказание ε или v) над пространственно-временными латентами. Данные: веб-видео + ~100 млн отобранных клипов + синтетические текстовые подписи. Вычисления: 10 000+ GPU-часов даже для небольшого исследовательского запуска; масштаб Sora — 100 000+.

## Реализация

`code/main.py` моделирует основную идею пространственно-временного DiT: разбиваем на патчи небольшое синтетическое видео, добавляем позиционное вложение для каждого патча и денойзим всю последовательность с помощью трансформерного внимания над патчами. Без numpy; чистый Python. Мы показываем, что временная согласованность возникает даже в 1-мерном случае, когда патчи соседних кадров используют общий денойзер и позиционные вложения.

### Шаг 1: разбиение на патчи синтетического 1-мерного «видео»

```python
def make_video(T_frames=8, rng=None):
    # a "video" is a sequence of 1-D values following a smooth trajectory
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### Шаг 2: позиционное вложение для каждого кадра

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### Шаг 3: денойзер видит всю последовательность

Вместо того чтобы денойзить каждый кадр независимо, наша маленькая сеть объединяет значения всех кадров + их позиционные вложения и предсказывает шум для всех кадров совместно.

### Шаг 4: тест временной согласованности

После обучения сгенерируйте видео. Измерьте разницу между соседними кадрами. Если модель усвоила временную структуру, разницы остаются меньше, чем при независимой генерации каждого кадра.

## Подводные камни

- **Независимая генерация по кадрам = мерцание.** Если запустить диффузию изображений на каждом кадре отдельно, вывод будет мерцать, потому что шум для каждого кадра независим. Видео-диффузия решает это, связывая кадры через внимание или общий шум.
- **Наивное 3D-внимание = OOM.** Полное 3D-внимание на 10-секундном латенте 1080p — это сотни миллиардов операций. Факторизуйте на пространственное + временное.
- **Разметка данных важнее размера.** Главное улучшение Sora по сравнению с предыдущими работами — обучение на подписях, детализированных примерно в 10 раз сильнее (клипы переразмечены GPT-4). Технический отчёт OpenAI прямо об этом говорит.
- **Кондиционирование по первому кадру.** Большинство продакшен-моделей также принимают изображение в качестве первого кадра. Это режим «изображение в видео» (image-to-video); обучение включает этот вариант.
- **Дрейф физики.** Длинные клипы (>10с) накапливают тонкие несогласованности. Помогает генерация со скользящим окном + привязка к ключевым кадрам.

## Заметка о продакшене: латенты видео — это проблема пропускной способности памяти

10-секундный клип в 1080p при 24 кадрах/с — это 240 кадров × 1920 × 1080 × 3 ≈ 1,5 ГБ сырых пикселей. После 4-кратного сжатия видео-VAE (`2 × spatial × 2 × temporal`) латент составляет ~100 МБ на запрос. Пропустите это через пространственно-временной DiT за 30 шагов с батчем 1 — и вы перемещаете ~3 ГБ на шаг через HBM — узким местом является пропускная способность памяти, а не FLOPs.

Три рычага продакшена, прямо из литературы по продакшен-инференсу (глава об инференсе):

- **TP по всему DiT.** Модели текст-в-видео обычно содержат ≥10 млрд параметров. TP=4 на 4 H100 — стандарт; PP=2 × TP=2 для моделей класса 405B. Задержка на шаг падает примерно линейно с ростом TP вплоть до стены all-reduce.
- **Батчинг кадров = непрерывный батчинг.** Во время генерации видео концептуально является батчем кадров, связанных вниманием. Непрерывный батчинг (планирование на лету) применим: начинайте рендерить кадр `t+1`, пока кадр `t-1` возвращается, если архитектура модели допускает генерацию со скользящим окном.
- **Кэш префилла на уровне клипа.** Для image-to-video кондиционирование по первому кадру аналогично префиллу промпта в LLM: вычисляйте его один раз, переиспользуйте в проходах временного декодера. Это фактически KV-кэш для видео.
