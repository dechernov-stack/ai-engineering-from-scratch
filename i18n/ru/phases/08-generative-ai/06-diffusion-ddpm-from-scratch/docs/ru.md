# Диффузионные модели — DDPM с нуля

> Хо, Джейн и Эббил (2020) дали области рецепт, от которого она не смогла отказаться. Уничтожайте данные шумом за тысячу маленьких шагов. Обучите одну нейросеть предсказывать этот шум. На этапе инференса обратите процесс вспять. Сегодня каждая мейнстримная модель для изображений, видео, 3D и музыки работает по этому циклу, возможно, с добавлением приёмов flow matching или consistency поверх него.

## Проблема

Вам нужен сэмплер для `p_data(x)`. GAN играют в минимаксную игру, которая часто расходится. VAE выдают размытые сэмплы из гауссовского декодера. На самом деле вам нужна обучающая целевая функция, которая (а) представляет собой единственный устойчивый лосс (без седловой точки, без минимакса), (б) является нижней границей на `log p(x)` (чтобы у вас были правдоподобия), и (в) даёт сэмплы качества уровня SOTA.

У Соль-Дикштейна и соавторов (2015) был теоретический ответ: определить марковскую цепь `q(x_t | x_{t-1})`, которая постепенно добавляет гауссовский шум, и обучить обратную цепь `p_θ(x_{t-1} | x_t)` для удаления шума. Хо, Джейн и Эббил (2020) показали, что лосс можно упростить до одной строки — предсказывать шум — и привели математику в порядок. В 2020 году это было курьёзом. В 2021 году это дало сэмплы state-of-the-art качества. В 2022 году это стало Stable Diffusion. В 2026 году это субстрат.

## Концепция

![DDPM: forward noise, reverse denoise](../assets/ddpm.svg)

**Прямой процесс `q`.** Добавляем гауссовский шум за `T` маленьких шагов. Замкнутая форма — причина, по которой математика поддаётся вычислению, — заключается в том, что кумулятивный шаг также является гауссовским:

```
q(x_t | x_0) = N( sqrt(α̅_t) · x_0,  (1 - α̅_t) · I )
```

где `α̅_t = ∏_{s=1..t} (1 - β_s)` для расписания `β_t`. Возьмите `β_t` от 1e-4 до 0.02 линейно за T=1000 шагов, и `x_T` приблизительно равно `N(0, I)`.

**Обратный процесс `p_θ`.** Обучите нейросеть `ε_θ(x_t, t)`, которая предсказывает добавленный шум. Имея `x_t`, удаляем шум по формуле:

```
x_{t-1} = (1 / sqrt(α_t)) · ( x_t - (β_t / sqrt(1 - α̅_t)) · ε_θ(x_t, t) )  +  σ_t · z
```

где `σ_t` — это либо `sqrt(β_t)`, либо обученная дисперсия. Выражение некрасивое, но это просто алгебра — решение относительно `x_{t-1}` по апостериорному распределению `q(x_{t-1} | x_t, x_0)` с подстановкой `x_0` его предсказанной по шуму оценкой.

**Обучающий лосс.**

```
L_simple = E_{x_0, t, ε} [ || ε - ε_θ( sqrt(α̅_t) · x_0 + sqrt(1 - α̅_t) · ε,  t ) ||² ]
```

Берём сэмпл `x_0` из данных, выбираем случайный `t`, сэмплируем `ε ~ N(0, I)`, вычисляем зашумлённый `x_t` за один шаг по замкнутой формуле и регрессируем на шум. Один лосс, без минимакса, без KL, без приёмов репараметризации.

**Сэмплирование.** Начинаем с `x_T ~ N(0, I)`. Итерируем обратный шаг от `t = T` до `1`. Готово.

## Почему это работает

Три интуиции:

1. **Удаление шума — лёгкая задача; генерация — трудная.** При `t=T` данные представляют собой чистый шум — сети нужно решить тривиальную задачу. При `t=0` сети нужно лишь очистить несколько пикселей. При промежуточных `t` задача сложна, но через одни и те же веса проходит множество градиентов со всех уровней шума.

2. **Сопоставление скоров под маской.** Венсан (2011) доказал, что предсказание шума эквивалентно оцениванию `∇_x log q(x_t | x_0)`, то есть *скора*. Обратное СДУ использует этот скор, чтобы идти вверх по градиенту плотности — это управляемое случайное блуждание в сторону областей высокой вероятности.

3. **ELBO сводится к простому MSE.** Полная вариационная нижняя граница содержит KL-слагаемое на каждом временном шаге. При параметризации DDPM эти KL-слагаемые упрощаются до MSE на предсказании шума с определёнными коэффициентами; Хо отбросил коэффициенты (назвав это «simple» лоссом), и качество *улучшилось*.

## Постройте это

`code/main.py` реализует одномерный DDPM. Данные — это смесь с двумя модами. «Сеть» — это крошечный MLP, который принимает `(x_t, t)` и выдаёт предсказанный шум. Обучение — это лосс в одну строку. Сэмплирование итерирует обратную цепь.

### Шаг 1: прямое расписание (замкнутая форма)

```python
betas = [1e-4 + (0.02 - 1e-4) * t / (T - 1) for t in range(T)]
alphas = [1 - b for b in betas]
alpha_bars = []
cum = 1.0
for a in alphas:
    cum *= a
    alpha_bars.append(cum)
```

### Шаг 2: сэмплируем `x_t` за один шаг

```python
def forward_sample(x0, t, alpha_bars, rng):
    a_bar = alpha_bars[t]
    eps = rng.gauss(0, 1)
    x_t = math.sqrt(a_bar) * x0 + math.sqrt(1 - a_bar) * eps
    return x_t, eps
```

### Шаг 3: один шаг обучения

```python
def train_step(x0, model, alpha_bars, rng):
    t = rng.randrange(T)
    x_t, eps = forward_sample(x0, t, alpha_bars, rng)
    eps_hat = model_forward(model, x_t, t)
    loss = (eps - eps_hat) ** 2
    return loss, gradient_step(model, ...)
```

### Шаг 4: обратное сэмплирование

```python
def sample(model, alpha_bars, T, rng):
    x = rng.gauss(0, 1)
    for t in range(T - 1, -1, -1):
        eps_hat = model_forward(model, x, t)
        beta_t = 1 - alphas[t]
        x = (x - beta_t / math.sqrt(1 - alpha_bars[t]) * eps_hat) / math.sqrt(alphas[t])
        if t > 0:
            x += math.sqrt(beta_t) * rng.gauss(0, 1)
    return x
```

Для одномерной задачи с 40 временными шагами и MLP на 24 единицы это обучается воспроизводить двумодовую смесь примерно за 200 эпох.

## Обусловливание по времени

Сети нужно знать, какой временной шаг она сейчас обрабатывает (удаляет шум). Два стандартных варианта:

- **Синусоидальный эмбеддинг.** Как позиционное кодирование в Transformer. `embed(t) = [sin(t/ω_0), cos(t/ω_0), sin(t/ω_1), ...]`. Пропускаем через MLP, транслируем в сеть.
- **Обусловливание через FiLM / group-norm.** Проецируем эмбеддинг в покомпонентные масштаб/сдвиг (FiLM) на каждом блоке.

Наш игрушечный код использует синусоидальное кодирование → конкатенацию. Производственные U-Net используют FiLM.

## Подводные камни

- **Расписание имеет большое значение.** Линейное `β` — это значение по умолчанию в DDPM, но косинусное расписание (Nichol & Dhariwal, 2021) даёт лучший FID при тех же вычислительных затратах. Переключайте расписания, если качество выходит на плато.
- **Эмбеддинг временного шага хрупок.** Передача сырого `t` как числа с плавающей точкой работает для игрушечной одномерной задачи, но не работает для изображений; всегда используйте полноценный эмбеддинг.
- **V-предсказание против ε-предсказания.** В узких режимах (очень маленькое или очень большое t) у `ε` плохое отношение сигнал/шум. V-предсказание (`v = α·ε - σ·x`) более стабильно; SDXL, SD3 и Flux используют его.
- **Classifier-free guidance.** На этапе инференса вычисляем как условное, так и безусловное `ε`, затем `ε_cfg = (1 + w) · ε_cond - w · ε_uncond` с `w ≈ 3-7`. Рассматривается в уроке 08.
- **1000 шагов — это много.** В продакшене используют DDIM (20-50 шагов), DPM-Solver (10-20 шагов) или дистилляцию (1-4 шага). См. урок 12.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Прямой процесс | «Добавление шума» | Фиксированная марковская цепь `q(x_t \| x_{t-1})`, разрушающая данные. |
| Обратный процесс | «Удаление шума» | Обученная цепь `p_θ(x_{t-1} \| x_t)`, восстанавливающая данные. |
| β-расписание | «Шумовая лестница» | Дисперсия на каждом шаге; линейная, косинусная или сигмоидная. |
| α̅ | «Альфа с чертой» | Кумулятивное произведение `∏(1 - β)`; даёт замкнутую форму `x_t` из `x_0`. |
| Simple loss | «MSE на шуме» | `\|\|ε - ε_θ(x_t, t)\|\|²`; все вариационные выводы сводятся к этому. |
| ε-предсказание | «Предсказать шум» | На выходе — добавленный шум; стандарт DDPM. |
| V-предсказание | «Предсказать скорость» | На выходе — `α·ε - σ·x`; лучше обусловливание по всем t. |
| DDPM | «Та самая статья» | Хо и др., 2020; линейное β, 1000 шагов, U-Net. |
| DDIM | «Детерминированный сэмплер» | Немарковский сэмплер, 20-50 шагов, та же обучающая целевая функция. |
| Classifier-free guidance | «CFG» | Смешивание условных и безусловных предсказаний шума для усиления обусловливания. |

## Заметка о продакшене: диффузионный инференс — это проблема числа шагов

В статье про DDPM используется T=1000 обратных шагов. Никто не выпускает это в продакшн в таком виде. Каждый реальный инференс-стек выбирает одну из трёх стратегий — и каждая из них чётко отображается на производственную формулировку вопроса «откуда берётся задержка»:

1. **Более быстрый сэмплер, та же модель.** DDIM (20-50 шагов), DPM-Solver++ (10-20), UniPC (8-16). Прямая замена обратного цикла; обученные веса `ε_θ` остаются нетронутыми. Сокращает задержку в 20-50 раз.
2. **Дистилляция.** Обучаем студента воспроизводить учителя за меньшее число шагов: Progressive Distillation (2 → 1), Consistency Models (произвольное → 1-4), LCM, SDXL-Turbo, SD3-Turbo. Сокращает задержку ещё в 5-10 раз, требует переобучения.
3. **Кэширование и компиляция.** `torch.compile(unet, mode="reduce-overhead")`, диффузионные бэкенды TensorRT-LLM, внимание `xformers`/SDPA, веса в bf16. Сокращает задержку на шаг примерно в 2 раза. Комбинируется с (1) и (2).

Для продакшен-сервера диффузии разговор о бюджете — тот же, что производственная литература описывает для LLM: задержка — это `num_steps × step_cost + VAE_decode`, пропускная способность — это `batch_size × (num_steps × step_cost)^-1`. TTFT мал (один шаг); эквивалент TPOT — это всё время ответа целиком, потому что генерация изображения происходит «всё сразу» с точки зрения пользователя.
