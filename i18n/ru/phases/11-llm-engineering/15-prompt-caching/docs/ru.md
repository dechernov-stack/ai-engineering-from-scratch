# Кэширование промптов и контекста

> Ваш системный промпт занимает 4000 токенов. Ваш RAG-контекст — 20 000 токенов. Вы отправляете оба с каждым запросом. И платите за оба — каждый раз. Кэширование промптов позволяет провайдеру держать этот префикс «тёплым» на своей стороне и выставлять вам счёт в размере 10% от обычной ставки при повторном использовании. При правильном применении это снижает стоимость инференса на 50–90% и задержку до первого токена на 40–85%.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 11 · 01 (Prompt Engineering), Phase 11 · 05 (Context Engineering), Phase 11 · 11 (Caching and Cost)
**Time:** ~60 минут

## Проблема

Кодирующий агент отправляет один и тот же системный промпт на 15 000 токенов в Claude на каждом ходу разговора. Двадцать ходов при $3/M input tokens is $0.90 только в затратах на ввод — ещё до каких-либо реальных сообщений пользователя. Умножьте на 10 000 ежедневных разговоров — и счёт достигает $9000/день за текст, который никогда не меняется.

Вы не можете сократить промпт без ущерба для качества. Вы не можете избежать его отправки — модели он нужен на каждом ходу. Единственный выход — перестать платить полную цену за префикс, который провайдер уже видел.

Этот выход — кэширование промптов. Anthropic выпустила его в августе 2024 года (с вариантом расширенного TTL в 1 час в 2025 году), OpenAI автоматизировала это позже в том же году, Google выпустила явное кэширование контекста вместе с Gemini 1.5, и теперь все три компании предлагают его как полноценную функцию в своих флагманских моделях.

## Концепция

![Prompt caching: write once, read cheap](../assets/prompt-caching.svg)

**Механизм.** Когда префикс запроса совпадает с префиксом недавнего запроса, провайдер отдаёт KV-кэш из предыдущего прогона вместо повторного кодирования токенов. Вы платите небольшую надбавку за запись в первый раз и получаете значительную скидку при чтении каждый раз после.

**Три варианта провайдеров в 2026 году.**

| Провайдер | Стиль API | Скидка при попадании | Надбавка за запись | TTL по умолчанию | Минимум для кэширования |
|---------|-----------|--------------|---------------|-------------|---------------|
| Anthropic | Явные маркеры `cache_control` на блоках контента | скидка 90% на ввод | надбавка 25% | 5 мин (можно продлить до 1 часа) | 1024 токена (Sonnet/Opus), 2048 (Haiku) |
| OpenAI | Автоматическое определение префикса | скидка 50% на ввод | нет | до 1 часа (без гарантий) | 1024 токена |
| Google (Gemini) | Явный API `CachedContent` | оплата за хранение; чтение по ~25% от обычной цены | плата за хранение за токен·час | задаётся пользователем (по умолчанию 1 час) | 4096 токенов (Flash), 32 768 (Pro) |

**Инвариант.** Все три провайдера кэшируют только префиксы. Если хоть один токен отличается между запросами, всё после первого отличающегося токена считается промахом. Располагайте *стабильные* части сверху, *переменные* — снизу.

### Удобный для кэширования макет

```
[system prompt]          <-- cache this
[tool definitions]       <-- cache this
[few-shot examples]      <-- cache this
[retrieved documents]    <-- cache if reused, else don't
[conversation history]   <-- cache up to last turn
[current user message]   <-- never cache (different every time)
```

Нарушьте порядок — поместите сообщение пользователя выше системного промпта, перемежайте динамические выборки между few-shot-примерами — и кэш никогда не сработает.

### Расчёт точки окупаемости

Надбавка Anthropic в 25% за запись означает, что кэшированный блок должен быть прочитан минимум дважды, чтобы в итоге сэкономить деньги. 1 запись + 1 чтение в среднем дают 0,675x стоимости за запрос (экономия 32%); 1 запись + 10 чтений в среднем дают 0,205x (экономия 80%). Правило: кэшируйте всё, что вы ожидаете использовать повторно минимум 3 раза в пределах TTL.

## Реализация

### Шаг 1: кэширование промптов Anthropic с явными маркерами

```python
import anthropic

client = anthropic.Anthropic()

SYSTEM = [
    {
        "type": "text",
        "text": "You are a senior Python reviewer. Follow the rubric exactly.\n\n" + RUBRIC_15K_TOKENS,
        "cache_control": {"type": "ephemeral"},
    }
]

def review(code: str):
    return client.messages.create(
        model="claude-opus-4-7",
        max_tokens=1024,
        system=SYSTEM,
        messages=[{"role": "user", "content": code}],
    )
```

Маркер `cache_control` указывает Anthropic хранить блок 5 минут. Повторное использование в этом окне — попадание; повторное использование после истечения срока — снова запись.

**Поля использования в ответе:**

```python
response = review(code_a)
response.usage
# InputTokensUsage(
#     input_tokens=120,
#     cache_creation_input_tokens=15023,   # paid at 1.25x
#     cache_read_input_tokens=0,
#     output_tokens=340,
# )

response_b = review(code_b)
response_b.usage
# cache_creation_input_tokens=0
# cache_read_input_tokens=15023           # paid at 0.1x
```

Проверяйте оба поля в CI — если `cache_read_input_tokens` остаётся нулевым между запросами, значит ваши ключи кэша «дрейфуют».

### Шаг 2: расширенный TTL в один час

Для длительных пакетных задач 5-минутный таймаут по умолчанию истекает между задачами. Задайте `ttl`:

```python
{"type": "text", "text": RUBRIC, "cache_control": {"type": "ephemeral", "ttl": "1h"}}
```

TTL в 1 час стоит в 2 раза больше надбавки за запись (50% сверх базовой цены вместо 25%), но быстро окупается в любой пакетной задаче, повторно использующей префикс более 5 раз.

### Шаг 3: автоматическое кэширование OpenAI

OpenAI не даёт ничего настраивать. Любой префикс свыше 1024 токенов, совпадающий с недавним запросом, автоматически получает скидку 50%.

```python
from openai import OpenAI
client = OpenAI()

resp = client.chat.completions.create(
    model="gpt-5",
    messages=[
        {"role": "system", "content": SYSTEM_PROMPT},   # long and stable
        {"role": "user", "content": user_msg},
    ],
)
resp.usage.prompt_tokens_details.cached_tokens  # the discounted portion
```

Применяется то же правило удобного для кэширования макета. Есть две вещи, которые ломают кэш OpenAI, но не ломают кэш Anthropic: изменение поля `user` (используется как компонент ключа кэша) и изменение порядка инструментов.

### Шаг 4: явное кэширование контекста Gemini

Gemini рассматривает кэш как полноценный объект, который вы создаёте и именуете:

```python
from google import genai
from google.genai import types

client = genai.Client()

cache = client.caches.create(
    model="gemini-3.8-flash",
    config=types.CreateCachedContentConfig(
        display_name="rubric-v3",
        system_instruction=RUBRIC,
        contents=[FEW_SHOT_EXAMPLES],
        ttl="3600s",
    ),
)

resp = client.models.generate_content(
    model="gemini-3.8-flash",
    contents=["Review this code:\n" + code],
    config=types.GenerateContentConfig(cached_content=cache.name),
)
```

Gemini взимает плату за хранение за токен·час, пока кэш существует, и за чтение по ставке ~25% от обычной цены на ввод. Это подходящий вариант, когда вы повторно используете один и тот же огромный промпт во множестве сессий на протяжении нескольких дней.

### Шаг 5: измерение частоты попаданий в продакшене

См. `code/main.py` для симулированного «бухгалтера» трёх провайдеров, который отслеживает количество записей/чтений/промахов и вычисляет смешанную стоимость на 1000 запросов. Ставьте деплои на гейт по целевой частоте попаданий — большинство продакшен-конфигураций Anthropic должны после «разогрева» видеть долю чтений >80%.

## Ловушки, которые всё ещё встречаются в 2026 году

- **Динамические временные метки сверху.** `"Current time: 2026-04-22 15:30:02"` в начале системного промпта. Каждый запрос промахивается. Переместите временные метки ниже точки разрыва кэша.
- **Изменение порядка инструментов.** Сериализуйте инструменты в стабильном порядке — перетасовка словаря между деплоями ломает каждое попадание.
- **Почти-дубликаты свободного текста.** «You are helpful.» против «You are a helpful assistant.» — разница в один байт = полный промах.
- **Слишком маленькие блоки.** Anthropic устанавливает минимум в 1024 токена (2048 для Haiku). Меньшие блоки молча не кэшируются.
- **Слепые панели затрат.** Разделяйте «входные токены» на кэшированные и некэшированные. Иначе падение трафика будет выглядеть как выигрыш от кэша.

## Применение

Стек кэширования 2026 года:

| Ситуация | Выбор |
|-----------|------|
| Агент со стабильным системным промптом на 10 тыс.+ токенов, много ходов | Anthropic `cache_control` с TTL 5 мин |
| Пакетная задача, повторно использующая префикс 30+ минут | Anthropic с `ttl: "1h"` |
| Серверлес-эндпоинты на GPT-5, без кастомной инфраструктуры | автоматическое кэширование OpenAI (просто сделайте префикс стабильным и длинным) |
| Многодневное повторное использование огромного корпуса кода/документов | явное кэширование Gemini `CachedContent` |
| Межпровайдерный фолбэк | Держите макет кэшируемого префикса идентичным у всех провайдеров, чтобы любое попадание работало |

Комбинируйте с семантическим кэшированием (Phase 11 · 11) для слоя пользовательских сообщений: кэширование промптов обрабатывает *токенно-идентичное* повторное использование, семантическое кэширование — *семантически-идентичное*.

## Ключевые термины

| Термин | Что обычно говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Кэширование промптов | «Делает длинные промпты дешёвыми» | Повторное использование KV-кэша на стороне провайдера для совпадающих префиксов; скидка 50–90% на повторяющиеся входные токены. |
| `cache_control` | «Маркер Anthropic» | Атрибут блока контента, объявляющий «всё до этого места кэшируемо»; `{"type": "ephemeral"}`. |
| Запись в кэш | «Оплата надбавки» | Первый запрос, заполняющий кэш; тарифицируется по ~1,25x от ставки на ввод у Anthropic, бесплатно у OpenAI. |
| Чтение из кэша | «Скидка» | Последующие запросы, совпадающие по префиксу; тарифицируются по 10% (Anthropic), 50% (OpenAI), ~25% (Gemini). |
| TTL | «Как долго он живёт» | Время в секундах, пока кэш остаётся «тёплым»; у Anthropic по умолчанию 5 мин (можно продлить до 1 ч), у OpenAI — до 1 ч без гарантий, у Gemini задаётся пользователем. |
| Расширенный TTL | «1-часовой кэш Anthropic» | `{"type": "ephemeral", "ttl": "1h"}`; надбавка за запись в 2 раза выше, но это оправдано для пакетного повторного использования. |
| Совпадение префикса | «Почему мой кэш промахнулся» | Кэш срабатывает только тогда, когда каждый токен от начала до точки разрыва побайтово идентичен. |
| Кэширование контекста (Gemini) | «Явный вариант» | Именованный, оплачиваемый за хранение объект кэша от Google; лучше всего подходит для многодневного повторного использования больших корпусов. |
