# Multi-Token Prediction (MTP)

> Каждая авторегрессионная LLM, от GPT-2 до Llama 3, обучается с одной функцией потерь на позицию: предсказать следующий токен. DeepSeek-V3 добавила вторую функцию потерь на позицию: предсказать токен, идущий после него. Дополнительные 14 млрд параметров (на модели размером 671 млрд) были дистиллированы обратно в основную модель через поток градиентов, а обученные MTP-головы были переиспользованы на этапе инференса как драфтеры спекулятивного декодирования с долей принятия 80%+. Прирост пропускной способности генерации в 1,8× достался бесплатно. В этом уроке строится последовательный MTP-модуль из технического отчёта DeepSeek, вычисляется функция потерь и схема распределения параметров общей головы, а также объясняется, почему MTP сохраняет каузальную цепочку, в то время как исходная параллельная MTP из работы Глёкля и др. её разрывала.

## The Problem

Предсказание следующего токена — это стандартная цель обучения LLM. Каждое скрытое состояние обучается предсказывать ровно одну вещь: непосредственно следующий токен. Это на удивление слабый сигнал. Большая часть информации в последовательности выходит за пределы одного токена — структура, связность, фактологичность, арифметический ход рассуждений. Модели приходится осваивать это, накапливая множество однотокенных сигналов на триллионах токенов.

MTP задаёт вопрос: что, если каждое скрытое состояние обучать предсказывать сразу несколько будущих токенов? Глёкль и др. (Meta, 2024) показали, что это помогает. В их реализации поверх основы было размещено несколько независимых выходных голов, каждая из которых предсказывала смещение на свою величину. Параллельно, просто, но головы видели одно и то же скрытое состояние без какого-либо иерархического уточнения — а предсказания не выстраивались в каузальную цепочку, поэтому их нельзя было использовать для спекулятивного декодирования.

DeepSeek-V3 (декабрь 2024) переработала MTP в виде последовательных модулей, которые сохраняют каузальную цепочку на каждой глубине предсказания. Модель предсказывает `t+1` из `h_i^(0)`, затем предсказывает `t+2` из нового скрытого состояния `h_i^(1)`, которое объединило `h_i^(0)` с эмбеддингом `E(t+1)`, и так далее. Каждая глубина — это собственный небольшой трансформерный блок. Общий эмбеддинг и общая выходная голова удерживают накладные расходы по параметрам на скромном уровне. В масштабе DeepSeek-V3 это 14 млрд дополнительных параметров во всех MTP-модулях поверх 671 млрд весов основной модели. Эти 2% накладных расходов окупились более плотными обучающими сигналами И готовым черновиком для спекулятивного декодирования на этапе инференса.

В этом уроке с нуля строится один MTP-модуль и функция потерь для D глубин. Математика получается аккуратной. Реализация занимает 150 строк.

## The Concept

### Рецепт последовательного MTP

DeepSeek-V3 добавляет `D` MTP-модулей поверх основной модели. Каждый модуль `k` (для `k = 1..D`) предсказывает токен на глубине `k` — то есть `t_{i+k}`, имея префикс до позиции `i`.

Модуль `k` состоит из:

- Трансформерного блока `T_k` с собственным вниманием и MLP.
- Матрицы проекции `M_k`, которая объединяет скрытое состояние предыдущей глубины с эмбеддингом истинного токена следующей глубины.
- Общего эмбеддинга `E` (того же, что и в основной модели).
- Общей выходной головы `Out` (той же, что и в основной модели).

При обучении для префикса до позиции `i` скрытое состояние для конкретной глубины вычисляется так:

```
h_i^(0) = main model backbone at position i
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   for k >= 1
```

Предсказание для конкретной глубины:

```
logits_{i+k} = Out(h_i^(k-1))   for k = 1..D
```

Функция потерь для конкретной глубины — это кросс-энтропия относительно истинного значения `t_{i+k}`:

```
L_k = CE(logits_{i+k}, t_{i+k})
```

Совместная функция потерь по глубинам:

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda` — небольшой весовой коэффициент: DeepSeek-V3 использует 0,3 на первых 10% обучения и 0,1 далее. Итоговая функция потерь обучения: `L_main + L_MTP`.

### Почему последовательно, а не параллельно

В исходной параллельной MTP Глёкля было D выходных голов, каждая из которых применялась напрямую к `h_i^(0)`. Каждая голова предсказывает `t_{i+k}` из одного и того же скрытого состояния основы. Это обучается нормально, но предсказания не обусловлены друг другом. Нельзя использовать выход `head_1`, чтобы помочь `head_2` — головы срабатывают параллельно.

Последовательная конструкция DeepSeek-V3 строит `h_i^(k)` из `h_i^(k-1)` плюс фактический эмбеддинг следующего токена `E(t_{i+k})`. Это сохраняет каузальную цепочку: чтобы предсказать `t_{i+k+1}`, модуль на глубине `k+1` видит, что было на `t_{i+k}`. Структурно это идентично тому, как авторегрессионный декодер потребляет собственный выход — что делает MTP-модули напрямую пригодными в качестве драфтеров спекулятивного декодирования.

На этапе инференса: подать `h_i^(k-1)` и черновой `t_{i+k}` в модуль `k+1`, получить предсказание для `t_{i+k+1}`. Повторить. Это в точности черновик в стиле EAGLE, использующий обученный MTP-модуль в качестве драфт-сети. DeepSeek-V3 сообщает о доле принятия 80%+ для первого MTP-модуля и ускорении примерно в 1,8×.

### Учёт параметров

Для модели со скрытым размером `h` и словарём `V`:

- Основная модель: миллиарды параметров плюс одна выходная голова размера `V * h`.
- Общая выходная голова: переиспользуется голова основной модели. Без дополнительных параметров.
- Общий эмбеддинг: переиспользуется эмбеддинг основной модели. Без дополнительных параметров.
- На каждый MTP-модуль:
  - Проекция `M_k`: `(2h) * h = 2h^2`.
  - Трансформерный блок `T_k`: внимание (`4h^2` для MHA) плюс MLP (обычно `8h^2` для SwiGLU с отношением 8/3). Примерно `12h^2` на блок.

Итого дополнительно на модуль: `~14h^2`. Для `h = 7168` DeepSeek-V3, D = 1 модуль: `~14 * 7168^2 = ~720M` параметров на бумаге. DeepSeek-V3 сообщает о 14 млрд — разница в основном связана с тем, что экспертные слои в MTP-модуле тоже устроены как MoE.

### Выигрыш для спекулятивного декодирования

Во время предобучения MTP-модули замедляют обучение примерно на 10% (больше прямых вычислений, дополнительная функция потерь). Выигрыш двоякий:

1. Более плотный обучающий сигнал. Каждое скрытое состояние видит D+1 целевых значений для обучения. Измеренный эффект на MMLU, GSM8K, MATH, HumanEval: стабильные улучшения на несколько процентных пунктов в абляциях DeepSeek-V3.

2. Бесплатный черновик для спекулятивного декодирования на этапе инференса. MTP-модуль уже обучен предсказывать несколько следующих токенов. Переиспользованный как драфт-сеть, он обеспечивает долю принятия 80%+. При таком уровне спекулятивное декодирование с N=3 или N=5 даёт прирост пропускной способности в 1,8×. 10%-ные затраты на время обучения окупаются уже при первом запуске инференса.

### Связь с EAGLE

EAGLE обучает небольшую драфт-модель ОТДЕЛЬНО после предобучения. MTP встраивает драфт прямо в предобучение. Оба подхода сходятся к похожим долям принятия, но через разные пайплайны:

| Dimension | EAGLE-3 | MTP (DeepSeek-V3) |
|-----------|---------|------------------|
| Когда обучается | После предобучения | Во время предобучения |
| Обратная совместимость с существующими весами | Да | Нет (требуется переобучение) |
| Параметры драфта | 1-2 трансформерных слоя | 1 трансформерный блок + проекция |
| Доля принятия | 0.88-0.92 | 0.80+ на глубине 1 |
| Выгода помимо ускорения | Только спекулятивное декодирование | Более плотный обучающий сигнал + ускорение |

## Build It

`code/main.py` строит один MTP-модуль от начала до конца: общий эмбеддинг, проекцию, трансформерный блок, общую выходную голову. Затем вычисляется кросс-энтропийная функция потерь для каждой глубины на короткой синтетической последовательности и выводится количество параметров по компонентам. Игрушечный словарь из 32 токенов делает числа удобочитаемыми.

### Step 1: общая таблица эмбеддингов

Одна таблица `vocab_size x hidden` используется основной моделью И каждым MTP-модулем на каждой глубине. Не вторая копия — буквально один и тот же тензор.

### Step 2: объединение для конкретной глубины

```python
def combine(prev_hidden, next_token_embed, M_k):
    # concat along feature dim, then project down to hidden
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # vector addition stand-in
    projected = matvec(M_k, concat)
    return projected
```

Настоящая DeepSeek-V3 конкатенирует два RMSNorm-нормализованных вектора в `[2h]` и проецирует матрицей `h x 2h`. В игрушечной версии для краткости на stdlib используется сложение векторов.

### Step 3: трансформерный блок на глубине k

Self-attention плюс MLP. В игрушечной версии однослойный блок линейного внимания и SwiGLU MLP сохраняют структуру видимой без numpy.

### Step 4: общая выходная голова

Переиспользуется выходная проекция основной модели. Логиты по словарю.

### Step 5: функция потерь для конкретной глубины

Кросс-энтропия softmax(logits) относительно истинного токена со смещением `k`. Агрегация по глубинам с масштабирующим коэффициентом `lambda / D`.

### Step 6: учёт параметров

Вывести общее количество параметров, количество общих (эмбеддинг, голова) и дополнительное количество на каждый модуль. Показать отношение дополнительных MTP-параметров к размеру основной модели.

## Use It

MTP интегрирован в DeepSeek-V3 (декабрь 2024) и серию DeepSeek-R1. На этапе инференса:

- Собственный сервинг-стек DeepSeek использует MTP-модули как спекулятивные декодеры из коробки.
- vLLM и SGLang имеют пути интеграции для MTP DeepSeek-V3 по состоянию на апрель 2026 года.
- Туториал AMD по ROCm SGLang показывает конкретную конфигурацию спекулятивного декодирования с MTP с измеренным ускорением в 1,8× на чекпойнте V3.

Когда использовать MTP в новом запуске предобучения:

- Вы контролируете весь пайплайн предобучения и хотите заложить более плотный обучающий сигнал.
- Вы знаете, что будете обслуживать модель в больших масштабах, и хотите бесплатное спекулятивное декодирование.
- Ваш скрытый размер составляет не менее 4096. На масштабе 1 млрд накладные расходы вредят больше, чем помогает выигрыш.

Когда не стоит использовать:

- Дообучение (fine-tuning) существующей предобученной плотной модели. MTP-модуль не обучен.
- Исследовательские модели, для которых нужен чистый базовый вариант для сравнения. MTP меняет архитектуру.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| MTP-модуль | «Дополнительный блок потерь» | Небольшой трансформерный блок плюс проекция, предсказывающий токен на `k` позиций вперёд относительно основной модели |
| Глубина предсказания | «Какое смещение» | Целое число `k` такое, что модуль `k` предсказывает `t_{i+k}` из префикса до позиции `i` |
| Параллельная MTP | «В стиле Глёкля» | D независимых голов на одном и том же скрытом состоянии основы, без условной цепочки |
| Последовательная MTP | «В стиле DeepSeek-V3» | Каждый модуль обусловлен скрытым состоянием предыдущей глубины плюс эмбеддингом следующего токена; сохраняет каузальную цепочку |
| Общая выходная голова | «Переиспользовать основную голову» | MTP-модули вызывают LM-голову основной модели, а не отдельную выходную проекцию |
| Общий эмбеддинг | «Переиспользовать основную таблицу» | Одна и та же таблица эмбеддингов словаря используется везде; без дублирования параметров |
| Матрица проекции M_k | «Объединить скрытое состояние + следующий токен» | Линейный слой `h x 2h`, который сворачивает предыдущее скрытое состояние и эмбеддинг целевого токена во вход для следующей глубины |
| Совместная функция потерь L_MTP | «Усреднённые дополнительные потери» | Среднее арифметическое кросс-энтропийных потерь по глубинам, масштабированное коэффициентом `lambda` |
| Доля принятия на глубине 1 | «Как часто черновик MTP прав» | Доля случаев, когда топ-1 предсказание MTP-модуля при D=1 совпадает с топ-1 предсказанием основной модели; 80%+ на DeepSeek-V3 |
| Весовой коэффициент лямбда | «Важность дополнительной потери» | Масштабирующий коэффициент для каждой глубины; 0,3 в начале обучения, 0,1 позже на DeepSeek-V3 |
