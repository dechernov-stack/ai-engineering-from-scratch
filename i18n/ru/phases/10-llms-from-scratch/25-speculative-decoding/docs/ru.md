# Спекулятивное декодирование и EAGLE

> Генерация одного токена фронтирной LLM требует полного прямого прохода через миллиарды параметров. Этот прямой проход избыточно затратен: в большинстве случаев гораздо меньшая модель может правильно угадать следующие 3-5 токенов, и большой модели нужно лишь *проверить* догадку. Когда догадка верна, вы получаете 5 токенов по цене одного. Спекулятивное декодирование (Leviathan et al. 2023) сделало это точным, а EAGLE-3 (2025) поднял частоту принятия до ~4,5 токена на одну проверку — ускорение в 4-5 раз при сохранении точного распределения выходных данных.

**Type:** Build
**Languages:** Python (с numpy)
**Prerequisites:** Phase 10 Lesson 12 (Inference Optimization), Phase 10 Lesson 04 (Pre-training Mini-GPT)
**Time:** ~75 минут

## Проблема

Пропускная способность декодирования для модели класса 70B на H100 обычно составляет 40-80 токенов/секунду. Каждый токен требует полного прямого прохода с чтением всех весов модели из HBM. Нельзя уменьшить модель, не изменив её выход. Нельзя увеличить размер батча сверх объёма памяти. Вы упираетесь в стену — если только не позволить модели выдавать более одного токена за прямой проход.

Авторегрессивная генерация выглядит изначально последовательной: `x_{t+1} = sample(p(· | x_{1:t}))`. Но здесь есть возможность для параллелизма. Если бы у вас был дешёвый предиктор, говорящий "следующие 4 токена, вероятно, [a, b, c, d]", вы могли бы проверить все 5 позиций за **один прямой проход большой модели** и принять самый длинный совпадающий префикс.

Leviathan, Kalai, Matias (2023, "Fast Inference from Transformers via Speculative Decoding") сделали это точным с помощью хитрого правила принятия/отклонения, которое сохраняет распределение сэмплирования целевой модели. То же распределение выходных данных, в 2-4 раза быстрее.

## Концепция

### Настройка двух моделей

- **Целевая модель (target model)** `M_p`: большая, медленная, высококачественная модель, из которой вы на самом деле хотите получать сэмплы. Распределение: `p(x)`.
- **Черновая модель (draft model)** `M_q`: маленькая, быстрая, менее качественная модель. Распределение: `q(x)`. Меньше в 5-30 раз.

На каждом шаге:

1. Черновая модель авторегрессивно предлагает `K` токенов: `x_1, x_2, ..., x_K ~ q`.
2. Целевая модель выполняет ОДИН прямой проход по всем `K+1` позициям параллельно, выдавая `p(x_k)` для каждого предложенного токена.
3. Принятие/отклонение каждого токена слева направо по модифицированному правилу отбраковки (rejection sampling), описанному ниже. Принимается самый длинный совпадающий префикс.
4. Если какой-либо токен отклонён, замена сэмплируется из скорректированного распределения, и процесс останавливается. В противном случае сэмплируется один бонусный токен из `p(· | x_1...x_K)`.

Если черновик идеально совпадает с целевой моделью, вы получаете K+1 токенов за один прямой проход целевой модели. Если черновик ошибается уже в позиции 1, вы получаете только 1 токен.

### Правило точности

Спекулятивное декодирование **доказуемо эквивалентно по распределению сэмплированию из p**. Правило отбраковки:

```
For each drafted token x_t:
    r ~ Uniform(0, 1)
    if r < p(x_t) / q(x_t):
        accept x_t
    else:
        sample replacement from residual: (p - q)+ / ||(p - q)+||_1
        stop
```

где `(p - q)+` обозначает положительную часть поточечной разности. Когда черновая и целевая модели согласны (`p ≈ q`), принятие почти равно 1. Когда они расходятся, остаточное распределение строится так, что итоговый сэмпл всё равно в точности соответствует `p`.

**Жадный случай (greedy).** Для сэмплирования при temperature=0 достаточно проверить `argmax(p) == x_t`. Если да — принять; если нет — вывести `argmax(p)` и остановиться.

### Ожидаемое ускорение

Если частота принятия токенов черновой модели равна `α`, ожидаемое число токенов, производимых за один прямой проход целевой модели, составляет:

```
E[tokens] = (1 - α^{K+1}) / (1 - α)        # K = draft length, α in [0, 1]
```

При `α = 0.8, K = 4`: `(1 - 0.8^5)/(1 - 0.8) = 3.36` токена за проход. Один прямой проход целевой модели стоит примерно `cost_q * K + cost_p` (K черновых шагов плюс одна проверка целевой моделью). Если `cost_p >> cost_q * K`, отношение ускорения по пропускной способности составляет `3.36× / 1 = 3.36×`.

Единственный реальный параметр — это `α`, который полностью зависит от согласованности черновой и целевой моделей. Хороший черновик — это всё.

### Обучение черновика: дистилляция

Случайная маленькая модель — плохой черновик. Стандартный рецепт — дистилляция из целевой модели:

1. Выбрать небольшую архитектуру (~1B для целевой модели 70B, ~500M для целевой модели 7B).
2. Прогнать целевую модель на большом текстовом корпусе; сохранить её распределения вероятностей следующего токена.
3. Обучить черновик с KL-дивергенцией относительно распределения целевой модели (а не относительно эталонных токенов).

Результат: `α`, обычно 0,6-0,8 на коде, 0,7-0,85 на чате на естественном языке. Ускорение 2-3× в продакшне.

### EAGLE: древовидное черновое декодирование + повторное использование признаков

Li, Wei, Zhang, Zhang (2024, "EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty") обнаружили две неэффективности в стандартном спекулятивном декодировании:

1. Черновая модель выполняет K последовательных шагов, каждый — полным стеком. Но черновик мог бы повторно использовать признаки (скрытые состояния) целевой модели с последней проверки — целевая модель уже вычислила богатые представления, которые черновик заново выводит с нуля.
2. Черновик выдаёт линейную цепочку. Если бы черновик мог выдавать *дерево* кандидатов (в каждом узле несколько догадок), единственный прямой проход целевой модели мог бы параллельно проверить несколько кандидатных путей с помощью древовидной маски внимания и выбрать самую длинную принятую ветвь.

Изменения в EAGLE-1:
- Вход черновика = последнее скрытое состояние целевой модели в позиции t, а не исходные токены.
- Архитектура черновика = 1 слой декодера трансформера (а не отдельная маленькая модель).
- Выход = дерево из K = 4-8 кандидатов на каждой глубине, глубина 4-6.

EAGLE-2 (2024) добавляет динамическую топологию дерева: дерево расширяется там, где черновик неуверен, и остаётся узким там, где он уверен. Повышает `α_effective` без увеличения стоимости проверки.

EAGLE-3 (Li et al. 2025, "EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test") убирает фиксированную зависимость от признаков верхнего слоя и обучает черновик с новой функцией потерь "симуляции тестового времени" — черновик обучается на выходах, соответствующих распределению целевой модели во время теста, а не на обучении с принудительным учителем (teacher forcing). Частота принятия возрастает с 0,75 (EAGLE-2) до 0,82 (EAGLE-3), а среднее число токенов на проверку — с 3,0 до 4,5.

### Проверка с древовидным вниманием (tree attention)

Когда черновик выдаёт дерево, целевая модель проверяет его за один прямой проход с помощью **маски древовидного внимания (tree attention mask)** — каузальной маски, кодирующей топологию дерева, а не чистую линию. Каждый токен обращает внимание только на своих предков в дереве. Проверочный проход по-прежнему остаётся одним прямым проходом, одним матричным умножением; топологическая маска требует лишь нескольких дополнительных записей KV.

```
        root
       /    \
      a      b
     / \    / \
    c  d   e   f
```

Если `a, b` — конкурирующие кандидаты для первого токена, а `c, d, e, f` — кандидаты для второго токена, все шесть позиций проверяются за один прямой проход. Выход — самый длинный префикс вдоль любого принятого пути.

### Когда это выигрывает, а когда нет

**Выигрывает:**
- Чат / автодополнение с предсказуемым текстом (код, распространённый английский, структурированный вывод). `α` высок.
- Сценарии с неиспользуемыми вычислительными ресурсами GPU во время декодирования (фаза, ограниченная памятью). Древовидное черновое декодирование использует доступные FLOPs.

**Проигрывает / нет выигрыша:**
- Сильно стохастические выходы (креативное письмо при высокой температуре). `α` падает к `1/|vocab|`.
- Пакетная обработка (batch serving) с очень высокой конкурентностью — батчинг уже заполняет FLOPs, мало места для древовидной проверки.
- Очень маленькие целевые модели, где черновик не намного меньше.

Производственные команды обычно сообщают об ускорении в реальном времени в 2-3× на чате, 3-5× на генерации кода и почти нулевом выигрыше на креативном письме.

## Постройте это

`code/main.py`:

- Эталонный `speculative_decode(target, draft, prompt, K, temperature)`, реализующий точное правило отбраковки и проверяющий, что он сохраняет распределение целевой модели (эмпирическое KL < 0,01 по сравнению с обычным сэмплированием целевой модели).
- Древовидный черновик в стиле EAGLE, строящий дерево глубины K с ветвлением по top-p.
- Построитель маски древовидного внимания, формирующий корректный каузальный паттерн для верификатора.
- Стенд для измерения частоты принятия, запускающий оба подхода на крошечной LM (дистилляция одной GPT-2-small из целевой GPT-2-medium).

```python
def speculative_step(p_target, q_draft, K, temperature=1.0):
    """One round of speculative decoding. Returns list of accepted tokens."""
    # 1. Draft K tokens
    draft_tokens = []
    q_probs = []
    state = draft_state_init()
    for _ in range(K):
        probs = softmax(q_draft(state) / temperature)
        t = np.random.choice(len(probs), p=probs)
        draft_tokens.append(t)
        q_probs.append(probs[t])
        state = draft_step(state, t)

    # 2. Target computes p at every drafted position + 1 extra
    p_probs_all = target_forward_batched(p_target, draft_tokens, temperature)

    # 3. Accept/reject left-to-right
    accepted = []
    for k, tok in enumerate(draft_tokens):
        r = np.random.uniform()
        if r < p_probs_all[k][tok] / q_probs[k]:
            accepted.append(tok)
        else:
            residual = np.maximum(p_probs_all[k] - q_probs[k], 0)
            residual /= residual.sum()
            accepted.append(np.random.choice(len(residual), p=residual))
            return accepted
    # 4. All K accepted → sample bonus token from target
    accepted.append(np.random.choice(len(p_probs_all[-1]), p=p_probs_all[-1]))
    return accepted
```

## Примените это

- **vLLM** и **SGLang** предоставляют полноценную поддержку спекулятивного декодирования "из коробки". В vLLM передайте `--speculative-config` JSON-объект с `method`, `model` и `num_speculative_tokens`; EAGLE-3 — это `"method": "eagle3"`.
- **NVIDIA TensorRT-LLM** нативно поддерживает деревья Medusa и EAGLE.
- **Эталонные черновые модели**: `Qwen/Qwen3-0.6B` (черновики для Qwen3-32B), `meta-llama/Llama-3.2-1B-Instruct` (черновики для Llama 3.x 70B).
- **Головы Medusa** (Cai et al. 2024, "Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads"): вместо черновой модели добавляются K параллельных голов предсказания прямо к целевой модели. Проще в развёртывании, несколько ниже частота принятия, чем у EAGLE.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|------------------------|
| Target model (целевая модель) | "Большая модель" | Медленная, высококачественная модель, из которой вы хотите получать сэмплы (распределение p) |
| Draft model (черновая модель) | "Спекулятор" | Маленький, быстрый предиктор (распределение q); меньше в 5-30 раз |
| K / длина черновика | "Заглядывание вперёд" | Число предполагаемых токенов на один проход проверки |
| α / частота принятия | "Процент попаданий" | Вероятность на один токен того, что предложение черновика будет принято |
| Точное правило отбраковки | "Тест принятия" | Сравнение r < p/q, сохраняющее распределение целевой модели |
| Остаточное распределение | "Скорректированное p-q" | (p - q)+ / ||(p - q)+||_1, распределение, из которого сэмплируется при отклонении |
| Древовидное черновое декодирование | "Ветвящаяся спекуляция" | Черновик выдаёт дерево кандидатов, проверяемое за один проход с древовидной маской внимания |
| Маска древовидного внимания | "Топологическая маска" | Каузальная маска, кодирующая топологию дерева, так что каждый узел обращает внимание только на своих предков |
| Головы Medusa | "Параллельные головы" | K дополнительных голов предсказания на самой целевой модели; без отдельной черновой модели |
| Повторное использование признаков EAGLE | "Черновик на скрытых состояниях" | Вход черновика — последнее скрытое состояние целевой модели, а не исходные токены, что уменьшает черновик |
| Функция потерь симуляции тестового времени | "Обучение EAGLE-3" | Обучение черновика на выходах, соответствующих распределению целевой модели во время теста, а не teacher forcing |
