## Проблема

Авторегрессивное декодирование на модели с 70 млрд параметров выполняется со скоростью примерно 35 токенов в секунду на H100. GPU далёк от насыщения. Пропускная способность памяти — это потолок: каждый токен загружает 70 млрд весов из HBM, выполняет один шаг арифметики и выдаёт одно число с плавающей точкой. Вычислительные блоки большую часть времени простаивают.

Спекулятивное декодирование превращает это в проблему пропускной способности, которую реально можно решить. Дешёвый драфт предлагает `N` токенов за `N` малых прямых проходов. Верификатор выполняется один раз на префиксе плюс все `N` драфтов. Если распределение верификатора в позиции `i` согласуется с драфтом (в статистическом смысле, который мы уточним), мы принимаем; если нет — отклоняем и сэмплируем коррекцию из остаточного распределения. Один прямой проход большой модели производит до `N+1` принятых токенов вместо одного.

Важнейшая теорема здесь — Leviathan, Kalman, Matias (ICML 2023): выходное распределение идентично тому, что получилось бы при прямом сэмплировании из верификатора. Не приблизительно. Идентично. Это и есть вся причина, по которой спекулятивное декодирование приемлемо в продакшне — это чистая оптимизация задержки без компромисса по качеству.

Фаза 7 · Урок 16 дал вам математику. Этот урок даёт вам стек обучения. Хороший драфт стоит в 2 раза больше ускорения, чем дешёвый драфт. EAGLE, EAGLE-2 и EAGLE-3 (Li et al., 2024–2025) превратили «драфт = уменьшенная версия той же модели» в точную инженерную дисциплину. Производственные инференс-серверы 2026 года используют EAGLE-3 по умолчанию.

## Концепция

### Инвариант: отбор с отклонением Левиафана

Пусть `p(t)` — распределение драфта для следующего токена при некотором префиксе, а `q(t)` — распределение верификатора. Сэмплируем токен драфта `d ~ p`. Принимаем с вероятностью `min(1, q(d) / p(d))`. При отклонении сэмплируем из остаточного распределения `(q - p)_+ / ||(q - p)_+||_1`. Результирующие выборки распределены согласно `q`. Это верно независимо от того, насколько плох `p` — чем хуже он, тем чаще вы отклоняете, но итог остаётся точным.

Выстройте `N` таких вызовов подряд, используя один прямой проход верификатора на `prefix + d_1 + ... + d_N`. Верификатор возвращает `q_1, q_2, ..., q_{N+1}` одновременно. Проходите слева направо. При первом отклонении в позиции `j` сэмплируйте из `residual(q_j, p_j)` и остановитесь. При полном принятии сэмплируйте один бонусный токен из `q_{N+1}`.

### Что определяет ускорение

Пусть `α` — ожидаемая доля принятия на один отрисованный токен драфта. Пусть `c = cost(draft) / cost(verifier)` — отношение стоимости. Ожидаемое число принятых токенов на один прямой проход верификатора:

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

Ожидаемое полное время работы на один принятый токен составляет `(N * c + 1) / E[accepted]`. Минимизируйте это по `N` и получите оптимальную точку. Для `α = 0.8, c = 0.05`: оптимальное значение `N` около 5–7, ускорение 3,2×. Для `α = 0.95, c = 0.02`: оптимальное значение `N` около 8–10, ускорение приближается к 5×.

Самый значимый рычаг — `α`. Переход от `α = 0.6` (ванильный драфт) к `α = 0.9` (EAGLE-3) при фиксированном `N = 5` переводит вас с 2,2 ожидаемых принятых токенов на прямой проход верификатора до 4,1. Почти вдвое больше пропускной способности при том же верификаторе.

### Двухлетняя эволюция

**Ванильное спекулятивное декодирование (Leviathan, 2023).** Драфт-модель — независимо обученная меньшая LLM из того же семейства. Легко подключить, `α ≈ 0.6`, ускорение около 2× в лучшем случае.

**EAGLE-1 (Li et al., 2024).** Драфт — крошечный трансформер, обычно с одним-двумя слоями, который принимает на вход скрытое состояние последнего слоя верификатора и предсказывает следующий токен напрямую. Поскольку драфт видит признаковое представление верификатора, его распределение намного ближе к распределению верификатора. `α` поднимается до 0,7–0,8.

**EAGLE-2 (Li et al., 2024).** Добавляет динамическое дерево драфтов: вместо предложения единственной последовательности из `N` токенов предлагается небольшое дерево кандидатов, каждый из которых оценивается верификатором за один прямой проход (tree attention), и выбирается путь с наивысшей вероятностью. Длина драфта становится адаптивной на каждом шаге. `α` на токен принятого пути поднимается выше 0,85.

**EAGLE-3 (Li et al., 2025, NeurIPS).** Ещё два изменения. Во-первых, полностью отказались от функции потерь для предсказания признаков — EAGLE-1/2 обучали драфт соответствовать скрытым состояниям верификатора, что ограничивает, насколько данные могут помочь. EAGLE-3 обучается напрямую на предсказании токенов. Во-вторых, обучающий тест (training-time test, TTT): во время обучения драфта его собственные предыдущие предсказания подаются обратно на вход в течение нескольких шагов — так же, как он работает при инференсе. Это выравнивает распределения обучения и теста и останавливает накопление ошибок. Измеренное ускорение: до 6,5× в чате, прирост пропускной способности на 38% при батче 64 в SGLang на H100.

### Откат KV-кэша

Верификация расширяет KV-кэш верификатора на `N` записей за один проход. Если отклонение происходит в позиции `j`, содержимое кэша после позиции `j-1` теперь некорректно. Два распространённых варианта реализации: запись во временный буфер с коммитом при принятии (vLLM, TensorRT-LLM) или хранение физического KV-кэша плюс логической длины с усечением при отклонении. В любом случае стоимость отката — это байты на слой на голову, что незначительно по сравнению со стоимостью прямого прохода.

Для поиска по дереву EAGLE-2 верификатор выполняет внимание с неказуальной маской, учитывающей топологию дерева. Инженерная часть довольно кропотливая, но вычисление — это стандартный вызов flash-attention с кастомной маской.

## Реализуйте это

См. `code/main.py`. Это полный спекулятивный цикл Левиафана со всеми компонентами: драфт из N, параллельный проход верификатора, отклонение по позициям, сэмплирование остатка, бонусный токен, откат KV-кэша и эмпирическая проверка того, что выходное распределение соответствует прямому сэмплированию из `q`.

### Шаг 1: правило отклонения

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### Шаг 2: остаточное распределение

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### Шаг 3: полный спекулятивный шаг

Функция `spec_step` отрисовывает `N` токенов из `p`, затем верифицирует их все за один параллельный проход `q`. Для каждого отрисованного токена применяется правило отклонения, и при первом отклонении сэмплируется коррекция из остатка. Если всё принято, выдаётся бонусный токен из `q_{N+1}`.

### Шаг 4: учёт отката KV-кэша

Симулятор отслеживает логическую `kv_length` для каждого воркера. При принятии `k` драфтов `kv_length += k`. При отклонении в позиции `j` кэш уже записан после `j`, но логическая длина устанавливается в `prefix_length + j + 1` — на один шаг после токена коррекции. Последующие чтения усекаются до логической длины.

### Шаг 5: проверка Левиафана

Запустите 50 000 спекулятивных шагов. Подсчитайте эмпирическое распределение принятых токенов. Сравните с 50 000 прямых выборок из `q`. Статистика хи-квадрат должна быть существенно ниже критического значения. Теорема подтверждается на практике.

### Шаг 6: ускорение в зависимости от α

Проведите развёртку качества драфта, отклоняя `p` от `q` с разными амплитудами. Измерьте `α`, затем постройте график ожидаемого числа токенов на вызов верификатора как функцию от `α` и `N`. Код выводит таблицу, показывающую, как качество драфта уровня EAGLE-3 (`α ≈ 0.9`) открывает доступ к 4–5 токенам на вызов верификатора.

SGLang с EAGLE-3 при батче 64 на H100: примерно в 1,38 раза больше пропускной способности по сравнению с ванильным декодированием при батче 64, согласно статье EAGLE-3.

Когда стоит использовать спекулятивное декодирование:

- Любая интерактивная рабочая нагрузка чата, где задержка p50 важнее пиковой пропускной способности.
- Генерация кода и структурированного вывода (JSON, SQL). `α` выше 0,9, потому что целевое распределение очень предсказуемо.
- Генерация длинных текстов (тысячи токенов). Амортизированное ускорение продолжает окупаться.

Когда не стоит:

- Очень маленькие модели (< 3 млрд параметров). Драфт не настолько дешевле верификатора.
- Развёртывания с крошечным батчем-1 на CPU. Накладные расходы памяти на драфт-модель могут того не стоить.
- Креативное сэмплирование при очень высокой температуре, где `α` обрушивается.

## Ключевые термины

| Термин | Что обычно говорят | Что это на самом деле означает |
|------|----------------|------------------------|
| Правило Левиафана | «min(1, q деленное на p)» | Бернуллиевское принятие/отклонение с вероятностью `min(1, q(d)/p(d))`, точно сохраняет распределение верификатора при сэмплировании из остатка при отклонении |
| Остаточное распределение | «(q минус p), нормализовано» | `(q - p)_+` с отсечением снизу нулём и перенормировкой — корректное распределение для сэмплирования при отклонении |
| Доля принятия α | «как часто драфт прав» | Ожидаемая вероятность бернуллиевского успеха на токен в рамках правила отклонения; определяет всю математику ускорения |
| EAGLE-1 | «драфт на скрытых состояниях» | Крошечный трансформерный драфт, обусловленный скрытым состоянием последнего слоя верификатора (Li et al., 2024) |
| EAGLE-2 | «динамическое дерево драфтов» | EAGLE-1 плюс дерево кандидатов-продолжений, оцениваемое tree attention за один проход верификатора |
| EAGLE-3 | «обучающий тест» | Отказ от функции потерь предсказания признаков, обучение на прямом предсказании токенов с подачей драфту собственных выходов во время обучения |
| Обучающий тест (TTT) | «исправление смещения экспозиции» | Запуск драфта авторегрессивно во время обучения, чтобы распределения входов на обучении и тесте совпадали — прямой аналог scheduled sampling |
| Откат KV-кэша | «отменить отклонённые драфты» | Учёт, сбрасывающий KV-кэш верификатора к длине принятого префикса после отклонения |
| Бонусный токен | «бесплатный» | Когда все `N` драфтов приняты, сэмплируется один дополнительный из `q_{N+1}` без дополнительной стоимости верификатора |
| Tree attention | «верификация множества кандидатов сразу» | Внимание с неказуальной маской, учитывающей топологию дерева драфтов; вычисляет `q_i` для каждого узла дерева за один прямой проход |
