# Native Sparse Attention (DeepSeek NSA)

> При 64k токенов внимание съедает 70-80% задержки декодирования. У каждой открытой модельной лаборатории есть план, как это исправить. NSA от DeepSeek (ACL 2025 best paper) — тот вариант, который прижился: три параллельные ветви внимания — сжатые грубозернистые токены, избирательно сохранённые мелкозернистые токены и скользящие окна для локального контекста — объединены через обучаемый гейт. Это аппаратно-согласованная (удобная для ядер), естественно обучаемая (работает при предобучении, а не прикручивается на этапе инференса) архитектура, и на декодировании 64k она работает быстрее FlashAttention, при этом соответствуя или превосходя качество полного внимания. Этот урок строит три ветви с нуля и показывает, почему разреженность дифференцируема сквозным образом.

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 7 · 12 (KV cache, flash-attention), Phase 7 · 15 (варианты внимания), Phase 10 · 16 (дифференциальное внимание)
**Time:** ~60 минут

## Learning Objectives

- Сформулировать три ветви внимания NSA и что захватывает каждая из них.
- Объяснить, почему NSA является «естественно обучаемым», тогда как предыдущие методы разреженного внимания работали только на этапе инференса.
- Вычислить экономию вычислений NSA по сравнению с полным вниманием при контексте 64k как функцию от размера блока сжатия и top-k отбора.
- Реализовать комбинацию трёх ветвей на stdlib Python на короткой синтетической последовательности и проверить поведение весов гейта.

## The Problem

Полное внимание при длине последовательности N стоит `O(N^2)` времени и `O(N)` KV-кэша на слой. При 64k токенов цифры по вычислениям и пропускной способности памяти катастрофичны. Измеренная теоретическая оценка из статьи NSA: внимание составляет 70-80% от общей задержки декодирования при 64k. Всё, что идёт дальше по цепочке — TTFT, токенов/сек, стоимость за миллион токенов — определяется стоимостью внимания.

Разреженное внимание — очевидный ответ. Предыдущие попытки делятся на два лагеря. Разреженность по фиксированному паттерну (скользящее окно, страйды, блочно-локальное) отбрасывает информацию и проваливается на задачах дальнего диапазона. Разреженность на этапе инференса (обрезка KV-кэша, H2O, StreamingLLM) применяется к модели, предобученной на плотном внимании, и восстанавливает лишь малую часть потенциального ускорения, потому что модель никогда не требовали маршрутизировать информацию через разреженный паттерн.

Native Sparse Attention (Yuan et al., DeepSeek + PKU + UW, ACL 2025 best paper, arXiv:2502.11089) делает и то, и другое: паттерн разреженности, который модель изучает во время предобучения, реализованный как согласованный с ядрами алгоритм, который действительно обеспечивает экономию вычислений на инференсе. Через два года NSA или его прямой потомок станет вниманием по умолчанию в каждой передовой модели с длинным контекстом.

## The Concept

### Три параллельные ветви

Для каждого запроса NSA выполняет внимание трижды, относительно трёх разных представлений KV-кэша:

1. **Сжатая ветвь.** Токены группируются в блоки размера `l` (обычно 32 или 64). Каждый блок сжимается в один суммирующий токен через небольшой обучаемый MLP. Запрос обращает внимание на эти сжатые токены, получая грубозернистое представление всей последовательности.

2. **Выбранная ветвь.** Используя оценки внимания из сжатой ветви, определяются top-k блоков, наиболее релевантных текущему запросу. Мелкозернистые (несжатые) токены из этих блоков считываются, и запрос обращает на них внимание целиком. Можно думать о внимании сжатой ветви как о сигнале маршрутизации для отбора.

3. **Ветвь скользящего окна.** Запрос обращает внимание на последние `W` токенов (обычно 512) для локального контекста. Эта ветвь захватывает насыщенные структурой краткодиапазонные паттерны (синтаксис, локальная кореференция), которые две другие могут упустить.

Результаты трёх ветвей объединяются через обучаемый гейт для каждой позиции:

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` — это веса гейта от небольшого MLP на основе запроса. Они не обязаны суммироваться в 1 — они могут взвешивать ветви независимо.

### Почему это «естественно обучаемо»

Шаг отбора (top-k блоков) дискретен. Дискретные операции разрывают поток градиента. Предыдущие работы по разреженному вниманию либо пропускали обратное распространение через отбор (ограничивая обучение), либо использовали непрерывные релаксации, которые не давали реальной разреженности на инференсе.

NSA обходит это: внимание сжатой ветви ЯВЛЯЕТСЯ дифференцируемым грубозернистым вниманием по всей последовательности. Операция top-k просто повторно использует верхние оценки внимания из сжатой ветви, чтобы выбрать, какие мелкозернистые блоки загружать. Градиенты текут через оценки сжатой ветви (которые влияют и на сжатый выход, И на логику отбора), а вклад выбранных блоков в итоговый выход также дифференцируем. Недифференцируемая операция `top_k` — это no-op в вычислительном графе прямого прохода — она лишь управляет тем, какие блоки загружаются из памяти.

Именно поэтому NSA можно использовать в предобучении сквозным образом. Модель учится маршрутизировать информацию через три ветви совместно, производя разреженный паттерн, который на инференсе действительно обеспечивает обещанное ускорение.

### Аппаратно-согласованное ядро

Ядро NSA спроектировано для современных иерархий памяти GPU. Ядро загружает запросы по группам GQA (внешний цикл), извлекает соответствующие разреженные KV-блоки для каждой группы (внутренний цикл) и выполняет внимание на SRAM. Поскольку каждая группа запросов видит одни и те же выбранные блоки (отбор происходит на уровне группы запросов, а не отдельной головы), загрузки KV амортизируются по группе. Арифметическая интенсивность остаётся высокой.

Статья сообщает о Triton-ядрах, работающих в 9 раз быстрее FlashAttention на декодировании 64k, причём коэффициент ускорения растёт с длиной последовательности. Предоставлены как прямые, так и обратные ядра.

### Бюджет вычислений

Пусть `N` — длина последовательности, `l` — размер блока сжатия, `k` — количество отобранных top-k блоков, `w` — скользящее окно, `b` — размер выбранного блока (обычно равен `l`).

- Сжатая ветвь: `O(N/l)` ключей на запрос, итого `O(N * N / l)`.
- Выбранная ветвь: `O(k * b)` ключей на запрос, итого `O(N * k * b)`.
- Ветвь скользящего окна: `O(w)` ключей на запрос, итого `O(N * w)`.

Итого: `O(N * (N/l + k*b + w))`.

При `N = 64k, l = 64, k = 16, b = 64, w = 512`: стоимость на запрос составляет `1000 + 1024 + 512 = 2536 keys`. Полное внимание — `64000 keys`. Сокращение вычислений в 25 раз.

При `N = 128k, l = 64, k = 16, b = 64, w = 512`: стоимость на запрос составляет `2000 + 1024 + 512 = 3536 keys`. Полное внимание — `128000 keys`. Сокращение в 36 раз. Выгода растёт с длиной последовательности, в чём и состоит весь смысл.

### Как это сравнивается

| Метод | Дифференцируемость | Реальное ускорение инференса | Дальнодиапазонная память |
|--------|---------------|----------------------|-------------------|
| Только скользящее окно | да | да | не справляется |
| Страйд / блочно-разреженное | да | да | частично |
| Обрезка KV (H2O, StreamingLLM) | N/A (этап инференса) | да | частично |
| MoBA (Moonshot) | частично | да | хорошо |
| NSA | да (естественно) | да (9x при 64k) | соответствует полному вниманию |

MoBA (Moonshot, arXiv:2502.13189) была опубликована одновременно и использует похожий подход «три лучше, чем одна», применяя принцип MoE к блокам внимания. NSA и MoBA — две архитектуры, которые нужно знать для предобучения с длинным контекстом в 2026 году.

## Build It

`code/main.py` реализует три ветви на короткой синтетической последовательности и показывает:

- MLP сжатия (для педагогической ясности используется простая базовая линия mean-pool; реальный NSA использует обучаемый MLP).
- Отбор top-k блоков, управляемый оценками сжатой ветви.
- Внимание скользящего окна на последних `w` токенах.
- Взвешенную комбинацию через гейт.
- Вывод подсчёта вычислений в сравнении с полным вниманием.

### Шаг 1: сжатие токенов в блоки

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### Шаг 2: внимание сжатой ветви

Выполните softmax-внимание запроса относительно сжатых ключей. Оценки сжатой ветви одновременно служат сигналом для top-k отбора.

### Шаг 3: отбор top-k блоков

Выберите индексы `k` блоков сжатия с наивысшими оценками. Загрузите исходные несжатые токены из этих блоков и выполните внимание на них.

### Шаг 4: внимание скользящего окна

Возьмите последние `w` токенов и выполните стандартное внимание относительно них.

### Шаг 5: гейт + объединение

Небольшой MLP на основе запроса производит три веса гейта. Итоговый выход — взвешенная сумма результатов трёх ветвей.

### Шаг 6: подсчёт вычислений

Выведите количество ключей, обрабатываемых на запрос для каждой ветви, и общую сумму. Сравните с `N` (полное внимание). На синтетической последовательности из 1024 токенов с `l = 32, k = 4, w = 128` NSA видит `32 + 128 + 128 = 288` ключей на запрос против 1024 у полного внимания — в 3,5 раза меньше.

## Use It

NSA уже используется в собственном пайплайне предобучения DeepSeek с длинным контекстом. Статус интеграции в публичных инференс-стеках по состоянию на апрель 2026:

- **DeepSeek internal**: нативно, опубликованные веса используют NSA или его преемника DSA (Deepseek Sparse Attention).
- **vLLM**: экспериментальная поддержка NSA в разработке для весов DeepSeek-V3.x.
- **SGLang**: опубликованы бенчмарки NSA; путь к продакшену следует за vLLM.
- **llama.cpp / CPU**: не поддерживается; издержки декомпозиции ядра не оправдывают себя при пропускной способности CPU.

Когда стоит обращаться к NSA:

- Предобучение или продолженное обучение, нацеленное на контекст от 64k и выше при серьёзном вычислительном бюджете.
- Инференс собственных чекпоинтов DeepSeek с длинным контекстом. Веса изначально построены на NSA.

Когда не стоит:

- Обслуживание существующей предобученной модели с плотным вниманием. Нельзя доработать NSA задним числом без продолженного обучения.
- Контекст менее 16k. Накладные расходы трёх ветвей перевешивают экономию.
- Интерактивный чат с батчем 1. Выгода для задержки декодирования проявляется только на длинных контекстах.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Compressed branch | «Грубый обзор» | Внимание над усреднёнными по блокам ключами, обеспечивающее глобальный контекст за O(N/l) ключей на запрос |
| Selected branch | «Top-k блоков» | Мелкозернистое внимание над `k` блоков с наивысшими оценками сжатой ветви |
| Sliding window | «Локальный контекст» | Внимание на последних `W` токенах для краткодиапазонных паттернов |
| Native trainability | «Предобучение со включённой разреженностью» | Паттерн разреженности изучается во время предобучения, а не прикручивается на этапе инференса |
| Compression block size l | «Размер группы для грубого обзора» | Сколько токенов объединяется в один суммирующий токен; типично 32-64 |
| Top-k | «Блоки для сохранения» | Количество сжатых блоков, чьи несжатые токены считываются; типично 16 |
| Sliding window W | «Радиус локального внимания» | Типично 512; меньше — ухудшает локальную связность, больше — тратит вычисления впустую |
| Branch gate | «Как смешивать три ветви» | Выход MLP для каждой позиции, взвешивающий вклад трёх ветвей |
| Hardware alignment | «Разреженность, удобная для ядра» | Паттерн разреженности выбран так, чтобы реальное ядро GPU достигало теоретического ускорения |
| DSA | «Преемник NSA» | Deepseek Sparse Attention, архитектура, последовавшая за NSA в линейке DeepSeek |
