# Multi-Head Attention (Многоголовое внимание)

> Одна голова внимания учит одно отношение за раз. Восемь голов учат восемь. Головы ничего не стоят. Берите больше.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 7 · 02 (Self-Attention from Scratch)
**Time:** ~75 минут

## Проблема

Одна голова self-attention вычисляет одну матрицу внимания. Эта матрица захватывает один вид отношений — обычно тот, который минимизирует функцию потерь, исходя из обучающего сигнала. Если в ваших данных вперемешку есть согласование подлежащего и сказуемого, кореференция, дальние связи в дискурсе и синтаксическое чанкинг, одна голова размазывает всё это в единое softmax-распределение и теряет половину сигнала.

Решение из статьи Vaswani 2017 года: запустить несколько функций внимания параллельно, каждую со своими проекциями Q, K, V, и склеить выходы. Каждая голова работает в подпространстве меньшей размерности `d_model / n_heads`. Общее число параметров остаётся тем же. Выразительная способность растёт.

Многоголовое внимание — стандарт, с которым поставляется каждый трансформер в 2026 году. Спор идёт только о том, *сколько* голов использовать и делят ли ключи и значения проекции между собой (Grouped-Query Attention, Multi-Query Attention, Multi-head Latent Attention).

## Концепция

![Multi-head attention splits, attends, concatenates](../assets/multi-head-attention.svg)

**Разделение.** Берём `X` формы `(N, d_model)`. Проецируем в Q, K, V, каждая из которых имеет форму `(N, d_model)`. Изменяем форму на `(N, n_heads, d_head)`, где `d_head = d_model / n_heads`. Транспонируем в `(n_heads, N, d_head)`.

**Параллельное внимание.** Запускаем scaled dot-product attention внутри каждой головы. Каждая голова выдаёт `(N, d_head)`. Головы работают с разными подпространствами эмбеддинга и не "общаются" друг с другом во время самого вычисления внимания.

**Конкатенация и проекция.** Собираем головы обратно в `(N, d_model)` и умножаем на обучаемую выходную матрицу `W_o` формы `(d_model, d_model)`. `W_o` — это место, где голов смешиваются.

**Почему это работает.** Каждая голова может специализироваться, не соревнуясь с другими за бюджет представления. Исследования с пробингом за 2019–2024 годы показывают отдельные роли голов: позиционные головы, голова, обращающая внимание на предыдущий токен, головы копирования, головы именованных сущностей, индукционные головы (которые лежат в основе обучения в контексте).

**Линия вариаций 2026 года:**

| Вариант | Q-головы | K/V-головы | Используется в |
|---------|---------|-----------|---------|
| Multi-head (MHA) | N | N | GPT-2, BERT, T5 |
| Multi-query (MQA) | N | 1 | PaLM, Falcon |
| Grouped-query (GQA) | N | G (например, N/8) | Llama 2 70B, Llama 3+, Qwen 2+, Mistral |
| Multi-head latent (MLA) | N | сжато до низкого ранга | DeepSeek-V2, V3 |

GQA — современный стандарт по умолчанию, поскольку сокращает память KV-кэша в `N/G` раз, сохраняя почти полное качество. MLA идёт дальше, сжимая K/V в латентное пространство, а затем распроецируя обратно во время вычислений — это стоит FLOPs, но экономит значительно больше памяти.

## Постройте это

### Шаг 1: разделение голов из одноголового внимания, которое у нас уже есть

Возьмите `SelfAttention` из Lesson 02 и оберните его парой split/concat. См. `code/main.py` для реализации на numpy; логика такова:

```python
def split_heads(X, n_heads):
    n, d = X.shape
    d_head = d // n_heads
    return X.reshape(n, n_heads, d_head).transpose(1, 0, 2)  # (heads, n, d_head)

def combine_heads(H):
    h, n, d_head = H.shape
    return H.transpose(1, 0, 2).reshape(n, h * d_head)
```

Одна операция reshape и одна transpose. Без циклов. Именно это PyTorch делает под капотом в `nn.MultiheadAttention`.

### Шаг 2: запустите scaled-dot-product attention для каждой головы

Каждая голова получает свой срез Q, K, V. Внимание становится батчевым matmul:

```python
def mha_forward(X, W_q, W_k, W_v, W_o, n_heads):
    Q = X @ W_q
    K = X @ W_k
    V = X @ W_v
    Qh = split_heads(Q, n_heads)         # (heads, n, d_head)
    Kh = split_heads(K, n_heads)
    Vh = split_heads(V, n_heads)
    scores = Qh @ Kh.transpose(0, 2, 1) / np.sqrt(Qh.shape[-1])
    weights = softmax(scores, axis=-1)
    out = weights @ Vh                    # (heads, n, d_head)
    concat = combine_heads(out)
    return concat @ W_o, weights
```

На реальном железе `Qh @ Kh.transpose(...)` — это один `bmm`. GPU видит единый батчевый matmul формы `(heads, N, d_head) × (heads, d_head, N) -> (heads, N, N)`. Добавление голов ничего не стоит.

### Шаг 3: вариант Grouped-Query Attention

Меняются только проекции ключей и значений. Q получает `n_heads` групп; K и V получают `n_kv_heads < n_heads` групп и повторяются, чтобы совпасть по размеру:

```python
def gqa_project(X, W, n_kv_heads, n_heads):
    kv = split_heads(X @ W, n_kv_heads)       # (kv_heads, n, d_head)
    repeat = n_heads // n_kv_heads
    return np.repeat(kv, repeat, axis=0)      # (n_heads, n, d_head)
```

При инференсе это экономит память, поскольку в KV-кэше живут только `n_kv_heads` копий, а не `n_heads`. Llama 3 70B использует 64 query-головы с 8 KV-головами — сокращение кэша в 8 раз.

### Шаг 4: исследуйте, чему научилась каждая голова

Запустите MHA на коротком предложении с 4 головами. Для каждой головы выведите матрицу внимания `(N, N)`. Вы увидите, что разные головы выделяют разную структуру даже при случайной инициализации — это отчасти сигнал, отчасти вращательная симметрия в подпространствах.

## Используйте это

В PyTorch, однострочная версия:

```python
import torch.nn as nn

mha = nn.MultiheadAttention(embed_dim=512, num_heads=8, batch_first=True)
```

GQA начиная с PyTorch 2.5+:

```python
from torch.nn.functional import scaled_dot_product_attention

# scaled_dot_product_attention auto-dispatches Flash Attention on CUDA.
# For GQA, pass Q of shape (B, n_heads, N, d_head) and K,V of shape
# (B, n_kv_heads, N, d_head). PyTorch handles the repeat.
out = scaled_dot_product_attention(q, k, v, is_causal=True, enable_gqa=True)
```

**Сколько голов?** Эмпирические правила из продакшн-моделей в 2026 году:

| Размер модели | d_model | n_heads | d_head |
|------------|---------|---------|--------|
| Small (~125M) | 768 | 12 | 64 |
| Base (~350M) | 1024 | 16 | 64 |
| Large (~1B) | 2048 | 16 | 128 |
| Frontier (~70B) | 8192 | 64 | 128 |

`d_head` почти всегда оказывается равным 64 или 128. Это единица измерения того, сколько может "увидеть" одна голова. Опуститесь ниже 32 — и головы начнут конфликтовать с коэффициентом масштабирования `sqrt(d_head)`; поднимитесь выше 256 — и теряется выгода от "множества маленьких специалистов".

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Голова (Head) | "Единая схема внимания" | Одна проекция Q/K/V размерности `d_head = d_model / n_heads` со своей матрицей внимания. |
| d_head | "Размерность головы" | Скрытая ширина на одну голову; почти всегда 64 или 128 в продакшене. |
| Разделение / объединение | "Трюки с reshape" | `(N, d_model) ↔ (n_heads, N, d_head)` reshape+transpose вокруг внимания. |
| W_o | "Выходная проекция" | Матрица `(d_model, d_model)`, применяемая после конкатенации голов; место, где головы смешиваются. |
| MQA | "Одна KV-голова" | Multi-Query Attention: единая общая проекция K/V. Наименьший KV-кэш, некоторая потеря качества. |
| GQA | "Стандарт с Llama 2" | Grouped-Query Attention с `n_kv_heads < n_heads`; повторяется, чтобы совпасть с Q. |
| MLA | "Трюк DeepSeek" | Multi-head Latent Attention: K,V сжимаются до латента низкого ранга, распаковываются во время внимания. |
| Индукционная голова | "Схема, лежащая в основе обучения в контексте" | Пара голов, которые обнаруживают предыдущие вхождения и копируют то, что следовало за ними. |
