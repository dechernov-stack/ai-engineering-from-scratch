# Спекулятивное декодирование — черновик, проверка, повтор

> Авторегрессионное декодирование последовательно. Каждый токен ждёт предыдущего. Спекулятивное декодирование разрывает эту цепочку: дешёвая модель черновиком предлагает N токенов, дорогая модель проверяет все N за один прямой проход. Когда черновик верен, вы платите за один большой прямой проход ради N генераций.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 7 · 07 (GPT Causal LM), Phase 7 · 12 (KV Cache & Flash Attention)
**Time:** ~60 минут

## Проблема

70B LLM, сэмплирующая один токен, тратит на это ~30 мс на H100. Черновая модель на 3B тратит ~3 мс. Если дать 3B-модели составить черновик из 5 токенов вперёд, а затем запустить 70B-модель *один раз* для проверки всех 5, итог составит `5×3 + 30 = 45 ms` при приёме до 5 токенов — против `5×30 = 150 ms` для прямолинейной генерации. В этом и заключается вся суть спекулятивного декодирования: обменять небольшой объём дополнительной памяти GPU (черновая модель) на снижение задержки декодирования в 2–4 раза.

Фокус должен сохранять распределение. Спекулятивное сэмплирование, предложенное Leviathan et al. (2023) и независимо Chen et al., гарантирует, что выходная последовательность **идентично распределена** тому, что произвела бы большая модель самостоятельно. Никакого компромисса в качестве. Просто быстрее.

Четыре семейства пар «черновик-верификатор» доминируют в инференсе 2026 года:

1. **Классический спекулятивный подход (Leviathan 2023).** Отдельная черновая модель (например, Llama 3 1B) + верификатор (например, Llama 3 70B).
2. **Medusa (Cai 2024).** Несколько декодирующих голов на верификаторе предсказывают позиции `t+1..t+k` параллельно. Отдельной черновой модели нет.
3. **Семейство EAGLE (Li 2024, 2025).** Лёгкий черновик, переиспользующий скрытые состояния верификатора; более высокая частота принятия, чем у классического подхода; типично 3–4×.
4. **Lookahead-декодирование (Fu 2024).** Итерация Якоби; черновая модель вообще не требуется. Самоспекуляция. Нишевый, но не требует зависимостей подход.

Каждый промышленный стек инференса в 2026 году по умолчанию поставляется со спекулятивным декодированием. vLLM, TensorRT-LLM, SGLang и llama.cpp поддерживают как минимум классический подход + EAGLE-2.

## Концепция

### Базовый алгоритм

Дан верификатор `M_q` и более дешёвый черновик `M_p`:

1. Пусть `x_1..x_k` — уже декодированный префикс.
2. **Черновик**: используем `M_p`, чтобы авторегрессионно предложить `d_{k+1}, d_{k+2}, ..., d_{k+N}` с черновыми вероятностями `p_1..p_N`.
3. **Параллельная проверка**: запускаем `M_q` один раз на `x_1..x_k, d_{k+1}, ..., d_{k+N}`, получая вероятности верификатора `q_1..q_{N+1}` для позиций `k+1..k+N+1`.
4. **Принять/отклонить каждый черновой токен слева направо**: для каждого `i` принять с вероятностью `min(1, q_i(d_i) / p_i(d_i))`.
5. При первом отклонении на позиции `j`: сэмплировать `t_j` из «остаточного» распределения `(q_j - p_j)_+`, нормализованного. Все черновики после `j` отбрасываются.
6. При принятии всех `N`: сэмплировать один дополнительный токен `t_{N+1}` из `q_{N+1}` (бесплатный бонусный токен).

Трюк с остаточным распределением — это математическая идея, которая гарантирует, что выход распределён точно так же, как если бы `M_q` сэмплировал с нуля.

### Что определяет ускорение

Пусть `α` = ожидаемая частота принятия на черновой токен. Пусть `c` = отношение стоимости черновика к стоимости верификатора. На шаг:

- Наивная генерация делает 1 вызов большой модели на токен.
- Спекулятивный подход делает 1 вызов большой модели на `(1 - α^{N+1}) / (1 - α) ≈ 1/(1-α)` токенов, когда `α` высоко.

Типичное эмпирическое правило при `α = 0.75` и `N = 5`: в 3 раза меньше вызовов большой модели. Стоимость черновика в 5 раз дешевле. Общее время работы падает примерно в 2,5 раза.

**От чего зависит α:**

- Насколько хорошо черновик аппроксимирует верификатор. Одно семейство / одни обучающие данные значительно повышают α.
- Стратегия декодирования. Жадный черновик против жадного верификатора: высокое α. Сэмплирование с температурой: сложнее согласовать; частота принятия падает.
- Тип задачи. Код и структурированный вывод принимаются чаще (предсказуемы); свободное творческое письмо принимается реже.

### Medusa — черновики без черновой модели

Medusa заменяет черновую модель дополнительными выходными головами на верификаторе. На позиции `t`:

```
shared trunk → hidden h_t
    ├── head_0: predict token at t+1  (standard LM head)
    ├── head_1: predict token at t+2
    ├── head_2: predict token at t+3
    ├── head_3: predict token at t+4
```

Каждая голова выдаёт собственные логиты. На этапе инференса вы сэмплируете из каждой головы, чтобы получить кандидатную последовательность, а затем проверяете одним прямым проходом с помощью схемы древовидного внимания (tree attention), которая учитывает все кандидатные продолжения одновременно.

Плюсы: не нужна вторая модель. Минусы: добавляются обучаемые параметры; требуется этап контролируемого дообучения (~1B токенов); частота принятия немного ниже, чем у классического спекулятивного подхода с хорошим черновиком.

### EAGLE — лучший черновик за счёт переиспользования скрытых состояний

EAGLE-1/2/3 (Li et al., 2024–2025) делает черновую модель крошечным трансформером (обычно 1 слой), который принимает на вход скрытые состояния последнего слоя верификатора. Поскольку черновик видит представление признаков верификатора, его предсказания сильно коррелируют с выходным распределением верификатора. Частота принятия растёт с ~0,6 (классический подход) до 0,85+.

EAGLE-3 (2025) добавил древовидный поиск по кандидатным продолжениям. vLLM и SGLang поставляют EAGLE-2/3 как путь спекуляции по умолчанию для Llama 3/4 и Qwen 3.

### Танец с KV-кэшем

Верификация подаёт `N` черновых токенов в верификатор за один прямой проход. Это расширяет KV-кэш верификатора на `N` записей. Если некоторые черновики отклонены, нужно откатить кэш до длины принятого префикса.

Промышленные реализации (`--speculative-config` в vLLM, LookaheadDecoder в TensorRT-LLM) решают это с помощью временных KV-буферов. Сначала запись, фиксация при принятии. Концептуально это не сложно, но возни хватает.

## Реализация

См. `code/main.py`. Мы реализуем базовый алгоритм спекулятивного сэмплирования (шаг отклонения + остаточное распределение) со следующим:

- «Большая модель» — это детерминированный softmax над вручную заданным распределением (чтобы можно было аналитически проверить математику принятия).
- «Черновая модель» — это возмущение большой модели.
- Цикл принятия/отклонения, который даёт то же маргинальное распределение, что и прямое сэмплирование.

### Шаг 1: шаг отклонения

```python
def accept_or_reject(q_prob, p_prob, draft_token, u):
    ratio = q_prob / p_prob if p_prob > 0 else float("inf")
    return u < min(1.0, ratio)
```

`u` — это равномерное случайное число. `q_prob` — вероятность верификатора для черновового токена. `p_prob` — вероятность черновой модели. Теорема Leviathan гласит, что это решение Бернулли, за которым следует сэмплирование из остатка при отклонении, точно сохраняет распределение верификатора.

### Шаг 2: остаточное распределение

```python
def residual_dist(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    return [r / s for r in raw]
```

Вычтите `p` из `q` поэлементно, обрежьте отрицательные значения до нуля, перенормируйте. Сэмплируйте из этого при любом отклонении.

### Шаг 3: один спекулятивный шаг

```python
def spec_step(prefix, q_model, p_model, N, rng):
    drafts = []
    p_probs = []
    ctx = list(prefix)
    for _ in range(N):
        p_dist = p_model(ctx)
        d = sample(p_dist, rng)
        drafts.append(d)
        p_probs.append(p_dist[d])
        ctx.append(d)

    q_dists = [q_model(prefix + drafts[:i]) for i in range(N + 1)]

    for i, d in enumerate(drafts):
        u = rng.random()
        q_prob = q_dists[i][d]
        p_prob = p_probs[i]
        if u < min(1.0, q_prob / p_prob if p_prob > 0 else float("inf")):
            prefix = prefix + [d]
        else:
            res = residual_dist(q_dists[i], p_model(prefix))
            prefix = prefix + [sample(res, rng)]
            return prefix
    prefix = prefix + [sample(q_dists[N], rng)]
    return prefix
```

Пять принятых → один бонус → шесть токенов получены за один проход верификатора.

### Шаг 4: измерить частоту принятия

Запустите 10 000 спекулятивных шагов при разных уровнях качества черновика. Постройте график зависимости частоты принятия от KL-дивергенции между распределениями черновика и верификатора. Вы должны увидеть чёткую монотонную зависимость.

### Шаг 5: проверить эквивалентность распределений

Эмпирически: гистограмма токенов, полученных спекулятивным циклом, должна совпадать с гистограммой, полученной прямым сэмплированием из верификатора. Это теорема Leviathan на практике. Критерий хи-квадрат подтверждает совпадение в пределах погрешности выборки.

## Применение

Промышленное применение:

```bash
# vLLM with EAGLE
vllm serve meta-llama/Llama-3.1-70B-Instruct \
    --speculative-config '{"method": "eagle", "model": "/models/llama-3.1-eagle-70b", "draft_tensor_parallel_size": 1, "num_speculative_tokens": 5}'

# vLLM with vanilla draft model
vllm serve meta-llama/Llama-3.1-70B-Instruct \
    --speculative-config '{"method": "draft_model", "model": "meta-llama/Llama-3.2-1B-Instruct", "num_speculative_tokens": 5}'
```

TensorRT-LLM имеет самый быстрый путь Medusa по состоянию на середину 2026 года. `faster-whisper` оборачивает спекулятивное декодирование для Whisper-large с небольшим черновиком.

**Выбор черновика:**

| Стратегия | Когда выбирать | Ускорение |
|----------|--------------|---------|
| Классический черновик (1B/3B из семейства Llama) | Быстрый прототип, без обучения | 1,8–2,3× |
| Головы Medusa | Можно дообучить верификатор | 2–3× |
| EAGLE-2 / 3 | Продакшн, максимальная скорость | 3–4× |
| Lookahead | Без черновика, без обучения, без лишних параметров | 1,3–1,6× |

**Когда НЕ стоит применять спекулятивное декодирование:**

- Генерация одной последовательности из 1–5 токенов. Накладные расходы доминируют.
- Крайне творческое / высокотемпературное сэмплирование (α падает).
- Развёртывания с ограниченной памятью (черновая модель добавляет расход VRAM).

2. **Среднее.** Постройте график ускорения (токенов на один прямой проход большой модели) в зависимости от `N` для `α = 0.5, 0.7, 0.85`. Определите оптимальное `N` для каждого α. (Подсказка: ожидаемое число токенов на вызов проверки = `(1 - α^{N+1}) / (1 - α)`.)
3. **Сложное.** Реализуйте мини-Medusa: возьмите капстоун-GPT из Lesson 14, добавьте 3 дополнительные LM-головы, предсказывающие позиции t+2, t+3, t+4. Обучите на tinyshakespeare с совместной многоголовой функцией потерь. Сравните частоту принятия с классическим черновиком, полученным усечением той же модели.
4. **Сложное.** Реализуйте откат: начните с KV-кэша префикса из 10 токенов, подайте 5 черновых токенов, смоделируйте отклонение на позиции 3. Проверьте, что ваши чтения кэша на следующей итерации корректно соответствуют «префикс + первые 2 принятых черновика».

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле значит |
|------|-----------------|-----------------------|
| Draft model (черновая модель) | «Дешёвая» | Меньшая модель, предлагающая кандидатные токены; обычно в 10–50 раз дешевле верификатора. |
| Verifier (верификатор) | «Большая» | Целевая модель, чьё распределение мы сохраняем; запускается один раз за спекулятивный шаг. |
| Acceptance rate — частота принятия (α) | «Как часто черновик прав» | Вероятность того, что верификатор примет черновик, на токен. Обычно 0,7–0,9. |
| Residual distribution — остаточное распределение | «Запасной вариант при отклонении» | `(q - p)_+`, нормализованное; сэмплирование из него при отклонении сохраняет распределение верификатора. |
| Bonus token — бонусный токен | «Бесплатный» | Когда все N черновиков приняты, сэмплируется ещё один токен из распределения следующего шага верификатора. |
| Medusa | «Спекуляция без черновика» | Несколько LM-голов на верификаторе параллельно предсказывают позиции t+1..t+k. |
| EAGLE | «Черновик по скрытым состояниям» | Крошечный трансформер-черновик, обусловленный скрытыми состояниями последнего слоя верификатора. |
| Lookahead decoding — lookahead-декодирование | «Итерация Якоби» | Самоспекуляция с использованием итерации неподвижной точки; без черновой модели. |
| Tree attention — древовидное внимание | «Проверить множество кандидатов сразу» | Ветвящаяся проверка, одновременно учитывающая несколько черновых продолжений. |
| KV rollback — откат KV-кэша | «Отменить отклонённые черновики» | Временный KV-буфер; фиксация при принятии, отбрасывание при отклонении. |
