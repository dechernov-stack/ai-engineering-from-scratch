# Mixture of Experts (MoE)

> Плотный трансформер на 70B активирует каждый параметр для каждого токена. MoE на 671B активирует только 37B на токен и превосходит его по каждому бенчмарку. Разреженность — самая важная идея масштабирования этого десятилетия.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 7 · 05 (Full Transformer), Phase 7 · 07 (GPT)
**Time:** ~45 минут

## Проблема

FLOPs плотного трансформера на инференсе равны количеству его параметров (умноженному на 2 для прямого прохода). Увеличивайте плотную модель — и каждый токен платит полную цену. К 2024 году фронтир упёрся в вычислительную стену: чтобы стать заметно умнее, требовалось экспоненциально больше FLOPs на токен.

Mixture of Experts разрывает эту связь. Замените каждый FFN на `E` независимых экспертов + маршрутизатор, который выбирает `k` экспертов на токен. Общее число параметров = `E × FFN_size`. Активных параметров на токен = `k × FFN_size`. Типичная конфигурация 2026 года: `E=256`, `k=8`. Хранение масштабируется с `E`, вычисления — с `k`.

Фронтир 2026 года почти полностью состоит из MoE: DeepSeek-V3 (671B всего / 37B активных), Mixtral 8×22B, Qwen2.5-MoE, Llama 4, Kimi K2, gpt-oss. В независимом рейтинге Artificial Analysis топ-10 моделей с открытым исходным кодом — все MoE.

## Концепция

![MoE layer: router selects k of E experts per token](../assets/moe.svg)

### Замена FFN

Блок плотного трансформера:

```
h = x + attn(norm(x))
h = h + FFN(norm(h))
```

Блок MoE:

```
h = x + attn(norm(x))
scores = router(norm(h))              # (N_tokens, E)
top_k = argmax_k(scores)              # pick k of E per token
h = h + sum_{e in top_k}(
        gate(scores[e]) * Expert_e(norm(h))
    )
```

Каждый эксперт — независимый FFN (обычно SwiGLU-подобный). Маршрутизатор — это один линейный слой. Каждый токен выбирает своих собственных `k` экспертов и получает взвешенную смесь их выходов.

### Проблема балансировки нагрузки

Если маршрутизатор направляет 90% токенов через эксперта 3, остальные эксперты голодают. Испробовано три решения:

1. **Вспомогательная функция потерь балансировки нагрузки** (Switch Transformer, Mixtral). Добавляется штраф, пропорциональный дисперсии использования экспертов. Работает, но добавляет гиперпараметр и второй градиентный сигнал.
2. **Ёмкость эксперта + отбрасывание токенов** (ранний Switch). Каждый эксперт обрабатывает не более `C × N/E` токенов; избыточные токены пропускают слой. Ухудшает качество.
3. **Балансировка без вспомогательных потерь** (DeepSeek-V3). Добавляется обучаемое смещение для каждого эксперта, которое сдвигает top-k выбор маршрутизатора. Смещение обновляется вне функции потерь обучения. Никакого штрафа в основной целевой функции. Главный прорыв 2024 года.

Подход DeepSeek-V3: после каждого шага обучения для каждого эксперта проверяется, выше или ниже целевого значения его использование. Смещение сдвигается на `±γ`. Для выбора используется `scores + bias`. Вероятности экспертов, используемые для гейтинга, — это неизменённые сырые `scores`. Маршрутизация отделена от выражения.

### Общие эксперты

DeepSeek-V2/V3 также разделяют экспертов на *общих* (shared) и *маршрутизируемых* (routed). Каждый токен проходит через всех общих экспертов. Маршрутизируемые эксперты выбираются через top-k. Общие эксперты захватывают общие знания; маршрутизируемые специализируются. V3 использует 1 общего эксперта плюс top-8 из 256 маршрутизируемых.

### Мелкозернистые эксперты

Классический MoE (GShard, Switch): каждый эксперт так же широк, как полный FFN. `E` небольшое (8–64), `k` небольшое (1–2).

Современный мелкозернистый MoE (DeepSeek-V3, Qwen-MoE): каждый эксперт уже (1/8 размера FFN). `E` велико (256+), `k` больше (8+). То же общее число параметров, но комбинации масштабируются гораздо быстрее. `C(256, 8) = 400 trillion` возможных «экспертов» на токен. Качество растёт, задержка остаётся неизменной.

### Профиль стоимости

На токен, на слой:

| Конфигурация | Активных параметров / токен | Всего параметров |
|--------|-----------------------|--------------|
| Mixtral 8×22B | ~39B | 141B |
| Llama 3 70B (плотная) | 70B | 70B |
| DeepSeek-V3 | 37B | 671B |
| Kimi K2 (MoE) | ~32B | 1T |

DeepSeek-V3 превосходит Llama 3 70B (плотную) почти по каждому бенчмарку, выполняя при этом **меньше активных FLOPs на токен**. Больше параметров = больше знаний. Больше активных FLOPs = больше вычислений на токен. MoE разделяет эти два аспекта.

### Подвох: память

Все эксперты находятся на GPU независимо от того, какие из них срабатывают. Модели на 671B нужно ~1,3 ТБ видеопамяти для весов в fp16. Развёртывание фронтир-MoE требует экспертного параллелизма — разбиения экспертов между GPU, маршрутизации токенов по сети. Задержка определяется преимущественно all-to-all коммуникацией, а не матричным умножением.

## Постройте это

См. `code/main.py`. Компактный слой MoE на чистой стандартной библиотеке с:

- `n_experts=8` SwiGLU-подобными экспертами (по одному линейному слою каждый, для иллюстрации)
- маршрутизацией top-k=2
- гейтинг-весами, нормализованными через softmax
- балансировкой без вспомогательных потерь через смещение для каждого эксперта

### Шаг 1: маршрутизатор

```python
def route(hidden, W_router, top_k, bias):
    scores = [sum(h * w for h, w in zip(hidden, W_router[e])) for e in range(len(W_router))]
    biased = [s + b for s, b in zip(scores, bias)]
    top_idx = sorted(range(len(biased)), key=lambda i: -biased[i])[:top_k]
    # softmax over ORIGINAL scores of the chosen experts
    chosen = [scores[i] for i in top_idx]
    m = max(chosen)
    exps = [math.exp(c - m) for c in chosen]
    s = sum(exps)
    gates = [e / s for e in exps]
    return top_idx, gates
```

Смещение влияет на выбор, а не на вес гейта. Это и есть трюк DeepSeek-V3 — смещение исправляет дисбаланс нагрузки, не влияя на предсказания модели.

### Шаг 2: пропустите 100 токенов через маршрутизатор

Отслеживайте, какие эксперты срабатывают и как часто. Без смещения использование неравномерно. С циклом обновления смещения (`-γ` для перегруженных экспертов, `+γ` для недогруженных) использование сходится к равномерному распределению за несколько итераций.

### Шаг 3: сравнение числа параметров

Выведите «плотный эквивалент» конфигурации MoE. В духе DeepSeek-V3: 256 маршрутизируемых + 1 общий, 8 активных, d_model=7168. Общее число параметров поражает воображение. Активное число составляет седьмую часть от плотной Llama 3 70B.

## Используйте это

Загрузка через HuggingFace:

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
model = AutoModelForCausalLM.from_pretrained("mistralai/Mixtral-8x22B-v0.1")
```

Производственный инференс 2026 года: vLLM поддерживает маршрутизацию MoE нативно. SGLang имеет самый быстрый путь экспертного параллелизма. Оба автоматически обрабатывают top-k выбор и экспертный параллелизм.

**Когда выбирать MoE:**
- Вам нужно качество уровня фронтира при меньшей стоимости инференса на токен.
- У вас есть видеопамять / инфраструктура экспертного параллелизма.
- Ваша нагрузка токеноёмкая (чат, код), а не контекстоёмкая (длинные документы).

**Когда НЕ стоит выбирать MoE:**
- Развёртывание на периферийных устройствах — вы платите за полное хранение для любого активного FLOP.
- Обслуживание одного пользователя с критичной задержкой — маршрутизация экспертов добавляет накладные расходы.
- Маленькие модели (<7B) — преимущество MoE в качестве проявляется только выше определённого вычислительного порога (~6B активных параметров).

## Ключевые термины

| Термин | Что обычно говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Эксперт | «Один FFN среди многих» | Независимая прямая нейронная сеть; параметры, выделенные под разреженный срез вычислений FFN. |
| Маршрутизатор | «Гейт» | Крошечный линейный слой, который оценивает каждый токен относительно каждого эксперта; top-k выбор. |
| Top-k маршрутизация | «k активных экспертов на токен» | Вычисление FFN для токена проходит ровно через k экспертов, взвешенных гейтом. |
| Вспомогательная функция потерь | «Штраф за балансировку нагрузки» | Дополнительный член функции потерь, штрафующий неравномерное использование экспертов. |
| Без вспомогательных потерь | «Трюк DeepSeek-V3» | Балансировка через смещение для каждого эксперта только в выборе маршрутизатора; без дополнительного градиента. |
| Общий эксперт | «Всегда включён» | Дополнительный эксперт, через которого проходит каждый токен; захватывает общие знания. |
| Экспертный параллелизм | «Разбиение по экспертам» | Распределение разных экспертов по разным GPU; маршрутизация токенов по сети. |
| Разреженность | «Активных параметров < общего числа параметров» | Отношение `k × expert_size / (E × expert_size)`; 37/671 ≈ 5,5% для DeepSeek-V3. |
