# T5, BART — модели энкодер-декодер

> Энкодеры понимают. Декодеры генерируют. Соедините их вместе — и получится модель, созданная для задач вход → выход: перевод, суммаризация, переписывание, транскрибация.

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 7 · 05 (Full Transformer), Phase 7 · 06 (BERT), Phase 7 · 07 (GPT)
**Time:** ~45 минут

## Проблема

GPT (только декодер) и BERT (только энкодер) каждый по-своему упрощают архитектуру 2017 года под разную цель. Но многие задачи по своей природе являются входо-выходными:

- Перевод: английский → французский.
- Суммаризация: статья на 5000 токенов → резюме на 200 токенов.
- Распознавание речи: аудио-токены → текстовые токены.
- Структурированное извлечение: текст → JSON.

Для таких задач энкодер-декодер подходит лучше всего. Энкодер формирует плотное представление источника. Декодер генерирует вывод, на каждом шаге применяя cross-attention к этому представлению. Обучение — сдвиг на один токен на стороне вывода. Та же функция потерь, что у GPT, но с условием на выход энкодера.

Две статьи определили современный подход:

1. **T5** (Raffel et al. 2019). «Text-to-Text Transfer Transformer». Каждая NLP-задача переформулирована как текст-на-входе, текст-на-выходе. Единая архитектура, единый словарь, единая функция потерь. Предобучена на предсказании замаскированных спанов (повредить спаны во входе, декодировать их на выходе).
2. **BART** (Lewis et al. 2019). «Bidirectional and Auto-Regressive Transformer». Денойзинг-автоэнкодер: повредить вход несколькими способами (перемешать, замаскировать, удалить, повернуть), заставить декодер восстановить оригинал.

В 2026 году формат энкодер-декодер сохраняется там, где важна структура входа:

- Whisper (речь → текст).
- Переводческий стек Google.
- Некоторые модели автодополнения/исправления кода с чёткой структурой «контекст и правка».
- Flan-T5 и варианты для задач структурированного рассуждения.

Декодер-only завоевал внимание, но энкодер-декодер никуда не исчез.

## Концепция

![Encoder-decoder with cross-attention](../assets/encoder-decoder.svg)

### Прямой проход

```
source tokens ─▶ encoder ─▶ (N_src, d_model)  ──┐
                                                 │
target tokens ─▶ decoder block                   │
                 ├─▶ masked self-attention       │
                 ├─▶ cross-attention ◀───────────┘
                 └─▶ FFN
                ↓
              next-token logits
```

Важно: энкодер запускается один раз на входные данные. Декодер работает авторегрессионно, но на каждом шаге применяет cross-attention к *тому же* выходу энкодера. Кэширование выхода энкодера даёт бесплатное ускорение для длинных входов.

### Предобучение T5 — повреждение спанов (span corruption)

Выбираются случайные спаны входа (средняя длина 3 токена, всего 15%). Каждый спан заменяется уникальным сентинел-токеном: `<extra_id_0>`, `<extra_id_1>` и т.д. Декодер выводит только повреждённые спаны с префиксом-сентинелом:

```
source: The quick <extra_id_0> fox jumps <extra_id_1> dog
target: <extra_id_0> brown <extra_id_1> over the lazy
```

Это более дешёвый сигнал, чем предсказание всей последовательности. В абляциях из статьи T5 этот подход конкурентоспособен с MLM (BERT) и prefix-LM (UniLM).

### Предобучение BART — денойзинг с несколькими типами шума

BART опробует пять функций зашумления:

1. Маскирование токенов.
2. Удаление токенов.
3. Заполнение текста (text infilling) (замаскировать спан, декодер вставляет нужную длину).
4. Перестановка предложений.
5. Поворот документа.

Комбинация text infilling + перестановки предложений дала лучшие результаты на последующих задачах. Декодер всегда восстанавливает оригинал. Вывод BART — это полная последовательность, а не только повреждённые спаны, поэтому затраты вычислений на предобучение выше, чем у T5.

### Инференс

Та же авторегрессионная генерация, что и у GPT. Применимы жадный поиск, beam search, top-p сэмплирование. Beam search (ширина 4–5) — стандарт для перевода и суммаризации, поскольку распределение выходов там уже, чем в чате.

### Когда выбирать какой вариант в 2026

| Задача | Энкодер-декодер? | Почему |
|------|------------------|-----|
| Перевод | Да, обычно | Чёткая исходная последовательность; фиксированное распределение выхода; beam search работает |
| Речь в текст | Да (Whisper) | Модальность входа отличается от выхода; энкодер формирует аудио-признаки |
| Чат / рассуждения | Нет, decoder-only | Нет устойчивого «входа» — диалог сам по себе и есть последовательность |
| Автодополнение кода | Обычно нет | Decoder-only с длинным контекстом побеждает; кодовые модели вроде Qwen 2.5 Coder — decoder-only |
| Суммаризация | Подходит и то, и другое | BART, PEGASUS превосходили ранние decoder-only базовые модели; современные decoder-only LLM им соответствуют |
| Структурированное извлечение | Подходит и то, и другое | T5 удобна тем, что «текст → текст» вмещает любой формат вывода |

Тренд с ~2022 года: decoder-only забирает задачи, которые раньше были за энкодер-декодером, потому что (a) инструктивно настроенные decoder-only LLM обобщаются на всё что угодно через промптинг, (b) одной архитектурой масштабироваться проще, чем двумя, (c) RLHF предполагает декодер. Энкодер-декодер держится там, где модальность входа отличается (речь, изображения) или где важно качество beam search.

## Реализация

См. `code/main.py`. Мы реализуем T5-стиль повреждения спанов для игрушечного корпуса — самая полезная отдельная часть этого урока, поскольку она встречается в каждом рецепте предобучения энкодер-декодер с тех пор.

### Шаг 1: повреждение спанов

```python
def corrupt_spans(tokens, mask_rate=0.15, mean_span=3.0, rng=None):
    """Pick spans summing to ~mask_rate of tokens. Return (corrupted_input, target)."""
    n = len(tokens)
    n_mask = max(1, int(n * mask_rate))
    n_spans = max(1, int(round(n_mask / mean_span)))
    ...
```

Формат цели — конвенция T5: `<sent0> span0 <sent1> span1 ...`. Повреждённый вход чередует неизменённые токены с сентинел-токенами в местах спанов.

### Шаг 2: проверка обратимости

Имея повреждённый вход и цель, восстановите исходное предложение. Если ваше повреждение обратимо, прямой проход определён корректно. Это проверка на здравый смысл — в реальном обучении так никогда не делают, но тест дешёвый и ловит ошибки на единицу в учёте спанов.

### Шаг 3: зашумление в стиле BART

Пять функций: `token_mask`, `token_delete`, `text_infill`, `sentence_permute`, `document_rotate`. Скомбинируйте две из них и покажите результат.

## Применение

Справочник HuggingFace:

```python
from transformers import T5ForConditionalGeneration, T5Tokenizer
tok = T5Tokenizer.from_pretrained("google/flan-t5-base")
model = T5ForConditionalGeneration.from_pretrained("google/flan-t5-base")

inputs = tok("translate English to French: Attention is all you need.", return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=32)
print(tok.decode(out[0], skip_special_tokens=True))
```

Приём T5: название задачи вставляется прямо во входной текст. Одна и та же модель обрабатывает десятки задач, потому что каждая задача — это текст-на-входе, текст-на-выходе. В 2026 году этот паттерн обобщён инструктивно настроенными decoder-only моделями, но первой его кодифицировала именно T5.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Энкодер-декодер | «Seq2seq трансформер» | Два стека: двунаправленный энкодер для входа, каузальный декодер с cross-attention для выхода. |
| Cross-attention | «Где источник говорит с целью» | Q декодера × K/V энкодера. Единственное место, где информация энкодера попадает в декодер. |
| Повреждение спанов | «Приём предобучения T5» | Замена случайных спанов сентинел-токенами; декодер выводит эти спаны. |
| Денойзинг-цель | «Игра BART» | Применить функцию шума к входу, обучить декодер восстанавливать чистую последовательность. |
| Сентинел-токен | «Заполнитель `<extra_id_N>`» | Специальные токены, которые помечают повреждённые спаны в источнике и повторно помечают их в цели. |
| Flan | «Инструктивно настроенная T5» | T5, дообученная на >1800 задачах; сделала энкодер-декодер конкурентоспособной в следовании инструкциям. |
| Beam search | «Стратегия декодирования» | Хранить top-k частичных последовательностей на каждом шаге; стандарт для перевода/суммаризации. |
| Teacher forcing | «Вход во время обучения» | Во время обучения декодеру подаётся истинный предыдущий токен выхода, а не сэмплированный. |
