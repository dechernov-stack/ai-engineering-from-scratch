# Суммаризация текста

> Экстрактивные системы сообщают, что сказано в документе. Абстрактивные системы сообщают, что имел в виду автор. Разные задачи — разные ловушки.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 5 · 02 (BoW + TF-IDF), Phase 5 · 11 (Machine Translation)
**Time:** ~75 минут

## Проблема

Новостная статья на 2000 слов попадает в вашу ленту. Вам нужны 120 слов, передающие её суть. Вы можете либо выбрать три самых важных предложения из статьи (экстрактивный подход), либо пересказать содержание своими словами (абстрактивный подход). Оба варианта называются суммаризацией. Это совершенно разные задачи.

Экстрактивная суммаризация — это задача ранжирования. Оцените каждое предложение, верните топ-`k`. Результат всегда грамматически корректен, поскольку взят дословно. Риск — пропустить содержание, распределённое по всей статье.

Абстрактивная суммаризация — это задача генерации. Трансформер создаёт новый текст, опираясь на исходный. Результат связный и сжатый, но может содержать галлюцинации — факты, которых не было в источнике. Риск — уверенная фабрикация.

В этом уроке мы построим оба варианта, с присущим каждому режимом отказа.

## Концепция

![Extractive TextRank vs abstractive transformer](../assets/summarization.svg)

**Экстрактивный подход.** Рассматривайте статью как граф, где узлы — это предложения, а рёбра — их сходство. Запустите PageRank (или что-то подобное) по графу, чтобы оценить предложения по степени их связанности со всем остальным. Предложения с наивысшей оценкой и составляют резюме. Каноническая реализация — **TextRank** (Mihalcea и Tarau, 2004).

**Абстрактивный подход.** Дообучите трансформерную архитектуру энкодер-декодер (BART, T5, Pegasus) на парах «документ-резюме». На этапе вывода модель читает документ и генерирует резюме токен за токеном через cross-attention. Pegasus, в частности, использует цель предобучения с пропуском предложений (gap-sentence), что делает его превосходным в суммаризации почти без дополнительного дообучения.

Оценка проводится с помощью **ROUGE** (Recall-Oriented Understudy for Gisting Evaluation). ROUGE-1 и ROUGE-2 оценивают пересечение по униграммам и биграммам. ROUGE-L оценивает наибольшую общую подпоследовательность. Чем выше, тем лучше, но 40 по ROUGE-L — это «хорошо», а 50 — «исключительно». В каждой статье указываются все три метрики. Используйте пакет `rouge-score`.

## Реализация

### Шаг 1: TextRank (экстрактивный)

```python
import math
import re
from collections import Counter


def sentence_split(text):
    return re.split(r"(?<=[.!?])\s+", text.strip())


def similarity(s1, s2):
    w1 = Counter(s1.lower().split())
    w2 = Counter(s2.lower().split())
    intersection = sum((w1 & w2).values())
    denom = math.log(len(w1) + 1) + math.log(len(w2) + 1)
    if denom == 0:
        return 0.0
    return intersection / denom


def textrank(text, top_k=3, damping=0.85, iterations=50, epsilon=1e-4):
    sentences = sentence_split(text)
    n = len(sentences)
    if n <= top_k:
        return sentences

    sim = [[0.0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if i != j:
                sim[i][j] = similarity(sentences[i], sentences[j])

    scores = [1.0] * n
    for _ in range(iterations):
        new_scores = [1 - damping] * n
        for i in range(n):
            total_out = sum(sim[i]) or 1e-9
            for j in range(n):
                if sim[i][j] > 0:
                    new_scores[j] += damping * sim[i][j] / total_out * scores[i]
        if max(abs(s - ns) for s, ns in zip(scores, new_scores)) < epsilon:
            scores = new_scores
            break
        scores = new_scores

    ranked = sorted(range(n), key=lambda k: scores[k], reverse=True)[:top_k]
    ranked.sort()
    return [sentences[i] for i in ranked]
```

Стоит отметить два момента. Функция сходства использует лог-нормализованное пересечение слов — это оригинальный вариант TextRank. Косинусное сходство TF-IDF векторов тоже подходит. Коэффициент затухания 0,85 и число итераций — стандартные значения PageRank по умолчанию.

### Шаг 2: абстрактивный подход с BART

```python
from transformers import pipeline

summarizer = pipeline("summarization", model="facebook/bart-large-cnn")

article = """(long news article text)"""

summary = summarizer(article, max_length=120, min_length=60, do_sample=False)
print(summary[0]["summary_text"])
```

BART-large-CNN дообучен на корпусе CNN/DailyMail. Он сразу выдаёт резюме в новостном стиле. Для других доменов (научные статьи, диалоги, юридические тексты) используйте соответствующий чекпойнт Pegasus или дообучите модель на своих данных.

### Шаг 3: оценка ROUGE

```python
from rouge_score import rouge_scorer

scorer = rouge_scorer.RougeScorer(["rouge1", "rouge2", "rougeL"], use_stemmer=True)
scores = scorer.score(reference_summary, generated_summary)
print({k: round(v.fmeasure, 3) for k, v in scores.items()})
```

Всегда используйте стемминг. Без него «running» и «run» считаются разными словами, и ROUGE занижает оценку.

### За пределами ROUGE (оценка суммаризации в 2026 году)

ROUGE была доминирующей метрикой суммаризации двадцать лет, и в 2026 году её одной уже недостаточно. Масштабный мета-анализ статей по NLG показал следующее:

- **BERTScore** (сходство контекстных эмбеддингов) набирал популярность до 2023 года и теперь приводится наряду с ROUGE в большинстве статей по суммаризации.
- **BARTScore** трактует оценку как генерацию: резюме оценивается по тому, насколько вероятным предобученный BART считает его при данном источнике.
- **MoverScore** (расстояние Earth Mover's Distance по контекстным эмбеддингам) вышел на первое место в бенчмарках суммаризации 2025 года, поскольку лучше ROUGE улавливает семантическое пересечение.
- **FactCC** и **QA-based faithfulness** были распространены в 2021-2023 годах, теперь их часто заменяет **G-Eval** (цепочка промптов на GPT-4, оценивающая связность, непротиворечивость, беглость и релевантность с помощью рассуждений по цепочке мыслей).
- **G-Eval** и похожие подходы с LLM-судьёй совпадают с человеческой оценкой примерно в 80% случаев при хорошо продуманных рубриках.

Рекомендация для production: указывайте ROUGE-L для сравнения с устаревшими подходами, BERTScore для семантического пересечения, G-Eval для связности и фактической точности. Калибруйте по 50-100 размеченным человеком резюме.

### Шаг 4: проблема фактической точности

Абстрактивные резюме склонны к галлюцинациям. Экстрактивные резюме несут гораздо меньший риск галлюцинаций, поскольку результат взят дословно из источника, хотя они всё же могут вводить в заблуждение, если исходные предложения вырваны из контекста, устарели или процитированы не по порядку. Именно это — главная причина, по которой production-системы по-прежнему предпочитают экстрактивные методы для контента, связанного с комплаенсом.

Типы галлюцинаций, которые стоит называть по имени:

- **Подмена сущности.** Источник говорит «John Smith». Резюме говорит «John Brown».
- **Дрейф чисел.** Источник говорит «25 000». Резюме говорит «25 миллионов».
- **Инверсия полярности.** Источник говорит «отклонил предложение». Резюме говорит «принял предложение».
- **Выдумывание фактов.** Источник не упоминает гендиректора. Резюме утверждает, что гендиректор одобрил решение.

Подходы к оценке, которые работают:

- **FactCC.** Бинарный классификатор, обученный на логическом следовании между предложением источника и предложением резюме. Предсказывает «фактично/нефактично».
- **Фактическая точность на основе QA.** Задайте QA-модели вопросы, ответы на которые есть в источнике. Если резюме подразумевает другие ответы, это флагируется.
- **F1 на уровне сущностей.** Сравните именованные сущности в источнике и в резюме. Сущности, присутствующие только в резюме, вызывают подозрение.

Для любого пользовательского сценария, где важна фактическая точность (новости, медицина, юриспруденция, финансы), экстрактивный подход — более безопасный выбор по умолчанию. Абстрактивному подходу нужна проверка фактической точности в цикле.

## Применение

Стек 2026 года:

| Сценарий использования | Рекомендация |
|---------|-------------|
| Новости, резюме из 3-5 предложений, английский | `facebook/bart-large-cnn` |
| Научные статьи | `google/pegasus-pubmed` или настроенный T5 |
| Мультидокументная, длинная суммаризация | Любая LLM с контекстом 32k+ токенов, через промпт |
| Суммаризация диалогов | `philschmid/bart-large-cnn-samsum` |
| Экстрактивная, низкий риск галлюцинаций по построению | TextRank или LSA / LexRank из `sumy` |

В 2026 году LLM с длинным контекстом часто превосходят специализированные модели, если вычислительные ресурсы не являются ограничением. Компромисс — стоимость и воспроизводимость; специализированные модели дают более стабильные результаты.

## Готовый продукт

Сохраните как `outputs/skill-summary-picker.md`:

```markdown
---
name: summary-picker
description: Pick extractive or abstractive, named library, factuality check.
version: 1.0.0
phase: 5
lesson: 12
tags: [nlp, summarization]
---

Given a task (document type, compliance requirement, length, compute budget), output:

1. Approach. Extractive or abstractive. Explain in one sentence why.
2. Starting model / library. Name it. `sumy.TextRankSummarizer`, `facebook/bart-large-cnn`, `google/pegasus-pubmed`, or an LLM prompt.
3. Evaluation plan. ROUGE-1, ROUGE-2, ROUGE-L (use rouge-score with stemming). Plus factuality check if abstractive.
4. One failure mode to probe. Entity swap is the most common in abstractive news summarization; flag samples where source entities do not appear in summary.

Refuse abstractive summarization for medical, legal, financial, or regulated content without a factuality gate. Flag input over the model's context window as needing chunked map-reduce summarization (not just truncation).
```

## Упражнения

1. **Лёгкое.** Запустите TextRank на 5 новостных статьях. Сравните топ-3 предложения с эталонным резюме. Измерьте ROUGE-L. Вы должны увидеть 30-45 по ROUGE-L на статьях в стиле CNN/DailyMail.
2. **Среднее.** Реализуйте оценку фактической точности на уровне сущностей: извлеките именованные сущности из источника и резюме (spaCy), вычислите полноту (recall) сущностей источника в резюме и точность (precision) сущностей резюме относительно источника. Высокая точность и низкая полнота означают безопасность, но краткость; низкая точность означает галлюцинированные сущности.
3. **Сложное.** Сравните BART-large-CNN с LLM (Claude или GPT-4) на 50 статьях CNN/DailyMail. Приведите ROUGE-L, фактическую точность (по F1 сущностей) и стоимость одного резюме. Зафиксируйте, где какая модель выигрывает.

## Ключевые термины

| Термин | Что говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Extractive (экстрактивный) | Выбор предложений | Возврат предложений дословно из источника. Никогда не галлюцинирует. |
| Abstractive (абстрактивный) | Пересказ | Генерация нового текста на основе источника. Может галлюцинировать. |
| ROUGE | Метрика резюме | Пересечение по N-граммам / LCS между выводом системы и эталоном. |
| TextRank | Графовый экстрактивный метод | PageRank по графу сходства предложений. |
| Factuality (фактическая точность) | Правильно ли это | Подтверждены ли утверждения резюме источником. |
| Hallucination (галлюцинация) | Выдуманное содержание | Содержание в резюме, не подтверждённое источником. |
