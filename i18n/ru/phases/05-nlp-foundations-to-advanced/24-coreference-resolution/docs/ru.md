# Разрешение кореференции

> «Она ему позвонила. Он не ответил. Врач был на обеде». Три упоминания двух людей — и никто не назван по имени. Разрешение кореференции выясняет, кто есть кто.

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 5 · 06 (NER), Phase 5 · 07 (POS & Parsing)
**Time:** ~60 минут

## Проблема

Извлеките каждое упоминание Apple Inc. из статьи на 300 слов. Легко, когда в статье написано «Apple». Сложно, когда написано «компания», «они», «технологический гигант из Купертино» или «фирма Джобса». Без привязки этих упоминаний к одной и той же сущности ваш пайплайн NER упускает 60–80% упоминаний.

Разрешение кореференции связывает все выражения, относящиеся к одной и той же реальной сущности, в один кластер. Это клей между поверхностным NLP (NER, синтаксический анализ) и семантикой более высокого уровня (IE, QA, суммаризация, графы знаний).

Почему это важно в 2026 году:

- Суммаризация: «Генеральный директор объявил...» против «Тим Кук объявил...» — в резюме должно быть названо имя генерального директора.
- Вопросно-ответные системы: «Кому она позвонила?» требует разрешения «она».
- Извлечение информации: граф знаний с «PER1 основал Apple» и «Джобс основал Apple» как отдельными записями — ошибка.
- Мультидокументное IE: объединение упоминаний в статьях об одном и том же событии из разных источников — это кросс-документная кореференция.

## Концепция

![Coreference clustering: mentions → entities](../assets/coref.svg)

**Задача.** Вход: документ. Выход: кластеризация упоминаний (спанов), где каждый кластер относится к одной сущности.

**Типы упоминаний.**

- **Именованная сущность.** «Тим Кук»
- **Номинальное.** «генеральный директор», «компания»
- **Местоименное.** «он», «она», «они», «это»
- **Аппозитивное.** «Тим Кук, генеральный директор Apple,»

**Архитектуры.**

1. **На основе правил (Hobbs, 1978).** Разрешение местоимений на основе синтаксического дерева с использованием грамматических правил. Хороший базовый подход. Удивительно трудно превзойти на местоимениях.
2. **Классификатор пар упоминаний.** Для каждой пары упоминаний (m_i, m_j) предсказывается, кореферентны ли они. Кластеризация через транзитивное замыкание. Стандарт до 2016 года.
3. **Ранжирование упоминаний.** Для каждого упоминания ранжируются кандидаты-антецеденты (включая «нет антецедента»). Выбирается лучший.
4. **End-to-end на основе спанов (Lee et al., 2017).** Трансформерный энкодер. Перечисляются все кандидатные спаны до ограничения по длине. Предсказываются оценки упоминаний. Предсказывается вероятность антецедента для каждого спана. Жадная кластеризация. Современный стандарт по умолчанию.
5. **Генеративный подход (2024+).** Промпт для LLM: «Перечисли каждое местоимение в этом тексте и его антецедент». Хорошо работает на простых случаях, испытывает трудности с длинными документами и редкими референтами.

**Метрики оценки.** Пять стандартных метрик (MUC, B³, CEAF, BLANC, LEA), поскольку ни одна метрика сама по себе не отражает качество кластеризации. Среднее значение первых трёх отчитывается как CoNLL F1. Современный уровень в 2026 году на CoNLL-2012: ~83 F1.

**Известные сложные случаи.**

- Определённые дескрипции, относящиеся к сущностям, введённым страницами ранее.
- Мостовая анафора («колёса» → ранее упомянутая машина).
- Нулевая анафора в языках вроде китайского и японского.
- Катафора (местоимение перед референтом): «Когда **она** вошла, Мэри улыбнулась».

## Реализация

### Шаг 1: предобученная нейронная кореференция (AllenNLP / spaCy-experimental)

```python
import spacy
nlp = spacy.load("en_coreference_web_trf")   # experimental model
doc = nlp("Apple announced new products. The company said they would ship soon.")
for cluster in doc._.coref_clusters:
    print(cluster, "->", [m.text for m in cluster])
```

На более длинном документе вы получите что-то вроде:
- Кластер 1: [Apple, Компания, они]
- Кластер 2: [новые продукты]

### Шаг 2: разрешитель местоимений на основе правил (учебный)

См. `code/main.py` для реализации только на стандартной библиотеке:

1. Извлечь упоминания: именованные сущности (спаны с заглавной буквы), местоимения (поиск по словарю), определённые дескрипции («the X»).
2. Для каждого местоимения рассмотреть предыдущие K упоминаний и оценить их по:
   - согласованию по роду/числу (эвристика)
   - близости (ближайшее выигрывает)
   - синтаксической роли (подлежащие предпочтительнее)
3. Связать антецедент с наивысшей оценкой.

Неконкурентоспособно по сравнению с нейронными моделями. Но показывает пространство поиска и решения, которые должна принимать end-to-end модель.

### Шаг 3: использование LLM для кореференции

```python
prompt = f"""Text: {text}

List every pronoun and noun phrase that refers to a person or company.
Cluster them by what they refer to. Output JSON:
[{{"entity": "Apple", "mentions": ["Apple", "the company", "it"]}}, ...]
"""
```

Два режима отказа, за которыми стоит следить. Во-первых, LLM чрезмерно объединяют («его» и «её», относящиеся к двум разным людям). Во-вторых, LLM незаметно пропускают упоминания в длинных документах. Всегда проверяйте с помощью проверок смещений спанов.

### Шаг 4: оценка

Стандартный скрипт conll-2012 вычисляет MUC, B³, CEAF-φ4 и выводит среднее значение. Для внутренней оценки начните с точности и полноты на уровне спанов на вашем размеченном тестовом наборе, затем добавьте F1 связывания упоминаний.

## Подводные камни

- **Взрыв синглетонов.** Некоторые системы сообщают каждое упоминание как отдельный кластер. B³ снисходителен к этому. MUC наказывает за это. Всегда проверяйте все три метрики.
- **Местоимения в длинном контексте.** Производительность падает примерно на 15 F1 на документах длиннее 2000 токенов. Разбивайте на части аккуратно.
- **Предположения о роде.** Жёстко закодированные правила рода ломаются на небинарных референтах, организациях, животных. Используйте обученные модели или нейтральную оценку.
- **Дрейф LLM на длинных документах.** Один вызов API не может надёжно кластеризовать упоминания в 50+ параграфах. Используйте скользящее окно + слияние.

## Применение

Стек 2026 года:

| Ситуация | Выбор |
|-----------|------|
| Английский, один документ | `en_coreference_web_trf` (spaCy-experimental) или нейронная кореференция AllenNLP |
| Мультиязычность | SpanBERT / XLM-R, обученные на OntoNotes или Multilingual CoNLL |
| Кросс-документная кореференция событий | Специализированные end-to-end модели (SOTA 2025–26) |
| Быстрый базовый уровень на LLM | GPT-4o / Claude со структурированным промптом для кореференции |
| Продакшен-диалоговые системы | Резервный вариант на правилах + нейронная основная модель + ручная проверка критичных слотов |

Паттерн интеграции, который применяется в продакшене в 2026 году: сначала запускается NER, затем кореференция, после чего кластеры кореференции объединяются с сущностями NER. Последующие задачи видят одну сущность на кластер, а не одну сущность на упоминание.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Mention (упоминание) | Ссылка | Фрагмент текста, относящийся к сущности (имя, местоимение, именная группа). |
| Antecedent (антецедент) | То, на что указывает «это» | Более раннее упоминание, с которым кореферентно более позднее. |
| Cluster (кластер) | Упоминания сущности | Набор упоминаний, все из которых относятся к одной и той же реальной сущности. |
| Anaphora (анафора) | Обратная ссылка | Более позднее упоминание относится к более раннему («он» → «Джон»). |
| Cataphora (катафора) | Прямая ссылка | Более раннее упоминание относится к более позднему («Когда он пришёл, Джон...»). |
| Bridging (мостовая связь) | Неявная ссылка | «Я купил машину. Колёса были плохие.» (колёса ИМЕННО этой машины.) |
| CoNLL F1 | Число в таблицах лидеров | Среднее значение F1-оценок MUC, B³, CEAF-φ4. |
