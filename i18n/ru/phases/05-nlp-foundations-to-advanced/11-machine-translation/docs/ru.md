# Машинный перевод

> Перевод — это задача, которая тридцать лет оплачивала исследования в NLP и продолжает оплачивать их сейчас.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 5 · 10 (Attention Mechanism), Phase 5 · 04 (GloVe, FastText, Subword)
**Time:** ~75 минут

## Проблема

Модель читает предложение на одном языке и выдаёт предложение на другом. Длина варьируется. Порядок слов варьируется. Некоторые слова исходного языка отображаются на несколько слов целевого и наоборот. Идиомы отказываются от взаимно однозначного соответствия. "I miss you" на французском — "tu me manques", буквально "ты мне не хватаешь". Никакое выравнивание на уровне слов этого не переживёт.

Машинный перевод — это задача, которая заставила NLP изобрести энкодер-декодеры, внимание, трансформеры и в итоге всю парадигму LLM. Каждый шаг вперёд случался потому, что качество перевода было измеримым, а разрыв между человеком и машиной упрямо не желал сокращаться.

Этот урок пропускает исторический экскурс и обучает рабочему пайплайну 2026 года: предобученный мультиязычный энкодер-декодер (NLLB-200 или mBART), субсловную токенизацию, лучевой поиск (beam search), оценку по BLEU и chrF, а также горстку режимов отказа, которые до сих пор незамеченными попадают в продакшен.

## Концепция

![MT pipeline: tokenize → encode → decode with attention → detokenize](../assets/mt-pipeline.svg)

Современный MT — это трансформерный энкодер-декодер, обученный на параллельных текстах. Энкодер читает исходный текст в токенизации своего языка. Декодер генерирует целевой текст по одному субслову за раз, используя выход энкодера через cross-attention (урок 10). Для декодирования используется лучевой поиск, чтобы избежать ловушки жадного декодирования. Выход детокенизируется, снимается ложный регистр (detruecasing), и результат сравнивается с эталоном.

Три операционных решения определяют качество MT в реальных условиях.

- **Токенизатор.** SentencePiece BPE, обученный на смешанном многоязычном корпусе. Общий словарь для разных языков — это именно то, что делает возможными zero-shot пары в NLLB.
- **Размер модели.** NLLB-200 distilled 600M помещается на ноутбуке. NLLB-200 3.3B — опубликованный вариант по умолчанию для продакшена. 54.5B — исследовательский потолок.
- **Декодирование.** Ширина луча 4-5 для общего контента. Штраф за длину, чтобы избежать слишком короткого вывода. Ограниченное декодирование, когда нужна согласованность терминологии.

## Построение

### Шаг 1: вызов предобученной модели MT

```python
from transformers import AutoTokenizer, AutoModelForSeq2SeqLM

model_id = "facebook/nllb-200-distilled-600M"
tok = AutoTokenizer.from_pretrained(model_id, src_lang="eng_Latn")
model = AutoModelForSeq2SeqLM.from_pretrained(model_id)

src = "The cats are running."
inputs = tok(src, return_tensors="pt")

out = model.generate(
    **inputs,
    forced_bos_token_id=tok.convert_tokens_to_ids("fra_Latn"),
    num_beams=5,
    length_penalty=1.0,
    max_new_tokens=64,
)
print(tok.batch_decode(out, skip_special_tokens=True)[0])
```

```text
Les chats courent.
```

Здесь важны три вещи. `src_lang` сообщает токенизатору, какой скрипт и сегментацию применять. `forced_bos_token_id` сообщает декодеру, на каком языке генерировать. Оба — специфичные для NLLB приёмы; mBART и M2M-100 используют свои собственные соглашения, и они не взаимозаменяемы.

### Шаг 2: BLEU и chrF

BLEU измеряет пересечение n-грамм между выходом и эталоном. Четыре размера эталонных n-грамм (1-4), геометрическое среднее точностей, штраф за слишком короткий вывод. Оценка находится в диапазоне [0, 100]. Широко используется. Трудно интерпретировать: 30 BLEU — "пригодно к использованию"; 40 — "хорошо"; 50 — "исключительно"; различия менее 1 BLEU — это шум.

chrF измеряет F-меру на уровне символов. Более чувствительна для морфологически богатых языков, где BLEU недооценивает совпадения. Часто приводится вместе с BLEU.

```python
import sacrebleu

hypotheses = ["Les chats courent."]
references = [["Les chats courent."]]

bleu = sacrebleu.corpus_bleu(hypotheses, references)
chrf = sacrebleu.corpus_chrf(hypotheses, references)
print(f"BLEU: {bleu.score:.1f}  chrF: {chrf.score:.1f}")
```

Всегда используйте `sacrebleu`. Она нормализует токенизацию, так что оценки сопоставимы между статьями. Написание собственной реализации вычисления BLEU — вот как появляются вводящие в заблуждение бенчмарки.

### Трёхуровневая иерархия оценки (2026)

Современная оценка MT использует три взаимодополняющих семейства метрик. Поставляйте в продакшен хотя бы с двумя из них.

- **Эвристические** (BLEU, chrF). Быстрые, основанные на эталоне, интерпретируемые, нечувствительные к перефразированию. Используйте для сравнения с устаревшими версиями и обнаружения регрессий.
- **Обученные** (COMET, BLEURT, BERTScore). Нейронные модели, обученные на человеческих оценках; сравнивают семантическое сходство перевода с исходным текстом и эталоном. COMET имеет наивысшую корреляцию с исследованиями MT начиная с 2023 года и является стандартом продакшена 2026 года там, где качество имеет значение.
- **LLM-как-судья** (без эталона). Промптинг большой модели для оценки переводов по беглости, адекватности, тону, культурной уместности. GPT-4-как-судья совпадает с человеческими оценками примерно в 80% случаев при хорошо продуманном рубрике. Используйте для открытого контента, где эталон отсутствует.

Практический стек 2026 года: `sacrebleu` для BLEU и chrF, `unbabel-comet` для COMET и промптированная LLM для итогового сигнала, ориентированного на человека. Калибруйте каждую метрику на 50-100 размеченных человеком примерах, прежде чем доверять ей на продакшен-данных.

Метрики без эталона (COMET-QE, BLEURT-QE, LLM-как-судья) позволяют оценивать переводы без эталонного текста, что важно для редких языковых пар, где эталонные переводы просто не существуют.

### Шаг 3: что ломается в продакшене

Рабочий пайплайн выше будет переводить бегло в 80% случаев и молча давать сбой в оставшихся 20%. Именованные режимы отказа:

- **Галлюцинации.** Модель придумывает содержание, которого не было в исходном тексте. Часто встречается в незнакомой доменной лексике. Симптом: вывод беглый, но утверждает факты, которых исходный текст не содержал. Смягчение: ограниченное декодирование по доменным терминам, проверка человеком на регулируемом контенте, мониторинг вывода, который значительно длиннее входа.
- **Генерация не на том языке.** Модель переводит не на тот язык. NLLB удивительно подвержена этому на редких языковых парах. Смягчение: проверяйте `forced_bos_token_id` и всегда декодируйте с проверкой выхода моделью определения языка.
- **Дрейф терминологии.** "Sign up" становится "s'inscrire" в документе 1 и "créer un compte" в документе 2. Для текста интерфейса и пользовательских строк согласованность важнее сырого качества. Смягчение: декодирование с ограничением по глоссарию или словарь пост-редактирования.
- **Несоответствие формальности.** Французское "tu" против "vous", уровни вежливости в японском. Модель выбирает ту форму, которая чаще встречалась при обучении. Для контента, обращённого к клиенту, это обычно неверно. Смягчение: префикс промпта с токеном формальности, если модель это поддерживает, или дообучение небольшой модели только на формальных корпусах.
- **Разрастание длины на коротком входе.** Очень короткие входные предложения часто порождают чрезмерно длинные переводы, потому что штраф за длину резко обрывается ниже ~5 исходных токенов. Смягчение: жёсткий максимум длины, пропорциональный длине исходного текста.

### Шаг 4: дообучение под домен

Предобученные модели — универсалы. Юридический, медицинский перевод или перевод игровых диалогов заметно выигрывают от дообучения на доменных параллельных данных. Рецепт не экзотический:

```python
from transformers import Trainer, TrainingArguments
from datasets import Dataset

pairs = [
    {"src": "The defendant pleaded guilty.", "tgt": "L'accusé a plaidé coupable."},
]

ds = Dataset.from_list(pairs)


def preprocess(ex):
    return tok(
        ex["src"],
        text_target=ex["tgt"],
        truncation=True,
        max_length=128,
        padding="max_length",
    )


ds = ds.map(preprocess, remove_columns=["src", "tgt"])

args = TrainingArguments(output_dir="out", per_device_train_batch_size=4, num_train_epochs=3, learning_rate=3e-5)
Trainer(model=model, args=args, train_dataset=ds).train()
```

Несколько тысяч качественных параллельных примеров превосходят несколько сотен тысяч зашумлённых примеров, собранных из веба. Качество обучающих данных — самый мощный рычаг в продакшене.

## Применение

Продакшен-стек 2026 года для MT:

| Сценарий использования | Рекомендуемая отправная точка |
|---------|---------------------------|
| Любой-в-любой, 200 языков | `facebook/nllb-200-distilled-600M` (ноутбук) или `nllb-200-3.3B` (продакшен) |
| Англоцентричный, высокое качество, 50 языков | `facebook/mbart-large-50-many-to-many-mmt` |
| Короткие запуски, дешёвый инференс, английский-французский/немецкий/испанский | модели Helsinki-NLP / Marian |
| Критичная к задержке работа на стороне браузера | ONNX-квантованный Marian (~50 МБ) |
| Максимальное качество, готовность платить | GPT-4 / Claude / Gemini с промптами для перевода |

LLM теперь превосходят специализированные модели MT на нескольких языковых парах по состоянию на 2026 год, особенно на идиоматическом контенте и длинном контексте. Компромисс — цена за токен и задержка. Выбирайте LLM, когда длина контекста, стилистическая согласованность или доменная адаптация через промптинг важнее пропускной способности.

## Внедрение

Сохраните как `outputs/skill-mt-evaluator.md`:

```markdown
---
name: mt-evaluator
description: Evaluate a machine translation output for shipping.
version: 1.0.0
phase: 5
lesson: 11
tags: [nlp, translation, evaluation]
---

Given a source text and a candidate translation, output:

1. Automatic score estimate. BLEU and chrF ranges you would expect. State whether a reference is available.
2. Five-point human-verifiable check list: (a) content preservation (no hallucinations), (b) correct language, (c) register / formality match, (d) terminology consistency with glossary if provided, (e) no truncation or length explosion.
3. One domain-specific issue to probe. E.g., for legal: named entities and statute citations. For medical: drug names and dosages. For UI: placeholder variables `{name}`.
4. Confidence flag. "Ship" / "Ship with review" / "Do not ship". Tie to the severity of issues found in step 2.

Refuse to ship a translation without a language-ID check on output. Refuse to evaluate without a reference unless the user explicitly opts in to reference-free scoring (COMET-QE, BLEURT-QE). Flag any content over 1000 tokens as likely needing chunked translation.
```

## Упражнения

1. **Лёгкое.** Переведите англоязычный абзац из 5 предложений на французский, а затем обратно на английский, используя `nllb-200-distilled-600M`. Измерьте, насколько близок результат обратного перевода к оригиналу. Вы должны увидеть сохранение смысла при дрейфе выбора слов.
2. **Среднее.** Реализуйте проверку определения языка на выходах перевода, используя `fasttext lid.176` или `langdetect`. Встройте её в вызов MT, чтобы переводы не на тот язык отлавливались до возврата результата.
3. **Сложное.** Дообучите `nllb-200-distilled-600M` на доменном корпусе из 5000 пар по вашему выбору. Измерьте BLEU на отложенном наборе до и после дообучения. Сообщите, какие виды предложений улучшились, а какие ухудшились.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| BLEU | Оценка перевода | Точность по n-граммам со штрафом за краткость. [0, 100]. |
| chrF | F-мера по символам | F-мера на уровне символов. Более чувствительна для морфологически богатых языков. |
| NMT | Нейронный MT | Трансформерный энкодер-декодер, обученный на параллельных текстах. Стандарт с 2017 года. |
| NLLB | No Language Left Behind | Семейство моделей MT от Meta на 200 языков. |
| Constrained decoding | Контролируемый вывод | Принудительное появление/отсутствие конкретных токенов или n-грамм в выводе. |
| Hallucination | Придуманный контент | Вывод модели, не подтверждённый исходным текстом. |
