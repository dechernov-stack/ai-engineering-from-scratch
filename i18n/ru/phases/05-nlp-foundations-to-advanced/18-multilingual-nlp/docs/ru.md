# Многоязычная обработка естественного языка

> Одна модель, 100+ языков, ноль обучающих данных для большинства из них. Кросс-языковой перенос — практическое чудо 2020-х годов.

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 5 · 04 (GloVe, FastText, Subword), Phase 5 · 11 (Machine Translation)
**Time:** ~45 минут

## Проблема

В английском языке есть миллиарды размеченных примеров. В урду — тысячи. В майтхили — почти ничего. Любая практическая NLP-система, обслуживающая глобальную аудиторию, должна работать и с «длинным хвостом» языков, для которых нет обучающих данных под конкретную задачу.

Многоязычные модели решают эту проблему, обучая одну модель сразу на многих языках. Общее представление позволяет переносить навыки, полученные на языках с большим объёмом ресурсов, на языки с малым объёмом ресурсов. Дообучите модель на англоязычном анализе тональности — и она выдаст удивительно хорошие предсказания тональности на урду «из коробки». Это называется zero-shot кросс-языковым переносом, и именно он изменил способ, которым NLP-технологии доставляются по всему миру.

В этом уроке мы разберём компромиссы, канонические модели и одно решение, которое сбивает с толку команды, только начинающие работу с многоязычностью: выбор исходного языка для переноса.

## Концепция

![Cross-lingual transfer via shared multilingual embedding space](../assets/multilingual.svg)

**Общий словарь.** Многоязычные модели используют токенизатор SentencePiece или WordPiece, обученный на тексте из всех целевых языков. Словарь является общим: одна и та же субсловная единица представляет одну и ту же морфему в родственных языках. `anti-` в английском и итальянском получает один и тот же токен.

**Общее представление.** Трансформер, предобученный на задаче masked language modeling на множестве языков, учится тому, что семантически похожие предложения на разных языках дают похожие скрытые состояния. mBERT, XLM-R и NLLB — все они демонстрируют это свойство. Эмбеддинги слова «cat» в английском кластеризуются рядом с «chat» во французском и «gato» в испанском, и то же самое происходит с эмбеддингами целых предложений.

**Zero-shot перенос.** Дообучите модель на размеченных данных на одном языке (обычно на английском). На этапе инференса запустите её на любом другом языке, поддерживаемом моделью. Разметка на целевом языке не нужна. Результаты сильные для типологически родственных языков и слабее для далёких.

**Few-shot дообучение.** Добавьте 100–500 размеченных примеров на целевом языке. Точность вырастает до 95–98% от базового показателя на английском для задач классификации. Это самый экономически эффективный рычаг в многоязычном NLP.

## Модели

| Модель | Год | Охват | Примечания |
|-------|------|----------|-------|
| mBERT | 2018 | 104 языка | Обучена на Википедии. Первая практичная многоязычная языковая модель. Слаба на языках с малым объёмом ресурсов. |
| XLM-R | 2019 | 100 языков | Обучена на CommonCrawl (намного больше, чем Википедия). Задаёт базовый уровень для кросс-языкового переноса. Base — 270M, Large — 550M. |
| XLM-V | 2023 | 100 языков | XLM-R со словарём на 1 млн токенов (против 250 тыс.). Лучше работает на языках с малым объёмом ресурсов. |
| mT5 | 2020 | 101 язык | Архитектура T5 для многоязычной генерации. |
| NLLB-200 | 2022 | 200 языков | Модель перевода от Meta; включает 55 языков с малым объёмом ресурсов. |
| BLOOM | 2022 | 46 языков + 13 языков программирования | Открытая LLM на 176B параметров, обученная многоязычно. |
| Aya-23 | 2024 | 23 языка | Многоязычная LLM от Cohere. Сильна в арабском, хинди, суахили. |

Выбирайте модель по сценарию использования. Для классификации хорошо подходит XLM-R-base как разумный вариант по умолчанию. Для задач генерации нужны mT5 или NLLB — в зависимости от того, перевод это или свободная генерация. Работа в стиле LLM хорошо сочетается с Aya-23 или Claude при явном многоязычном промптинге.

## Решение о выборе исходного языка (исследования 2026 года)

Большинство команд по умолчанию выбирают английский как исходный язык для дообучения. Недавние исследования (2026) показывают, что это часто неверно.

Схожесть языков предсказывает качество переноса лучше, чем просто объём корпуса. Для славянских целевых языков немецкий или русский часто превосходят английский. Для индийских целевых языков хинди часто превосходит английский. Метрика схожести **qWALS** (2026, основана на признаках World Atlas of Language Structures) количественно это подтверждает. **LANGRANK** (Lin et al., ACL 2019) — это отдельный, более ранний метод, который ранжирует кандидатов на роль исходного языка на основе комбинации лингвистической схожести, объёма корпуса и генетического родства.

Практическое правило: если у вашего целевого языка есть типологически близкий родственник с большим объёмом ресурсов, попробуйте сначала дообучить модель на нём, а затем сравните с дообучением на английском.

## Реализация

### Шаг 1: zero-shot кросс-языковая классификация

```python
from transformers import AutoTokenizer, AutoModelForSequenceClassification
import torch

tok = AutoTokenizer.from_pretrained("joeddav/xlm-roberta-large-xnli")
model = AutoModelForSequenceClassification.from_pretrained("joeddav/xlm-roberta-large-xnli")


def classify(text, candidate_labels, hypothesis_template="This text is about {}."):
    scores = {}
    for label in candidate_labels:
        hypothesis = hypothesis_template.format(label)
        inputs = tok(text, hypothesis, return_tensors="pt", truncation=True)
        with torch.no_grad():
            logits = model(**inputs).logits[0]
        entail_score = torch.softmax(logits, dim=-1)[2].item()
        scores[label] = entail_score
    return dict(sorted(scores.items(), key=lambda x: -x[1]))


print(classify("I love this product!", ["positive", "negative", "neutral"]))
print(classify("मुझे यह उत्पाद पसंद है!", ["positive", "negative", "neutral"]))
print(classify("J'adore ce produit !", ["positive", "negative", "neutral"]))
```

Одна модель, три языка, один и тот же API. XLM-R, обученная на данных NLI, хорошо переносится на классификацию с помощью трюка с entailment (логическим следованием).

### Шаг 2: многоязычное пространство эмбеддингов

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2")

pairs = [
    ("The cat is sleeping.", "Le chat dort."),
    ("The cat is sleeping.", "El gato está durmiendo."),
    ("The cat is sleeping.", "Die Katze schläft."),
    ("The cat is sleeping.", "The dog is barking."),
]

for eng, other in pairs:
    emb_eng = model.encode([eng], normalize_embeddings=True)[0]
    emb_other = model.encode([other], normalize_embeddings=True)[0]
    sim = float(np.dot(emb_eng, emb_other))
    print(f"  {eng!r} <-> {other!r}: cos={sim:.3f}")
```

Переводы оказываются близко друг к другу в пространстве эмбеддингов. Другое английское предложение оказывается дальше. Именно это делает возможными кросс-языковой поиск, кластеризацию и вычисление сходства.

### Шаг 3: стратегия few-shot дообучения

```python
from transformers import TrainingArguments, Trainer
from datasets import Dataset


def few_shot_finetune(base_model, base_tokenizer, examples):
    ds = Dataset.from_list(examples)

    def tokenize_fn(ex):
        out = base_tokenizer(ex["text"], truncation=True, max_length=128)
        out["labels"] = ex["label"]
        return out

    ds = ds.map(tokenize_fn)
    args = TrainingArguments(
        output_dir="out",
        per_device_train_batch_size=8,
        num_train_epochs=5,
        learning_rate=2e-5,
        save_strategy="no",
    )
    trainer = Trainer(model=base_model, args=args, train_dataset=ds)
    trainer.train()
    return base_model
```

Для 100–500 примеров на целевом языке `num_train_epochs=5` и `learning_rate=2e-5` — безопасные варианты по умолчанию. Более высокие скорости обучения приводят к разрушению многоязычного выравнивания, и в итоге получается модель, работающая только с английским.

## Оценка, которая действительно работает

- **Точность по каждому языку на отложенных выборках.** Не агрегированная. Агрегат скрывает «длинный хвост».
- **Сравнение с одноязычным базовым решением.** Для языков с достаточным объёмом данных одноязычная модель, обученная с нуля, иногда превосходит многоязычную. Проверяйте.
- **Тесты на уровне сущностей.** Именованные сущности на целевом языке. У многоязычных моделей часто слабая токенизация для письменностей, далёких от латиницы.
- **Кросс-языковая согласованность.** Одинаковый смысл на двух языках должен давать одинаковое предсказание. Измеряйте разрыв.

## Применение

Стек 2026 года:

| Задача | Рекомендация |
|-----|-------------|
| Классификация, 100 языков | дообученная XLM-R-base (~270M) |
| Zero-shot классификация текста | `joeddav/xlm-roberta-large-xnli` |
| Многоязычные эмбеддинги предложений | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` |
| Перевод, 200 языков | `facebook/nllb-200-distilled-600M` (см. урок 11) |
| Генеративная многоязычность | Claude, GPT-4, Aya-23, mT5-XXL |
| NLP для языков с малым объёмом ресурсов | XLM-V или доменно-специфичное дообучение на родственном языке с большим объёмом ресурсов |

Всегда закладывайте бюджет на дообучение на целевом языке, если производительность важна. Zero-shot — это отправная точка, а не окончательный ответ.

### Налог токенизации (что идёт не так для языков с малым объёмом ресурсов)

Многоязычные модели используют один общий токенизатор для всех своих языков. Этот словарь обучен на корпусе, где доминируют английский, французский, испанский, китайский, немецкий. Для любого языка вне этого доминирующего набора незаметно накапливаются три «налога»:

- **Налог на «плодовитость» (fertility).** Текст на языке с малым объёмом ресурсов токенизируется на гораздо большее число токенов на слово, чем английский. Предложению на хинди может потребоваться в 3-5 раз больше токенов, чем эквивалентному предложению на английском. Эти 3-5 раз «съедают» окно контекста, эффективность обучения и задержку.
- **Налог на восстановление вариантов.** Каждая опечатка, диакритический вариант, несовпадение при нормализации Unicode или вариация регистра становится для модели холодной, никак не связанной последовательностью в пространстве эмбеддингов. Модель не может выучить орфографические соответствия, которые носителю языка кажутся очевидными.
- **Налог на перелив ёмкости.** Первые два налога расходуют позиции контекста, глубину слоёв и измерения эмбеддингов. То, что остаётся на собственно рассуждение, систематически меньше, чем то, что получает от той же модели язык с большим объёмом ресурсов.

Практический симптом: ваша модель обучается на хинди вроде бы нормально, кривая потерь выглядит правильно, перплексия на валидации выглядит приемлемо, а продакшен-выводы оказываются тонко, но неверно построены. Морфология разрушается в середине предложения. Редкие словоформы остаются невосстановимыми. **Невозможно компенсировать сломанный токенизатор одним лишь увеличением объёма данных.**

Способы смягчения: выбирайте токенизатор с хорошим покрытием для вашего целевого языка (словарь XLM-V на 1 млн токенов — это прямое решение); проверяйте «плодовитость» токенизации на отложенном целевом тексте перед обучением; используйте резервный байтовый уровень (SentencePiece `byte_fallback=True`, байтовый BPE в стиле GPT-2) для действительно «длиннохвостых» письменностей, чтобы ничего никогда не оказывалось вне словаря (OOV).

## Упражнения

1. **Лёгкое.** Запустите пайплайн zero-shot классификации на 10 предложениях на язык для английского, французского, хинди и арабского. Приведите точность для каждого языка. Вы должны увидеть высокую точность для французского, приемлемую для хинди, нестабильную для арабского.
2. **Среднее.** Используя `paraphrase-multilingual-MiniLM-L12-v2`, постройте кросс-языковой ретривер для небольшого смешанного многоязычного корпуса. Делайте запрос на английском, получайте документы на любом языке. Измерьте recall@5.
3. **Сложное.** Сравните дообучение с английским и с хинди в качестве исходного языка для задачи классификации на хинди. Используйте 500 примеров на целевом языке для few-shot дообучения в обоих режимах. Укажите, какой исходный язык даёт лучшую точность на хинди и насколько. Это миниатюрная версия тезиса LANGRANK.

## Ключевые термины

| Термин | Что говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Многоязычная модель | Одна модель, много языков | Общий словарь и параметры для разных языков. |
| Кросс-языковой перенос | Обучение на одном языке, применение на другом | Дообучение на исходном языке, оценка на целевом без разметки целевого языка. |
| Zero-shot | Без разметки на целевом языке | Перенос без дообучения на целевом языке. |
| Few-shot | Небольшая разметка на целевом языке | 100–500 примеров на целевом языке, используемых для дообучения. |
| mBERT | Первая многоязычная языковая модель | BERT на 104 языка, предобученный на Википедии. |
| XLM-R | Стандартный базовый уровень для кросс-языкового переноса | RoBERTa на 100 языков, предобученная на CommonCrawl. |
| NLLB | 200-язычный переводчик от Meta | No Language Left Behind. Включает 55 языков с малым объёмом ресурсов. |
