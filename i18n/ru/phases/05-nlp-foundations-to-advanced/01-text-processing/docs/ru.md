**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 2 · 14 (Naive Bayes)
**Time:** ~45 минут

## Проблема

Модель не может прочитать «The cats were running.». Она читает целые числа.

Каждая NLP-система начинается с одних и тех же трёх вопросов. Где начинается слово. Какой у слова корень. Как считать «run», «running», «ran» одним и тем же, когда это полезно, и разными вещами, когда нет.

Ошибитесь в токенизации — и модель обучится на мусоре. Если ваш токенизатор считает `don't` одним токеном, а `do n't` — двумя, распределение обучающих данных расходится. Если ваш стеммер сводит `organization` и `organ` к одному и тому же стему, тематическое моделирование разваливается. Если вашему лемматизатору нужен контекст части речи, а вы его не передаёте, глаголы начинают обрабатываться как существительные.

В этом уроке мы с нуля реализуем три этапа предобработки, а затем посмотрим, как ту же работу выполняют NLTK и spaCy, чтобы увидеть компромиссы.

## Концепция

Три операции. У каждой своя задача и свой режим отказа.

**Токенизация** разбивает строку на токены. Слово «токен» намеренно расплывчато, потому что нужная степень дробления зависит от задачи. Уровень слов — для классического NLP. Подслова — для трансформеров. Символы — для языков без пробелов.

**Стемминг** отрезает суффиксы по правилам. Быстро, грубо, тупо. `running -> run`. `organization -> organ`. Второй пример — это как раз режим отказа.

**Лемматизация** приводит слово к словарной форме, используя знания грамматики. Медленнее, точнее, требует таблицы соответствий или морфологического анализатора. `ran -> run` (нужно знать, что «ran» — прошедшее время от «run»). `better -> good` (нужно знать формы сравнения).

Эмпирическое правило. Используйте стемминг, когда важна скорость и допустим шум (индексация для поиска, грубая классификация). Используйте лемматизацию, когда важен смысл (ответы на вопросы, семантический поиск, всё, что будет читать пользователь).

## Реализация

### Шаг 1: токенизатор слов на регулярных выражениях

Простейший полезный токенизатор разбивает строку по не-буквенно-цифровым символам, сохраняя при этом знаки пунктуации как отдельные токены. Не идеально, не финально, но реализуется одной строкой.

```python
import re

def tokenize(text):
    return re.findall(r"[A-Za-z]+(?:'[A-Za-z]+)?|[0-9]+|[^\sA-Za-z0-9]", text)
```

Три шаблона в порядке приоритета. Слова с необязательным внутренним апострофом (`don't`, `it's`). Чистые числа. Любой одиночный не-пробельный не-буквенно-цифровой символ как самостоятельный токен (пунктуация).

```python
>>> tokenize("The cats weren't running at 3pm.")
['The', 'cats', "weren't", 'running', 'at', '3', 'pm', '.']
```

Режимы отказа, на которые стоит обратить внимание. `3pm` разбивается на `['3', 'pm']`, потому что мы чередуем последовательности букв и последовательности цифр. Для большинства задач этого достаточно. URL-адреса, электронные адреса, хэштеги — всё это ломается. Для продакшена добавьте шаблоны перед общими правилами.

### Шаг 2: стеммер Портера (только шаг 1a)

Полный алгоритм Портера состоит из пяти фаз правил. Один только шаг 1a покрывает самые частые английские суффиксы и демонстрирует общий паттерн.

```python
def stem_step_1a(word):
    if word.endswith("sses"):
        return word[:-2]
    if word.endswith("ies"):
        return word[:-2]
    if word.endswith("ss"):
        return word
    if word.endswith("s") and len(word) > 1:
        return word[:-1]
    return word
```

```python
>>> [stem_step_1a(w) for w in ["caresses", "ponies", "caress", "cats"]]
['caress', 'poni', 'caress', 'cat']
```

Читайте правила сверху вниз. Правило `ies -> i` — причина того, почему получается `ponies -> poni`, а не `pony`. В настоящем алгоритме Портера есть шаг 1b, который бы это исправил. Правила конкурируют друг с другом. Побеждает то, что идёт раньше. Порядок важнее любого отдельного правила.

### Шаг 3: лемматизатор на основе таблицы соответствий

Настоящая лемматизация требует морфологии. Учебная, но рабочая версия использует небольшую таблицу лемм и запасной (fallback) вариант.

```python
LEMMA_TABLE = {
    ("running", "VERB"): "run",
    ("ran", "VERB"): "run",
    ("runs", "VERB"): "run",
    ("better", "ADJ"): "good",
    ("best", "ADJ"): "good",
    ("cats", "NOUN"): "cat",
    ("cat", "NOUN"): "cat",
    ("were", "VERB"): "be",
    ("was", "VERB"): "be",
    ("is", "VERB"): "be",
}

def lemmatize(word, pos):
    key = (word.lower(), pos)
    if key in LEMMA_TABLE:
        return LEMMA_TABLE[key]
    if pos == "VERB" and word.endswith("ing"):
        return word[:-3]
    if pos == "NOUN" and word.endswith("s"):
        return word[:-1]
    return word.lower()
```

```python
>>> lemmatize("running", "VERB")
'run'
>>> lemmatize("cats", "NOUN")
'cat'
>>> lemmatize("better", "ADJ")
'good'
>>> lemmatize("watched", "VERB")
'watched'
```

Последний случай — ключевой момент для понимания. `watched` отсутствует в нашей таблице, а наш fallback обрабатывает только `ing`. Настоящая лемматизация покрывает `ed`, неправильные глаголы, сравнительные формы прилагательных, множественное число со сменой звука (`children -> child`). Именно поэтому в продакшен-системах используют WordNet, модуль морфологии spaCy или полноценный морфологический анализатор.

### Шаг 4: собираем всё в конвейер

```python
def preprocess(text, pos_tagger=None):
    tokens = tokenize(text)
    stems = [stem_step_1a(t.lower()) for t in tokens]
    tags = pos_tagger(tokens) if pos_tagger else [(t, "NOUN") for t in tokens]
    lemmas = [lemmatize(word, pos) for word, pos in tags]
    return {"tokens": tokens, "stems": stems, "lemmas": lemmas}
```

Недостающий элемент — тегер частей речи (POS-теггер). Phase 5 · 07 (POS Tagging) посвящён его реализации. Пока же назначайте всем по умолчанию `NOUN` и держите это ограничение в уме.

## Использование готовых решений

NLTK и spaCy поставляют готовые к продакшену версии. Каждая — в несколько строк.

### NLTK

```python
import nltk
nltk.download("punkt_tab")
nltk.download("wordnet")
nltk.download("averaged_perceptron_tagger_eng")

from nltk.tokenize import word_tokenize
from nltk.stem import PorterStemmer, WordNetLemmatizer
from nltk import pos_tag

text = "The cats were running."
tokens = word_tokenize(text)
stems = [PorterStemmer().stem(t) for t in tokens]
lemmatizer = WordNetLemmatizer()
tagged = pos_tag(tokens)


def nltk_pos_to_wordnet(tag):
    if tag.startswith("V"):
        return "v"
    if tag.startswith("J"):
        return "a"
    if tag.startswith("R"):
        return "r"
    return "n"


lemmas = [lemmatizer.lemmatize(t, nltk_pos_to_wordnet(tag)) for t, tag in tagged]
```

`word_tokenize` обрабатывает сокращения, Юникод, граничные случаи, которые упускает ваше регулярное выражение. `PorterStemmer` прогоняет все пять фаз. `WordNetLemmatizer` требует перевода POS-тега из схемы Penn Treebank, используемой NLTK, в набор сокращений WordNet. Код для этого перевода выше — та деталь, которую пропускает большинство туториалов.

### spaCy

```python
import spacy

nlp = spacy.load("en_core_web_sm")
doc = nlp("The cats were running.")

for token in doc:
    print(token.text, token.lemma_, token.pos_)
```

```
The      the     DET
cats     cat     NOUN
were     be      AUX
running  run     VERB
.        .       PUNCT
```

spaCy скрывает весь конвейер за `nlp(text)`. Токенизация, POS-теггинг и лемматизация выполняются автоматически. Быстрее NLTK на больших объёмах. Точнее «из коробки». Но за это приходится платить тем, что отдельные компоненты сложно заменить по отдельности.

### Что выбрать в зависимости от ситуации

| Ситуация | Выбор |
|-----------|------|
| Обучение, исследования, замена отдельных компонентов | NLTK |
| Продакшен, многоязычность, важна скорость | spaCy |
| Конвейер трансформера (всё равно будете токенизировать токенизатором модели) | Используйте `tokenizers` / `transformers` и пропустите классическую предобработку |

### Два режима отказа, о которых никто не предупреждает

Большинство туториалов объясняют алгоритмы и на этом останавливаются. Но реальный конвейер предобработки подстерегают две вещи, которые почти никогда не освещаются.

**Дрейф воспроизводимости.** NLTK и spaCy меняют поведение токенизации и лемматизатора между версиями. То, что в spaCy 2.x давало `['do', "n't"]`, в 3.x может дать `["don't"]`. Ваша модель обучена на одном распределении. Инференс теперь работает на другом. Точность тихо деградирует, и никто не понимает почему. Фиксируйте версии библиотек в `requirements.txt`. Напишите регрессионный тест предобработки, который фиксирует ожидаемую токенизацию 20 примеров предложений. Запускайте его при каждом обновлении.

**Рассогласование обучения и инференса.** Обучаете модель с агрессивной предобработкой (приведение к нижнему регистру, удаление стоп-слов, стемминг), разворачиваете на сырых пользовательских данных — и наблюдаете обвал качества. Это самый частый сбой продакшен-NLP. Если вы применяете предобработку при обучении, вы обязаны применять ту же самую функцию при инференсе. Поставляйте предобработку как функцию внутри пакета модели, а не как ячейку в ноутбуке, которую команда эксплуатации перепишет по-своему.

## Упражнения

1. **Лёгкое.** Расширьте `tokenize` так, чтобы URL-адреса оставались единым токеном. Тест: `tokenize("Visit https://example.com today.")` должен дать один URL-токен.
2. **Среднее.** Реализуйте шаг 1b алгоритма Портера. Если слово содержит гласную и заканчивается на `ed` или `ing`, удаляйте окончание. Обработайте правило удвоенной согласной (`hopping -> hop`, а не `hopp`).
3. **Сложное.** Постройте лемматизатор, использующий WordNet в качестве таблицы соответствий, а при отсутствии записи в WordNet — ваш стеммер Портера в качестве запасного варианта. Измерьте точность на размеченном корпусе в сравнении с чистым WordNet и чистым Портером.

## Ключевые термины

| Термин | Что обычно говорят | Что это означает на самом деле |
|------|-----------------|-----------------------|
| Токен | Слово | Любая единица, которую потребляет модель. Может быть словом, подсловом, символом или байтом. |
| Стем | Корень слова | Результат отсечения суффиксов по правилам. Не всегда настоящее слово. |
| Лемма | Словарная форма | Форма, которую вы бы искали в словаре. Для корректного вычисления требует грамматического контекста. |
| POS-тег | Часть речи | Категория вроде NOUN, VERB, ADJ. Необходима для точной лемматизации. |
| Морфология | Правила изменения формы слова | Как слово меняет форму в зависимости от времени, числа, падежа. Лемматизация зависит от неё. |
