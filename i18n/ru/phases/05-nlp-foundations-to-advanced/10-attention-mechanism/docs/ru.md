# Механизм внимания — Прорыв

> Декодер перестаёт щуриться на сжатое резюме и начинает смотреть на весь источник целиком. Всё, что будет дальше, — это внимание плюс инженерия.

**Type:** Build
**Languages:** Python
**Prerequisites:** Фаза 5 · 09 (Модели Seq2Seq)
**Time:** ~45 минут

## Проблема

Урок 09 закончился сдержанной неудачей. GRU-энкодер-декодер, обученный на игрушечной задаче копирования, показывает 89% точности при длине 5, но почти случайный результат при длине 80. Причина структурная, а не ошибка обучения: вся информация, которую собрал энкодер, должна уместиться в одно скрытое состояние фиксированного размера, и декодер больше ничего не видит.

Бахданау, Чо и Бенджио опубликовали в 2014 году исправление в три строки. Вместо того чтобы давать декодеру только финальное состояние энкодера, сохраняем все состояния энкодера. На каждом шаге декодера вычисляем взвешенное среднее состояний энкодера, где веса показывают «насколько декодеру сейчас нужно смотреть на позицию энкодера `i`?». Это взвешенное среднее и есть контекст, и оно меняется на каждом шаге декодера.

В этом вся идея. Трансформеры её расширили. Self-attention применили её к одной последовательности. Multi-head attention запустило её параллельно. Но версия 2014 года уже сломала «бутылочное горлышко», и как только вы её освоили, переход к трансформерам — это инженерия, а не новая концепция.

## Концепция

![Bahdanau attention: decoder queries all encoder states](../assets/attention.svg)

На каждом шаге декодера `t`:

1. Используем предыдущее скрытое состояние декодера `s_{t-1}` в качестве **запроса** (query).
2. Сравниваем его с каждым скрытым состоянием энкодера `h_1, ..., h_T`. Один скаляр на каждую позицию энкодера.
3. Применяем softmax к оценкам, получая веса внимания `α_{t,1}, ..., α_{t,T}`, сумма которых равна 1.
4. Вектор контекста `c_t = Σ α_{t,i} * h_i`. Взвешенное среднее состояний энкодера.
5. Декодер принимает `c_t` плюс предыдущий выходной токен и выдаёт следующий токен.

Взвешенное среднее — это и есть суть. Когда декодеру нужно перевести «Je» в «I», он придаёт высокий вес состоянию энкодера над «Je» и низкий — остальным. Когда нужно «not», высокий вес получает «pas». Вектор контекста пересобирается на каждом шаге.

## Размерности (то, на чём спотыкаются все)

Именно здесь любая реализация внимания в первый раз ломается. Читайте медленно.

| Элемент | Размерность | Примечания |
|-------|-------|-------|
| Скрытые состояния энкодера `H` | `(T_enc, d_h)` | Если BiLSTM, `d_h = 2 * d_hidden` |
| Скрытое состояние декодера `s_{t-1}` | `(d_s,)` | Один вектор |
| Оценка внимания `e_{t,i}` | скаляр | По одной на позицию энкодера |
| Вес внимания `α_{t,i}` | скаляр | После softmax по всем `i` |
| Вектор контекста `c_t` | `(d_h,)` | Та же размерность, что и у состояния энкодера |

**Оценка Бахданау (аддитивная).** `e_{t,i} = v_α^T * tanh(W_a * s_{t-1} + U_a * h_i)`.

- `s_{t-1}` имеет размерность `(d_s,)`, `h_i` имеет размерность `(d_h,)`.
- `W_a` имеет размерность `(d_attn, d_s)`. `U_a` имеет размерность `(d_attn, d_h)`.
- Их сумма внутри tanh имеет размерность `(d_attn,)`.
- `v_α` имеет размерность `(d_attn,)`. Скалярное произведение с `v_α` сворачивается в скаляр. **Вот что делает `v_α`.** Это не магия. Это проекция, превращающая вектор размерности внимания в скалярную оценку.

**Оценка Луонга (мультипликативная).** Три варианта:

- `dot`: `e_{t,i} = s_t^T * h_i`. Требует `d_s == d_h`. Жёсткое ограничение. Пропускайте, если ваш энкодер двунаправленный.
- `general`: `e_{t,i} = s_t^T * W * h_i` с `W` размерности `(d_s, d_h)`. Снимает ограничение на равенство размерностей.
- `concat`: по сути форма Бахданау. Используется редко, поскольку первые два варианта дешевле.

**Одна ловушка Бахданау / Луонга, которую стоит назвать.** Бахданау использует `s_{t-1}` (состояние декодера *до* генерации текущего слова). Луонг использует `s_t` (состояние *после*). Их перепутывание даёт едва заметно неверные градиенты, которые крайне трудно отладить. Выберите одну статью и придерживайтесь её соглашения.

## Постройте это

### Шаг 1: аддитивное внимание (Бахданау)

```python
import numpy as np


def additive_attention(decoder_state, encoder_states, W_a, U_a, v_a):
    projected_dec = W_a @ decoder_state
    projected_enc = encoder_states @ U_a.T
    combined = np.tanh(projected_enc + projected_dec)
    scores = combined @ v_a
    weights = softmax(scores)
    context = weights @ encoder_states
    return context, weights


def softmax(x):
    x = x - np.max(x)
    e = np.exp(x)
    return e / e.sum()
```

Сверьте размерности с таблицей выше. `encoder_states` имеет размерность `(T_enc, d_h)`. `projected_enc` имеет размерность `(T_enc, d_attn)`. `projected_dec` имеет размерность `(d_attn,)` и транслируется (broadcast). `combined` имеет размерность `(T_enc, d_attn)`. `scores` имеет размерность `(T_enc,)`. `weights` имеет размерность `(T_enc,)`. `context` имеет размерность `(d_h,)`. Готово, отправляем в прод.

### Шаг 2: Luong dot и general

```python
def dot_attention(decoder_state, encoder_states):
    scores = encoder_states @ decoder_state
    weights = softmax(scores)
    return weights @ encoder_states, weights


def general_attention(decoder_state, encoder_states, W):
    projected = W.T @ decoder_state
    scores = encoder_states @ projected
    weights = softmax(scores)
    return weights @ encoder_states, weights
```

По три строки на каждый вариант. Вот почему статья Луонга произвела эффект. Та же точность на большинстве задач, но намного меньше кода.

### Шаг 3: разобранный числовой пример

Дано три состояния энкодера (примерно соответствующие "cat", "sat", "mat") и состояние декодера, которое больше всего совпадает с первым, — распределение внимания концентрируется на позиции 0. Если состояние декодера смещается к совпадению с последним, внимание перемещается на позицию 2. Вектор контекста это отслеживает.

```python
H = np.array([
    [1.0, 0.0, 0.2],
    [0.5, 0.5, 0.1],
    [0.1, 0.9, 0.3],
])

s_close_to_cat = np.array([0.9, 0.1, 0.2])
ctx, w = dot_attention(s_close_to_cat, H)
print("weights:", w.round(3))
```

```
weights: [0.464 0.305 0.231]
```

Побеждает первая строка. Затем приблизьте состояние декодера к третьему состоянию энкодера и посмотрите, как сдвигаются веса. Вот и всё. Внимание — это явное выравнивание (alignment).

### Шаг 4: почему это мост к трансформерам

Переведите язык выше в термины Q/K/V:

- **Query (запрос)** = состояние декодера `s_{t-1}`
- **Key (ключ)** = состояния энкодера (то, с чем сравниваем)
- **Value (значение)** = состояния энкодера (то, что взвешиваем и суммируем)

В классическом внимании ключи и значения — это одно и то же. Self-attention их разделяет: можно сравнивать последовательность саму с собой, используя разные обученные проекции для K и V. Multi-head attention запускает это параллельно с разными обученными проекциями. Трансформеры складывают весь этот этап много раз и отказываются от RNN.

Математика та же самая. Размерности те же самые. Педагогический скачок от внимания Бахданау к scaled dot-product attention — это в основном вопрос обозначений.

## Используйте это

PyTorch и TensorFlow поставляют внимание "из коробки".

```python
import torch
import torch.nn as nn

mha = nn.MultiheadAttention(embed_dim=128, num_heads=8, batch_first=True)
query = torch.randn(2, 5, 128)
key = torch.randn(2, 10, 128)
value = torch.randn(2, 10, 128)

output, weights = mha(query, key, value)
print(output.shape, weights.shape)
```

```
torch.Size([2, 5, 128]) torch.Size([2, 5, 10])
```

Это и есть слой внимания трансформера. Батч запросов из 5 позиций, батч ключей/значений из 10 позиций, по 128 измерений, 8 голов. `output` — это новые запросы, дополненные контекстом. `weights` — это матрица выравнивания 5x10, которую можно визуализировать.

### Когда классическое внимание всё ещё важно

- Педагогика. Однослойная, одноголовая, RNN-версия делает каждую концепцию наглядной.
- Последовательностные задачи на устройстве, куда трансформеры не помещаются.
- Любая статья 2014–2017 годов. Вы неправильно её поймёте, не зная соглашения Бахданау.
- Детальный анализ выравнивания в машинном переводе. Необработанные веса внимания — инструмент интерпретируемости даже для трансформерных моделей, и чтобы их читать, нужно понимать, что они из себя представляют.

### Ловушка «вес внимания как объяснение»

Веса внимания выглядят интерпретируемыми. Это веса, суммирующиеся до единицы по позициям; их можно построить на графике; высокий вес означает «смотрел сюда». Рецензенты их обожают.

На деле они не так интерпретируемы, как кажется. Джейн и Уоллес (2019) показали, что распределения внимания можно переставлять и заменять произвольными альтернативами без изменения предсказаний модели для некоторых задач. Никогда не представляйте веса внимания как доказательство рассуждения модели без абляции или контрфактуальной проверки.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Внимание (Attention) | Смотреть на вещи | Взвешенное среднее последовательности значений, веса которого вычислены из сходства запроса и ключа. |
| Query, Key, Value | QKV | Три проекции: Q спрашивает, K — то, с чем сравнивать, V — то, что возвращается. |
| Аддитивное внимание | Бахданау | Оценка через нейросеть прямого распространения: `v^T tanh(W q + U k)`. |
| Мультипликативное внимание | Luong dot / general | Оценка — это `q^T k` или `q^T W k`. Дешевле, та же точность на большинстве задач. |
| Матрица выравнивания | Красивая картинка | Веса внимания в виде сетки `(T_dec, T_enc)`. Читая её, видно, на что смотрела модель. |
