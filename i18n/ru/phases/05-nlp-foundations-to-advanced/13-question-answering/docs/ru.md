# Системы ответов на вопросы (Question Answering)

> Три системы сформировали современный QA. Экстрактивный подход находил фрагменты текста. Retrieval-augmented заземлял ответы в документах. Генеративный подход формировал ответы сам. Каждый современный ИИ-ассистент — это смесь этих трёх подходов.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 5 · 11 (Machine Translation), Phase 5 · 10 (Attention Mechanism)
**Time:** ~75 минут

## Проблема

Пользователь вводит «Когда вышел первый iPhone?» и ожидает «29 июня 2007 года». Не «История Apple долгая и разнообразная». Не изолированное «2007» без единого предложения вокруг. Прямой, обоснованный, верный ответ.

Три архитектуры доминировали в QA последнее десятилетие.

- **Экстрактивный QA.** Дан вопрос и отрывок текста, заведомо содержащий ответ; требуется найти начальный и конечный индексы фрагмента-ответа в этом отрывке. SQuAD — канонический бенчмарк.
- **QA открытого домена (Open-domain QA).** Отрывок не задан. Сначала нужно найти релевантный отрывок, затем извлечь или сгенерировать ответ. Это основа любого RAG-пайплайна сегодня.
- **Генеративный / Closed-book QA.** Большая языковая модель отвечает из своей параметрической памяти. Без поиска. Самый быстрый на инференсе, наименее надёжный по фактам.

Тренд 2026 года — гибридный: найти несколько лучших отрывков, затем попросить генеративную модель ответить, опираясь на эти отрывки. Это и есть RAG, и урок 14 подробно разбирает половину про поиск. Этот урок строит половину про QA.

## Концепция

![QA architectures: extractive, retrieval-augmented, generative](../assets/qa.svg)

**Экстрактивный.** Вопрос и отрывок кодируются вместе трансформером (семейство BERT). Обучаются две «головы», предсказывающие индексы начального и конечного токена ответа. Функция потерь — кросс-энтропия по допустимым позициям. На выходе — фрагмент из отрывка. Никогда не галлюцинирует (по построению), никогда не обрабатывает вопросы, на которые отрывок не может ответить (по построению).

**Retrieval-augmented (RAG).** Два этапа. Сначала ретривер находит топ-`k` отрывков из корпуса. Затем ридер (экстрактивный или генеративный) формирует ответ, используя эти отрывки. Разделение на ретривер и ридер позволяет обучать и оценивать каждый компонент независимо. Современный RAG часто добавляет между ними реранкер.

**Генеративный.** LLM на основе декодера (GPT, Claude, Llama) отвечает из выученных весов. Без этапа поиска. Отлично работает на общеизвестных фактах, катастрофически — на редких или недавних. Частота галлюцинаций обратно пропорциональна частоте встречаемости факта в данных предобучения.

## Построение

### Шаг 1: экстрактивный QA с предобученной моделью

```python
from transformers import pipeline

qa = pipeline("question-answering", model="deepset/roberta-base-squad2")

passage = (
    "Apple Inc. released the first iPhone on June 29, 2007. "
    "The device was announced by Steve Jobs at Macworld in January 2007."
)
question = "When was the first iPhone released?"

answer = qa(question=question, context=passage)
print(answer)
```

```python
{'score': 0.98, 'start': 57, 'end': 70, 'answer': 'June 29, 2007'}
```

`deepset/roberta-base-squad2` обучена на SQuAD 2.0, который включает вопросы без ответа. По умолчанию пайплайн `question-answering` возвращает фрагмент с наивысшим скором даже когда выигрывает «нулевой» скор модели — он *не* возвращает пустой ответ автоматически. Чтобы получить явное поведение «нет ответа», передайте в вызов пайплайна `handle_impossible_answer=True`: тогда пайплайн вернёт пустой ответ только когда нулевой скор превышает скор всех фрагментов. В любом случае всегда проверяйте поле `score`.

### Шаг 2: retrieval-augmented пайплайн (набросок)

```python
from sentence_transformers import SentenceTransformer
import numpy as np

encoder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

corpus = [
    "Apple Inc. released the first iPhone on June 29, 2007.",
    "Macworld 2007 featured the iPhone announcement by Steve Jobs.",
    "Android launched in 2008 as Google's mobile operating system.",
    "The first iPod was released in 2001.",
]
corpus_embeddings = encoder.encode(corpus, normalize_embeddings=True)


def retrieve(question, top_k=2):
    q_emb = encoder.encode([question], normalize_embeddings=True)
    sims = (corpus_embeddings @ q_emb.T).squeeze()
    order = np.argsort(-sims)[:top_k]
    return [corpus[i] for i in order]


def answer(question):
    passages = retrieve(question, top_k=2)
    combined = " ".join(passages)
    return qa(question=question, context=combined)


print(answer("When was the first iPhone released?"))
```

Двухэтапный пайплайн. Плотный ретривер (Sentence-BERT) находит релевантные отрывки по семантическому сходству. Экстрактивный ридер (RoBERTa-SQuAD) извлекает фрагмент-ответ из объединённых лучших отрывков. Работает на небольших корпусах. Для корпуса на миллион документов используйте FAISS или векторную базу данных.

### Шаг 3: генеративный подход с RAG

```python
def rag_generate(question, llm):
    passages = retrieve(question, top_k=3)
    prompt = f"""Context:
{chr(10).join('- ' + p for p in passages)}

Question: {question}

Answer using only the context above. If the context does not contain the answer, say "I don't know."
"""
    return llm(prompt)
```

Шаблон промпта имеет значение. Явное указание модели опираться на контекст и отвечать «я не знаю», когда контекста недостаточно, снижает частоту галлюцинаций на 40-60% по сравнению с наивным промптингом. Более проработанные шаблоны добавляют цитаты, оценки уверенности и структурированное извлечение.

### Шаг 4: оценка, отражающая реальный мир

SQuAD использует **Exact Match (EM)** и **токенный F1**. EM — это строгое совпадение после нормализации (нижний регистр, удаление пунктуации, удаление артиклей) — либо предсказание совпадает точно, либо оценка 0. F1 вычисляется по пересечению токенов между предсказанием и эталоном и даёт частичный балл. Обе метрики недооценивают перефразирования: «29 июня 2007» против «29-го июня 2007» обычно получает 0 по EM (порядковое числительное ломает нормализацию), но всё же набирает существенный F1 за счёт пересекающихся токенов.

Для продакшен-QA:

- **Точность ответа** (оцениваемая LLM или человеком, поскольку метрики не улавливают семантическую эквивалентность).
- **Точность цитирования.** Действительно ли цитируемый отрывок подтверждает ответ? Легко проверяется автоматически сравнением строк между сгенерированными цитатами и найденными отрывками.
- **Калибровка отказа.** Когда ответа нет в найденных отрывках, корректно ли система говорит «я не знаю»? Измеряйте частоту ложной уверенности.
- **Полнота поиска (retrieval recall).** Перед оценкой ридера измерьте, попадает ли нужный отрывок в топ-`k` ретривера. Ридер не может исправить отсутствующий отрывок.

### RAGAS: фреймворк оценки для продакшена 2026 года

`RAGAS` специально создан для RAG-систем и является стандартом в 2026 году. Он оценивает четыре измерения без необходимости в эталонных ответах:

- **Faithfulness (достоверность).** Подтверждается ли каждое утверждение в ответе контекстом из поиска? Измеряется через NLI-основанное определение логического следования. Ваша основная метрика галлюцинаций.
- **Answer relevance (релевантность ответа).** Отвечает ли ответ на вопрос? Измеряется генерацией гипотетических вопросов из ответа и сравнением с реальным вопросом.
- **Context precision (точность контекста).** Какая доля найденных фрагментов была действительно релевантна? Низкая точность = шум в промпте.
- **Context recall (полнота контекста).** Содержал ли найденный набор всю нужную информацию? Низкая полнота = ридер не может справиться.

Оценка без эталонов позволяет оценивать на живом продакшен-трафике без курируемых эталонных ответов. Добавьте сверху LLM-as-judge для открытых вопросов, где метрики точного совпадения бесполезны.

`pip install ragas`. Подключите ваш ретривер + ридер. Получите четыре скаляра на запрос. Настройте алерты на регрессии.

## Применение

Стек 2026 года.

| Сценарий использования | Рекомендация |
|---------|-------------|
| Дан отрывок, найти фрагмент-ответ | `deepset/roberta-base-squad2` |
| Над фиксированным корпусом, closed-book неприемлем | RAG: плотный ретривер + LLM-ридер |
| Реал-тайм над хранилищем документов | RAG с гибридным (BM25 + dense) ретривером + реранкер (урок 14) |
| Диалоговый QA (уточняющие вопросы) | LLM с историей диалога + RAG на каждом ходе |
| Строго фактические, регулируемые области | Экстрактивный подход над авторитетным корпусом; никогда только генеративный |

Экстрактивный QA немодный в 2026 году, потому что RAG с LLM покрывает больше случаев. Он всё ещё применяется там, где требуется буквальное цитирование: юридические исследования, регуляторное соответствие, инструменты аудита.

## Упражнения

1. **Лёгкое.** Настройте экстрактивный пайплайн SQuAD выше на 10 отрывках из Wikipedia. Составьте вручную 10 вопросов. Измерьте, как часто ответ верен. Вы должны получить 7-9 верных при чистых отрывках и вопросах.
2. **Среднее.** Добавьте классификатор отказа. Когда верхний скор поиска ниже порога (скажем, 0.3 косинусного сходства), возвращайте «я не знаю» вместо вызова ридера. Настройте порог на отложенном наборе.
3. **Сложное.** Постройте RAG-пайплайн над корпусом из 10 000 документов по вашему выбору. Реализуйте гибридный поиск (BM25 + dense) со слиянием RRF (см. урок 14). Измерьте точность ответов с гибридным этапом и без него. Задокументируйте, какие типы вопросов выигрывают больше всего.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Extractive QA | Найти фрагмент-ответ | Предсказать начальный и конечный индексы ответа внутри заданного отрывка. |
| Open-domain QA | QA над корпусом | Отрывок не задан; нужно сначала найти, затем ответить. |
| RAG | Найти, затем сгенерировать | Retrieval-augmented generation. Пайплайн ретривер + ридер. |
| SQuAD | Канонический бенчмарк | Stanford Question Answering Dataset. Метрики EM + F1. |
| Hallucination | Выдуманный ответ | Ответ ридера, не подтверждённый найденным контекстом. |
| Refusal calibration | Знать, когда промолчать | Система корректно отвечает «я не знаю», когда не может ответить. |
