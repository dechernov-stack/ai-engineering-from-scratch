## Концепция

### OpenAI Moderation API

`omni-moderation-latest` (2024). Построен на GPT-4o. Классифицирует текст + изображения за один вызов. Бесплатен для большинства разработчиков.

Категории (13 булевых значений в схеме ответа):
- harassment, harassment/threatening
- hate, hate/threatening
- self-harm, self-harm/intent, self-harm/instructions
- sexual, sexual/minors
- violence, violence/graphic
- illicit, illicit/violent

Мультимодальная поддержка применяется к `violence`, `self-harm` и `sexual`, но не к `sexual/minors`; остальные категории — только текстовые.

В кодовом харнессе в `code/main.py` мы для педагогической простоты сворачиваем подкатегории `/threatening`, `/intent`, `/instructions` и `/graphic` в их родительские категории верхнего уровня. В промышленном коде следует использовать полную схему из 13 категорий.

На 42% лучше на многоязычном тестовом наборе, чем конечная точка модерации предыдущего поколения. Оценки по каждой категории; приложения сами устанавливают пороги.

### Llama Guard 3/4

Рассмотрено в уроке 16. 14 категорий опасностей MLCommons (организованы иначе, чем 13 булевых значений в схеме ответа OpenAI). Поддерживает 8 языков (v3). Llama Guard 4 (апрель 2025) нативно мультимодальна, 12B.

Таксономии OpenAI и Llama Guard частично пересекаются, но расходятся. У OpenAI "illicit" — широкая категория; у Llama Guard отдельно выделены "violent crimes" и "non-violent crimes". При развёртывании выбор делается исходя из соответствия политике-таксономии.

### Perspective API (Google Jigsaw)

Система оценки токсичности, появившаяся раньше волны LLM-в-роли-модератора (до 2020 года). Категории: TOXICITY, SEVERE_TOXICITY, INSULT, PROFANITY, THREAT, IDENTITY_ATTACK. Основная одномерная оценка (TOXICITY) с подкатегориальными вариантами.

Широко используется как базовая линия для исследований в области модерации контента, поскольку API стабилен, документирован и имеет годы калиброванных данных. Для современных LLM-смежных сценариев Llama Guard или OpenAI Moderation обычно подходят лучше.

### Трёхслойный паттерн

1. **Модерация входа.** Классифицировать запрос пользователя до генерации. Отклонять при срабатывании флага. Задержка: один вызов классификатора.
2. **Модерация выхода.** Классифицировать вывод модели перед выдачей. Заменять на отказ при срабатывании флага. Задержка: один вызов классификатора после генерации.
3. **Кастомная модерация.** Доменно-специфичные правила (регулярные выражения, белые списки, бизнес-политика). Выполняется либо на входе, либо на выходе.

Три слоя по замыслу последовательны: модерация входа должна завершиться до генерации, а модерация выхода выполняется после генерации. Параллелизм применяется внутри слоя — одновременный запуск нескольких классификаторов (например, OpenAI Moderation + Llama Guard + Perspective) на одном и том же тексте скрывает задержку каждого отдельного классификатора. В качестве необязательной оптимизации, пока завершается модерация входа, может отображаться заглушка ответа ("один момент, проверяю...") с отложенным стримингом первого токена. Поведение при срабатывании флага настраивается: отказ, санитизация, эскалация на проверку человеком.

### Режимы отказа

- **Только вход.** Не улавливает галлюцинации на выходе (кодирующие атаки из уроков 12-14 обходят классификаторы входа).
- **Только выход.** Позволяет любому входу достичь модели; увеличивает стоимость; раскрывает атакующему внутренние рассуждения.
- **Только кастомный.** Не устойчив по всем категориям; регулярные выражения хрупки.

Слоистая модерация — вариант по умолчанию. "Ремень и подтяжки" (двойная подстраховка).

## Применить на практике

`code/main.py` строит трёхслойный модерационный харнесс: модератор входа (ключевые слова + оценка по категории), модератор выхода (тот же классификатор на выходе), кастомный модератор (доменные правила). Вы можете пропускать входные данные через харнесс и наблюдать, какой слой что улавливает.

## Довести до результата

Этот урок производит `outputs/skill-moderation-stack.md`. Учитывая конкретное развёртывание, он рекомендует конфигурацию стека модерации: какой классификатор на входе, какой на выходе, какие кастомные правила и какой судья для пограничных случаев.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|------------------------|
| OpenAI Moderation | "omni-moderation-latest" | Классификатор на основе GPT-4o с 13 категориями (текст) и частичной мультимодальной поддержкой |
| Perspective API | "Google Jigsaw toxicity" | Базовая линия оценки токсичности до-LLM-эры |
| Llama Guard | "MLCommons 14-category" | Классификатор опасностей от Meta (v3: 8B, текст, 8 языков; v4: 12B, мультимодальный) |
| Модерация входа | "pre-generation filter" | Классификатор запроса пользователя до вызова модели |
| Модерация выхода | "post-generation filter" | Классификатор вывода модели перед выдачей |
| Кастомная модерация | "domain rules" | Специфичные для развёртывания правила (регулярные выражения, белый список, политика) |
| Слоистая модерация | "all three layers" | Стандартный паттерн промышленного развёртывания |
