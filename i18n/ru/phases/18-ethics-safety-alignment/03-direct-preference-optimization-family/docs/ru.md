# Семейство методов прямой оптимизации предпочтений (Direct Preference Optimization)

> Rafailov et al. (2023) показали, что оптимум RLHF имеет замкнутую форму относительно данных о предпочтениях, а значит можно обойтись без явной модели вознаграждения и оптимизировать политику напрямую. Эта идея породила целое семейство — IPO, KTO, SimPO, ORPO, BPO — каждый метод устраняет свой отказ DPO. В 2026 году алгоритмы прямого выравнивания применяются в большем числе передовых пост-обучающих запусков, чем PPO. Но кривая переоптимизации из Урока 2 никуда не делась: DAA не избегают Гудхарта, они лишь смещают точку, в которой он проявляется.

**Type:** Learn
**Languages:** Python (stdlib, компаратор шести вариантов функции потерь предпочтений)
**Prerequisites:** Phase 18 · 01 (InstructGPT), Phase 18 · 02 (Reward hacking), Phase 10 · 08 (основы DPO)

## Цели обучения

- Вывести замкнутую форму DPO из оптимума RLHF с KL-регуляризацией.
- Сформулировать, какой отказ DPO устраняет каждый из методов IPO, KTO, SimPO, ORPO, BPO.
- Различать «разрыв неявного вознаграждения» и «силу предпочтения» и объяснить, почему важно тождественное отображение в IPO.
- Объяснить, почему Rafailov et al. (NeurIPS 2024) доказывают, что DAA переоптимизируются, несмотря на отсутствие явной модели вознаграждения.

## Проблема

Целевая функция RLHF (Урок 1):

```
max_pi E_{x,y~pi} [ r(x, y) ] - beta * KL(pi || pi_ref)
```

имеет известный оптимум:

```
pi*(y|x) = (1/Z(x)) * pi_ref(y|x) * exp(r(x, y) / beta)
```

Таким образом, вознаграждение неявно определяется отношением оптимальной политики к референсной:

```
r(x, y) = beta * log(pi*(y|x) / pi_ref(y|x)) + beta * log Z(x)
```

Подставьте это в правдоподобие предпочтений Брэдли-Терри, и статистическая сумма `Z(x)` сокращается, поскольку зависит только от `x`. Остаётся функция потерь, зависящая только от параметров политики — модель вознаграждения не нужна. Это и есть DPO.

Загвоздка: вывод предполагает, что оптимум достижим, данные о предпочтениях находятся внутри распределения, а референсная политика — истинный якорь моды. Ни одно из этих условий не выполняется в точности. Каждый представитель семейства устраняет нарушение одного из этих допущений.

## Концепция

### DPO (Rafailov et al., 2023)

```
L_DPO = -log sigmoid(
  beta * log(pi(y_w | x) / pi_ref(y_w | x))
  - beta * log(pi(y_l | x) / pi_ref(y_l | x))
)
```

Что может пойти не так:

- Разрыв неявного вознаграждения `beta * (log(pi/pi_ref)_w - log(pi/pi_ref)_l)` не ограничен. Даже небольшое предпочтение может породить сколь угодно большой разрыв.
- Функция потерь толкает логарифмические вероятности выбранного и отвергнутого ответов в противоположные стороны. Она может снижать абсолютную логарифмическую вероятность выбранного ответа, пока отвергнутый падает быстрее. Это явление называется Degraded Chosen Response (деградация выбранного ответа).
- Пары предпочтений вне распределения (редкая-редкая против редкая-редкая) порождают произвольные неявные вознаграждения.

### IPO (Azar et al., 2024)

Identity Preference Optimization заменяет log-sigmoid тождественным отображением вероятности предпочтения. Функция потерь превращается в квадратичную ошибку относительно ограниченной цели:

```
L_IPO = (log(pi(y_w | x) / pi_ref(y_w | x)) - log(pi(y_l | x) / pi_ref(y_l | x)) - 1/(2 beta))^2
```

Разрыв ограничен `1/(2 beta)`. Сила предпочтения и разрыв неявного вознаграждения пропорциональны. Взрывного роста нет.

### KTO (Ethayarajh et al., 2024)

Kahneman-Tversky Optimization полностью отказывается от парной структуры. По одному помеченному выходу и бинарному сигналу «желательно»/«нежелательно» строится функция полезности в духе теории перспектив:

```
v(x, y) = sigma(beta * log(pi(y|x) / pi_ref(y|x)) - z_ref)
```

с разными весами для выигрышей и потерь (неприятие потерь). Преимущество: можно использовать непарные данные, которых гораздо больше.

### SimPO (Meng et al., 2024)

Simple Preference Optimization выравнивает обучающий сигнал с генерацией. Референсная политика полностью убирается, а логарифмическое правдоподобие нормализуется по длине:

```
L_SimPO = -log sigmoid(
  (beta / |y_w|) * log pi(y_w | x)
  - (beta / |y_l|) * log pi(y_l | x)
  - gamma
)
```

с отступом (margin) `gamma` для стабилизации. Нормализация по длине устраняет стимул эксплуатировать смещение по длине — отказ DPO, при котором более длинный `y_w` по построению даёт больший разрыв логарифмических вероятностей.

### ORPO (Hong et al., 2024)

Odds-Ratio Preference Optimization добавляет член предпочтения к стандартной функции отрицательного логарифмического правдоподобия SFT:

```
L_ORPO = L_NLL(y_w) + lambda * L_OR
L_OR = -log sigmoid(log(odds(y_w) / odds(y_l)))
```

Референсная политика не нужна — роль регуляризатора играет сам член SFT. Обучение проводится за один этап от базовой модели сразу до выровненной. Отдельная контрольная точка SFT не требуется.

### BPO (заявка на ICLR 2026, OpenReview id=b97EwMUWu7)

Выявляет проблему Degraded Chosen Responses: DPO сохраняет ранжирование `y_w > y_l`, но абсолютная логарифмическая вероятность `y_w` может падать. BPO добавляет однострочную поправку, штрафующую понижение логарифмической вероятности выбранного ответа. Сообщается о приросте точности на +10,1% на Llama-3.1-8B-Instruct в задачах математических рассуждений по сравнению с DPO.

### Универсальный результат: DAA всё равно переоптимизируются

Rafailov et al. «Scaling Laws for Reward Model Overoptimization in Direct Alignment Algorithms» (NeurIPS 2024) обучали политики с помощью DPO, IPO, SLiC на нескольких наборах данных при разных бюджетах KL. Кривые «эталонное вознаграждение против KL» имеют ту же форму пика и обвала, что и у Gao et al. Неявное вознаграждение запрашивает образцы вне распределения во время обучения; KL-регуляризация этого не стабилизирует.

DAA не избегают Гудхарта. Они меняют поверхность, на которой он проявляется — с «переоптимизации модели вознаграждения» на «переоптимизацию отношения к референсной политике». Универсальное решение — более качественные данные, ансамбли, ранняя остановка — применимо к обоим случаям.

### Как выбирать между ними (2026)

- Если есть большой набор парных данных предпочтений: DPO с консервативным beta, SimPO — если заметно смещение по длине.
- Если есть непарная бинарная обратная связь: KTO.
- Если нужен одноэтапный конвейер от базовой модели: ORPO.
- Если в логах DPO наблюдается деградация логарифмической вероятности выбранного ответа: BPO.
- Если сила предпочтений сильно варьируется и DPO насыщается: IPO.

Каждая лаборатория прогоняет все пять методов на тестовой батарее и выбирает победителя под конкретную задачу. Нет причин полагать, что оптимум одинаков для математических рассуждений и безопасности.

## Используйте это

`code/main.py` сравнивает шесть функций потерь (DPO, IPO, KTO, SimPO, ORPO, BPO) на игрушечном наборе данных предпочтений, где истинная сила предпочтения варьируется от пары к паре. Каждая функция потерь оптимизируется на одной и той же выборке из 500 пар с небольшой softmax-политикой. Строятся графики итоговой доли побед, дрейфа логарифмической вероятности выбранного ответа и разброса неявного вознаграждения для каждого метода.

## Упражнения

1. Запустите `code/main.py`. Сообщите итоговое падение логарифмической вероятности выбранного ответа для DPO и BPO. BPO должен сохранять более высокую абсолютную вероятность выбранного ответа — проверьте это.

2. Измените данные предпочтений так, чтобы все пары имели одинаковую силу. Какой из шести методов наиболее устойчив? Какой деградирует? Объясните преимущество IPO в этом случае.

3. Сделайте отвергнутые ответы в среднем в 2 раза длиннее выбранных. Не меняя ничего другого, численно покажите эксплуатацию длины в DPO и то, как это исправляет SimPO.

4. Rafailov et al. (NeurIPS 2024) утверждают, что DAA переоптимизируются. Воспроизведите упрощённую одноточечную версию: постройте график KL-дивергенции «выбранный минус отвергнутый» и пронаблюдайте переоптимизацию в DPO при большом beta.

5. Прочитайте аннотацию статьи BPO (OpenReview b97EwMUWu7). Запишите однострочную поправку, которую BPO добавляет к DPO. Сверьте с реализацией в `code/main.py`.

## Ключевые термины

| Термин | Что говорят | Что это означает на самом деле |
|------|-----------------|------------------------|
| DPO | «RLHF без модели вознаграждения» | Функция потерь, выведенная из замкнутой формы оптимума RLHF; зависит только от параметров политики |
| Неявное вознаграждение | «логарифм отношения» | `beta * log(pi(y\|x) / pi_ref(y\|x))` — вознаграждение, подразумеваемое DPO |
| IPO | «ограниченный DPO» | Заменяет log-sigmoid тождественным отображением; разрыв неявного вознаграждения ограничен `1/(2 beta)` |
| KTO | «непарный DPO» | Функция полезности в духе теории перспектив над одиночными метками с неприятием потерь |
| SimPO | «DPO без референсной политики» | Логарифмическое правдоподобие, нормализованное по длине, плюс отступ; без референсной политики |
| ORPO | «одноэтапный DPO» | NLL плюс член предпочтения на основе отношения шансов; обучается от базовой модели за один проход |
| BPO | «DPO, сохраняющий выбранный ответ» | DPO плюс штраф за снижение абсолютной логарифмической вероятности выбранного ответа |
| Degraded Chosen | «выбранный ответ падает» | DPO снижает логарифмическую вероятность выбранного ответа, пока отвергнутый падает быстрее |
| DAA | «алгоритм прямого выравнивания» | Любой метод на основе функции потерь предпочтений, обходящийся без явной модели вознаграждения |
