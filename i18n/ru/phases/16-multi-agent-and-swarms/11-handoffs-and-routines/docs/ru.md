# Передачи управления и рутины — Stateless-оркестрация

> Swarm от OpenAI (октябрь 2024) свёл мультиагентную оркестрацию к двум примитивам: **рутины** (инструкции + инструменты в виде системного промпта) и **передачи управления** (handoff) — инструмент, который возвращает другого Agent. Никакой машины состояний, никакого DSL с ветвлениями — LLM маршрутизирует, вызывая нужный handoff-инструмент. OpenAI Agents SDK (март 2025) — это продакшен-наследник. Сам Swarm остаётся самым чистым концептуальным референсом — весь его исходный код умещается в несколько сотен строк. Паттерн вирусный, потому что поверхность API сводится примерно к "agent = промпт + инструменты; handoff = функция, возвращающая agent". Ограничение: stateless, то есть память — проблема вызывающей стороны.

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 04 (Primitive Model)
**Time:** ~60 минут

## Проблема

Каждый мультиагентный фреймворк хочет, чтобы вы учили его DSL: узлы и рёбра LangGraph, crews и tasks CrewAI, GroupChat и менеджеры AutoGen. Эти DSL — реальные абстракции, но из-за них всё кажется тяжелее, чем должно быть.

Swarm движется в противоположном направлении: использует возможность вызова инструментов (tool-calling), которая у модели уже есть. Передачи управления становятся вызовами инструментов. Оркестратор — это тот агент, который в данный момент владеет диалогом. Машина состояний неявно заложена в системных промптах агентов.

## Концепция

### Два примитива

**Рутина.** Системный промпт, который определяет роль агента и доступные ему инструменты. Представьте это как ограниченный набор инструкций: "ты агент триажа; если пользователь спрашивает о возвратах, передай управление агенту возвратов".

**Передача управления (handoff).** Инструмент, который агент может вызвать и который возвращает новый объект Agent. Среда исполнения Swarm обнаруживает возвращаемое значение типа Agent и переключает активного агента для следующего хода.

Это и есть вся абстракция целиком.

```
def transfer_to_refunds():
    return refund_agent  # Swarm sees Agent return → switch active agent

triage_agent = Agent(
    name="triage",
    instructions="Route the user to the right specialist.",
    functions=[transfer_to_refunds, transfer_to_sales, transfer_to_support],
)
```

Системный промпт агента триажа заставляет его выбирать нужную передачу управления на основе сообщения пользователя. Маршрутизацию выполняет вызов инструмента со стороны LLM.

### Почему это вирусно

- **Маленький API.** Всего два понятия для изучения.
- **Использует то, что модель уже умеет.** Вызов инструментов уже production-grade у всех провайдеров.
- **Никакой нагрузки машины состояний.** Вы не описываете граф; кому передавать управление, описывают промпты самих агентов.

### Компромисс со stateless

Swarm явно не сохраняет состояние между запусками. Фреймворк ведёт историю сообщений в рамках одного запуска, но ничего не персистирует. Память, непрерывность, долгоживущие задачи — всё это проблема вызывающей стороны.

В продакшене (OpenAI Agents SDK, март 2025) это было одной из главных вещей, которые изменились: SDK добавляет встроенное управление сессиями, guardrails и трейсинг, сохраняя при этом примитив передачи управления.

### Когда Swarm/handoffs подходят

- **Паттерны триажа.** Фронтовой агент направляет пользователя к специалисту.
- **Передача управления на основе навыков.** "Если задаче нужен код — вызови кодера; если нужно исследование — вызови исследователя."
- **Короткие, ограниченные диалоги.** Поддержка клиентов, FAQ-в-тикет, простые воркфлоу.

### Когда Swarm испытывает трудности

- **Длинные сессии с общей памятью.** Передача управления сбрасывает состояние диалога до промпта нового агента плюс историю. Без управляемой вызывающей стороной памяти персистентного состояния между агентами нет.
- **Параллельное исполнение.** Handoff работает по одному за раз — активный агент переключается. Параллелизм требует, чтобы вызывающая сторона оркестрировала несколько запусков Swarm.
- **Аудит и воспроизведение.** Stateless-запуски сложно воспроизвести точно; выбор handoff со стороны LLM не детерминирован.

### OpenAI Agents SDK (март 2025)

Продакшен-наследник добавляет:

- **Состояние сессии.** Персистентный тред между запусками.
- **Guardrails.** Хуки валидации входа/выхода.
- **Трейсинг.** Каждый вызов инструмента и передача управления логируются.
- **Фильтры передачи управления.** Контроль того, какой контекст передаётся при handoff.

Примитив передачи управления сохраняется; вокруг него добавляется продакшен-эргономика.

### Swarm против GroupChat

Оба используют маршрутизацию на основе LLM, но различаются тем, **кто выбирает следующего**:

- GroupChat: селектор (функция или LLM) выбирает следующего говорящего извне.
- Swarm: текущий агент сам выбирает себе преемника, вызывая handoff-инструмент.

Swarm — это "агент решает, что дальше"; GroupChat — "менеджер решает, что дальше". Решение в Swarm живёт внутри вызова инструмента активным агентом; решение в GroupChat живёт внутри `GroupChatManager`.

```figure
sw-handoff-routing
```

## Соберите это

`code/main.py` реализует Swarm с нуля: dataclass Agent, механизм передачи управления (инструмент возвращает Agent) и цикл исполнения, который обнаруживает переключения агентов.

Демо: агент триажа направляет к специалисту по возвратам, продажам или поддержке. У каждого специалиста свои инструменты. Цикл исполнения печатает каждую передачу управления.

Запуск:

```
python3 code/main.py
```

## Подготовьте к продакшену

Чек-лист:

- **Логирование передач управления.** Каждый handoff записывает событие трейса с агентом-источником, агентом-назначением, снимком контекста.
- **Правила передачи контекста.** Определите, что переносится при handoff: полная история (дорого), последние N сообщений или резюме.
- **Guardrail на передаче управления.** Передача управления специалисту с другими правами на инструменты должна быть аутентифицирована — иначе prompt injection может принудить к нежелательным передачам.
- **Обнаружение циклов.** Два агента, перебрасывающих управление туда-сюда — частый сбой; обнаруживайте простой проверкой кольца последних K.
- **Агент-резервный вариант.** Если цель handoff не существует, откатитесь на безопасный вариант по умолчанию.

## Упражнения

1. Запустите `code/main.py`, выполните триаж к агенту возвратов. Убедитесь, что активный агент на втором ходу — агент возвратов.
2. Добавьте правило обнаружения циклов: если одни и те же два агента передавали управление друг другу 3 раза подряд, принудительно завершите выполнение. Спроектируйте резервный вариант.
3. Прочитайте документацию OpenAI Agents SDK о фильтрах передачи управления. Реализуйте версию "суммаризация-при-передаче": исходящий агент сжимает контекст в резюме-список перед тем, как входящий агент примет управление.
4. Сравните handoff в Swarm с селектором GroupChatManager. Какой паттерн усугубляет prompt injection и почему?
5. Прочитайте кукбук Swarm (https://developers.openai.com/cookbook/examples/orchestrating_agents). Найдите одно явное архитектурное решение Swarm, которое OpenAI Agents SDK изменил или сохранил.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|----------------|------------------------|
| Рутина (Routine) | "Промпт агента" | Системный промпт + список инструментов. Определяет роль и доступные передачи управления. |
| Передача управления (Handoff) | "Перевод к другому агенту" | Инструмент, который может вызвать активный агент и который возвращает новый Agent. Среда исполнения переключает активного агента. |
| Stateless | "Нет памяти между запусками" | Swarm ничего не персистирует; память — ответственность вызывающей стороны. |
| Активный агент | "Кто сейчас говорит" | Агент, который в данный момент владеет диалогом. Handoff меняет это. |
| Передача контекста | "Что переносится при handoff" | Политика того, какую историю видит входящий агент: полную, последние N или резюмированную. |
| Цикл передачи управления | "Агенты перекидываются туда-сюда" | Режим сбоя, когда два агента продолжают передавать управление друг другу. |
| OpenAI Agents SDK | "Продакшен-Swarm" | Наследник марта 2025; добавляет сессии, guardrails, трейсинг поверх примитива передачи управления. |
| Фильтр передачи управления | "Гейт на передаче" | Возможность SDK инспектировать и изменять контекст на границе handoff. |
