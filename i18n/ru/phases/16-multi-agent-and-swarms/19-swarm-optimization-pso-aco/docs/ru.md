# Роевая оптимизация для LLM (PSO, ACO)

> Биоинспирированная оптимизация переживает возвращение в контексте LLM. **LMPSO** (arXiv:2504.09247) использует PSO, где скорость каждой частицы — это промпт, а LLM генерирует следующего кандидата; хорошо работает на структурированных последовательных выходах (математические выражения, программы). **Model Swarms** (arXiv:2410.11163) рассматривает каждого LLM-эксперта как частицу PSO на многообразии весов модели и сообщает о **среднем приросте 13,3%** по сравнению с 12 базовыми подходами на 9 датасетах, используя всего 200 примеров. **SwarmPrompt** (ICAART 2025) гибридизирует PSO + Grey Wolf для оптимизации промптов. **AMRO-S** (arXiv:2603.12933) — это вдохновлённые ACO феромонные специалисты для маршрутизации мультиагентных LLM-систем — **ускорение в 4,7 раза**, интерпретируемые доказательства маршрутизации, асинхронное обновление с проверкой качества, отделяющее инференс от обучения. В этом уроке реализуется PSO на пространстве параметров промпта и ACO на маршрутизации агентов, измеряется, почему эти классические алгоритмы подходят эпохе LLM, а когда — нет.

## Проблема

У вас есть промпт, который набирает 62% на вашей оценке задачи. Вы хотите его улучшить. Наивный ход — ручная подстройка без градиента, что плохо масштабируется. Обучению с подкреплением нужны сигналы вознаграждения и достаточно прогонов для обучения. Обратное распространение через промпты по сути невозможно — промпт это дискретная строка, а не дифференцируемый параметр.

Классическая биоинспирированная оптимизация — PSO для непрерывных пространств поиска, ACO для выбора пути — была создана как раз для такого режима: без градиента, на основе популяции, дёшево на каждую оценку. Сочетая их с LLM для безградиентного шага поиска, вы получаете удивительно практичный оптимизатор.

Те же паттерны применимы к *маршрутизации* агентов в мультиагентных системах. Феромонный след в стиле ACO фиксирует, какой агент лучше всего справился с каким типом задач, позволяет маршрутизатору эксплуатировать этот след и ослабляет феромоны со временем, чтобы маршруты можно было переоткрывать.

## Концепция

### Напоминание о PSO (Kennedy & Eberhart 1995)

Particle Swarm Optimization: популяция частиц в непрерывном пространстве поиска. Каждая частица имеет позицию `x_i` и скорость `v_i`. На каждой итерации:

```
v_i <- w * v_i + c1 * r1 * (p_best_i - x_i) + c2 * r2 * (g_best - x_i)
x_i <- x_i + v_i
evaluate fitness(x_i)
update p_best_i if improved
update g_best if global best
```

Где `p_best` — собственный лучший результат частицы, `g_best` — лучший результат роя, `w, c1, c2` — веса инерции, когнитивного и социального факторов, `r1, r2` — случайные множители.

### PSO на выходах LLM — LMPSO

arXiv:2504.09247 адаптирует PSO для структурированных выходов, генерируемых LLM (математические выражения, программы). Каждая частица — это кандидатный выход. Скорость — это *промпт*, описывающий, как изменить текущий выход в направлении личного/глобального лучшего. LLM генерирует новый выход из промпта скорости. «Инерция» скорости — это промпт вроде «вноси небольшие инкрементальные изменения».

Это хорошо работает, когда:
- Выход структурирован (парсится, оценивается).
- Фитнес вычисляется автоматически (запуск тестов, арифметическая оценка).
- Популяция небольшая (~10-30 частиц), чтобы общее число вызовов LLM оставалось управляемым.

Это плохо работает, когда фитнес требует проверки человеком — стоимость каждой итерации становится неприемлемой.

### Model Swarms

arXiv:2410.11163 переносит PSO с уровня выходов на уровень *модели*. Каждая «частица» — это экспертная LLM (параметры). Рой перемещает параметры в сторону коллективного лучшего через безградиентное обновление. Заявлено: средний прирост 13,3% по сравнению с 12 базовыми подходами на 9 датасетах, всего при 200 примерах на итерацию.

Ключевая идея в том, что экспертные LLM-модели уже находятся рядом в общем многообразии параметров (веса адаптеров, LoRA-дельты). PSO в этом низкоразмерном подпространстве дёшев и эффективен.

### Напоминание об ACO (Dorigo 1992)

Ant Colony Optimization: муравьи перемещаются по графу; каждый путь имеет феромонный след. Вероятности движения муравья взвешиваются силой феромона. Муравьи, завершившие задачу, откладывают феромон пропорционально качеству решения. Феромон со временем ослабевает.

### AMRO-S — ACO для маршрутизации агентов

arXiv:2603.12933 использует ACO для маршрутизации мультиагентных систем. Каждый тип задачи — это «пункт назначения»; каждый агент — возможный маршрут. Феромоны усиливают маршруты, которые дают хорошие результаты. Ключевые вклады:

- **Интерпретируемые доказательства маршрутизации.** Сила феромона — это читаемый человеком сигнал.
- **Асинхронное обновление с проверкой качества.** Феромоны обновляются только после прохождения проверок качества, отделяя инференс от обучения.
- **Ускорение в 4,7 раза** на бенчмарке мультиагентной маршрутизации.

Проверка качества важна: без неё быстрые, но неправильные агенты накапливают феромон, и система замыкается на плохих маршрутах.

### Когда использовать PSO / ACO для LLM

**Используйте PSO, когда:**
- Пространство поиска непрерывно или отображается на непрерывные параметры (эмбеддинги промптов, веса LoRA, числовые параметры генерации).
- Фитнес дёшев и автоматичен.
- Популяция может быть небольшой (10-30).

**Используйте ACO, когда:**
- У вас есть задача маршрутизации или выбора пути.
- Решения усиливаются со временем (одни и те же типы задач повторяются).
- Вам нужны интерпретируемые доказательства для решений о маршрутизации.

**Не используйте ни то, ни другое, когда:**
- Фитнес требует проверки человеком (слишком дорого на итерацию).
- Пространство поиска дискретно и комбинаторно таким образом, что PSO его не покрывает (используйте генетические алгоритмы).
- Решения в реальном времени требуют строгой задержки (PSO/ACO сходятся медленно по сравнению с однопроходными эвристиками).

### Почему биоинспирированные методы всё ещё побеждают

Градиентным методам нужны дифференцируемые сигналы. Выходы LLM и решения о маршрутизации не тривиально дифференцируемы. Псевдоградиентные методы (роутеры, обученные с подкреплением, тюнеры промптов в стиле DPO) работают, но требуют дорогого обучения.

PSO и ACO нуждаются лишь в функции *оценки*. Если вы можете оценить кандидатный выход или решение о маршрутизации, вы можете оптимизировать по этому пространству. Это значительно снижает планку применимости.

### Практические ограничения

- **Бюджет популяции.** N частиц × T итераций × стоимость одной оценки. Для оценок LLM при ~$0.02 / call, a 20-particle PSO running 50 iterations costs ~$20. Планируйте соответственно.
- **Разведка против эксплуатации.** Скорость ослабления феромона и инерция PSO — это компромисс; слишком быстрое ослабление → забывание решений; слишком медленное → застревание на ранних локальных оптимумах.
- **Катастрофический дрейф.** Оба алгоритма могут сходиться, а затем расходиться, если ландшафт фитнеса меняется (новое распределение данных). Отслеживайте стабильность лучшего фитнеса.

## Соберите это

`code/main.py` реализует:

- `LMPSO` — PSO по числовым параметрам промпта (температура, веса top_k). «Генерация LLM» каждой частицы симулируется как скриптовая функция фитнеса. Алгоритм прогоняется 30 итераций, показывается сходимость g_best.
- `AMRO_S` — маршрутизация в стиле ACO. 3 агента, 4 типа задач, матрица феромонов, 100 маршрутизированных задач. Выводит распределение (тип задачи → выбор агента) во времени, демонстрируя формирование следов.
- Сравнение: случайная маршрутизация против ACO-маршрутизации на одном и том же потоке задач. Измеряет качество и задержку.

Запуск:

```
python3 code/main.py
```

Ожидаемый вывод:
- LMPSO: фитнес g_best улучшается от случайного до почти оптимального за 30 итераций.
- AMRO-S: таблица феромонов стабилизируется на правильном агенте для каждого типа задачи; ACO-маршрутизация превосходит случайную примерно на 30-40% по качеству, а также снижает задержку (меньше повторов).

`outputs/skill-swarm-optimizer.md` помогает выбрать между PSO, ACO, генетическими алгоритмами и градиентными оптимизаторами для задач оптимизации LLM / агентов.

## Внедрение

- **Начинайте с малого.** 10-20 частиц, 20-50 итераций. Увеличивайте масштаб только если кривая сходимости показывает явный выигрыш.
- **Логируйте феромоны или g_best на каждой итерации.** Отладка роевых оптимизаторов без следа мучительна.
- **Применяйте проверку качества при обновлениях.** Особенно для ACO-маршрутизации: быстрые, но неправильные агенты не должны накапливать феромон.
- **Сбрасывайте ослабление при сдвиге распределения.** Когда распределение ваших оценок меняется, устаревшие феромоны неактуальны; сбрасывайте или временно удваивайте скорость ослабления.
- **Ограничивайте стоимость на итерацию.** Выводите метрику стоимости на итерацию. PSO, который стоит $500 за итерацию и даёт прирост 0,5%, не готов к продакшену.

## Ключевые термины

| Термин | Что говорят | Что это на самом деле означает |
|------|----------------|------------------------|
| PSO | «Particle Swarm Optimization» | Kennedy-Eberhart 1995. Безградиентный оптимизатор на основе популяции. |
| ACO | «Ant Colony Optimization» | Dorigo 1992. Оптимизация пути/маршрута через феромонные следы. |
| LMPSO | «PSO с генерацией LLM» | arXiv:2504.09247. Скорость — это промпт; LLM производит кандидатов. |
| Model Swarms | «PSO на весах экспертов» | arXiv:2410.11163. Безградиентное обновление в подпространстве параметров модели. |
| AMRO-S | «ACO для маршрутизации агентов» | arXiv:2603.12933. Матрица феромонов по типу задачи × агенту. |
| p_best / g_best | «Личный / глобальный лучший» | Лучшие найденные на данный момент решения для частицы и для всего роя. |
| Феромон | «Память маршрутизации» | Сила на ребре; со временем ослабевает; откладывается при хорошем качестве. |
| Обновление с проверкой качества | «Учиться только на хороших прогонах» | Отложение феромона обусловлено проверкой качества. |
