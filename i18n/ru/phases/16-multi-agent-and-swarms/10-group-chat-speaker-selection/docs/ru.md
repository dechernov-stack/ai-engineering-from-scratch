# Групповой чат и выбор говорящего

> Оркестрация с общим разговором помещает N агентов в один разговор; функция-селектор (LLM, round-robin или кастомная) выбирает, кто говорит следующим. Это архетип эмерджентного многоагентного разговора — агенты не знают своей роли в статическом графе, они просто реагируют на общий пул. AutoGen GroupChat и AG2 GroupChat — эталонные реализации: семантика GroupChat из AutoGen v0.2 была сохранена в форке AG2; AutoGen v0.4 переписал её как событийно-управляемую модель акторов. Microsoft перевела AutoGen в режим поддержки в феврале 2026 года и объединила её с Semantic Kernel в Microsoft Agent Framework (RC февраль 2026). Примитив GroupChat сохраняется и в AG2, и в Microsoft Agent Framework — выучите его один раз, используйте везде.

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 04 (Primitive Model)
**Time:** ~60 минут

## Проблема

Статические графы (LangGraph) отлично подходят, когда рабочий процесс известен заранее. Реальные разговоры не статичны: иногда кодер обращается к ревьюеру, иногда к исследователю, иногда к писателю. Жёсткое кодирование каждой возможной передачи управления приводит к взрыву числа рёбер. Вам нужны *агенты, реагирующие на общий пул*, с некоторой функцией, решающей, кто говорит следующим.

Именно это и делает AutoGen GroupChat.

## Концепция

### Форма

```
              ┌─── shared pool ────┐
              │   m1  m2  m3  ...  │
              └─────────┬──────────┘
                        │ (everyone reads all)
      ┌───────┬─────────┼─────────┬───────┐
      ▼       ▼         ▼         ▼       ▼
    Agent A  Agent B  Agent C  Agent D  Selector
                                           │
                                           ▼
                                  "next speaker = C"
```

Каждый агент видит каждое сообщение. Функция-селектор вызывается на каждом ходу, чтобы выбрать, кто будет говорить следующим.

### Три разновидности селектора

**Round-robin.** Фиксированный цикл. Детерминированный. Масштабируется линейно по N, но игнорирует контекст — кодер получает ход, даже когда тема — юридическая проверка.

**LLM-selected.** Вызов LLM, которая читает недавний пул и возвращает наилучшего следующего говорящего. Учитывает контекст, но медленный: каждый ход добавляет вызов LLM. Вариант по умолчанию в AutoGen.

**Custom.** Python-функция с любой нужной вам логикой. Типичный вариант: выбор через LLM с резервными правилами (например, «после кодера всегда давать ход верификатору»).

### API ConversableAgent

```
agent = ConversableAgent(
    name="coder",
    system_message="You write Python.",
    llm_config={...},
)
chat = GroupChat(agents=[coder, reviewer, tester], messages=[])
manager = GroupChatManager(groupchat=chat, llm_config={...})
```

`GroupChatManager` хранит селектор. Когда агент завершает свой ход, менеджер вызывает селектор, который возвращает следующего агента. Цикл продолжается до выполнения условия завершения.

### Завершение

Три распространённых паттерна:

- **Максимум раундов.** Жёсткое ограничение на общее число ходов.
- **Токен «TERMINATE».** Агенты могут выдать сигнальное сообщение; менеджер останавливается, когда оно появляется.
- **Проверка достижения цели.** Лёгкий верификатор запускается на каждом ходу и останавливает чат, когда задача выполнена.

### Родословная: форки и слияния

В начале 2025 года Microsoft начала масштабное переписывание AutoGen (v0.4) вокруг событийно-управляемой модели акторов. Сообщество форкнуло семантику GroupChat из AutoGen v0.2 как AG2, сохранив API, который ранние пользователи уже интегрировали.

В феврале 2026 года Microsoft объявила, что AutoGen перейдёт в режим поддержки, а событийно-управляемая модель акторов будет объединена в **Microsoft Agent Framework** (RC февраль 2026, теперь объединена с Semantic Kernel). Концепция GroupChat сохраняется в обеих ветках; детали реализации различаются. AG2 — предпочтительный upstream для кода, совместимого с v0.2.

### Когда GroupChat подходит

- **Эмерджентные разговоры.** Вы не хотите заранее прописывать каждого возможного следующего говорящего.
- **Задачи со смешением ролей.** Кодер спрашивает исследователя, исследователь спрашивает архивариуса, архивариус спрашивает кодера обратно. Поток — не DAG.
- **Исследовательское решение задач.** Думайте «мозговой штурм на встрече», а не «сборочная линия».

### Когда это не работает

- **Строгий детерминизм.** Селектор на базе LLM может быть непоследовательным. Один и тот же запрос, разные запуски, разные следующие говорящие.
- **Каскады подхалимства.** Агенты уступают тому, кто говорил наиболее уверенно. Противодействуйте этому явным промптингом.
- **Раздувание контекста.** Каждый агент читает каждое сообщение; после 10 ходов контекст становится огромным. Используйте проекции (Урок 15) для ограничения представлений.
- **«Горячие» говорящие.** Один агент доминирует в разговоре, потому что селектор благоволит его специализации. Введите баланс говорящих как характеристику селектора.

### Групповой чат против супервизора

Те же примитивы, разные настройки по умолчанию:

- Супервизор: один агент планирует, а остальные исполняют. Селектор — это «спросить планировщика, что делать».
- Групповой чат: все агенты — равноправные партнёры; селектор — это функция над общим пулом.

Оба используют четыре примитива из Урока 04. Групповой чат по умолчанию использует оркестрацию с выбором через LLM и общее состояние всего пула.

## Построить это

`code/main.py` реализует GroupChat с нуля на stdlib. Три агента (кодер, ревьюер, менеджер), варианты round-robin и LLM-selected, а также завершение по токену `TERMINATE`.

Демо выводит стенограмму разговора, а также трассировку решений селектора для обоих вариантов.

Запуск:

```
python3 code/main.py
```

## Использовать это

`outputs/skill-groupchat-selector.md` настраивает селектор GroupChat для заданной задачи — round-robin против LLM-selected против кастомного, и какие входные данные селектора (недавние сообщения, специализации агентов, счётчики ходов) использовать.

## Отправить в продакшн

Чек-лист:

- **Ограничение максимума раундов.** Всегда. 10-20 для типичных задач.
- **Метрика баланса говорящих.** Отслеживайте количество ходов на агента; оповещайте, когда дисбаланс превышает порог.
- **Токен завершения.** `TERMINATE` или выделенный агент-верификатор.
- **Проекция или ограниченная память.** После ~10 сообщений рассмотрите возможность давать каждому агенту только ограниченное представление, чтобы предотвратить раздувание контекста.
- **Логирование селектора.** Для вариантов с выбором через LLM логируйте как входные данные селектора, так и его выбор. Иначе отладка невозможна.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| GroupChat | «Агенты в одной чат-комнате» | Общий пул сообщений + функция-селектор. Примитив AutoGen / AG2. |
| Speaker selection | «Кто говорит следующим» | Функция, выбирающая следующего агента. Round-robin, LLM-selected или кастомная. |
| GroupChatManager | «Ведущий встречи» | Компонент AutoGen, владеющий селектором и управляющий циклом ходов. |
| ConversableAgent | «Базовый агент» | Базовый класс AutoGen; агент, который может отправлять и получать сообщения. |
| Termination token | «Слово „стоп“» | Сигнальная строка (обычно `TERMINATE`), завершающая чат. |
| Hot speaker | «Один агент доминирует» | Отказ, при котором селектор постоянно выбирает одного и того же агента. |
| Context bloat | «Пул растёт неограниченно» | Каждый агент читает все предыдущие сообщения; контекст растёт с числом ходов. |
| Projection | «Ограниченное представление» | Представление общего пула, специфичное для роли, предотвращающее раздувание контекста. |
