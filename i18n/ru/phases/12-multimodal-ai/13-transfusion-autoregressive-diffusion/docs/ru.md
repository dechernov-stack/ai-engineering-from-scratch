# Transfusion: авторегрессия для текста + диффузия для изображений в одном трансформере

> Chameleon и Emu3 поставили всё на дискретные токены. Они работают, но узкое место квантования заметно — качество изображений выходит на плато ниже уровня диффузионных моделей с непрерывным пространством. Transfusion (Meta, Zhou et al., август 2024) делает противоположную ставку: оставить изображения непрерывными, полностью отказаться от VQ-VAE и обучать один трансформер с двумя функциями потерь. Текстовые токены получают предсказание следующего токена. Патчи изображения получают диффузионную функцию потерь / flow-matching. Обе цели оптимизируют одни и те же веса. Архитектура, лежащая в основе Stable Diffusion 3 (MMDiT), — близкий родственник. В этом уроке разбирается тезис Transfusion, строится игрушечный тренер с двумя потерями и прослеживается маска внимания, которая позволяет одному трансформеру выполнять обе задачи.

**Type:** Build
**Languages:** Python (stdlib, тренер с двумя потерями на игрушечном датасете масштаба MNIST)
**Prerequisites:** Phase 12 · 11 (Chameleon), Phase 8 (Generative AI)
**Time:** ~180 минут

## Learning Objectives

- Собрать трансформер, который использует две функции потерь (NTP для текстовых токенов, диффузионная MSE для патчей изображения) на одном бэкбоне.
- Объяснить, почему двунаправленное внимание внутри патчей изображения вместе с каузальным вниманием по текстовым токенам — правильный выбор маски.
- Сравнить подход в стиле Transfusion (непрерывные изображения, диффузионная функция потерь) с подходом в стиле Chameleon (дискретные изображения, NTP) по вычислительным затратам, качеству и сложности кода.
- Назвать вклад MMDiT: специфичные для модальности веса в каждом блоке, совместное внимание в residual-потоке.

## The Problem

Спор о дискретных и непрерывных токенах изображений старше, чем LLM. Непрерывные представления (сырые пиксели, латенты VAE) сохраняют детали. Дискретные токены (индексы VQ) хорошо ложатся на родной словарь трансформера, но теряют детали на этапе квантования.

Chameleon / Emu3 выбрали дискретный путь: одна функция потерь, одна архитектура, но точность изображений ограничена качеством токенизатора.

Диффузионные модели выбрали непрерывный путь: исключительное качество изображений, но отдельная от LLM модель, сложная инженерия расписания шума и отсутствие чистой интеграции с генерацией текста.

Transfusion задаёт вопрос: можно ли получить и то, и другое? Оставить изображения непрерывными, всё же обучать одну модель, использовать две функции потерь, сшитые в один шаг градиента.

## The Concept

### Архитектура с двумя функциями потерь

Единый декодер-трансформер обрабатывает последовательность, которая содержит:

- Текстовые токены (дискретные, из BPE-словаря).
- Патчи изображения (непрерывные, блоки пикселей 16x16, спроецированные в скрытую размерность через линейное вложение — так же, как входной слой энкодера ViT).
- Теги `<image>` и `</image>`, отмечающие, где расположены непрерывные патчи.

Прямой проход выполняется один раз. Функция потерь выбирает одну из двух голов для каждого токена:

- Для текстовых токенов: стандартная кросс-энтропия на голове логитов словаря.
- Для патчей изображения: диффузионная функция потерь на непрерывных патчах — предсказание шума, добавленного к каждому патчу.

Градиент проходит через общее тело трансформера. Обе функции потерь одновременно улучшают общие веса.

### Маска внимания: каузальный текст + двунаправленное изображение

Текстовые токены должны быть каузальными — нельзя позволять текстовому токену обращать внимание на будущий текст, иначе teacher forcing ломается. Патчи изображения, напротив, представляют один снимок; внутри одного блока изображения они должны обращать внимание друг на друга двунаправленно.

Маска:

```
M[i, j] = 1 if:
  (i is text and j is text and j <= i)   # causal for text
  OR (i is image and j is image and same_image_block(i, j))   # bidirectional within image
  OR (i is text and j is image and j < i_image_end)   # text attends to previous images
  OR (i is image and j is text and j < i_image_start)   # image attends to preceding text
```

Реализуется как блочно-треугольная маска при обучении и при инференсе.

### Диффузионная функция потерь внутри трансформера

Диффузионная функция потерь стандартна: к патчу изображения добавляется шум, модель должна предсказать добавленный шум (или, эквивалентно, чистый патч). Версия Transfusion использует flow matching — предсказание поля скорости от зашумлённого к чистому состоянию.

При обучении:
1. Для каждого патча изображения x0 выбирается случайный шаг времени t.
2. Выбирается шум ε, вычисляется xt = (1-t) * x0 + t * ε (линейная интерполяция для flow matching).
3. Трансформер предсказывает v_theta(xt, t); функция потерь = MSE(v_theta(xt, t), ε - x0).
4. Обратное распространение ошибки идёт вместе с потерями NTP для текста из той же последовательности.

При инференсе генерация выглядит так:
- Текстовые токены: стандартный авторегрессивный сэмплинг.
- Патчи изображения: цикл диффузионного сэмплинга (обычно 10-30 шагов), обусловленный предшествующими текстовыми токенами.

### MMDiT: вариант из Stable Diffusion 3

Stable Diffusion 3 (Esser et al., март 2024) представила MMDiT (Multimodal Diffusion Transformer) примерно одновременно с Transfusion. Эти архитектуры — родственники.

Ключевые отличия MMDiT:

- Специфичные для модальности веса в каждом блоке. Каждый блок трансформера имеет отдельные веса Q, K, V и MLP для текстовых токенов и для патчей изображения. Внимание совместное (межмодальное); всё остальное — специфично для модальности.
- Обучение на rectified flow. Конкретный вариант flow matching с известным сэмплингом и более простой математикой, чем у DDPM.
- Масштаб. MMDiT — бэкбон для SD3 (варианты с 2 и 8 млрд параметров). В статье Transfusion масштабирование доходит до 7 млрд.

Обе архитектуры сходятся к одной и той же базовой идее: один трансформер выполняет NTP для текста и диффузию для непрерывных представлений изображения.

### Почему это превосходит подход в стиле Chameleon

Разрыв в качестве между непрерывной диффузией и дискретным NTP в генерации изображений измерим. В статье Transfusion сообщается:

- При 7 млрд параметров модель превосходит модель в стиле Chameleon того же размера по FID на 3-5 пунктов.
- Не требуется обучение токенизатора — энкодер изображения проще (линейная проекция в скрытое пространство, как во входном слое ViT).
- Инференс может распараллелить устранение шума в патчах изображения, в отличие от авторегрессивных токенов изображения.

Недостаток: Transfusion — модель с двумя функциями потерь, из-за чего динамика обучения сложнее. Веса функций потерь нужно подбирать. Несоответствие расписаний NTP и диффузии может привести к доминированию одной из голов.

### Что находится ниже по течению

Janus-Pro (Урок 12.15) уточняет идею Transfusion, разделяя визуальный энкодер для понимания и генерации — SigLIP для одного, VQ для другого — при общем теле трансформера. Show-o (Урок 12.14) заменяет диффузию на дискретную диффузию (маскированное предсказание). Семейство моделей единой генерации быстро ветвится после Transfusion.

Продакшн-VLM 2026 года, генерирующие изображения — Gemini 3 Pro, GPT-5, путь генерации изображений в Claude Opus 4.7 — почти наверняка используют какого-то потомка этого семейства. Детали являются собственностью компаний.

## Use It

`code/main.py` строит игрушечный Transfusion на крошечной задаче в духе MNIST:

- Текстовые подписи — короткие последовательности целых чисел, описывающие цифру (0-9).
- Изображения — сетки 4x4 из байтов.
- Пара линейных проекций с общими весами выступает заменой трансформера; NTP функция потерь для текста, MSE функция потерь для зашумлённых патчей.
- Цикл обучения чередует две функции потерь, маска внимания строится явно.
- Генерация производит текстовую подпись и изображение 4x4 за один прямой проход.

Трансформер здесь игрушечный. Настоящие артефакты — это механика двух функций потерь, построение маски внимания и цикл инференса.

2. Реализуйте блочно-треугольную маску для последовательности: `[T, T, <image>, P, P, P, P, </image>, T]`. Отметьте каждую запись как 0 или 1.

3. В MMDiT есть специфичные для модальности веса QKV. Какой прирост числа параметров это даёт по сравнению с полностью общим трансформером Transfusion? При 7 млрд параметров — оправдано ли это?

4. Генерация: по текстовому промпту модель выполняет NTP для 50 токенов, затем встречает `<image>`, затем выполняет диффузию для 256 патчей за 20 шагов устранения шума. Сколько всего прямых проходов?

5. Прочитайте раздел 3 статьи SD3. Опишите rectified flow и объясните, почему он сходится за меньшее число шагов инференса, чем DDPM.

## Key Terms

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|------------------------|
| Обучение с двумя функциями потерь | «NTP + диффузия» | Один трансформер оптимизирует одновременно кросс-энтропию для текстовых токенов и MSE для непрерывных патчей изображения в одном шаге градиента |
| Flow matching | «Rectified flow» | Вариант диффузии, предсказывающий поле скорости от шума к чистым данным; более простая математика, чем у DDPM |
| MMDiT | «Multimodal DiT» | Архитектура Stable Diffusion 3: совместное внимание, специфичные для модальности MLP и нормализации |
| Блочно-треугольная маска | «Каузальный текст + двунаправленное изображение» | Маска внимания, каузальная по тексту, но двунаправленная внутри областей изображения |
| Непрерывное представление изображения | «Без VQ» | Патчи изображения как вещественные векторы, а не индексы дискретного словаря |
| Предсказание скорости | «v-параметризация» | Выход сети — поле скорости между шумом и данными, а не сам шум |
