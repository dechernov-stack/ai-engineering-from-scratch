# От CLIP к BLIP-2 — Q-Former как мост между модальностями

> CLIP выравнивает изображение и текст, но не умеет генерировать подписи, отвечать на вопросы или вести диалог. BLIP-2 (Salesforce, 2023) решил эту задачу небольшим обучаемым мостом: 32 обучаемых вектора-запроса обращаются к признакам замороженного ViT через cross-attention, а затем напрямую встраиваются во входной поток замороженной LLM. 188M параметров моста соединили 11B LLM с ViT-g/14. Любая VLM на основе адаптеров вплоть до 2026 года — MiniGPT-4, InstructBLIP, родственники LLaVA — потомок этой идеи. Этот урок разбирает архитектуру Q-Former, объясняет его двухэтапное обучение и строит игрушечную версию, подающую визуальные токены в замороженный текстовый декодер.

**Type:** Build
**Languages:** Python (stdlib, демонстрация cross-attention + обучаемых запросов)
**Prerequisites:** Phase 12 · 02 (CLIP), Phase 7 (Transformers)
**Time:** ~180 минут

## Learning Objectives

- Объяснить, почему обучаемое «бутылочное горлышко» между замороженным vision-энкодером и замороженной LLM выигрывает у end-to-end дообучения по стоимости и стабильности.
- Реализовать блок cross-attention, где фиксированный набор обучаемых запросов обращается к внешним признакам изображения.
- Пройти по двум этапам предобучения BLIP-2: представленческому (ITC + ITM + ITG), а затем генеративному (LM-лосс с замороженным декодером).
- Сравнить Q-Former с более простым MLP-проектором, используемым в LLaVA, и аргументировать, когда какой выбор выигрывает.

## The Problem

У вас есть замороженный ViT, который выдаёт 256 патч-токенов размерности 1408 на изображение. У вас есть замороженная 7B LLM, которая ожидает эмбеддинги токенов размерности 4096. Очевидный мост — линейный слой из 1408 в 4096 — работает, но подача всех 256 патч-токенов в контекст LLM стоит 256 дополнительных токенов на изображение. На батче из 32 изображений это 8192 токена, потраченных только на визуальную модальность.

Вопрос BLIP-2: можно ли сжать представление изображения из 256 токенов в гораздо меньшее число (скажем, 32), сохранив достаточно информации, чтобы LLM могла составлять подписи, отвечать на вопросы и рассуждать об изображении? И можно ли обучить этот мост, не трогая замороженные магистрали, оставив стоимость обучения равной только параметрам моста?

Ответ: Q-Former. 32 обучаемых вектора-«запроса», которые выполняют cross-attention к патч-токенам ViT, формируя визуальную сводку из 32 токенов, которую потребляет LLM. 188M параметров в сумме. Обучается с контрастивной, сопоставительной и генеративной целевыми функциями ещё до того, как вообще задействуется LLM.

## The Concept

### Обучаемые запросы

Основной приём Q-Former: вместо того чтобы текстовые токены LLM обращались к патчам изображения, вводится новый набор из 32 обучаемых векторов-запросов `Q`, и уже *они* обращаются к патчам изображения. Запросы — это параметры модели: они обучаются в процессе тренировки, и одни и те же 32 запроса используются для каждого изображения.

После cross-attention каждый запрос содержит сжатую сводку изображения — «опиши главный объект», «опиши фон», «посчитай объекты» и т. д. Запросы не специализируются буквально на семантических метках — они учат ту кодировку, которая снижает значения последующих функций потерь.

### Архитектура

Q-Former — это небольшой трансформер (12 слоёв, ~100M параметров) с двумя путями:

1. Путь запросов: 32 вектора-запроса проходят через self-attention (между собой), затем cross-attention над патч-токенами замороженного ViT, затем FFN.
2. Текстовый путь: BERT-подобный текстовый энкодер разделяет веса self-attention и FFN с путём запросов. Cross-attention для текстового пути отключён.

На этапе обучения оба пути работают одновременно. Запросы и текст взаимодействуют через общий self-attention, что означает, что запросы могут обуславливаться на текст для задач, требующих этого (ITM, ITG). На этапе вывода при передаче в VLM работают только запросы, выдавая 32 визуальных токена.

### Двухэтапное обучение

BLIP-2 предобучается в два этапа:

Этап 1: обучение представлений (без LLM). Три функции потерь:
- ITC (image-text contrastive): контрастив в стиле CLIP между агрегированными токенами-запросами и CLS-токеном текста.
- ITM (image-text matching): бинарный классификатор — соответствует ли эта пара изображение-текст друг другу? С майнингом сложных негативных примеров.
- ITG (image-grounded text generation): каузальная голова языковой модели на тексте, обусловленная запросами. Заставляет запросы кодировать содержимое, пригодное для генерации текста.

Обучается только Q-Former. ViT заморожен. LLM не задействована.

Этап 2: генеративное обучение. Подключается замороженная LLM (OPT-2.7B или Flan-T5-XL и т. п.). 32 выхода запросов проецируются в размерность эмбеддингов LLM небольшим линейным слоем. Они предваряют текстовый промпт. Обучаются только линейная проекция и Q-Former на LM-лоссе по объединённой последовательности промпт + изображение + подпись.

После этапа 2 Q-Former + проекция составляют полный визуальный адаптер. На инференсе: изображение → ViT → Q-Former → линейная проекция → добавляется перед текстом → замороженная LLM выдаёт результат.

### Экономика параметров

BLIP-2 с ViT-g/14 (1.1B, заморожен) + OPT-6.7B (6.7B, заморожена) + Q-Former (188M, обучается) = 8B всего, 188M обучается. Один только Q-Former составляет ~2,4% параметров всего стека. Стоимость обучения отражает это: дни на нескольких A100 против недель для end-to-end.

Качество: BLIP-2 сравним или превосходит Flamingo-80B в zero-shot VQA, будучи в 50 раз меньше. Мост работает.

### InstructBLIP и инструкция-зависимый Q-Former

InstructBLIP (2023) расширяет Q-Former дополнительным входом: самим текстом инструкции. На этапе cross-attention запросы теперь имеют доступ как к патчам изображения, так и к инструкции. Запросы могут специализироваться под конкретную инструкцию («посчитай машины», «опиши настроение»), а не учить единую фиксированную сводку. Прирост на бенчмарках на отложенных задачах.

### MiniGPT-4 и подход «только проектор»

MiniGPT-4 сохранил Q-Former, но обучал только выходную линейную проекцию, заморозив всё остальное. Дёшево, но ценой качества — запросы были от BLIP-2, а не свои. Хорошо для быстрой итерации, но не лучшая архитектура.

### Почему LLaVA пошла более простым путём

LLaVA (2023, Урок 12.05) заменила Q-Former на обычный 2-слойный MLP, проецирующий каждый патч-токен ViT в пространство LLM — 576 токенов на изображение для сетки 24x24, все подаются в LLM. Худшее сжатие, но позволяет LLM обращаться к исходным патчам. В своё время это было спорно; к концу 2023 года подход стал доминирующим, поскольку данные визуальных инструкций (LLaVA-Instruct-150k) доказали, что MLP можно обучить сохранять достаточно сигнала. Компромисс: контекст LLaVA заполняется быстрее, но она естественно масштабируется на мульти-изображения и видео.

К 2026 году область разделилась: Q-Former выживает там, где важен бюджет токенов (длинное видео, много изображений); MLP-проектор доминирует там, где приоритет — сырое качество на токен.

### Gated cross-attention: Flamingo, предок

Flamingo (Урок 12.04) предшествовала BLIP-2 и использовала ту же идею cross-attention, но на каждом слое замороженной LLM, а не как единый мост. BLIP-2 показал, что можно сжать всё до входного слоя и это всё равно будет работать. Gemini и Idefics сочетают оба подхода: чередующиеся входные токены плюс опциональный gated cross-attention для in-context few-shot.

### Потомки 2026 года

- Q-Former: BLIP-2, InstructBLIP, MiniGPT-4 и большинство видео-языковых моделей — по соображениям бюджета токенов.
- Perceiver resampler: вариант Flamingo (Урок 12.04); семейство Idefics, Eagle, OmniMAE.
- MLP-проектор: LLaVA, LLaVA-NeXT, LLaVA-OneVision, Cambrian-1.
- Attention pool: VILA, PaliGemma.

Все четыре варианта валидны. Решающий вопрос — ограничены ли вы бюджетом токенов или качеством на токен.

## Use It

`code/main.py` строит стиль Q-Former cross-attention на stdlib:

1. Симулирует 256 патч-токенов изображения (размерность 128).
2. Инстанцирует 32 обучаемых запроса (размерность 128).
3. Выполняет масштабированное скалярное cross-attention (Q из запросов, K/V из патчей).
4. Проецирует в размерность LLM (512) через линейный слой.
5. Выводит 32 визуальных токена, готовых к подаче в LLM.

Вся математика на чистом Python (вложенные циклы по векторам). Игрушечный, но корректный по размерностям пример. Матрица весов внимания печатается, чтобы было видно, из каких патчей тянет каждый запрос.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Q-Former | «Querying transformer» | Небольшой трансформер с 32 обучаемыми векторами-запросами, выполняющими cross-attention к признакам замороженного ViT |
| Learnable queries | «Мягкий промпт для зрения» | Фиксированный набор параметров, выступающий стороной запроса в cross-attention; обучается для конкретной модели, общий для всех входов |
| Cross-attention | «Q отсюда, K/V оттуда» | Внимание, где запрос, ключ и значение берутся из разных источников; то, как запросы извлекают данные из патчей ViT |
| ITC | «Image-text contrastive» | Лосс в стиле CLIP, применённый к агрегированным запросам Q-Former против CLS-токена текста |
| ITM | «Image-text matching» | Бинарный классификатор на парах с майнингом сложных негативных примеров; заставляет запросы различать тонкие несоответствия |
| ITG | «Image-grounded text generation» | Каузальный LM-лосс, где текст генерируется с обусловленностью на запросы; заставляет запросы кодировать содержимое, пригодное для декодирования в текст |
| Two-stage pretraining | «Сначала представления, потом генерация» | Этап 1 обучает только Q-Former (ITC/ITM/ITG); Этап 2 подключает замороженную LLM и обучает только проекцию + Q-Former |
| Frozen backbone | «Не дообучать» | Веса vision-энкодера и LLM зафиксированы; обучается только мост |
| Projection head | «Линейный слой в размерность LLM» | Финальный линейный слой, отображающий выход Q-Former в размерность эмбеддингов LLM |
| Perceiver resampler | «Версия Flamingo» | Схожий cross-attention с обучаемыми запросами, используемый Flamingo на каждом слое, а не как единый мост |
