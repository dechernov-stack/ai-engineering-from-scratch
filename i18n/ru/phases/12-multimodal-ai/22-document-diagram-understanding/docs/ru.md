# Понимание документов и диаграмм

> Документы — это не фотографии. PDF, научная статья, счёт-фактура или рукописная форма имеют вёрстку, таблицы, диаграммы, сноски, заголовки и семантическую структуру, которую обычное понимание изображений не способно уловить. До-VLM стек представлял собой конвейер: Tesseract OCR + LayoutLMv3 + эвристики извлечения таблиц. Волна VLM заменила это OCR-free моделями — Donut (2022), Nougat (2023), DocLLM (2023) — которые напрямую генерируют структурированную разметку. К 2026 году передовой подход сводится к простому «подать изображение страницы в Claude Opus 4.7 с нативным разрешением 2576px», и структурированная разметка на выходе получается бесплатно. Этот урок рассматривает трёхэтапную арку развития ИИ для документов.

**Type:** Build
**Languages:** Python (stdlib, каркас layout-aware парсера документов)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 5 (NLP)
**Time:** ~180 минут

## Learning Objectives

- Объяснить три эры ИИ для документов: конвейер OCR, OCR-free, VLM-native.
- Описать три входных потока LayoutLMv3: текст, вёрстку (bbox), фрагменты изображения, с унифицированным маскированием.
- Сравнить Donut (OCR-free, изображение → разметка), Nougat (научная статья → LaTeX), DocLLM (генеративная модель с учётом вёрстки), PaliGemma 2 (VLM-native).
- Выбрать модель для работы с документами под новую задачу (счета-фактуры, научные статьи, рукописные формы, китайские чеки).

## The Problem

«Понять этот PDF» — обманчиво сложная задача. Информация содержится в:

- Текстовом содержимом (90% сигнала).
- Вёрстке (заголовки, сноски, боковые панели, двухколоночный формат).
- Таблицах (строки, столбцы, объединённые ячейки).
- Рисунках и диаграммах.
- Рукописных пометках.
- Шрифтах и типографике (заголовок vs основной текст).

Необработанный вывод OCR выдаёт только текст, теряя всё остальное. Система, работающая со счетами-фактурами, должна знать, что «Итого: $1,245» находится в нижнем правом углу, а не в сноске.

## The Concept

### Эра 1 — конвейер OCR (до 2021)

Классический стек:

1. PDF → изображение для каждой страницы.
2. Tesseract (или коммерческий OCR) извлекает текст с ограничивающими рамками для каждого слова.
3. Анализатор вёрстки определяет блоки (заголовок, таблица, абзац).
4. Распознаватель структуры таблиц разбирает таблицы.
5. Доменные правила + регулярные выражения извлекают поля.

Работает для чистого печатного текста. Ломается на рукописном тексте, перекошенных сканах, сложных таблицах, не-английских алфавитах. Каждый случай сбоя требует отдельного пути обработки исключений.

### TrOCR (2021)

TrOCR (Li et al., arXiv:2109.10282) заменил классическую CNN-CTC архитектуру Tesseract на трансформер encoder-decoder, обученный на синтетических и реальных изображениях с текстом. Явное улучшение на рукописном и многоязычном тексте. Всё ещё конвейер (детектор, затем TrOCR, затем вёрстка), но этап OCR значительно улучшился.

### Эра 2 — OCR-free (2022-2023)

Первые OCR-free модели сказали: полностью пропустим детекцию, отображая пиксели изображения напрямую в структурированный вывод.

Donut (Kim et al., arXiv:2111.15664):
- Трансформер encoder-decoder, энкодер — Swin-B.
- Вывод — JSON для понимания форм, markdown для суммаризации или любая другая схема под конкретную задачу.
- Нет OCR, нет вёрстки, нет детекции.

Nougat (Blecher et al., arXiv:2308.13418):
- Обучена специально на научных статьях.
- Вывод — LaTeX / markdown.
- Обрабатывает уравнения, многоколоночную вёрстку, рисунки.
- Модель, к которой обращается каждый arXiv-парсер.

Это специализированные модели, а не универсальные. Donut на научной статье даёт сбой; Nougat на счёте-фактуре даёт сбой.

### LayoutLMv3 (2022)

Другое направление. LayoutLMv3 (Huang et al., arXiv:2204.08387) сохраняет OCR, но добавляет понимание вёрстки:

- Три входных потока: текстовые токены OCR, 2D ограничивающие рамки для каждого токена, фрагменты изображения.
- Задача маскированного обучения охватывает все три модальности (маскированный текст, маскированные фрагменты, маскированная вёрстка).
- Последующие задачи: классификация, извлечение сущностей, QA по таблицам.

LayoutLMv3 — пик понимания документов на основе OCR. Силён в формах и счетах-фактурах. Требует OCR на предшествующем этапе. Лучшая до-VLM точность на стандартизированных бенчмарках документов.

### DocLLM (2023)

DocLLM (Wang et al., arXiv:2401.00908) — генеративный собрат LayoutLM. Генерирует произвольные ответы, обусловленные токенами вёрстки. Лучше подходит для QA по документам; всё ещё зависит от входных данных OCR.

### Эра 3 — VLM-native (2024+)

VLM 2024 года стали достаточно хороши, чтобы полностью заменить конвейер. Подаём полное изображение страницы в высоком разрешении в VLM, задаём вопрос, получаем ответ.

- LLaVA-NeXT 336-tile AnyRes работает для небольших документов.
- Qwen2.5-VL с динамическим разрешением обрабатывает 2048+ пикселей нативно.
- Claude Opus 4.7 поддерживает документы разрешением 2576px.
- PaliGemma 2 (апрель 2025) обучается специально для документов + рукописного текста.

Разрыв между VLM-native и конвейером OCR быстро сократился. К 2026 году VLM-native побеждает в:

- Текст на сцене (рукописный + печатный, смешанные алфавиты).
- Сложные таблицы с объединёнными ячейками.
- Математические уравнения, встроенные в текст.
- Рисунки с текстовыми аннотациями.

Конвейеры OCR всё ещё побеждают в:

- Чисто сканируемых рабочих нагрузках в массовом масштабе, где важна задержка на страницу.
- Надёжности конвейера (детерминированные сбои против галлюцинаций VLM).
- Регулируемых средах, требующих аудируемого вывода OCR.

### Передовая Claude 4.7 / GPT-5

При нативном вводе разрешением 2576 пикселей передовые VLM понимают документы с точностью, близкой к человеческой. Показатели бенчмарков начала 2026 года:

- DocVQA: Claude 4.7 ~95.1, PaliGemma 2 ~88.4, Nougat ~77.3, конвейерный LayoutLMv3 ~83.
- ChartQA: Claude 4.7 ~92.2, GPT-4V ~78.
- VisualMRC: Claude 4.7 ~94.

Разрыв закрытых моделей в основном определяется разрешением и масштабом базовой LLM. Открытые модели на 7B отстают на несколько пунктов, но догоняют.

### Математические уравнения и вывод LaTeX

Научным статьям нужен точный вывод LaTeX для уравнений. Nougat была обучена именно этому. VLM, обученные с целевыми значениями LaTeX (Qwen2.5-VL-Math, производные Nougat), выдают пригодный для использования LaTeX. Без явного обучения на LaTeX VLM выдают читаемые, но неточные транскрипции.

Для конвейеров научных статей в 2026 году: сначала пропустить PDF через Nougat, затем применить VLM к сложным страницам.

### Рукописный текст

Всё ещё самая сложная подзадача. Смешанный печатный + рукописный текст (записи врачей, заполненные формы) — область, где конвейеры OCR всё ещё превосходят VLM по стоимости. VLM, ориентированные только на рукописный текст, улучшаются (Claude 4.7, PaliGemma 2).

### Рецепт 2026 года

Для нового проекта в сфере ИИ для документов:

- Чисто печатные счета-фактуры в большом масштабе: LayoutLMv3 + правила, экономически эффективно.
- Смешанные документы (научные + рукописные + формы): VLM-native (PaliGemma 2 или Qwen2.5-VL).
- Полная обработка arXiv: Nougat для математики, VLM для рисунков.
- Регулируемая сфера: конвейер OCR + VLM-валидатор для перекрёстной проверки.

## Key Terms

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|------------------------|
| Конвейер OCR | «Стиль Tesseract» | Поэтапный стек: детекция -> OCR -> вёрстка -> правила; детерминированный, хрупкий |
| OCR-free | «Стиль Donut» | Трансформер изображение-в-вывод, пропускающий явный OCR; единая модель |
| Layout-aware | «LayoutLM» | Вход включает координаты bbox для каждого токена; унифицированное маскирование по модальностям |
| VLM-native | «Передовая VLM» | Подача изображения страницы напрямую в Claude/GPT/Qwen VLM в высоком разрешении; без конвейера |
| DocVQA | «Бенчмарк документов» | Стандарт VQA для документов; наиболее цитируемая оценка |
| Вывод разметки | «LaTeX / MD» | Структурированный формат вывода вместо произвольного текста; обеспечивает дальнейшую автоматизацию |
