# Семейство Qwen-VL и Dynamic-FPS видео

> Семейство Qwen-VL — Qwen-VL (2023), Qwen2-VL (2024), Qwen2.5-VL (2025), Qwen3-VL (2025) — самая влиятельная открытая линейка vision-language моделей в 2026 году. Каждое поколение делало одну решающую архитектурную ставку, которую остальная открытая экосистема копировала в течение двенадцати месяцев: нативное динамическое разрешение через M-RoPE, dynamic-FPS сэмплирование с абсолютным временны́м выравниванием, window attention в ViT и структурированные форматы агентного вывода. К моменту выхода Qwen3-VL рецепт стабилизировался: кодировщик 2D-RoPE-ViT с входами нативного соотношения сторон, MLP-проектор в большую языковую базу Qwen3 и этапы обучения, где OCR, grounding и агентное поведение рассматривались как цели первого класса. Этот урок разбирает семейство хронологически, чтобы вы поняли, почему каждая настройка находится там, где она находится.

**Type:** Изучение
**Languages:** Python (stdlib, энкодер M-RoPE + сэмплер dynamic-FPS)
**Prerequisites:** Фаза 12 · 06 (patch-n'-pack)
**Time:** ~120 минут

## Цели обучения

- Вычислить три осевых поворота M-RoPE (временной, по высоте, по ширине) и объяснить, почему нужны все три.
- Выбрать стратегию dynamic-FPS сэмплирования для видео и рассуждать о соотношении токенов в секунду и точности детекции событий.
- Назвать четыре поколенческих апгрейда Qwen-VL по порядку и что каждый из них дал.
- Собрать формат агентного JSON-вывода в стиле Qwen2.5-VL и разобрать структурированные вызовы инструментов из ответа VLM.

## Проблема

Qwen-VL вышла в августе 2023 года как прямой ответ на LLaVA-1.5 и BLIP-2. Разрыв, на который нацелилась команда Qwen, был тройным: разрешение, видео и структурированный вывод.

Разрешение: LLaVA-1.5 работала при 336x336. Нормально для фотографий, бесполезно для счёта-фактуры на китайском языке или скриншота плотной таблицы. Первое новшество Qwen-VL — 448x448 и привязанный к координатам вывод bounding-box'ов, позволяющий модели указывать на объекты.

Видео: Video-LLaMA складывала покадровые энкодеры и подавала их в LLM. Это работало для коротких роликов, но не для многоминутных видео, где временна́я ось и есть сигнал. Команда Qwen хотела единый энкодер, понимающий время.

Структурированный вывод: LLaVA выдавала текст в свободной форме. Агенту нужен JSON. Qwen-VL обучалась на явных форматах JSON-вывода, включая координаты bounding-box'ов в виде текста.

Каждое поколение Qwen-VL развивает одну из этих трёх осей.

## Концепция

### Qwen-VL (август 2023)

Первое поколение: OpenCLIP ViT-bigG/14 в качестве энкодера (2,5 млрд параметров), совместимый с Llama Q-Former (1 шаг с 256 запросами), база Qwen-7B. Вклад:

- Разрешение 448x448 (на тот момент SOTA для открытой VLM).
- Grounding: обучение на парах изображение-текст с явным выводом координатных токенов. «The cat is at <box>(112, 204), (280, 344)</box>».
- Многоязычное обучение на китайском и английском с самого начала.

Бенчмарки на тот момент: конкурентоспособна с GPT-4V на английском, доминирует на китайском. Главной новостью было именно обучение с grounding-супервизией.

### Qwen2-VL (сентябрь 2024) — M-RoPE и нативное разрешение

Qwen2-VL заменила стек с фиксированным разрешением + Q-Former на нативно динамический по разрешению энкодер ViT. Ключевые изменения:

- Нативное динамическое разрешение. ViT принимает любое HxW, кратное 28 (патч 14 с 2x пространственным слиянием). Изображение 1120x672 (40x24 объединённых патчей) даёт 960 визуальных токенов. Без ресайза, без тайлинга, без миниатюры.
- M-RoPE (Multimodal RoPE). Каждый токен несёт 3D-позицию (t, h, w) вместо 1D. Для изображений t=0, для видео t = индекс кадра. RoPE поворачивает векторы запроса/ключа на частоту по каждой оси. Без таблицы позиционных эмбеддингов.
- MLP-проектор. Отказ от Q-Former; используется 2-слойный MLP на объединённых патч-токенах.
- Видео с динамическим FPS. Видео по умолчанию сэмплируется с частотой 1-2 FPS, но модель принимает произвольное количество кадров.

Результат: Qwen2-VL-7B сравнялась с GPT-4o по нескольким мультимодальным бенчмаркам и превзошла его на DocVQA (94,5 против 88,4). Решающим шагом стало именно архитектурное изменение.

### Qwen2.5-VL (февраль 2025) — dynamic FPS + абсолютное время

Главным сдвигом Qwen2.5-VL стало видео. Dynamic FPS — это не просто «сэмплировать больше кадров при необходимости». В статье это формализовано:

- Токены абсолютного времени. Вместо позиционных индексов (кадр 0, 1, 2...) используются реальные временны́е метки. «At 0:04, the cat jumps». Модель видит токены `<time>0.04</time>`, чередующиеся с токенами кадров.
- Dynamic FPS. Сэмплирование с 1 FPS для медленной съёмки, 4+ FPS для экшна. Выбор делает пользователь или тренер; M-RoPE адаптируется.
- Window attention в ViT. Пространственное внимание оконное (локальное внутри блоков) для повышения пропускной способности; глобальное внимание каждые несколько слоёв.
- Явный формат JSON-вывода. Обучение на данных с вызовами инструментов: «{\"tool\": \"click\", \"coords\": [380, 220]}». Готовность к агентному использованию "из коробки".
- Масштабирование MRoPE-v2. Позиции масштабируются с максимальным размером входа, чтобы 10-минутное видео не исчерпало диапазон частот.

Бенчмарки: Qwen2.5-VL-72B превосходит GPT-4o на большинстве видео-бенчмарков, сравнивается с Gemini 2.0 на документах и устанавливает открытую SOTA для GUI-grounding (ScreenSpot: 84% точности против 38% у GPT-4o).

### Qwen3-VL (ноябрь 2025)

Qwen3-VL — инкрементальный апгрейд, который скорее консолидирует, чем изобретает заново: более крупный LLM-бэкбон (Qwen3-72B), расширенные обучающие данные, улучшенный OCR, более сильное рассуждение через «режим размышления» Qwen3. ViT и M-RoPE остаются прежними. Статья фокусируется на улучшениях данных и обучения, а не архитектуры.

Вывод по линейке: к 2025 году архитектура Qwen-VL стабилизировалась. Дополнительные поколения масштабируют вычисления и данные, а не примитивы.

### M-RoPE математически

Классический RoPE поворачивает запрос `q` размерности `d` на позицию `m`, используя парные координаты:

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE разбивает скрытую размерность на три диапазона. Пусть `d = 96`. Назначим 32 измерения временно́й оси, 32 — высоте, 32 — ширине. Каждый диапазон поворачивается по своей оси-позиции. Патч на (t=5, h=10, w=20) получает повороты `R_t(5)`, `R_h(10)`, `R_w(20)`, применённые к трём его диапазонам.

Текстовые токены используют `t = text_index, h = 0, w = 0` (или нормализованный выбор), сохраняя совместимость. Видеокадры используют `t = frame_time, h = row, w = col`. Одиночные изображения используют `t = 0`.

Преимущество: одно позиционное кодирование обрабатывает текст, изображение и видео без ветвящегося кода или разных таблиц позиций.

### Логика dynamic-FPS сэмплирования

Дано видео длительностью `T` секунд и целевой бюджет токенов `B`:

1. Вычислить максимальный доступный FPS: `fps_max = B / (T * tokens_per_frame)`.
2. Выбрать целевой FPS из `{1, 2, 4, 8}`, удовлетворяющий `fps <= fps_max`.
3. Если движения много (эвристика optical-flow или явный запрос пользователя), выбрать более высокий FPS. Если движения мало — более низкий.
4. Сэмплировать равномерно с выбранным FPS; вставить токены `<time>t</time>` между кадрами.

Qwen2.5-VL обучает этой логике неявно; на этапе инференса пользователь управляет ею через параметр `fps`. 60-секундная экшн-последовательность с 4 FPS по 81 токену на кадр = 19440 токенов, что приемлемо в контексте 32k.

### Структурированный агентный вывод

Агентное обучение Qwen2.5-VL явно нацелено на структурированные вызовы инструментов:

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

Парсинг детерминирован: JSON.parse по выводу модели. Сравните со свободной формой «click at (1024, 512)», которая требовала regex и обработки неоднозначностей. Именно этот сдвиг объясняет, почему оценки ScreenSpot у Qwen2.5-VL выросли с 55% у Qwen2-VL до 84%.

## Применение

`code/main.py` реализует:

- Вычисление позиций M-RoPE для упакованной последовательности, смешивающей текст, патчи изображений и кадры видео.
- Сэмплер dynamic-FPS: по (длительность, бюджет, уровень_движения) выбирает FPS и выдаёт временны́е метки кадров.
- Игрушечный парсер JSON-вывода в стиле Qwen2.5-VL, обрабатывающий ответы с вызовами инструментов и полями координат.

Запустите его, а затем ощутите разницу, когда замените фиксированный FPS на dynamic-FPS для 5-минутного видео.

## Ключевые термины

| Термин | Как говорят | Что это на самом деле означает |
|------|-----------------|------------------------|
| M-RoPE | «Мультимодальный RoPE» | 3D-вращающееся позиционное эмбеддирование с временны́м, высотным и широтным диапазонами в скрытой размерности |
| Dynamic FPS | «Умное сэмплирование» | Частота сэмплирования кадров, выбираемая для каждого видео на основе движения, длительности и бюджета токенов |
| Токен абсолютного времени | «Токен временно́й метки» | `<time>t</time>`, чередующийся в последовательности, чтобы модель видела реальные секунды, а не индекс кадра |
| Window attention | «Локальное внимание» | Пространственное self-attention, ограниченное малыми окнами ради скорости; глобальное внимание добавляется периодически |
| Структурированный агентный вывод | «Режим JSON» | Супервизия обучающих данных, обучающая VLM выдавать разбираемый JSON с координатами и названиями инструментов |
| min_pixels / max_pixels | «Границы разрешения» | Управления Qwen2.5-VL для каждого запроса, ограничивающие общее количество пикселей и, следовательно, количество токенов |
| Grounding | «Указание на объект» | Вывод координат bounding-box'ов в виде текстовых токенов; используется начиная с Qwen-VL v1 |
