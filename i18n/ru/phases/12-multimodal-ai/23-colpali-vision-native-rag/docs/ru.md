# ColPali и vision-native Document RAG

> Традиционный RAG разбирает PDF на текст, делит его на чанки, эмбеддит чанки, хранит векторы. На каждом шаге теряется сигнал: OCR теряет данные диаграмм, чанкинг ломает строки таблиц, текстовые эмбеддинги игнорируют рисунки. ColPali (Faysse et al., июль 2024) задал более простой вопрос: зачем вообще извлекать текст? Эмбеддить изображение страницы напрямую через PaliGemma, использовать late interaction в стиле ColBERT для поиска — и сохранить весь сигнал компоновки, рисунков, шрифтов и форматирования, который несёт документ. Опубликованные бенчмарки: точность сквозного пайплайна на 20-40% выше, чем у text-RAG, на визуально насыщенных документах. ColQwen2, ColSmol и VisRAG расширили этот паттерн. В этом уроке разбирается тезис vision-native RAG и строится крошечный ColPali-подобный индексатор.

**Type:** Build
**Languages:** Python (stdlib, multi-vector indexer + MaxSim scorer)
**Prerequisites:** Phase 11 (LLM Engineering — RAG basics), Phase 12 · 05 (LLaVA)
**Time:** ~180 minutes

## Цели обучения

- Объяснить разницу между retrieval на bi-encoder (один вектор на документ) и retrieval с late interaction (много векторов на документ).
- Описать операцию MaxSim из ColBERT и то, как ColPali обобщает её с текстовых токенов на патчи изображений.
- Построить крошечный ColPali-подобный индексатор: страница → эмбеддинги патчей → MaxSim по эмбеддингам терминов запроса → top-k страниц.
- Сравнить ColPali + генератор Qwen2.5-VL с text-RAG + GPT-4 на кейсе со счетами / финансовыми отчётами.

## Проблема

Text-RAG на PDF отбрасывает бóльшую часть документа. Рост выручки за Q3 в финансовом отчёте обычно показан на диаграмме; результаты в медицинском отчёте — на аннотированных изображениях; блок подписи в юридическом контракте — это факт компоновки, а не текстовый факт.

Пайплайн text-RAG:

1. PDF → текст через OCR / pdftotext.
2. Текст → чанки по 300-500 токенов.
3. Чанк → эмбеддинг bi-encoder (один вектор).
4. Запрос пользователя → эмбеддинг → косинусное сходство → top-k чанков.
5. Чанки + запрос → LLM.

Пять этапов с потерей сигнала. Диаграммы не захватываются. Таблицы ломаются при разбиении на чанки. Многоколоночная компоновка схлопывается. Аннотации к рисункам исчезают.

Решение ColPali: пропустить OCR, эмбеддить изображение страницы напрямую. Использовать late interaction в стиле ColBERT для поиска, чтобы модель могла обращать внимание на мелкозернистые патчи во время запроса.

## Концепция

### ColBERT (2020)

ColBERT (Khattab & Zaharia, arXiv:2004.12832) — метод текстового поиска. Вместо одного вектора на документ он производит один вектор на токен. Во время запроса:

- Токены запроса получают собственные эмбеддинги (N_q векторов).
- Токены документа получают эмбеддинги (N_d векторов, обычно кэшируются).
- Оценка = сумма по токенам запроса максимума по токенам документа косинусного сходства: Σ_i max_j cos(q_i, d_j).

Это и есть операция MaxSim. Каждый токен запроса «выбирает» наиболее подходящий токен документа. Итоговая оценка — сумма.

Плюсы: сильный recall, учитывает семантику на уровне термов. Минусы: N_d векторов на документ, дорогое хранение.

### ColPali

ColPali (Faysse et al., arXiv:2407.01449) применяет паттерн ColBERT к изображениям.

- Каждая страница кодируется PaliGemma (ViT + языковая часть) в эмбеддинги патчей: N_p векторов на страницу.
- Каждый пользовательский запрос (текст) кодируется в эмбеддинги токенов запроса: N_q векторов.
- Оценка = Σ_i max_j cos(q_i, p_j), то есть MaxSim между текстовыми токенами запроса и патчами изображения страницы.
- Извлекаются top-k страниц по суммарной оценке.

На этапе индексации документа: эмбеддить каждую страницу с помощью PaliGemma, хранить все эмбеддинги патчей. На этапе запроса: эмбеддить токены запроса, вычислить MaxSim против всех сохранённых эмбеддингов страниц, вернуть top-k.

Плюсы: сквозной пайплайн превосходит text-RAG на 20-40% на визуально насыщенных документах. Каждый вектор патча захватывает локальную компоновку и содержимое.

Минусы: N_p патчей × 4-байтовые числа с плавающей точкой × D-мерные векторы на страницу = хранилище растёт быстро. Смягчается квантованием PQ / OPQ.

### ColQwen2 и ColSmol

ColQwen2 (illuin-tech, 2024-2025) заменяет PaliGemma на Qwen2-VL. Лучший базовый энкодер, лучше поиск.

ColSmol — вариант меньшего масштаба для локального / edge-использования. Ретривер ColSmol с ~1 млрд параметров работает на потребительском GPU.

### VisRAG

VisRAG (Yu et al., arXiv:2410.10594) — иной вариант: вместо MaxSim по патчам каждая страница сворачивается в единый вектор с помощью VLM, затем применяется bi-encoder поиск. Быстрее индексация + меньше хранилище, но слабее recall.

Компромисс качество-стоимость: ColPali — для качества, VisRAG — для масштаба.

### M3DocRAG

M3DocRAG (Cho et al., arXiv:2411.04952) расширяет мультимодальный поиск на рассуждения по нескольким страницам и документам. Извлекает страницы из разных документов, составляет многостраничный контекст для VLM.

### ViDoRe — бенчмарк

Сопутствующий бенчмарк ColPali. Visual Document Retrieval Evaluation. Задачи включают финансовые отчёты, научные статьи, административные документы, медицинские записи, руководства. Метрика: nDCG@5.

ColPali-v1 набирает ~80% nDCG@5 на ViDoRe; text-RAG на тех же документах набирает ~50-60%.

### Сквозной пайплайн RAG

Для vision-native RAG:

1. Индексация: PDF → изображения страниц → кодирование PaliGemma → хранение всех эмбеддингов патчей.
2. Запрос: текст пользователя → эмбеддинги токенов запроса → MaxSim против всех проиндексированных страниц → top-k страниц.
3. Генерация: изображения top-k страниц + запрос → VLM (Qwen2.5-VL или Claude) → ответ.

Нигде нет OCR. Рисунки, диаграммы, шрифты, компоновка — всё попадает в ответ.

### Арифметика хранения

Финансовый отчёт на 50 страниц с 729 патчами на страницу и 128-мерными эмбеддингами:

- ColPali: 50 * 729 * 128 * 4 байта = ~18 МБ сырых данных, ~4 МБ после PQ.
- Text-RAG: 50 чанков * 768-мерный вектор * 4 байта = ~150 кБ.

ColPali требует примерно в 30 раз больше хранилища на документ. В масштабе OPQ / PQ снижает это до ~5-10x, что обычно допустимо.

### Когда text-RAG всё ещё выигрывает

- Чисто текстовые документы без сигнала компоновки (статьи из вики, логи чатов). Text-RAG проще и дешевле по хранилищу.
- Многомиллионностраничные архивы, где хранение доминирует в стоимости.
- Строгие регуляторные требования, требующие извлекаемого OCR-текста наряду с поиском.

Для всего остального в 2026 году — финансовых отчётов, научных статей, юридических контрактов, медицинских записей, документации по UX — побеждает vision-native RAG.

## Примените это

`code/main.py`:

- Игрушечный энкодер патчей: отображает «страницу» (небольшую сетку векторов признаков) в массив эмбеддингов патчей.
- Скорер MaxSim: вычисляет оценку в стиле ColBERT между набором эмбеддингов токенов запроса и набором патчей страницы.
- Индексирует 5 игрушечных страниц, выполняет 3 запроса, возвращает top-k с оценками.

3. ColPali индексирует страницы как наборы патчей. Что изменится, если вместо этого индексировать на уровне слов (как делает ColBERT)? Какие здесь компромиссы?

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|------------------------|
| Late interaction | «ColBERT-style» | Поиск с использованием эмбеддингов на уровне токена или патча + MaxSim, а не единого вектора документа |
| MaxSim | «Max-over-patches» | Для каждого токена запроса выбирается токен документа с наивысшим сходством; сумма по всему запросу |
| Bi-encoder | «Single-vector» | Один вектор на документ; быстрее, но теряет гранулярность |
| Multi-vector | «Many-vectors-per-doc» | Хранение N_p векторов на документ / страницу; стоимость хранения растёт, но recall улучшается |
| Patch embedding | «Page feature» | Один вектор на патч изображения от энкодера VLM, кэшируется для каждой страницы |
| ViDoRe | «Vision doc bench» | Набор бенчмарков ColPali для визуального поиска документов |
| PQ quantization | «Product quantization» | Сжатие, сохраняющее сходство векторов при уменьшении объёма хранилища примерно в 8 раз |
