# Мультимодальные агенты и управление компьютером (капстоун)

> Продукт 2026 года на переднем крае — это мультимодальный агент, который читает скриншоты, нажимает кнопки, перемещается по веб-интерфейсам, заполняет формы и выполняет рабочие процессы от начала до конца. SeeClick и CogAgent (2024) доказали работоспособность примитива GUI-grounding. Ferret-UI добавил поддержку мобильных устройств. ChartAgent представил визуальное использование инструментов для работы с графиками. VisualWebArena и AgentVista (2026) — это бенчмарки, за которыми гонится передний край индустрии, и даже Gemini 3 Pro и Claude Opus 4.7 набирают ~30% на сложных задачах AgentVista. Этот капстоун объединяет все нити Фазы 12: восприятие (VLM высокого разрешения), рассуждение (LLM с использованием инструментов), grounding (вывод координат), долгосрочную память и оценку.

**Type:** Капстоун
**Languages:** Python (stdlib, схема действий + каркас цикла агента)
**Prerequisites:** Фаза 12 · 05 (LLaVA), Фаза 12 · 09 (Qwen-VL JSON), Фаза 14 (Инженерия агентов)
**Time:** ~240 минут

## Цели обучения

- Спроектировать цикл мультимодального агента: восприятие → рассуждение → действие → наблюдение → повтор.
- Построить схему вывода для GUI-grounding (координаты клика, ввод текста, прокрутка, перетаскивание), которую VLM может выдавать в формате JSON.
- Сравнить агентов, работающих только со скриншотами, с агентами на основе дерева доступности и гибридными агентами.
- Настроить оценку мультимодального агента на небольшом срезе бенчмарка VisualWebArena.

## Проблема

Рабочий процесс на сайте бронирования: «найди мне рейс в Токио на 15 апреля, место у прохода, дешевле $800, забронируй его».

Мультимодальному агенту нужно:

1. Сделать скриншот браузера.
2. Разобрать скриншот + URL + цель в план.
3. Выдать структурированное действие: клик (в точке x,y), ввести «Tokyo» (в элемент E), прокрутить вниз, выбрать (радиокнопку).
4. Применить действие в браузере.
5. Наблюдать новое состояние (следующий скриншот).
6. Повторять, пока задача не будет выполнена.

Каждый шаг — это вызов мультимодальной VLM. Вывод VLM должен быть разбираемым JSON. Ошибки накапливаются от шага к шагу, поэтому важна возможность восстановления.

## Концепция

### GUI-grounding — примитив

GUI-grounding — это: имея скриншот и инструкцию на естественном языке, выдать координату (x, y) для клика (или другое действие).

SeeClick (arXiv:2401.10935) стал первым открытым результатом такого масштаба: дообучение VLM на синтетических и реальных данных GUI, вывод координат в виде обычных текстовых токенов. Работает.

CogAgent (arXiv:2312.08914) добавил кодирование высокого разрешения 1120x1120 для плотных интерфейсов. Результат: ~84% на задачах веб-навигации.

Ferret-UI (arXiv:2404.05719) сфокусирован на мобильных интерфейсах, интегрируется с данными доступности iOS.

Формат вывода обычно — JSON:

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc` помогает с восстановлением: если координаты смещаются между скриншотами, семантическая подсказка позволяет системе повторно выполнить grounding.

### Схемы действий

Типичная схема действий содержит 6-10 типов действий:

- `click`: (x, y)
- `type`: (text, x?, y?)
- `scroll`: (direction, amount)
- `drag`: (x0, y0, x1, y1)
- `select`: (option_index)
- `hover`: (x, y)
- `navigate`: (url)
- `wait`: (ms)
- `done`: (success, explanation)

Агент выдаёт одно действие за шаг. Обёртка браузера выполняет его и возвращает новое состояние.

### Только скриншот vs дерево доступности

Два режима ввода:

- Только скриншот: полное изображение, без структурной информации. Наиболее универсален; работает на любом приложении.
- Дерево доступности: структурированный DOM / информация доступности iOS. Намного надёжнее для grounding; работает там, где дерево доступно.
- Гибридный: оба варианта сразу, дерево используется как надёжный источник grounding для атомарных действий, а скриншот — для семантического контекста.

Продакшн-агенты используют гибридный подход, когда это возможно. Автоматизация браузера (Selenium + accessibility) всегда имеет дерево; десктопные приложения — иногда.

### Долгосрочная память

Рабочий процесс из 20 шагов генерирует 20 скриншотов. Контекст VLM заполняется быстро. Три стратегии сжатия:

- Summary-chain: после каждых 5 шагов суммировать произошедшее, отбрасывать старые скриншоты.
- Skip-frame: сохранять первый, последний и каждый 3-й скриншот.
- Протоколируемый лог инструментов: выполнять действия, вести текстовый лог того, что было сделано; не пересматривать старые скриншоты.

API computer-use Claude использует шаблон лога. Проще, надёжнее.

### Визуальное использование инструментов

ChartAgent (arXiv:2510.04514) вводит визуальное использование инструментов для понимания графиков: обрезка, увеличение, OCR, вызов внешнего детектирования. Агент может выдать «обрезать до региона (100, 200, 300, 400), затем вызвать OCR» как вызов инструмента. Инструмент возвращает текст; VLM продолжает рассуждение.

Этот паттерн обобщается: set-of-mark prompting, аннотация областей и внешние инструменты детектирования — всё укладывается в одну и ту же схему «выдать вызов инструмента, получить структурированный ответ».

### Бенчмарки 2026 года

- ScreenSpot-Pro. GUI-grounding на ~1 тыс. веб-скриншотов. Открытый SOTA Qwen2.5-VL-72B ~85%. Передний край ~90%.
- VisualWebArena. Сквозные веб-задачи (магазин, форум, доска объявлений). Открытый SOTA ~20%. Gemini 3 Pro ~27%.
- AgentVista (arXiv:2602.23166). Самый сложный бенчмарк 2026 года. Реалистичные рабочие процессы в 12 доменах. Модели переднего края набирают 27-40%; открытые модели — 10-20%.
- WebArena / WebShop. Более старые бенчмарки; насыщены моделями переднего края.

### Почему это всё ещё сложно

Узкие места производительности агента:

1. Визуальный grounding в мелком масштабе. «Нажми маленький крестик» часто не удаётся при мобильном разрешении.
2. Долгосрочное планирование. После 10 действий агент отклоняется от цели.
3. Восстановление после ошибок. Когда клик не срабатывает (не та кнопка), обнаружение и восстановление редко присутствуют в обучающих данных.
4. Контекст между страницами. Переключение между вкладками или длинные формы приводят к потере состояния.

Направления исследований: архитектуры памяти, явное перепланирование, мультимодальная верификация (сопоставление скриншотов для проверки успешности действия).

### Практическая сборка капстоуна

Задача капстоуна: построить агента для управления компьютером, который:

1. Читает HTML + скриншот мокапа страницы сайта бронирования.
2. Планирует многошаговую последовательность: поиск → выбор → заполнение формы → отправка.
3. Выдаёт JSON-действия, соответствующие схеме действий.
4. Оценивается на фиксированном срезе из 10 задач.

Урок предоставляет каркасный код, который легко расширить до реального браузера.

```figure
mm-agent-loop
```

## Используйте это

`code/main.py` — это каркас капстоуна:

- JSON-определение схемы действий (10 действий).
- Состояние мокап-браузера в виде словаря.
- Каркас цикла агента: получить состояние, выдать действие, применить, повторить.
- Мини-бенчмарк из 10 задач (синтетические страницы) для измерения сквозного показателя успеха.
- Хук восстановления после ошибок на случай сбоя действия.

## Примените это

Этот урок формирует навык `outputs/skill-multimodal-agent-designer.md`. Дан продукт для управления компьютером (домен, набор действий, цель оценки) — спроектировать полный цикл агента, стратегию памяти, режим grounding и ожидаемый результат на бенчмарке.

## Упражнения

1. Расширьте схему действий инструментом `screenshot_region` (обрезка + увеличение). Какие задачи от этого выигрывают?

2. Прочтите AgentVista (arXiv:2602.23166). Опишите самую сложную категорию задач и причину, по которой модели переднего края всё ещё терпят неудачу.

3. Сжатие долгосрочной памяти: спроектируйте summary-chain, в котором одновременно «живыми» хранятся ≤4 скриншота, а в лог записывается произвольное количество.

4. Постройте хук восстановления после ошибок: что делает агент дальше при сбое действия (кнопка не найдена)?

5. Сравните агента на основе только скриншотов Claude 4.7 с гибридным агентом (скриншот + дерево доступности) Qwen2.5-VL на 10 веб-задачах. Кто побеждает на каких задачах?
