# Flamingo и Gated Cross-Attention для Few-Shot VLM

> Flamingo от DeepMind (2022) первым сделал сразу две вещи. Он показал, что единая модель может обрабатывать произвольно чередующиеся последовательности изображений, видео и текста. И показал, что VLM способны к обучению в контексте — дайте few-shot промпт с тремя примерами пар (изображение, подпись), и модель подпишет новое изображение без единого шага градиентного спуска. Механизм: вентильные (gated) слои кросс-внимания, вставленные между существующими слоями замороженной LLM, с обучаемым tanh-вентилем, который начинается с нуля, так что текстовая способность LLM сохраняется при инициализации. Этот урок разбирает Perceiver resampler Flamingo и архитектуру gated cross-attention — предка чередующихся входов Gemini и визуальных токенов Idefics2.

**Type:** Learn
**Languages:** Python (stdlib, демонстрация gated cross-attention + Perceiver resampler)
**Prerequisites:** Phase 12 · 03 (BLIP-2 Q-Former)
**Time:** ~120 минут

## Learning Objectives

- Объяснить, как gated cross-attention сохраняет текстовую способность замороженной LLM при инициализации за счёт tanh(gate) = 0.
- Разобрать Perceiver resampler: N патчей изображения → K фиксированных "латентных" запросов через кросс-внимание.
- Описать, как Flamingo обрабатывает чередующиеся последовательности изображение-текст с каузальным маскированием, учитывающим расположение изображений.
- Воспроизвести структуру few-shot мультимодального промпта (3 примера изображение-подпись, затем запрос-изображение).

## The Problem

BLIP-2 подаёт 32 визуальных токена во входной слой замороженной LLM. Это работает для одного изображения на промпт. Но что если нужно подать *много* изображений, чередующихся с текстом, как в "вот изображение A, подпишите его; вот изображение B, подпишите его; а вот изображение C, подпишите его"? Самовнимание LLM должно было бы обрабатывать токены изображений и текста в едином потоке, и вопрос, какие позиции могут обращать внимание на какие изображения, становится запутанным.

Ответ Flamingo: вообще не менять входной поток LLM. Вставить дополнительные слои кросс-внимания между существующими блоками LLM. Текстовые токены по-прежнему проходят через каузальное самовнимание LLM как обычно. Между каждыми несколькими блоками LLM текстовые токены также выполняют кросс-внимание к визуальным признакам через новый вентильный слой. Вентиль (инициализированный нулём) означает, что на шаге ноль новые слои являются тождественными (no-op) — модель ведёт себя точно как предобученная LLM. По мере обучения вентиль открывается, и визуальная информация начинает поступать.

Второй вопрос, на который ответил Flamingo: как обрабатывать переменное число изображений (0, 1 или много) на промпт? Perceiver resampler — небольшой модуль кросс-внимания, который берёт любое число патчей и производит фиксированное число визуальных латентных токенов. Слой кросс-внимания LLM видит одну и ту же форму независимо от того, сколько изображений в промпте.

## The Concept

### Замороженная LLM

Flamingo стартует с замороженной Chinchilla 70B LLM. Все 70B весов не тронуты. Существующие текстовое самовнимание и FFN работают как обычно.

### Perceiver resampler

Для каждого изображения в промпте ViT производит N токенов-патчей. Perceiver resampler имеет K фиксированных обучаемых латентов (Flamingo использует K=64). Каждый блок resampler состоит из двух подшагов:

1. Кросс-внимание: K латентов обращают внимание на N токенов-патчей (Q из латентов, K/V из патчей).
2. Самовнимание + FFN внутри латентов.

После 6 блоков resampler выход составляет K=64 визуальных токена размерности 1024, независимо от того, сколько патчей произвёл ViT. Изображение 224x224 (196 патчей) и изображение 480x480 (900 патчей) оба выходят как 64 токена resampler.

Для видео resampler применяется по времени: патчи каждого кадра производят 64 латента, а временное позиционное кодирование позволяет модели отличать t=0 от t=N. Всё видео становится T * 64 визуальными токенами.

### Gated cross-attention

Между каждыми M слоями замороженной LLM (Flamingo использует M=4) вставляется новый вентильный блок кросс-внимания:

```
x_after_llm_block = llm_block(x_before)
cross = cross_attn(x_after, resampler_output)
gated = tanh(alpha) * cross + x_after
x_before_next_block = gated
```

- `alpha` — обучаемый скаляр, инициализированный нулём.
- `tanh(0) = 0`, так что при инициализации вентильная ветвь даёт нулевой вклад.
- По мере того как `alpha` отходит от нуля, вклад кросс-внимания плавно растёт.
- Остаточное соединение означает, что даже полностью открытый вентиль не перезаписывает текстовое представление LLM; он лишь добавляет визуальную информацию поверх.

Это самое важное архитектурное решение в Flamingo: визуальное обуславливание аддитивно, вентильно и равно нулю при инициализации. Flamingo на шаге 0 — это идеальная Chinchilla 70B на чисто текстовых входах.

### Маскированное кросс-внимание для чередующихся входов

В промпте вида "<image A> caption A <image B> caption B <image C> ?" каждый текстовый токен должен видеть только те изображения, которые были перед ним в последовательности. Маска кросс-внимания обеспечивает: текстовый токен в позиции `t` обращает внимание только на токены resampler того изображения, индекс которого `i < i_t`, где `i_t` — ближайшее предшествующее изображение перед позицией `t`. "Видит только последнее предшествующее изображение" или "видит все предшествующие изображения" — оба варианта допустимы; Flamingo выбрал первый.

### Few-shot обучение в контексте

Промпт Flamingo выглядит так:

```
<image1> A photo of a cat. <image2> A photo of a dog. <image3> A photo of a
```

Модель видит паттерн завершения и выдаёт "bird" (или что изображено на image3). Никаких шагов градиентного спуска. Способность замороженной LLM к обучению в контексте переносится через gated cross-attention — это ключевой вывод статьи и причина, по которой он важен.

### Данные для обучения

Flamingo обучался на трёх датасетах:

1. MultiModal MassiveWeb (M3W): 43M веб-страниц с чередующимися изображениями и текстом, с реконструкцией порядка чтения.
2. Image-Text Pairs (ALIGN + LTIP): 4.4B пар.
3. Video-Text Pairs (VTP): 27M коротких видеоклипов.

OBELICS (2023) — открытая репродукция чередующегося веб-корпуса, на котором обучаются Idefics, Idefics2 и большинство открытых "Flamingo-подобных" моделей.

### OpenFlamingo и Otter

OpenFlamingo (2023) — открытая репродукция. Архитектура идентична (Perceiver resampler + gated cross-attention поверх замороженной LLaMA или MPT). Чекпойнты на 3B, 4B, 9B. Качество отстаёт от Flamingo из-за меньшей базовой LLM и меньшего количества данных.

Otter (2023) строится на основе OpenFlamingo с инструктивной настройкой на MIMIC-IT (датасет мультимодальных инструкций), показывая, что gated cross-attention также работает для следования инструкциям.

### Потомки

- Idefics / Idefics2 / Idefics3: линия Hugging Face с gated cross-attention, постепенно упрощающаяся (Idefics2 отказался от resampler в пользу прямых токенов патчей с адаптивным пулингом).
- Переход Flamingo-к-Chameleon: к 2024 году многие команды перешли на раннее слияние (early-fusion) (Lesson 12.11); gated cross-attention в стиле Flamingo остаётся в продакшене там, где требуется заморозка backbone.
- Чередующийся вход Gemini: концептуально наследует гибкость чередующегося формата Flamingo, хотя точный механизм является проприетарным.

### Сравнение с BLIP-2

| | BLIP-2 | Flamingo |
|---|---|---|
| Визуальный мост | Q-Former один раз на входе | Gated cross-attention каждые M слоёв |
| Визуальные токены | 32 на изображение | 64 на изображение на слой кросс-внимания |
| Замороженная LLM | Да | Да |
| Few-shot в контексте | Слабо | Сильно — центральная идея статьи |
| Чередующиеся входы | Нет нативной поддержки | Да, целевой дизайн |
| Данные обучения | 130M пар | 1.3B пар + 43M чередующихся страниц |
| Количество параметров | 188M обучаемых | ~10B обучаемых (слои cross-attn) |
| Вычисления | Дни на 8 A100 | Недели на тысячах TPUv4 |

Выбирайте BLIP-2 для одноизображенческого VQA с ограниченным бюджетом. Выбирайте Flamingo/Idefics2 для чередующегося, few-shot или мультиизображенческого рассуждения.

## Use It

`code/main.py` демонстрирует:

1. Perceiver resampler на 36 фиктивных токенах-патчах с 8 обучаемыми латентами (чистое кросс-внимание на Python).
2. Шаг gated cross-attention с `alpha = 0` → выход равен входу (LLM не изменена), затем `alpha = 2.0` → визуальный вклад примешан.
3. Построитель чередующейся маски, который производит 2D-маску внимания для последовательности "(изображение 1) (текст 1) (изображение 2) (текст 2)".

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Perceiver resampler | "Кросс-внимание с фиксированными латентами" | Модуль, производящий K фиксированных токенов из переменного числа входных патчей |
| Gated cross-attention | "Мост с tanh-вентилем" | Остаточный слой `y = tanh(alpha)*cross + x`, обучаемая alpha, инициализация 0 |
| Interleaved input | "Смешанная последовательность" | Формат промпта, где изображения и текст свободно смешаны в порядке чтения |
| Frozen LLM | "Без градиентов LLM" | Веса текстовой LLM не обновляются; обучаются только resampler + слои cross-attn |
| Few-shot | "Примеры в контексте" | Дать несколько пар (изображение, ответ) в промпте; модель обобщает без дообучения |
| OBELICS | "Чередующийся веб-корпус" | Открытый датасет из 141M веб-страниц с изображениями и текстом в порядке чтения |
| Chinchilla | "Замороженная база 70B" | Замороженная текстовая LLM Flamingo, из статьи DeepMind о Chinchilla |
| Gate schedule | "Как движется alpha" | Скорость, с которой вентиль кросс-внимания открывается во время обучения |
| Cross-attn frequency | "Каждые M слоёв" | Как часто вставляется блок gated cross-attention; Flamingo использует M=4 |
| OpenFlamingo | "Открытая репродукция" | Открытый чекпойнт MosaicML/LAION на 3-9B; архитектурно идентичен Flamingo |
