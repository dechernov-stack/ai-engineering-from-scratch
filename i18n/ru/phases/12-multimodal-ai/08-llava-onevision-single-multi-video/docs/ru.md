# LLaVA-OneVision: единое изображение, несколько изображений и видео в одной модели

> До LLaVA-OneVision (Li et al., август 2024) мир открытых VLM состоял из отдельных линий развития: LLaVA-1.5 для единичных изображений, модели для нескольких изображений вроде Mantis и VILA, видеомодели вроде Video-LLaVA и Video-LLaMA. Каждая побеждала в своём бенчмарке и проваливалась в остальных. LLaVA-OneVision показала, что единая учебная программа способна обучить одну модель доминировать во всех трёх сценариях, и что возникающие эффекты переноса задач (навыки единичного изображения переносятся на видео, рассуждения по нескольким изображениям переносятся на единичное изображение) превосходят сумму специализированных моделей. Рецепт обманчиво прост: бюджет визуальных токенов, остающийся постоянным во всех сценариях, плюс явная учебная программа, которая движется от единичного изображения к OneVision (несколько изображений) и далее к видео. В этом уроке разбираются бюджет, учебная программа и возникающее поведение.

**Type:** Build
**Languages:** Python (stdlib, решатель бюджета токенов + планировщик учебной программы)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 12 · 06 (любое разрешение)
**Time:** ~180 минут

## Цели обучения

- Спроектировать бюджет визуальных токенов, остающийся постоянным для единичного изображения, нескольких изображений и видео на входе.
- Упорядочить учебную программу обучения так, чтобы навыки переносились с единичного изображения на видео без катастрофического забывания.
- Объяснить, почему одна модель превосходит специализированные модели того же числа параметров, если учебная программа выстроена правильно.
- Назвать три возникающие способности, о которых сообщается в LLaVA-OneVision: рассуждение с нескольких камер, промптинг set-of-mark, агент для скриншотов iPhone.

## Проблема

Изображение, несколько изображений и видео нагружают модель по-разному.

Единичное изображение требует высокоразрешённых токенов (AnyRes, ~2880 визуальных токенов) для распознавания текста (OCR) и мелких деталей. Бюджет на один образец: одно изображение, 2880 токенов.

Несколько изображений требуют нескольких изображений умеренного разрешения (~576 токенов каждое), чтобы рассуждение между изображениями умещалось в контекст. Бюджет на один образец: 4-8 изображений, по 576 каждое, 2300-4600 токенов.

Видео требует много кадров низкого разрешения (~196 токенов на кадр после пулинга), чтобы уловить временную динамику. Бюджет на один образец: 8-32 кадра, по 196 каждый, 1600-6200 токенов.

Если вы обучаете отдельные модели, вы выбираете один бюджет. Если вы обучаете одну модель, нужно, чтобы бюджет разумно масштабировался между сценариями, не раздувая контекст.

До OneVision стандартным ответом было «обучать один сценарий, остальные игнорировать». Video-LLaVA достраивала видео поверх модели изображений дополнительными этапами обучения. LLaVA-NeXT добавила поддержку нескольких изображений с помощью тайлинга. Ни одна из них не справлялась чисто со всеми тремя сценариями.

## Концепция

### Бюджет токенов OneVision

LLaVA-OneVision выбирает единый бюджет визуальных токенов примерно в 3000-4000 токенов на образец, распределяемый по-разному в зависимости от сценария:

- Единичное изображение: AnyRes-9 (тайлы 3x3 + миниатюра), каждый тайл в разрешении 384 с 729 патчами, агрессивный билинейный пулинг 2x2 → 182 на тайл. Итого: 9 * 182 + 182 = 1820 токенов. Либо AnyRes-4 с 729 на тайл = 2916 + 729.
- Несколько изображений: каждое изображение в умеренном разрешении (384, без тайлинга), 729 токенов без пулинга. Бюджет для 6 изображений → 4374 токена.
- Видео: 32 кадра в разрешении 384 с агрессивным билинейным пулингом 3x3 → 81 токен на кадр. Итого: 32 * 81 = 2592 токена.

Такое распределение поддерживает примерно постоянное общее число токенов. LLM никогда не видит пакет, который выходит за пределы её контекста. Энкодер выдаёт разную геометрию в зависимости от сценария, но LLM потребляет один и тот же бюджет.

### Трёхэтапная учебная программа

LLaVA-OneVision обучается в три этапа:

1. SFT на единичных изображениях (этап SI). Все данные — единичное изображение плюс текст. Обучение на высокоразрешённом входе AnyRes. Это обучает восприятию, OCR и пониманию мелких деталей. Используются данные LLaVA-NeXT плюс специфичные для OneVision данные с единичными изображениями.
2. SFT OneVision (этап OV). Смесь единичных изображений + нескольких изображений + видео (равномерно выбранные кадры). Обучение на едином бюджете токенов. Это обучает модель обрабатывать разнородные формы пакетов. Без сброса весов — продолжение с этапа SI.
3. Перенос задач (этап TT). Продолжение с целевой смесью задач, обычно с бо́льшим упором на несколько изображений или видео в зависимости от продукта. Опциональная дообучающая настройка для развёртывания.

Критически важно: порядок учебной программы имеет значение. Обучение сначала на видео или сначала на нескольких изображениях даёт худшую производительность на изображениях, чем обучение сначала на единичном изображении, даже при тех же данных. В статье это явно подтверждается абляциями.

### Почему работает учебная программа

Обучение на единичных изображениях строит перцептивную базу. Токены патчей несут мелкозернистые визуальные признаки; LLM учится интегрировать их с текстом. Несколько изображений и видео вносят структурные сложности (какое изображение какое, что произошло сначала), которые трудно освоить без сильной перцептивной базы.

Если обучать все сценарии вместе с нуля, модель недообучается восприятию (ограниченный объём данных с единичными изображениями на пакет) и переобучается на структуру (много данных с несколькими изображениями / видео). Результат: модель, которая следует паттернам рассуждения между изображениями, но визуально поверхностна.

Упорядочивание учебной программы даёт силу восприятия с этапа SI, затем композиционное/временное рассуждение с этапа OV, не теряя ни того, ни другого.

### Возникающие межсценарные навыки

В статье LLaVA-OneVision сообщается о трёх возникающих способностях:

1. Рассуждение с нескольких камер. Обучена на нескольких изображениях + видео по отдельности; на этапе инференса модели предлагается рассуждать о сцене вождения с нескольких камер. Модель корректно интегрирует виды, несмотря на то, что никогда не видела именно такой формат при обучении.
2. Промптинг set-of-mark. Пользователь размечает объекты на изображении пронумерованными метками; модель рассуждает о том, «что делает метка 3 относительно метки 7». Не обучена ни на метках, ни на аннотациях; научилась этому за счёт сочетания пространственной привязки + референсов между несколькими изображениями.
3. Агент для скриншотов iPhone. Пользователь предоставляет скриншот экрана iPhone и просит спланировать следующий клик. Обучена на скриншотах интерфейса, видео рабочих процессов пользователя и парах «до/после» из нескольких изображений. Обобщается на сценарий использования агентом.

Это не обученные задачи — они возникают из композиционной структуры учебной программы.

### Пулинг визуальных токенов

Бюджет токенов требует пулинга. OneVision использует билинейную интерполяцию на 2D-сетке патчей: 24x24 = 576 патчей превращается в 12x12 = 144 (коэффициент 2x) или 8x8 = 64 (коэффициент 3x). Пулинг выполняется в пространстве сетки патчей, а не в пространстве токенов, чтобы сохранить локальность.

Выбор коэффициента пулинга для каждого сценария сам по себе является гиперпараметром. Меньше пулинга = больше токенов = более богатое представление. Больше пулинга = меньше токенов = больше кадров / изображений помещается.

### LLaVA-OneVision-1.5

Продолжение 2025 года (LLaVA-OneVision-1.5, arXiv 2509.23661) «полностью открыто» в части обучающих данных, весов модели и кода. Сокращает разрыв с проприетарными моделями на некоторых бенчмарках и демократизирует рецепт. Та же учебная программа, больше данных, более качественная базовая LLM. Без изменений архитектуры.

### Сравнение с Qwen2.5-VL

Qwen2.5-VL (Урок 12.09) делает иной выбор. Он использует M-RoPE и динамический FPS вместо фиксированного пулинга. Его бюджет масштабируется в зависимости от входа — минутное видео использует больше токенов, чем пятисекундное. LLaVA-OneVision фиксирует бюджет и масштабирует пулинг. Оба подхода работают; они обменивают настраиваемость на предсказуемость.

## Примените это

`code/main.py` — это планировщик учебной программы и бюджета для VLM в стиле OneVision. Получив бюджет токенов на образец и целевую смесь сценариев (скажем, 40% единичное изображение, 30% несколько изображений, 30% видео), он:

- Распределяет разрешение, коэффициент пулинга и число кадров по сценариям.
- Проверяет, что каждый сценарий укладывается в общий бюджет.
- Сообщает ожидаемое число токенов, FLOPs LLM и какие сценарии недополучают токены.
- Выводит поэтапный план обучения.

Используйте его для планирования дообучения OneVision или для проверки на здравый смысл стоимости одного запроса при развёртывании VLM.

## Довести до результата

Этот урок производит `outputs/skill-onevision-budget-planner.md`. Получив целевое распределение задач и бюджет на образец, он выдаёт коэффициент AnyRes, пулинг на кадр, число кадров видео и веса этапов учебной программы. Используйте это всякий раз, когда обучаете или дообучаете VLM с единым сценарием.

## Упражнения

1. Ваш продукт поддерживает 80% единичных изображений, 10% нескольких изображений (2-4 изображения), 10% видео (8-16 кадров). Спроектируйте бюджет токенов. Куда бы вы направили дополнительный бюджет, сэкономленный на отказе от интенсивной обработки нескольких изображений?

2. Прочитайте раздел 4.3 статьи LLaVA-OneVision (возникающие способности). Предложите четвёртый возникающий навык, который учебная программа, вероятно, раскрыла бы, но о котором в статье не сообщается.

3. Поменяйте порядок учебной программы — сначала обучайте на нескольких изображениях, затем на единичном изображении, затем на видео. Предскажите, какие бенчмарки ухудшатся и почему.

4. В статье сообщается о видеобенчмарках, обученных всего на 8 кадрах на образец. Обобщается ли это на 30-секундные видео при инференсе? Что сломается первым — бюджет токенов или временное рассуждение?

5. Билинейный пулинг патчей 24x24 в 12x12 — это сокращение в 4 раза по каждому измерению. Реализуйте пулинг на stdlib Python и проверьте, что среднее по каждому блоку 2x2 совпадает с билинейным выводом.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|------------------------|
| Сценарий OneVision | «Единичное изображение, несколько изображений или видео» | Одна из трёх форм входа, обрабатываемых единой VLM; бюджет остаётся постоянным во всех случаях |
| Бюджет токенов | «Сколько токенов на образец» | Общее число визуальных токенов, которые видит LLM на образец при обучении / инференсе, обычно 3000-4000 |
| Учебная программа | «Порядок обучения» | Порядок этапов (единичное изображение → несколько изображений → видео), выбранный для возникающего переноса |
| Билинейный пулинг | «Сжатие токенов» | Применение билинейной интерполяции к сетке патчей (2D) для уменьшения числа токенов с сохранением локальности |
| Возникающий навык | «Не обучен, но всё равно работает» | Способность, проявляющаяся при инференсе без соответствующих обучающих данных, благодаря составу учебной программы |
| AnyRes-k | «Конфигурация с k тайлами» | k подтайлов фиксированного разрешения плюс одна миниатюра, типичное k ∈ {4, 9} |
| Перенос задач | «Обобщение между сценариями» | Навыки, выученные на единичном изображении, применимые к видео (и наоборот) через общий бэкбон |
