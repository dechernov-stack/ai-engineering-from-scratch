# Свёртки с нуля

> Свёртка — это крошечный полносвязный слой, который вы скользите по изображению, используя одни и те же веса в каждой позиции.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 3 (Deep Learning Core), Phase 4 Lesson 01 (Image Fundamentals)
**Time:** ~75 минут

## Цели обучения

- Реализовать 2D-свёртку с нуля, используя только NumPy, включая версию с вложенными циклами и векторизованную версию через `im2col`
- Вычислять выходной пространственный размер для любой комбинации размера входа, размера ядра, паддинга и шага, и обосновать формулу `(H - K + 2P) / S + 1`
- Вручную спроектировать ядра (edge, blur, sharpen, Sobel) и объяснить, почему каждое из них даёт именно такой паттерн активаций
- Собрать свёртки в стек экстрактора признаков и связать глубину стека с размером рецептивного поля

## Проблема

Полносвязный слой на изображении 224x224 RGB потребовал бы 224 * 224 * 3 = 150 528 входных весов на один нейрон. Один скрытый слой с 1000 нейронов — это уже 150 миллионов параметров, причём ещё до того, как вы выучили что-то полезное. Хуже того: у такого слоя нет понятия, что собака в левом верхнем углу и собака в правом нижнем — это один и тот же паттерн. Он рассматривает каждую позицию пикселя как независимую, что в корне неверно для изображений: сдвиг кошки на три пикселя не должен заставлять сеть заново учить это понятие.

Два свойства, которые нужны модели изображений, — это **трансляционная эквивариантность** (выход сдвигается, когда сдвигается вход) и **разделение параметров** (один и тот же детектор признаков работает повсюду). Полносвязные слои не дают ни того, ни другого. Свёртка даёт оба свойства бесплатно.

Свёртка была придумана не для глубокого обучения. Это та же операция, что лежит в основе JPEG-сжатия, гауссова размытия в Photoshop, детекции краёв в промышленном зрении и любого аудиофильтра, который когда-либо выпускался. Причина, по которой CNN доминировали на ImageNet с 2012 по 2020 год, в том, что свёртка — это корректный априорный принцип для данных, где близкие значения связаны между собой, а один и тот же паттерн может встречаться где угодно.

## Концепция

### Одно ядро, скольжение

2D-свёртка берёт небольшую матрицу весов, называемую ядром (или фильтром), скользит ей по входу и в каждой позиции вычисляет сумму поэлементных произведений. Эта сумма становится одним выходным пикселем.

```mermaid
flowchart LR
    subgraph IN["Input (H x W)"]
        direction LR
        I1["5 x 5 image"]
    end
    subgraph K["Kernel (3 x 3)"]
        K1["learned<br/>weights"]
    end
    subgraph OUT["Output (H-2 x W-2)"]
        O1["3 x 3 map"]
    end
    I1 --> |"slide kernel<br/>compute dot product<br/>at each position"| O1
    K1 --> O1

    style IN fill:#dbeafe,stroke:#2563eb
    style K fill:#fef3c7,stroke:#d97706
    style OUT fill:#dcfce7,stroke:#16a34a
```

Конкретный пример 3x3 на входе 5x5 (без паддинга, шаг 1):

```
Input X (5 x 5):                Kernel W (3 x 3):

  1  2  0  1  2                   1  0 -1
  0  1  3  1  0                   2  0 -2
  2  1  0  2  1                   1  0 -1
  1  0  2  1  3
  2  1  1  0  1

The kernel slides across every valid 3 x 3 window. Output Y is 3 x 3:

 Y[0,0] = sum( W * X[0:3, 0:3] )
 Y[0,1] = sum( W * X[0:3, 1:4] )
 Y[0,2] = sum( W * X[0:3, 2:5] )
 Y[1,0] = sum( W * X[1:4, 0:3] )
 ... and so on
```

Эта формула — **разделяемые веса, локальность, скользящее окно** — и есть вся идея целиком. Всё остальное — это учёт деталей.

### Формула выходного размера

Дан пространственный размер входа `H`, размер ядра `K`, паддинг `P`, шаг `S`:

```
H_out = floor( (H - K + 2P) / S ) + 1
```

Запомните это. Вам придётся вычислять это десятки раз на каждую архитектуру.

| Сценарий | H | K | P | S | H_out |
|----------|---|---|---|---|-------|
| Valid-свёртка, без паддинга | 32 | 3 | 0 | 1 | 30 |
| Same-свёртка (сохраняет размер) | 32 | 3 | 1 | 1 | 32 |
| Даунсэмплинг в 2 раза | 32 | 3 | 1 | 2 | 16 |
| Pool 2x2 | 32 | 2 | 0 | 2 | 16 |
| Большое рецептивное поле | 32 | 7 | 3 | 2 | 16 |

«Same padding» означает выбрать P так, чтобы H_out == H при S == 1. Для нечётного K это P = (K - 1) / 2. Именно поэтому ядра 3x3 так распространены — это наименьшее нечётное ядро, у которого всё ещё есть центр.

### Паддинг

Без паддинга каждая свёртка уменьшает карту признаков. Поставьте 20 свёрток подряд, и ваше изображение 224x224 превратится в 184x184, что расходует вычисления на границе впустую и усложняет остаточные (residual) связи, которым нужны совпадающие формы.

```
Zero padding (P = 1) on a 5 x 5 input:

  0  0  0  0  0  0  0
  0  1  2  0  1  2  0
  0  0  1  3  1  0  0
  0  2  1  0  2  1  0       Now the kernel can centre on pixel
  0  1  0  2  1  3  0       (0, 0) and still have three rows and
  0  2  1  1  0  1  0       three columns of values to multiply.
  0  0  0  0  0  0  0
```

Режимы, которые встречаются на практике: `zero` (самый распространённый), `reflect` (зеркальное отражение края, избегает жёстких границ в генеративных моделях), `replicate` (копирование края), `circular` (циклическое обёртывание, используется в тороидальных задачах).

### Шаг (stride)

Шаг — это размер шага скольжения. `stride=1` — значение по умолчанию. `stride=2` уменьшает пространственные размеры вдвое и является классическим способом даунсэмплинга внутри CNN без отдельного слоя пулинга — каждая современная архитектура (ResNet, ConvNeXt, MobileNet) где-нибудь использует свёртки с шагом вместо max-pool.

```
Stride 1 on a 5 x 5 input, 3 x 3 kernel:

  starts: (0,0) (0,1) (0,2)        -> output row 0
          (1,0) (1,1) (1,2)        -> output row 1
          (2,0) (2,1) (2,2)        -> output row 2

  Output: 3 x 3

Stride 2 on the same input:

  starts: (0,0) (0,2)              -> output row 0
          (2,0) (2,2)              -> output row 1

  Output: 2 x 2
```

### Несколько входных каналов

Реальные изображения имеют три канала. Свёртка 3x3 на RGB-входе на самом деле представляет собой объём 3x3x3: по одному срезу 3x3 на каждый входной канал. В каждой пространственной позиции вы перемножаете и суммируете по всем трём срезам и добавляете смещение (bias).

```
Input:   (C_in,  H,  W)        3 x 5 x 5
Kernel:  (C_in,  K,  K)        3 x 3 x 3 (one kernel)
Output:  (1,     H', W')       2D map

For a layer that produces C_out output channels, you stack C_out kernels:

Weight:  (C_out, C_in, K, K)   e.g. 64 x 3 x 3 x 3
Output:  (C_out, H', W')       64 x 3 x 3

Parameter count: C_out * C_in * K * K + C_out   (the + C_out is biases)
```

Последняя строка — это то, что вам придётся вычислять при проектировании модели. Свёртка 3x3 с 64 каналами на входе с 3 каналами имеет `64 * 3 * 3 * 3 + 64 = 1,792` параметров. Дёшево.

### Приём im2col

Вложенные циклы легко читать, но они медленные. GPU хотят крупных умножений матриц. Приём: развернуть каждое окно рецептивного поля входа в один столбец большой матрицы, развернуть ядро в строку, и вся свёртка становится единственным матричным умножением.

```mermaid
flowchart LR
    X["Input<br/>(C_in, H, W)"] --> IM2COL["im2col<br/>(extract patches)"]
    IM2COL --> COLS["Cols matrix<br/>(C_in * K * K, H_out * W_out)"]
    W["Weight<br/>(C_out, C_in, K, K)"] --> FLAT["Flatten<br/>(C_out, C_in * K * K)"]
    FLAT --> MM["matmul"]
    COLS --> MM
    MM --> OUT["Output<br/>(C_out, H_out * W_out)<br/>reshape to (C_out, H_out, W_out)"]

    style X fill:#dbeafe,stroke:#2563eb
    style W fill:#fef3c7,stroke:#d97706
    style OUT fill:#dcfce7,stroke:#16a34a
```

Каждая промышленная реализация свёртки — это тот или иной вариант данного приёма плюс трюки с тайлингом кэша (direct conv, Winograd, FFT conv для больших ядер). Поймите im2col — и вы поймёте суть.

### Рецептивное поле

Одна свёртка 3x3 смотрит на 9 входных пикселей. Поставьте две свёртки 3x3 подряд — и нейрон во втором слое смотрит уже на 5x5 входных пикселей. Три свёртки 3x3 дают 7x7. В общем виде:

```
RF after L stacked K x K convs (stride 1) = 1 + L * (K - 1)

With strides:   RF grows multiplicatively with stride along each layer.
```

Вся причина, по которой «3x3 до самого конца» работает (VGG, ResNet, ConvNeXt), в том, что две свёртки 3x3 видят ту же область входа, что и одна свёртка 5x5, но с меньшим числом параметров и дополнительной нелинейностью между ними.

## Реализация

### Шаг 1: Паддинг массива

Начните с мельчайшего примитива: функции, которая дополняет нулями массив H x W.

```python
import numpy as np

def pad2d(x, p):
    if p == 0:
        return x
    h, w = x.shape[-2:]
    out = np.zeros(x.shape[:-2] + (h + 2 * p, w + 2 * p), dtype=x.dtype)
    out[..., p:p + h, p:p + w] = x
    return out

x = np.arange(9).reshape(3, 3)
print(x)
print()
print(pad2d(x, 1))
```

Приём с конечными осями `x.shape[:-2]` означает, что одна и та же функция работает на `(H, W)`, `(C, H, W)` или `(N, C, H, W)` без изменений.

### Шаг 2: 2D-свёртка с вложенными циклами

Эталонная реализация — медленная, но однозначная. Именно это делает `torch.nn.functional.conv2d` в принципе.

```python
def conv2d_naive(x, w, b=None, stride=1, padding=0):
    c_in, h, w_in = x.shape
    c_out, c_in_w, kh, kw = w.shape
    assert c_in == c_in_w

    x_pad = pad2d(x, padding)
    h_out = (h + 2 * padding - kh) // stride + 1
    w_out = (w_in + 2 * padding - kw) // stride + 1

    out = np.zeros((c_out, h_out, w_out), dtype=np.float32)
    for oc in range(c_out):
        for i in range(h_out):
            for j in range(w_out):
                hs = i * stride
                ws = j * stride
                patch = x_pad[:, hs:hs + kh, ws:ws + kw]
                out[oc, i, j] = np.sum(patch * w[oc])
        if b is not None:
            out[oc] += b[oc]
    return out
```

Четыре вложенных цикла (выходной канал, строка, столбец, плюс неявное суммирование по C_in, kh, kw). Это эталон истины, с которым вы будете сверять каждую более быструю реализацию.

### Шаг 3: Проверка на ядре, спроектированном вручную

Постройте вертикальное ядро Собеля, примените его к синтетическому ступенчатому изображению и понаблюдайте, как загорается вертикальный край.

```python
def synthetic_step_image():
    img = np.zeros((1, 16, 16), dtype=np.float32)
    img[:, :, 8:] = 1.0
    return img

sobel_x = np.array([
    [[-1, 0, 1],

], dtype=np.float32)[None]

```

Ожидайте больших положительных значений в столбце 7 (увеличение яркости слева направо) и нулей везде остальное. Этот единственный вывод — ваша проверка на здравый смысл, что математика верна.

### Шаг 4: im2col

Преобразуйте каждое окно размера ядра во входе в столбец матрицы. Для `C_in=3, K=3` каждый столбец состоит из 27 чисел.

```python
def im2col(x, kh, kw, stride=1, padding=0):
    c_in, h, w = x.shape
    x_pad = pad2d(x, padding)
    h_out = (h + 2 * padding - kh) // stride + 1
    w_out = (w + 2 * padding - kw) // stride + 1

    cols = np.zeros((c_in * kh * kw, h_out * w_out), dtype=x.dtype)
    col = 0
    for i in range(h_out):
        for j in range(w_out):
            hs = i * stride
            ws = j * stride
            patch = x_pad[:, hs:hs + kh, ws:ws + kw]
            cols[:, col] = patch.reshape(-1)
            col += 1
    return cols, h_out, w_out
```

Это всё ещё цикл Python, но теперь основная вычислительная нагрузка будет приходиться на одно векторизованное матричное умножение.

### Шаг 5: Быстрая свёртка через im2col + матричное умножение

Замените четверной цикл на одно матричное умножение.

```python
def conv2d_im2col(x, w, b=None, stride=1, padding=0):
    c_out, c_in, kh, kw = w.shape
    cols, h_out, w_out = im2col(x, kh, kw, stride, padding)
    w_flat = w.reshape(c_out, -1)
    out = w_flat @ cols
    if b is not None:
        out += b[:, None]
    return out.reshape(c_out, h_out, w_out)
```

Проверка корректности: запустите обе реализации и сравните.

```python
rng = np.random.default_rng(0)
x = rng.normal(0, 1, (3, 16, 16)).astype(np.float32)
w = rng.normal(0, 1, (8, 3, 3, 3)).astype(np.float32)
b = rng.normal(0, 1, (8,)).astype(np.float32)

y_naive = conv2d_naive(x, w, b, padding=1)
y_im2col = conv2d_im2col(x, w, b, padding=1)

print(f"max abs diff: {np.max(np.abs(y_naive - y_im2col)):.2e}")
```

`max abs diff` должно быть около `1e-5` — разница обусловлена порядком накопления чисел с плавающей точкой, а не ошибкой.

### Шаг 6: Набор ядер, спроектированных вручную

Пять фильтров, демонстрирующих, что способен выразить один свёрточный слой ещё до какого-либо обучения.

```python
KERNELS = {
    "identity": np.array([[0, 0, 0], [0, 1, 0], [0, 0, 0]], dtype=np.float32),
    "blur_3x3": np.ones((3, 3), dtype=np.float32) / 9.0,
    "sharpen": np.array([[0, -1, 0], [-1, 5, -1], [0, -1, 0]], dtype=np.float32),
    "sobel_x": np.array([[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]], dtype=np.float32),
    "sobel_y": np.array([[-1, -2, -1], [0, 0, 0], [1, 2, 1]], dtype=np.float32),
}

def apply_kernel(img2d, kernel):
    x = img2d[None].astype(np.float32)
    w = kernel[None, None]

```

Применённые к любому изображению в оттенках серого: blur размывает, sharpen усиливает контраст краёв, Sobel-x подсвечивает вертикальные края, Sobel-y подсвечивает горизонтальные края. Это именно те паттерны, которые в итоге выучил *первый* обученный свёрточный слой в AlexNet и VGG — потому что хорошей модели изображений нужны детекторы краёв и пятен независимо от того, какая задача последует дальше.

## Применение

`nn.Conv2d` в PyTorch оборачивает ту же самую операцию с autograd, CUDA-ядрами и оптимизацией cuDNN. Семантика форм идентична.

```python
import torch
import torch.nn as nn

conv = nn.Conv2d(in_channels=3, out_channels=64, kernel_size=3, stride=1, padding=1)
print(conv)
print(f"weight shape: {tuple(conv.weight.shape)}   # (C_out, C_in, K, K)")
print(f"bias shape:   {tuple(conv.bias.shape)}")
print(f"param count:  {sum(p.numel() for p in conv.parameters())}")

x = torch.randn(8, 3, 224, 224)
y = conv(x)
print(f"\ninput  shape: {tuple(x.shape)}")
print(f"output shape: {tuple(y.shape)}")
```

Замените `padding=1` на `padding=0` — и выход уменьшится до 222x222. Замените `stride=1` на `stride=2` — и он уменьшится до 112x112. Та же формула, которую вы запомнили выше.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|----------------|----------------------|
| Convolution (свёртка) | «Скольжение фильтром» | Обучаемое скалярное произведение, применяемое в каждой пространственной позиции с разделяемыми весами; математически это кросс-корреляция, но все называют это свёрткой |
| Kernel / filter (ядро / фильтр) | «Детектор признаков» | Небольшой тензор весов формы (C_in, K, K), скалярное произведение которого с окном входа даёт один выходной пиксель |
| Stride (шаг) | «Насколько далеко вы прыгаете» | Размер шага между последовательными положениями ядра; шаг 2 уменьшает каждое пространственное измерение вдвое |
| Padding (паддинг) | «Нули по краям» | Дополнительные значения, добавляемые вокруг входа, чтобы ядро могло центрироваться на граничных пикселях; `same`-паддинг сохраняет выходной размер равным входному |
| Receptive field (рецептивное поле) | «Сколько видит нейрон» | Участок исходного входа, от которого зависит данная выходная активация; растёт с глубиной и шагом |
| im2col | «Трюк с GEMM» | Переупорядочивание каждого рецептивного окна в столбцы так, что свёртка становится одним большим матричным умножением — ядро любой быстрой реализации свёртки |
| Depthwise conv | «Одно ядро на канал» | Свёртка с `groups == C_in`, вычисляющая каждый выходной канал только из соответствующего входного канала; основа MobileNet и ConvNeXt |
| Translation equivariance (трансляционная эквивариантность) | «Сдвиг на входе — сдвиг на выходе» | Свойство, при котором сдвиг входа на k пикселей сдвигает выход на k пикселей; достигается бесплатно за счёт разделяемых весов |
