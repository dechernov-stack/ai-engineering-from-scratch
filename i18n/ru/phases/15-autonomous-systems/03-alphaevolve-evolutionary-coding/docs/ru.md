# AlphaEvolve — Эволюционные кодирующие агенты

> Соедините передовую модель кодирования с эволюционным циклом и машинно-проверяемым оценщиком. Дайте циклу достаточно времени на работу. Он обнаруживает процедуру умножения комплексных матриц 4x4, использующую 48 скалярных умножений — первое улучшение над алгоритмом Штрассена за 56 лет. Он также находит эвристику планировщика Borg в масштабах Google, которая восстанавливает ~0,7% вычислительных ресурсов кластера в продакшене. Архитектура намеренно скучна. Победы приходят от строгости оценщика.

**Type:** Learn
**Languages:** Python (stdlib, игрушечная реализация эволюционного цикла)
**Prerequisites:** Phase 15 · 01 (постановка задачи в длинном горизонте), Phase 15 · 02 (самообучаемое рассуждение)
**Time:** ~60 минут

## Проблема

Большие языковые модели умеют писать код. Эволюционные алгоритмы умеют искать среди вариантов кода. И то, и другое пробовали по отдельности десятилетиями; и то, и другое упиралось в потолок. Потолок LLM — конфабуляция: модель пишет правдоподобный код, который не делает того, что заявлено. Потолок эволюционных алгоритмов — стоимость поиска: случайные мутации синтаксиса редко дают компилируемые программы, не говоря уже о более качественных.

AlphaEvolve (Novikov et al., DeepMind, arXiv:2506.13131, июнь 2025) объединяет их. LLM предлагает целевые правки к базе данных программ; автоматический оценщик присваивает оценку каждому варианту; высокооцененные варианты становятся родителями для следующих поколений. LLM берёт на себя дорогостоящий этап написания правдоподобного кода; оценщик ловит конфабуляции. Цикл выполняется от часов до недель.

Заявленные результаты: умножение комплексных матриц 4x4 с 48 скалярными умножениями (граница Штрассена 1969 года составляла 49), эвристика планирования Borg в продакшене Google, ускорение ядра FlashAttention на 32,5%, улучшение пропускной способности обучения Gemini.

Архитектура работает потому, что оценщик машинно-проверяем. Там, где это не так, она не работает. Эта асимметрия и есть урок.

## Концепция

### Цикл

1. Начните с исходной программы `P_0`, которая корректна, но неоптимальна.
2. Поддерживайте базу данных вариантов программ, каждый из которых оценён оценщиком.
3. Выберите одного или нескольких родителей из базы данных (в стиле MAP-elites или островной модели).
4. Попросите LLM (Gemini Flash для множества кандидатов, Gemini Pro для сложных случаев) создать модифицированный вариант родителя.
5. Скомпилируйте, запустите и оцените вариант на отложенном оценщике.
6. Вставьте в базу данных, проиндексировав по оценке и вектору признаков.
7. Повторите.

Важны две детали. Во-первых, LLM получает на вход больше, чем просто родительскую программу — обычно несколько лучших вариантов из базы данных, сигнатуру оценщика и краткое описание задачи. Задача модели — предложить целевое изменение, которое может улучшить оценку. Во-вторых, база данных структурирована (сетка MAP-elites, островная модель), так что цикл исследует разнообразие, а не только текущего лидера.

### Почему оценщик не обсуждается

Все победы AlphaEvolve приходят из областей, где оценщик быстр, детерминирован и его сложно обмануть:

- **Алгоритм умножения матриц**: юнит-тест, который перемножает матрицы и проверяет побитовое равенство.
- **Эвристика планирования Borg**: симулятор уровня продакшена, воспроизводящий историческую нагрузку кластера и измеряющий потраченные впустую вычисления.
- **Ядро FlashAttention**: тест на корректность плюс бенчмарк реального времени на реальном оборудовании.
- **Пропускная способность обучения Gemini**: измеряемые GPU-секунды на шаг.

В каждом случае оценщик ловит тот класс ошибок LLM, который иначе бы доминировал: сфабрикованные заявления о корректности, заявления о производительности, исчезающие при проверке на оборудовании, и сбои в граничных случаях. Уберите оценщика — и цикл будет оптимизировать под красивый код.

### Взлом вознаграждения — обратная сторона этого утверждения

Эволюция оптимизирует то, что измеряет оценщик. Если оценщик несовершенен, цикл найдёт это несовершенство. В непроверяемой области цикл оптимизировал бы под поверхностный признак, а не под намеченное поведение. DeepMind прямо отмечает это в статье: успехи AlphaEvolve переносятся только на те области, где строгость оценщика соответствует амбициям поиска.

Конкретные примеры взлома вознаграждения в циклах кодового поиска 2025–2026 годов:

- Цели оптимизации, вознаграждающие «время до завершения», вознаграждали отправку пустых решений.
- Оценки бенчмарков, вознаграждающие «корректность по тестам», вознаграждали запоминание тестов и переобучение под них.
- Прокси-метрика «качества кода» вознаграждала удаление комментариев и переименование переменных без каких-либо семантических изменений.

Решение в AlphaEvolve: использовать отложенный оценщик, который LLM никогда не видела, со входными данными, генерируемыми в момент оценки. Даже в этом случае DeepMind рекомендует тщательную проверку любого предлагаемого развёртывания.

### Почему LLM + поиск превосходят каждый по отдельности

LLM способна создавать компилируемые, семантически правдоподобные модификации. Генетический алгоритм со случайными мутациями на файле Python в 2000 строк почти всегда порождает синтаксические ошибки. LLM также концентрирует поиск в правдоподобных окрестностях (изменить одну функцию, а не случайные байты), что резко сокращает число бесполезных обращений к оценщику.

Оценщик, в свою очередь, ловит конфабуляции LLM. LLM с уверенностью заявит, что функция «асимптотически имеет сложность O(n log n)», хотя на самом деле это O(n^2); бенчмарк реального времени закрывает этот вопрос.

### Место AlphaEvolve в стеке передовых систем

| Система | Генератор | Оценщик | Область | Пример победы |
|---|---|---|---|---|
| AlphaEvolve | Gemini | корректность + бенчмарк | алгоритмы, ядра, планировщики | умножение матриц 4x4 с 48 умножениями |
| FunSearch (DeepMind, 2023) | PaLM / Codey | корректность | комбинаторная математика | нижние границы cap-set |
| AI Scientist v2 (Sakana, L5) | GPT/Claude | критика LLM + эксперимент | исследования ML | статья на воркшопе ICLR |
| Darwin Godel Machine (L4) | каркас агента | SWE-bench / Polyglot | код агентов | 20% → 50% на SWE-bench |

Все четыре — вариации одного и того же рецепта: генератор плюс оценщик, цикл. Разница в том, что именно оценивает оценщик и насколько он строг.

## Используйте это

`code/main.py` реализует минимальный цикл в стиле AlphaEvolve для игрушечной задачи символьной регрессии. «LLM» — это прокси на stdlib, предлагающий небольшие синтаксические мутации программы, вычисляющей целевую функцию. «Оценщик» измеряет среднеквадратичную ошибку на отложенных тестовых точках.

Обратите внимание:

- Как лучшая оценка улучшается от поколения к поколению.
- Как сетка MAP-elites сохраняет живыми разнообразные решения, не позволяя циклу сходиться к локальному минимуму.
- Как удаление отложенного теста (оценщик только на обучающих данных) позволяет циклу эффектно переобучиться.

## Примените на практике

`outputs/skill-evaluator-rigor-audit.md` — это предварительное условие для рассмотрения цикла в стиле AlphaEvolve в новой области: действительно ли ваш оценщик ловит именно те сбои, которые вас волнуют?

## Упражнения

1. Запустите `code/main.py`. Отметьте траекторию лучшей оценки. Отключите отложенный оценщик (флаг `--no-holdout`) и запустите снова. Количественно оцените переобучение.

2. Прочитайте раздел 3 статьи AlphaEvolve о сетке MAP-elites. Спроектируйте дескриптор вектора признаков для новой задачи (например, проходы оптимизации компилятора), который сохранял бы разнообразие поиска.

3. Результат с 48 умножениями для матриц 4x4 улучшил границу Штрассена в 49 умножений спустя 56 лет. Прочитайте Приложение F статьи и объясните тремя предложениями, почему оценщик для этой задачи особенно легко сделать правильным и почему большинство областей на неё не похожи.

4. Предложите одну область, в которой AlphaEvolve потерпит неудачу. Укажите точно, где и почему ломается оценщик.

5. Для известной вам области напишите сигнатуру оценщика, которую вы бы использовали. Включите (a) условия корректности, (b) метрику производительности, (c) правило генерации отложенных входных данных, (d) хотя бы одну проверку против взлома вознаграждения.

## Ключевые термины

| Термин | Что говорят | Что это на самом деле означает |
|---|---|---|
| AlphaEvolve | «Эволюционный кодирующий агент DeepMind» | Gemini + база данных программ + машинно-проверяемый оценщик |
| MAP-elites | «Архив, сохраняющий разнообразие» | Сетка, индексируемая по векторам признаков; в каждой ячейке хранится лучший вариант с данным дескриптором |
| Островная модель | «Параллельные субпопуляции эволюции» | Независимые популяции, периодически мигрирующие друг в друга; предотвращает преждевременную сходимость |
| Машинно-проверяемый оценщик | «Детерминированный оракул» | Юнит-тест, симулятор или бенчмарк, который LLM не может подделать — необходимое условие для этого цикла |
| Взлом вознаграждения | «Оптимизация меры, а не цели» | Цикл находит способ максимизировать оценку, не выполняя предполагаемую задачу |
| Исходная программа | «Отправная точка» | Изначально корректная, но неоптимальная программа, из которой эволюционирует цикл |
| Отложенный оценщик | «Данные для оценки, которых LLM никогда не видела» | Входные данные, генерируемые в момент оценки, чтобы предотвратить запоминание |
