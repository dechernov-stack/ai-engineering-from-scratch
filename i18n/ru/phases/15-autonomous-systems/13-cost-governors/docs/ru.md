# Бюджеты действий, лимиты итераций и регуляторы затрат

> Месячные расходы на LLM у агента среднего интернет-магазина выросли с $1,200 to $4,800 после того, как команда включила навык «отслеживание заказов». Это не баг в ценообразовании. Это агент, который нашёл новый цикл и продолжал тратить внутри него. Microsoft Agent Governance Toolkit (2 апреля 2026 года) кодифицирует защиту от подобных случаев: лимит `max_tokens` на запрос, бюджеты токенов и долларов на задачу, лимиты в день/месяц, лимиты итераций, многоуровневая маршрутизация моделей, кэширование промптов, окна контекста, контрольные точки HITL на дорогих действиях, аварийные выключатели при превышении бюджета. Anthropic Claude Code Agent SDK поставляет те же примитивы под другими названиями. Лимиты финансовой скорости — например, отключение доступа при расходах более $50 за 10 минут — отлавливают циклы быстрее, чем месячные ограничения.

**Type:** Learn
**Languages:** Python (стандартная библиотека, многослойный симулятор регулятора затрат)
**Prerequisites:** Phase 15 · 10 (Режимы разрешений), Phase 15 · 12 (Устойчивое выполнение)
**Time:** ~60 минут

## Проблема

Автономные агенты тратят реальные деньги на каждом шаге. Плохой ответ чат-бота — это плохая реплика; плохой цикл агента — это счёт. Задокументированный в индустрии термин для этого типа сбоя — «Denial of Wallet» («отказ кошелька») — агент продолжает рассуждать, продолжает вызывать инструменты, продолжает накручивать счёт, и ничто его не останавливает, потому что ничто не было спроектировано для этого.

Решение — это не одно число. Это стек лимитов на разных временных масштабах и уровнях детализации: на запрос, на задачу, на час, на день, на месяц. Хорошо спроектированный стек отлавливает неконтролируемый цикл в течение минут, медленную утечку — в течение часов, а неудачный релиз — в течение дня. Этот же стек вообще сохраняет бюджет, когда агент работает долго и автономно.

Это инженерный урок: математика тривиальна, а дисциплина — вот где команды терпят неудачу. Список лимитов ниже полностью взят либо из Microsoft Agent Governance Toolkit, либо из документации Anthropic Claude Code Agent SDK.

## Концепция

### Стек регуляторов затрат

1. **`max_tokens` на запрос.** Просто. Предотвращает генерацию неограниченного завершения любым отдельным вызовом.
2. **Бюджет токенов на задачу.** В рамках всего запуска не превышать N токенов. Жёсткая остановка при достижении лимита.
3. **Долларовый бюджет на задачу.** То же, что и токены, но в валюте. `max_budget_usd` в Claude Code.
4. **Лимит вызовов инструментов.** Не более N вызовов `WebFetch`, N вызовов `shell_exec` и т. д.
5. **Лимит итераций (`max_turns`).** Общее число итераций цикла агента; предотвращает бесконечные циклы рассуждений.
6. **Лимит в минуту / час / день / месяц.** Скользящие окна. Отлавливает утечки на разных временных масштабах.
7. **Лимит финансовой скорости.** Например, «если расходы превышают $50 за 10 минут, отключить доступ». Отлавливает сжигание бюджета циклами раньше, чем сработают месячные лимиты.
8. **Многоуровневая маршрутизация моделей.** По умолчанию используется меньшая модель; переключение на более крупную происходит только когда классификатор определяет, что задача этого требует.
9. **Кэширование промптов.** Системный промпт и стабильный контекст хранятся в кэше провайдера; стоимость токенов при повторной отправке близка к нулю.
10. **Окна контекста.** Сжатие / суммаризация для удержания активного контекста ниже порога; прямое снижение стоимости токенов.
11. **Контрольные точки HITL на дорогих действиях.** Перед действием, заведомо дорогим (длительный вызов инструмента, большая загрузка, дорогостоящее обновление модели), требуется касание человека.
12. **Аварийный выключатель при превышении бюджета.** Сессия прерывается при срабатывании любого лимита. Превышение фиксируется; требуется отдельный путь для повторного включения.

### Почему стек, а не один лимит

Единый месячный лимит отлавливает неконтролируемого агента только после того, как кошелёк уже опустел. Единый лимит на запрос ничего не отлавливает на уровне сессии. Разные типы сбоев требуют разных временных масштабов:

- **Неконтролируемый цикл** (агент застрял в 5-секундном повторе): отлавливается лимитом скорости.
- **Медленная утечка** (агент выполняет примерно в 2 раза больше ожидаемой работы на задачу): отлавливается дневным лимитом.
- **Неудачный релиз** (новая версия использует в 5 раз больше токенов): отлавливается недельным / месячным лимитом.
- **Легитимный всплеск** (реальный спрос, а не баг): отлавливается почасовым / дневным лимитом с понятным логом.

### Поверхность бюджета в фреймворке

Claude Code Agent SDK предоставляет (публичная документация):

- `max_turns` — лимит итераций.
- `max_budget_usd` — долларовый лимит; сессия прерывается при превышении.
- `allowed_tools` / `disallowed_tools` — белый и чёрный списки инструментов.
- Точки перехвата перед использованием инструмента для собственного учёта затрат.

Комбинируйте с лестницей режимов разрешений (Урок 10). Сессия `autoMode` без `max_budget_usd` — это неуправляемая автономия. Anthropic прямо формулирует, что Auto Mode требует средств контроля бюджета; классификатор ортогонален стоимости.

### EU AI Act, OWASP Agentic Top 10

Microsoft Agent Governance Toolkit охватывает OWASP Agentic Top 10 и требования статьи 14 EU AI Act (человеческий надзор). Для продакшена в ЕС логирование и обеспечение лимитов не являются опциональными.

### Задокументированный случай с $1,200 → $4,800

Реальный случай из документации Microsoft: агент интернет-магазина, чьи месячные расходы утроились после добавления нового инструмента. Инструмент позволял агенту опрашивать статус заказа в каждой сессии. Не было обнаружения циклов. Не было лимита на инструмент. Не было оповещения о росте от недели к неделе. Решением стал лимит на инструмент плюс оповещение о дневном росте. Это шаблон: каждая новая поверхность инструмента — это потенциальный новый цикл; каждому новому инструменту нужен собственный лимит и собственное оповещение.

## Примените это

`code/main.py` симулирует запуск агента со стеком регуляторов затрат и без него. Симулируемый агент после нескольких ходов сваливается в цикл опроса; многоуровневый стек отлавливает это в пределах окна скорости, в то время как единый месячный лимит не сработал бы ещё несколько дней.

## Внедрите это

`outputs/skill-agent-budget-audit.md` проверяет стек регуляторов затрат предлагаемого развёртывания агента и выявляет отсутствующие уровни.

## Упражнения

1. Запустите `code/main.py`. Убедитесь, что лимит скорости срабатывает раньше лимита итераций на траектории циклического опроса. Теперь отключите лимит скорости и измерьте, сколько «потратит» агент, прежде чем сработает лимит итераций.

2. Спроектируйте набор лимитов на инструменты для браузерного агента (Урок 11). Какому инструменту нужен самый жёсткий лимит? Какой инструмент может работать без ограничений без риска?

3. Прочитайте документацию Microsoft Agent Governance Toolkit. Перечислите все типы лимитов, названные в инструментарии. Сопоставьте каждый с одним из типов сбоя (неконтролируемый цикл, медленная утечка, неудачный релиз, всплеск).

4. Оцените стоимость ночного запуска без присмотра для реалистичной задачи (например, «разобрать 50 issue в репозитории»). Установите `max_budget_usd` на уровне 2x от вашей точечной оценки. Обоснуйте этот коэффициент 2x.

5. `max_budget_usd` в Claude Code срабатывает на совокупной стоимости сессии. Спроектируйте дополнительный лимит скорости, который вы бы применяли внешне. Что запускает отключение и как выглядит повторное включение?

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|---|---|---|
| Denial of Wallet | «Неконтролируемый счёт» | Цикл агента, генерирующий расходы без лимита для остановки |
| max_tokens | «Лимит на запрос» | Потолок размера одного завершения |
| max_turns | «Лимит итераций» | Потолок числа итераций цикла агента в сессии |
| max_budget_usd | «Долларовый аварийный выключатель» | Лимит стоимости сессии; прерывает при превышении |
| Velocity limit | «Лимит скорости» | Ограничение расходов за короткое окно (например, $50 / 10 мин) |
| Tiered routing | «Сначала маленькая модель» | По умолчанию дешёвая модель; переключение только по решению классификатора |
| Prompt caching | «Кэшированный системный промпт» | Кэш на стороне провайдера снижает стоимость повторной отправки токенов почти до нуля |
| HITL checkpoint | «Контрольная точка одобрения человеком» | Требуется касание человека перед дорогим действием |
