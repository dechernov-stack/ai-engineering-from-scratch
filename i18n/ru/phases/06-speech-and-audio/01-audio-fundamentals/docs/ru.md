# Основы работы со звуком — волновые формы, дискретизация, преобразование Фурье

## Проблема

Микрофон выдаёт сигнал «давление-время». Ваша нейросеть потребляет тензоры. Между ними лежит набор соглашений, нарушение которых порождает незаметные ошибки: модель вроде бы обучается нормально, но WER удваивается, или TTS выдаёт шипение, или система клонирования голоса запоминает микрофон вместо говорящего.

Любая ошибка в речевых системах сводится к одному из трёх вопросов:

1. С какой частотой дискретизации были записаны данные, и чего ожидает модель?
2. Присутствует ли в сигнале элайзинг (наложение спектров)?
3. Вы работаете с сырыми отсчётами или с частотным представлением?

Разберитесь с этим правильно — и остальная часть Фазы 6 будет вам по силам. Ошибётесь — и даже Whisper-Large-v4 выдаст мусор.

## Концепция

![Waveform, sampling, DFT, and frequency bins visualized](../assets/audio-fundamentals.svg)

**Волновая форма.** Одномерный массив чисел с плавающей точкой в `[-1.0, 1.0]`. Индексируется номером отсчёта. Чтобы перевести в секунды, разделите на частоту дискретизации: `t = n / sr`. 10-секундный клип при 16 кГц — это массив из 160 000 чисел с плавающей точкой.

**Частота дискретизации (sr).** Сколько отсчётов в секунду. Распространённые значения в 2026 году:

| Частота | Применение |
|------|-----|
| 8 кГц | Телефония, устаревший VOIP. Частота Найквиста 4 кГц «убивает» согласные. Не использовать для ASR. |
| 16 кГц | Стандарт для ASR. Whisper, Parakeet, SeamlessM4T v2 — все работают с 16 кГц. |
| 22,05 кГц | Обучение вокодеров TTS для более старых моделей. |
| 24 кГц | Современный TTS (Kokoro, F5-TTS, xTTS v2). |
| 44,1 кГц | CD-аудио, музыка. |
| 48 кГц | Кино, профессиональное аудио, высококачественный TTS (VALL-E 2, NaturalSpeech 3). |

**Теорема Найквиста-Шеннона.** Частота дискретизации `sr` позволяет однозначно представить частоты вплоть до `sr/2`. Граница `sr/2` — это *частота Найквиста*. Энергия выше частоты Найквиста подвергается *элайзингу* — сворачивается вниз, в более низкие частоты, — и искажает сигнал. Перед понижением частоты дискретизации всегда применяйте фильтр нижних частот.

**Разрядность.** 16-битный PCM (знаковый int16, диапазон ±32 767) — универсальный формат обмена. 24 бита — для музыки, 32-битное число с плавающей точкой — для внутренней цифровой обработки сигналов. Библиотеки вроде `soundfile` читают int16, но отдают массивы float32 в `[-1, 1]`.

**Преобразование Фурье.** Любой конечный сигнал представляется суммой синусоид разных частот. Дискретное преобразование Фурье (ДПФ) вычисляет для `N` отсчётов `N` комплексных коэффициентов — по одному на частотный бин. `bin k` соответствует частоте `k · sr / N` Гц. Модуль — это амплитуда на данной частоте, угол — фаза.

**FFT.** Быстрое преобразование Фурье: алгоритм `O(N log N)` для вычисления ДПФ, когда `N` является степенью двойки. Любая аудио-библиотека под капотом использует FFT. FFT на 1024 отсчёта при 16 кГц даёт 512 полезных частотных бинов, охватывающих диапазон 0–8 кГц с разрешением 15,6 Гц.

**Фреймирование + окно.** Мы не применяем FFT ко всему клипу целиком. Мы нарезаем его на перекрывающиеся *фреймы* (обычно по 25 мс с шагом 10 мс), умножаем каждый фрейм на оконную функцию (Hann, Hamming), чтобы устранить разрывы на границах, затем применяем FFT к каждому фрейму. Это кратковременное преобразование Фурье (STFT). Урок 02 продолжает с этого места.

## Реализация

### Шаг 1: прочитать клип и построить график волновой формы

`code/main.py` использует только стандартный модуль `wave`, чтобы демонстрация не требовала внешних зависимостей. В продакшене вы будете использовать `soundfile` или `torchaudio.load` (оба возвращают кортежи `(waveform, sr)`):

```python
import soundfile as sf
waveform, sr = sf.read("clip.wav", dtype="float32")  # shape (T,), sr=int
```

### Шаг 2: синтезировать синусоиду с нуля

```python
import math

def sine(freq_hz, sr, seconds, amp=0.5):
    n = int(sr * seconds)
    return [amp * math.sin(2 * math.pi * freq_hz * i / sr) for i in range(n)]
```

Синусоида 440 Гц (концертное ля) при 16 кГц в течение 1 секунды — это 16 000 чисел с плавающей точкой. Записать с помощью `wave.open(..., "wb")`, используя 16-битное PCM-кодирование.

### Шаг 3: вычислить ДПФ вручную

```python
def dft(x):
    N = len(x)
    out = []
    for k in range(N):
        re = sum(x[n] * math.cos(-2 * math.pi * k * n / N) for n in range(N))
        im = sum(x[n] * math.sin(-2 * math.pi * k * n / N) for n in range(N))
        out.append((re, im))
    return out
```

`O(N²)` — годится для `N=256`, чтобы убедиться в корректности, но бесполезно для реального аудио. В реальном коде вызывается `numpy.fft.rfft` или `torch.fft.rfft`.

### Шаг 4: найти доминирующую частоту

Индекс пика модуля `k_star` соответствует частоте `k_star * sr / N`. Запустив это на синусоиде 440 Гц, вы должны получить пик в бине `440 * N / sr`.

### Шаг 5: продемонстрировать элайзинг

Дискретизируйте синусоиду 7 кГц с частотой 10 кГц (Найквист = 5 кГц). Тон 7 кГц находится выше Найквиста и сворачивается в `10 − 7 = 3 kHz`. Пик FFT появляется на 3 кГц. Это классическая демонстрация элайзинга и причина, по которой в каждом ЦАП/АЦП установлен «кирпичный» фильтр нижних частот.

## Применение

Стек, который вы реально будете использовать в 2026 году:

| Задача | Библиотека | Почему |
|------|---------|-----|
| Чтение/запись WAV/FLAC/OGG | `soundfile` (обёртка libsndfile) | Самая быстрая, стабильная, возвращает float32. |
| Передискретизация | `torchaudio.transforms.Resample` или `librosa.resample` | Корректная антиалиасинговая фильтрация встроена. |
| STFT / Mel | `torchaudio` или `librosa` | Дружелюбна к GPU; экосистема PyTorch. |
| Потоковая передача в реальном времени | `sounddevice` или `pyaudio` | Кроссплатформенные привязки к PortAudio. |
| Проверка файла | `ffprobe` или `soxi` | CLI, быстро, показывает sr/каналы/кодек. |

Правило принятия решений: **сначала приведите в соответствие частоту дискретизации, а потом всё остальное**. Whisper ожидает 16 кГц, моно, float32. Подайте ему 44,1 кГц стерео — и вы получите мусор, который будет выглядеть как ошибка модели.

## Упражнения

1. **Лёгкое.** Синтезируйте 1-секундную смесь 220 Гц + 440 Гц + 880 Гц при 16 кГц. Выполните ДПФ. Убедитесь, что получены три пика в ожидаемых бинах.
2. **Среднее.** Запишите 3-секундный WAV-файл своего голоса при 48 кГц. Понизьте частоту до 16 кГц с помощью `torchaudio.transforms.Resample` (с антиалиасингом), затем до 16 кГц с помощью наивной децимации (каждый третий отсчёт). Выполните FFT для обоих. Где проявляется элайзинг?

## Ключевые термины

| Термин | Что обычно говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Частота дискретизации | Сколько отсчётов в секунду | Частота в Гц, с которой АЦП измеряет сигнал. |
| Найквист | Максимальная частота, которую можно представить | `sr/2`; энергия выше неё сворачивается обратно вниз. |
| Разрядность | Разрешение каждого отсчёта | `int16` = 65 536 уровней; `float32` = 24-битная точность в `[-1, 1]`. |
| ДПФ | Преобразование Фурье для последовательностей | `N` отсчётов → `N` комплексных частотных коэффициентов. |
| FFT | Быстрое ДПФ | Алгоритм `O(N log N)`, требующий `N` = степень двойки. |
| Бин | Частотный столбец | `k · sr / N` Гц; разрешение = `sr / N`. |
| STFT | Спектрограмма изнутри | Фреймированное и оконное FFT во времени. |
| Элайзинг | Странные частотные призраки | Энергия выше Найквиста, зеркально отражающаяся вниз в более низкие бины. |
