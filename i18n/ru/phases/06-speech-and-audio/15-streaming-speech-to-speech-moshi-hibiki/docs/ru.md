# Потоковый Speech-to-Speech — Moshi, Hibiki и полнодуплексный диалог

> 2024-2026 годы заново определили голосовой ИИ. Moshi поставляет единую модель, которая слушает и говорит одновременно с задержкой 200 мс. Hibiki выполняет перевод речи в речь кусок за куском. Обе модели отказываются от пайплайна ASR → LLM → TTS в пользу единой полнодуплексной архитектуры поверх токенов кодека Mimi. Это новый эталонный дизайн.

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 6 · 13 (Neural Audio Codecs), Phase 6 · 11 (Real-Time Audio), Phase 7 · 05 (Full Transformer)
**Time:** ~75 минут

## Проблема

Каждый голосовой агент, построенный по материалам уроков 11 + 12, имеет фундаментальный предел задержки около 300-500 мс: срабатывает VAD, обрабатывает STT, рассуждает LLM, генерирует TTS. У каждого этапа своя минимальная задержка. Можно настраивать и распараллеливать, но форма пайплайна ограничивает вас сверху.

Moshi (Kyutai, 2024-2026) задаёт другой вопрос: а что, если пайплайна нет вообще? Что, если одна модель принимает аудио на входе и напрямую, непрерывно выдаёт аудио на выходе, а текст выступает промежуточным «внутренним монологом», а не обязательным этапом?

Ответ — **полнодуплексный speech-to-speech**. Теоретическая задержка 160 мс (80 мс кадр Mimi + 80 мс акустическая задержка). Практическая задержка 200 мс на одном GPU L4. Это вдвое меньше, чем достигает лучший в своём классе конвейерный голосовой агент.

## Концепция

![Moshi architecture: two parallel Mimi streams + inner-monologue text](../assets/moshi-hibiki.svg)

### Архитектура Moshi

**Входы.** Два потока кодека Mimi, оба на частоте 12.5 Гц × 8 кодбуков:

- Поток 1: аудио пользователя (закодированное Mimi, поступает постоянно)
- Поток 2: собственное аудио Moshi (сгенерированное Moshi)

**Трансформер.** Temporal Transformer с 7 млрд параметров обрабатывает оба потока и текстовый поток «внутреннего монолога» Moshi. На каждом шаге длительностью 80 мс он:

1. Потребляет последние токены Mimi пользователя (8 кодбуков).
2. Потребляет самые свежие токены Mimi Moshi (8 кодбуков, по мере их генерации).
3. Генерирует следующий текстовый токен Moshi (внутренний монолог).
4. Генерирует следующие токены Mimi Moshi (8 кодбуков через небольшой Depth Transformer).

Все три потока — аудио пользователя, аудио Moshi, текст Moshi — работают параллельно. Moshi может слышать пользователя во время собственной речи; может прервать сама себя, когда прерывает пользователь; может вставлять бэк-channel-реплики («угу») без прерывания основной реплики.

**Depth transformer.** Внутри кадра 8 кодбуков предсказываются не параллельно — между ними есть зависимости. Небольшой 2-слойный «depth transformer» предсказывает их последовательно в пределах 80 мс. Это стандартная факторизация для авторегрессионных кодек-LM (используется также в VALL-E, VibeVoice).

### Почему помогает текстовый «внутренний монолог»

Без явного текста модели приходится неявно моделировать язык в акустическом потоке. Ключевая идея Moshi: заставить модель одновременно выдавать текстовые токены вместе с аудио. Текстовый поток по сути является транскриптом того, что говорит Moshi. Это улучшает семантическую связность, упрощает замену языковой модели-головы и даёт транскрипты «бесплатно».

### Hibiki: потоковый перевод речи в речь

Та же архитектура, обученная на парах переводов. Исходное аудио на входе, аудио на целевом языке на выходе — непрерывно. Hibiki-Zero (февраль 2026) устраняет необходимость в данных для обучения с выравниванием на уровне слов — используются данные на уровне предложений + RL-обучение GRPO для оптимизации задержки.

Изначально поддерживаются четыре языковые пары; адаптация под новый язык требует ≈1000 часов данных.

### Более широкий стек Kyutai (2026)

- **Moshi** — полнодуплексный диалог (сначала французский, английский хорошо поддерживается)
- **Hibiki / Hibiki-Zero** — одновременный перевод речи
- **Kyutai STT** — потоковый ASR (500 мс или 2.5 с упреждения)
- **Kyutai Pocket TTS** — TTS на 100 млн параметров, работает на CPU (январь 2026)
- **Unmute** — полный пайплайн, объединяющий всё это на публичных серверах

Пропускная способность на GPU L40S: 64 одновременные сессии со скоростью 3× реального времени.

### Sesame CSM — родственница

Sesame CSM (2025) использует похожую идею — основу Llama-3 с головой кодека Mimi. Но CSM однонаправленна (принимает контекст + текст, производит речь), а не полнодуплексна. Это лучший по «голосовому присутствию» TTS на рынке; но не то же самое, что полнодуплексная способность Moshi.

## Реализация

### Шаг 1: интерфейс

Moshi предоставляет WebSocket-сервер, принимающий 80-мс чанки аудио, закодированного Mimi, и возвращающий 80-мс чанки аудио, закодированного Mimi. В обе стороны. Постоянно.

```python
import asyncio
import websockets
from moshi.client_utils import encode_audio_mimi, decode_audio_mimi

async def moshi_chat():
    async with websockets.connect("ws://localhost:8998/api/chat") as ws:
        mic_task = asyncio.create_task(stream_mic_to(ws))
        spk_task = asyncio.create_task(stream_from_to_speaker(ws))
        await asyncio.gather(mic_task, spk_task)
```

### Шаг 2: полнодуплексный цикл

```python
async def stream_mic_to(ws):
    async for chunk_80ms in mic_stream_at_12_5_hz():
        mimi_tokens = encode_audio_mimi(chunk_80ms)
        await ws.send(serialize(mimi_tokens))

async def stream_from_to_speaker(ws):
    async for msg in ws:
        mimi_tokens, text_token = deserialize(msg)
        audio = decode_audio_mimi(mimi_tokens)
        await play(audio)
```

Оба направления работают одновременно. Стандартным транспортом служит Python asyncio или Rust futures.

### Шаг 3: обучающая цель (концептуально)

Для каждого 80-мс кадра `t`:

- Вход: `user_mimi[0..t]`, `moshi_mimi[0..t-1]`, `moshi_text[0..t-1]`
- Предсказание: `moshi_text[t]`, затем `moshi_mimi[t, codebook_0..7]`

Текст предсказывается раньше аудио (внутренний монолог); аудио предсказывается последовательно по кодбукам внутри depth transformer.

### Шаг 4: где Moshi выигрывает, а где нет

Moshi выигрывает:

- Сквозная задержка менее 250 мс на недорогом оборудовании.
- Естественные бэк-channel-реплики и прерывания.
- Отсутствие связующего кода пайплайна.

Moshi не выигрывает:

- Вызов инструментов (не обучена этому; нужен отдельный путь через LLM).
- Длинные рассуждения (Moshi — диалоговая модель на ~8 млрд параметров, а не Claude/GPT-4).
- Фактическая точность по узкоспециализированным темам.
- Большинство продакшн-сценариев для предприятий (в 2026 году всё ещё используются пайплайны).

## Подводные камни

- **Ограниченный вызов инструментов.** Moshi — диалоговая модель, а не агентный фреймворк. Комбинируйте с пайплайном для инструментов.
- **Условие на конкретный голос.** Moshi использует одну обученную персону; клонирование — отдельный прогон обучения.
- **Охват языков.** Французский + английский отлично поддерживаются, остальные — ограниченно. Hibiki-Zero помогает, но обучающие данные всё равно нужны.
- **Стоимость ресурсов.** Полноценная сессия Moshi занимает слот GPU; это не дешёвый паттерн развёртывания с разделяемыми арендаторами.

## Упражнения

1. **Лёгкое.** Запустите `code/main.py`. Он символически имитирует архитектуру с двумя потоками + внутренним монологом.
2. **Среднее.** Загрузите Moshi с HuggingFace, запустите сервер, протестируйте один разговор. Измерьте задержку по настенным часам от конца речи пользователя до начала ответа Moshi.
3. **Сложное.** Возьмите вашего конвейерного агента из урока 12 и сравните P50-задержку с Moshi на 20 сопоставленных тестовых репликах. Опишите, когда пайплайн всё же архитектурно выигрывает.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Полный дуплекс (Full-duplex) | Слышать и говорить одновременно | Два аудиопотока активны одновременно в одной модели. |
| Внутренний монолог (Inner monologue) | Текстовый поток модели | Moshi выдаёт текстовые токены параллельно с аудио-выходом. |
| Depth transformer | Предсказатель межкодбуковых зависимостей | Небольшой трансформер, предсказывающий 8 кодбуков в пределах одного 80-мс кадра. |
| Mimi | Кодек Kyutai | 12.5 Гц × 8 кодбуков; семантический+акустический; основа Moshi. |
| Потоковый S2S (Streaming S2S) | Аудио → аудио в реальном времени | Перевод/диалог кусок за куском, без этапов пайплайна. |
| Бэк-channeling | Реакции вроде «угу» | Moshi может выдавать небольшие подтверждения, не прерывая своей очереди. |
