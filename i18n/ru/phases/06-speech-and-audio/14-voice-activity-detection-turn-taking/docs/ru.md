# Определение голосовой активности и очерёдности реплик — Silero, Cobra и трюк с flush

> Любой голосовой агент живёт или умирает за счёт двух решений: говорит ли пользователь сейчас, и закончил ли он. VAD отвечает на первый вопрос. Определение конца реплики (VAD + пауза-задержка + семантическая модель окончания) отвечает на второй. Ошибитесь в любом из них — и ваш ассистент либо перебивает пользователей, либо никогда не замолкает.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 6 · 11 (Real-Time Audio), Phase 6 · 12 (Voice Assistant)
**Time:** ~45 минут

## Проблема

Три отдельных решения, которые голосовой агент принимает на каждом 20-мс чанке:

1. **Является ли этот фрейм речью?** — VAD. Бинарно, покадрово.
2. **Начал ли пользователь новую реплику?** — обнаружение начала.
3. **Закончил ли пользователь?** — определение конца (конец реплики).

Наивный ответ (порог по энергии) не работает при любом шуме — трафик, клавиатура, гул толпы. Ответ 2026 года: Silero VAD (открытый, на основе глубокого обучения) + модель определения конца реплики (семантическое определение окончания) + пауза-задержка, откалиброванная по VAD.

## Концепция

![VAD cascade: energy → Silero → turn-detector → flush trick](../assets/vad-turn-taking.svg)

### Трёхуровневый каскад VAD

**Уровень 1: энергетический фильтр.** Самый дешёвый. Порог RMS на уровне -40 dBFS. Отфильтровывает явную тишину, но срабатывает на любой шум выше порога.

**Уровень 2: Silero VAD** (2020-2026, MIT). 1 млн параметров. Обучена на 6000+ языках. Работает ~1 мс на 30-мс чанк на одном потоке CPU. 87,7% TPR при 5% FPR. Вариант по умолчанию с открытым исходным кодом.

**Уровень 3: семантический детектор конца реплики.** Модель определения конца реплики от LiveKit (2024-2026) или собственный небольшой классификатор. Отличает «пауза в середине предложения» от «закончил говорить». Использует лингвистический контекст (интонация + последние слова), а не только тишину.

### Ключевые параметры и их значения по умолчанию

- **Порог.** Silero выдаёт вероятность; речь классифицируется при &gt; 0.5 (по умолчанию) или &gt; 0.3 (чувствительный режим). Более низкий порог = меньше обрезаний первых слов, больше ложных срабатываний.
- **Минимальная длительность речи.** Отклонять речь короче 250 мс — обычно это кашель или шум стула.
- **Пауза-задержка (определение конца).** После того как VAD возвращается к 0, подождать 500-800 мс перед объявлением конца реплики. Слишком коротко → перебивает пользователя. Слишком долго → ощущается вялым.
- **Буфер предзаписи (pre-roll).** Хранить 300-500 мс аудио до срабатывания VAD. Предотвращает обрезание «привет».

### Трюк с flush (Kyutai 2025)

Потоковые STT-модели имеют задержку опережающего просмотра (500 мс для Kyutai STT-1B, 2.5 с для STT-2.6B). Обычно вам пришлось бы ждать столько же после окончания речи для получения транскрипта. Трюк с flush: когда VAD фиксирует конец речи, **отправить сигнал flush в STT**, который форсирует немедленный вывод. STT обрабатывает со скоростью ~4× от реального времени, поэтому 500-мс буфер обрабатывается за ~125 мс.

От начала до конца: 125 мс VAD + flush STT = разговорная задержка.

### Сравнение VAD 2026 года

| VAD | TPR @ 5% FPR | Задержка | Лицензия |
|-----|--------------|---------|---------|
| WebRTC VAD (Google, 2013) | 50.0% | 30 мс | BSD |
| Silero VAD (2020-2026) | 87.7% | ~1 мс | MIT |

## Собираем

### Шаг 1: энергетический фильтр

```python
def energy_vad(chunk, threshold_dbfs=-40.0):
    rms = (sum(x * x for x in chunk) / len(chunk)) ** 0.5
    dbfs = 20.0 * math.log10(max(rms, 1e-10))
    return dbfs > threshold_dbfs
```

### Шаг 2: Silero VAD на Python

```python
from silero_vad import load_silero_vad, get_speech_timestamps

vad = load_silero_vad()
audio = torch.tensor(waveform_16k, dtype=torch.float32)
segments = get_speech_timestamps(
    audio, vad, sampling_rate=16000,
    threshold=0.5,
    min_speech_duration_ms=250,
    min_silence_duration_ms=500,
    speech_pad_ms=300,
)
for s in segments:
    print(f"{s['start']/16000:.2f}s - {s['end']/16000:.2f}s")
```

### Шаг 3: конечный автомат для конца реплики

```python
class TurnDetector:
    def __init__(self, silence_hangover_ms=500, min_speech_ms=250):
        self.state = "idle"
        self.speech_ms = 0
        self.silence_ms = 0
        self.silence_hangover_ms = silence_hangover_ms
        self.min_speech_ms = min_speech_ms

    def update(self, is_speech, chunk_ms=20):
        if is_speech:
            self.speech_ms += chunk_ms
            self.silence_ms = 0
            if self.state == "idle" and self.speech_ms >= self.min_speech_ms:
                self.state = "speaking"
                return "START"
        else:
            self.silence_ms += chunk_ms
            if self.state == "speaking" and self.silence_ms >= self.silence_hangover_ms:
                self.state = "idle"
                self.speech_ms = 0
                return "END"
        return None
```

### Шаг 4: скелет трюка с flush

```python
def flush_on_end(stt_client, audio_buffer):
    stt_client.send_audio(audio_buffer)
    stt_client.send_flush()
    return stt_client.recv_transcript(timeout_ms=150)
```

Для работы этого подхода STT (Kyutai, Deepgram, AssemblyAI) должна поддерживать flush. Потоковый Whisper этого не умеет — он блочный и всегда ждёт чанки.

## Применяем

| Ситуация | Выбор VAD |
|-----------|-----------|
| Открытый, быстрый, общего назначения | Silero VAD |
| Коммерческий колл-центр | Cobra VAD |
| На устройстве (телефон) | Silero VAD ONNX |
| Исследования / диаризация | pyannote segmentation |
| Резервный вариант без зависимостей | WebRTC VAD (устаревший) |
| Нужно качественное определение конца реплики | Silero + слой LiveKit turn-detector |

Эмпирическое правило: никогда не поставляйте энергетический VAD как единственное решение, если у вас действительно нет другого варианта.

## Подводные камни

- **Фиксированный порог.** Работает в тишине, не работает в шуме. Либо калибруйте на устройстве, либо переключайтесь на Silero.
- **Слишком короткая пауза-задержка.** Агент перебивает в середине предложения. 500-800 мс — оптимальная зона для разговорной речи.
- **Слишком долгая задержка.** Ощущается вялым. Проведите A/B-тестирование с целевыми пользователями.
- **Отсутствие буфера предзаписи.** Первые 200-300 мс аудио пользователя теряются. Всегда храните скользящий буфер предзаписи.
- **Игнорирование семантического определения окончания.** «Хм, дайте подумать...» содержит длинные паузы. Пользователи ненавидят, когда их перебивают на середине мысли. Используйте turn-detector от LiveKit или аналогичный.

## Публикуем

Сохраните как `outputs/skill-vad-tuner.md`. Выберите модель VAD, порог, задержку, предзапись и стратегию определения конца реплики для рабочей нагрузки.

## Упражнения

1. **Лёгкое.** Запустите `code/main.py`. Он симулирует последовательность речь + тишина + речь + кашель и тестирует три уровня VAD.
2. **Среднее.** Установите `silero-vad`, обработайте 5-минутную запись, настройте порог, чтобы минимизировать как обрезания первых слов, так и ложные срабатывания. Отчитайтесь о точности/полноте.
3. **Сложное.** Постройте мини-детектор конца реплики: Silero VAD + 3-слойный MLP на эмбеддингах последних 10 слов (используйте sentence-transformers). Обучите на вручную размеченном датасете концов реплик. Превзойдите только-Silero на 10% по F1.

## Ключевые термины

| Термин | Как говорят обычно | Что это на самом деле означает |
|------|-----------------|-----------------------|
| VAD | Детектор голоса | Бинарно покадрово: является ли это речью? |
| Turn detection | Определение конца | VAD + пауза-задержка + семантическое окончание. |
| Silence hangover | Ожидание после речи | Время ожидания перед объявлением конца реплики; 500-800 мс. |
| Pre-roll | Буфер перед речью | Хранить 300-500 мс аудио до срабатывания VAD. |
| Flush trick | Трюк Kyutai | VAD → flush-STT → 125 мс вместо задержки в 500 мс. |
| Semantic endpoint | «Они хотели остановиться?» | ML-классификатор, анализирующий слова, а не только тишину. |
| TPR @ FPR 5% | Точка ROC | Стандартный бенчмарк VAD; 87,7% для Silero, 50% для WebRTC. |
