# EAGLE-3: спекулятивное декодирование в продакшене

> Спекулятивное декодирование сочетает быструю черновую (draft) модель с целевой (target) моделью. Черновая модель предлагает K токенов; целевая проверяет их за один проход вперёд; принятые токены достаются «бесплатно». В 2026 году EAGLE-3 — это промышленный вариант: он обучает черновую голову на скрытых состояниях целевой модели, а не на сырых токенах, что поднимает долю принятых токенов alpha в диапазон 0.6-0.8 на обычном чате. Правильный вопрос — не «насколько быстра черновая модель», а «каков alpha на моём трафике?». Если alpha падает ниже ~0.55, спекулятивное декодирование при высокой конкурентности даёт чистый минус, потому что каждый отклонённый черновой токен стоит второго прохода целевой модели. Этот урок учит сначала измерять alpha, а уже потом включать флаг.

**Type:** Learn
**Languages:** Python (stdlib, игрушечный симулятор доли принятых токенов)
**Prerequisites:** Phase 17 · 04 (Serving Engine Internals), Phase 10 · 18 (Multi-Token Prediction)

## The Problem

Декодирование упирается в память. На H100, запускающем Llama 3.3 70B FP8, каждый декодированный токен считывает ~140 ГБ/с весов и выдаёт один токен. Вычислительные мощности GPU во время декодирования почти простаивают — узкое место не в пропускной способности матричных умножений, а в пропускной способности HBM.

Спекулятивное декодирование использует этот разрыв. Генерируется K токенов-кандидатов дешёвой черновой моделью, затем целевой модели предлагается проверить все K за один проход вперёд. Каждый проверенный токен фактически достаётся бесплатно (амортизируется в батч из K токенов, который целевой модели в любом случае пришлось бы обрабатывать).

Классический подход с черновой моделью использует меньшую модель того же семейства (Llama 3.2 1B в роли черновика для Llama 3.3 70B). Это работает, но доля принятых токенов посредственная — распределение меньшей модели расходится с целевым. EAGLE, затем EAGLE-2, затем EAGLE-3 обучают лёгкую черновую голову прямо на внутренних состояниях целевой модели, так что распределение черновика гораздо точнее отслеживает целевое. Именно поэтому alpha растёт с 0.4 при подходе с отдельной черновой моделью до 0.6-0.8 с EAGLE-3.

Загвоздка: в vLLM 2026 EAGLE-3 — опциональная функция. `speculative_config` нужно задать явно. Нет флага — нет ускорения. Команды, которые включают её без измерения alpha на реальном трафике, часто видят, что хвостовая задержка становится хуже, а не лучше.

## The Concept

### Что на самом деле даёт спекулятивное декодирование

Без спекулятивного декодирования стоимость на токен — один проход целевой модели. Со спекулятивным декодированием при длине черновика K и доле принятых токенов alpha ожидаемое число токенов на один проход целевой модели — `1 + K * alpha`. Ускорение равно `(1 + K * alpha) / (1 + epsilon)`, где epsilon — накладные расходы на черновик-плюс-проверку. При K=5, alpha=0.7: `(1 + 5*0.7) / (1 + 0.1) = 4.5 / 1.1 = 4.1x`. Реальные цифры группируются вокруг 2-3x, потому что alpha редко бывает настолько высокой на продакшен-трафике, а epsilon растёт при большом размере батча.

### Почему alpha — единственная метрика, которая имеет значение

Отклонённые токены не исчезают бесследно — они вынуждают сделать второй проход целевой модели для первого отклонённого токена. На нагрузке, где alpha падает до 0.4, вы платите за накладные расходы черновика плюс проверку плюс повторную генерацию. При высокой конкурентности (скажем, 256 одновременных запросов) батч декодирования уже достаточно велик, так что разрыв по пропускной способности памяти между «только целевая модель» и «целевая модель с проверкой» сокращается. На большей части оборудования 2026 года при alpha ниже 0.55 спекулятивное декодирование даёт чистый минус.

Alpha зависит от нагрузки. На обычном чате в стиле ShareGPT EAGLE-3, обученный на ShareGPT, достигает 0.6-0.8. На трафике из специализированных доменов (код, медицина, право) черновая голова, обученная на общих данных, падает до 0.4-0.6. Обучение домен-специфичной черновой головы восстанавливает alpha — это лёгкая и быстрая задача обучения по сравнению с дообучением целевой модели.

### Поколения EAGLE кратко

- **Классическая черновая модель**: небольшая модель того же семейства. Alpha 0.3-0.5. Инфраструктура простая — загружены две модели, черновик выполняет K проходов на один проход целевой модели.
- **EAGLE-1 (2024)**: единая черновая голова, обученная на скрытых состояниях целевой модели (последний слой). Alpha ~0.5-0.6. Небольшие накладные расходы по параметрам поверх целевой модели.
- **EAGLE-2 (2025)**: адаптивная длина черновика и древовидные черновики (проверка нескольких ветвей за один проход целевой модели). Alpha ~0.6-0.7. Более сложный планировщик черновика.
- **EAGLE-3 (2025-2026)**: черновая голова, обученная на нескольких слоях целевой модели (не только на последнем), лучшее согласование. Alpha ~0.6-0.8 на обычном чате.

### Рецепт продакшена 2026 года

1. Разверните целевую модель в чистом виде. Измерьте базовые TTFT, ITL, пропускную способность при целевой конкурентности.
2. Включите черновик EAGLE-3 через vLLM `speculative_config`. Перезапустите бенчмарк.
3. Логируйте долю принятых токенов alpha. vLLM V1 отчитывается об этом как `spec_decode_metrics.accepted_tokens_per_request`. Разделите на запрошенную длину черновика, чтобы получить alpha.
4. Если alpha < 0.55 на распределении продакшен-трафика, отключите спекулятивное декодирование или обучите домен-специфичный черновик EAGLE-3.
5. При продакшен-конкурентности перезапустите тест. Убедитесь, что P99 ITL не ухудшился.

### Подводный камень продакшена: хвост P99

Среднее ITL снижается со спекулятивным декодированием. P99 может ухудшиться, если не настроить всё правильно. Отклонённые черновики запускают двухпроходную последовательность (черновик + неудачная проверка + повтор). При полном батче эти два прохода сериализуются. Следите за P99 ITL, а не за P50.

### Где EAGLE-3 уже развёрнут

Google развернул спекулятивное декодирование в AI Overviews в 2025 году (то же качество, более быстрый ответ). vLLM V1 поставляет `speculative_config` как документированный интерфейс, и его матрица функций отмечает совместимость спекулятивного декодирования с chunked prefill. SGLang поддерживает EAGLE-3 как рекомендуемый путь черновика для нагрузок с большим количеством общих префиксов.

### Математика безубыточности в одну строку

Ожидаемое ускорение: `S(alpha, K) = (1 + K*alpha) / (1 + verify_overhead)`. Приравнивая `S = 1`, решаем относительно alpha: `alpha_breakeven = verify_overhead / K`. При типичном verify_overhead ~0.15 и K=5: `alpha_breakeven = 0.03`. Но это чистая математика декодирования. При высокой конкурентности накладные расходы на проверку растут, а батч декодирования уже амортизирует чтения памяти между последовательностями, так что эффективная alpha_breakeven на практике поднимается до ~0.45-0.55.

### Когда не стоит использовать спекулятивное декодирование

- Офлайн-генерация батчами по 1, где задержка не важна. Используйте чистую целевую модель.
- Очень короткие выходы (менее 50 токенов). Накладные расходы черновика и проверки доминируют.
- Специализированные домены без домен-обученной черновой головы. Alpha слишком низкая.
- Предположение, что любая пара функций совместима по умолчанию. Сверяйтесь с матрицей совместимости vLLM для вашей версии: v0.18.0 отмечает спекулятивное декодирование совместимым с chunked prefill.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Спекулятивное декодирование | «draft plus verify» | Предложить K токенов дешёвой моделью, проверить все K за один проход целевой модели |
| Доля принятых токенов alpha | «spec accept rate» | Доля черновых токенов, принятых целевой моделью; единственная метрика, которая имеет значение |
| Длина черновика K | «spec k» | Сколько токенов предлагает черновик за один проход целевой модели; типично 4-8 |
| Накладные расходы на проверку epsilon | «spec overhead» | Дополнительная стоимость проверки-и-повтора по сравнению с чистым проходом целевой модели; растёт с размером батча |
| EAGLE-3 | «latest EAGLE» | Вариант 2025-2026 годов; обучает черновую голову на нескольких слоях целевой модели; alpha 0.6-0.8 на обычном чате |
| `speculative_config` | «vLLM spec config» | Явное включение в vLLM V1; отсутствие значения по умолчанию означает отсутствие ускорения |
| N-gram spec decode | «N-gram draft» | Черновик на стороне GPU с использованием N-gram-поиска в промпте; совместим с chunked prefill |
| Alpha безубыточности | «no-op alpha» | Alpha, при которой спекулятивное декодирование даёт нулевое ускорение; следите за ней при продакшен-конкурентности |
| Двухпроходный отклонённый черновик | «reroll cost» | Два прохода целевой модели при отклонении черновиков; определяет хвост P99 |
