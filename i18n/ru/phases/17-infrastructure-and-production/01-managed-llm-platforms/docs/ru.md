# Управляемые платформы LLM — Bedrock, Vertex AI, Azure OpenAI

> Три гиперскейлера, три разных стратегии. AWS Bedrock — это маркетплейс моделей: Claude, Llama, Titan, Stability, Cohere за одним API. Azure OpenAI — это эксклюзивное партнёрство с OpenAI плюс Provisioned Throughput Units (PTU) для выделенной мощности. Vertex AI делает ставку в первую очередь на Gemini — у неё лучшая история по длинному контексту и мультимодальности. В 2026 году Artificial Analysis фиксирует у Azure OpenAI медианную задержку ~50 мс, а у Bedrock — ~75 мс на эквивалентах Llama 3.1 405B — разрыв объясняется PTU, потому что выделенная мощность обгоняет общую по требованию. Правило принятия решения — не «что быстрее», а «какой каталог моделей и какая поверхность FinOps подходят моему продукту». Этот урок учит выбирать, опираясь на зафиксированные компромиссы, а не на интуицию.

**Type:** Learn
**Languages:** Python (stdlib, игрушечный компаратор стоимости и задержки)

## Learning Objectives

- Назвать три стратегии платформ (маркетплейс vs эксклюзивность vs Gemini-first) и сопоставить каждую с продуктовым сценарием использования.
- Объяснить, что покупают Provisioned Throughput Units (PTU) в Azure OpenAI, и почему Bedrock по требованию обычно показывает задержку примерно на 25 мс больше на масштабе 405B.
- Нарисовать схему поверхности атрибуции FinOps для каждой платформы (Bedrock Application Inference Profiles vs Vertex project-per-team vs Azure scopes + резервации PTU).
- Сформулировать политику «минимум два провайдера» и объяснить, почему привязка к одному вендору — дорогая ошибка в 2026 году.

## The Problem

Вы выбрали Claude 3.7 Sonnet для своего продукта. Теперь его нужно обслуживать. Вы можете вызывать API Anthropic напрямую, можете вызывать его через AWS Bedrock, а можете пройти через шлюз (gateway). Прямой API — самый простой вариант; Bedrock добавляет BAA, VPC endpoints, IAM и атрибуцию через CloudWatch. Шлюз добавляет отказоустойчивость, единый биллинг и лимиты запросов между провайдерами.

Более глубокий вопрос — это каталог. Если вам нужны Claude, Llama и Gemini в одном продукте, вы не сможете купить их всё в одном месте, если только это место — не Bedrock плюс Vertex плюс Azure OpenAI одновременно. Гиперскейлеры не взаимозаменяемы — каждый сделал свою ставку на то, кто владеет слоем моделей.

Этот урок описывает три ставки, разрыв по задержке, разрыв по FinOps и риск привязки к вендору.

## The Concept

### Три стратегии

**AWS Bedrock** — маркетплейс. Claude (Anthropic), Llama (Meta), Titan (собственная модель AWS), Stability (изображения), Cohere (эмбеддинги), Mistral, плюс подкаталоги для изображений и эмбеддингов. Один API, одна поверхность IAM, один экспорт в CloudWatch. Ставка Bedrock — клиенты хотят вариативность больше, чем единственную модель.

**Azure OpenAI** — эксклюзивное партнёрство. Вы получаете GPT-4 / 4o / 5 / серию o, DALL·E, Whisper и тонкую настройку моделей OpenAI в дата-центрах Azure. В каталоге «Azure OpenAI Service» нет моделей не от OpenAI — они находятся в Azure AI Foundry (отдельный продукт). Ставка Azure — OpenAI остаётся на переднем крае, а клиенты хотят корпоративный контроль именно над этими отношениями.

**Vertex AI** — сначала Gemini, всё остальное — потом. Gemini 1.5 / 2.0 / 2.5 Flash и Pro, плюс Model Garden (сторонние модели). Ставка Vertex — мультимодальность с длинным контекстом: контекст Gemini на 1М токенов — это отличительная черта.

### Разрыв по задержке на масштабе

Artificial Analysis проводит непрерывные бенчмарки. На эквивалентных развёртываниях Llama 3.1 405B (общая мощность по требованию) медианная задержка до первого токена у Azure OpenAI — около 50 мс; у Bedrock — около 75 мс. Этот разрыв — не провал AWS, а разница в модели предоставления мощности. Azure продаёт PTU (Provisioned Throughput Units), которые резервируют GPU-мощность для вашего тенанта. У Bedrock есть эквивалент (Provisioned Throughput), но он стоит от ~$21/час за единицу, и большинство клиентов остаются на общей мощности по требованию.

Общая мощность по требованию конкурирует с трафиком всех остальных клиентов. Выделенная мощность — нет. Если SLA вашего продукта требует TTFT < 100 мс на P99, вам придётся либо купить PTU в Azure, либо купить Bedrock Provisioned Throughput, либо смириться с дефолтным разбросом.

### Экономика Provisioned Throughput

Azure PTU: зарезервированный блок вычислительных мощностей для инференса. До ~70% экономии по сравнению с оплатой по требованию для предсказуемых нагрузок. Стоимость фиксирована в час независимо от трафика — вы платите за резервацию даже при простое. Точка безубыточности обычно находится в районе 40-60% устойчивой загрузки.

Bedrock Provisioned Throughput: $21-$50 в час в зависимости от модели и региона. Похожая математика — точка безубыточности примерно на уровне половины пиковой загрузки. Требуется ежемесячное обязательство.

Выделенная мощность Vertex продаётся по SKU для каждой модели Gemini; цены варьируются в зависимости от модели и региона и менее публично афишируются.

### Поверхность FinOps — настоящее отличие

**Bedrock Application Inference Profiles** — самая чистая атрибуция среди маркетплейсов. Присвойте профилю теги `team`, `product`, `feature`; направьте через него все вызовы моделей; CloudWatch разбивает стоимость по профилю без постобработки. Добавлено в 2025 году, по-прежнему самое гранулярное решение среди нативных инструментов гиперскейлеров.

Атрибуция **Vertex** — это project-per-team плюс метки везде. Вы моделируете каждую команду как проект GCP, ставите метки на каждый ресурс и используете BigQuery Billing Export + DataStudio для сводок. Больше работы, но BigQuery даёт произвольный SQL по данным о расходах.

**Azure** опирается на области подписки/группы ресурсов плюс теги, а резервации PTU выступают как объект расходов первого класса. Теги наследуются от групп ресурсов, а не от запросов, поэтому атрибуция на уровне запроса требует пользовательских метрик Application Insights или шлюза, который проставляет заголовки.

Паттерн: у Bedrock самая чистая нативная атрибуция, у Vertex — самая гибкая через BigQuery, у Azure — самая непрозрачная, если не настроить инструментирование.

### Привязка к вендору — риск 2026 года

Приверженность одному гиперскейлеру была нормальной, пока доминировала одна модель. В 2026 году передний край сдвигается ежемесячно — Claude 3.7 в один квартал, Gemini 2.5 в следующий, GPT-5 ещё через квартал. Привязка к одной платформе отрезает вас от двух третей переднего края.

Паттерн, который принимают работающие команды: минимум два провайдера для любого продуктово-критичного вызова LLM. Bedrock плюс Azure OpenAI — распространённая пара: Claude из одного источника, GPT из другого, отказоустойчивость между ними, один и тот же шлюз. Рост стоимости незначителен, потому что шлюз маршрутизирует оптимально; рост доступности во время сбоев (как инцидент Azure OpenAI в январе 2025 года, сбой AWS us-east-1) — решающий фактор.

### Резидентность данных, BAA и регулируемые отрасли

Bedrock: BAA в большинстве регионов; VPC endpoints; guardrails. Распространённый выбор по умолчанию в финтехе.
Azure OpenAI: HIPAA, SOC 2, ISO 27001; резидентность данных в ЕС; выбор по умолчанию для регулируемого предприятия.
Vertex: HIPAA, GDPR, резидентность данных по регионам; комплаенс-стек Google Cloud.

Все три соответствуют базовым требованиям. Различия — в политиках хранения данных, в том, как обрабатываются логи, и в том, читает ли мониторинг злоупотреблений ваш трафик (по умолчанию включён у большинства; возможность отключения доступна для предприятий).

### Цифры, которые стоит запомнить

- Медианный TTFT Azure OpenAI на эквивалентах Llama 3.1 405B: ~50 мс (с PTU).
- Медианный TTFT Bedrock по требованию: ~75 мс.
- Bedrock Provisioned Throughput: $21-$50/час за единицу.
- Точка безубыточности Azure PTU: ~40-60% устойчивой загрузки.
- Экономия PTU по сравнению с оплатой по требованию при высокой загрузке: до 70%.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Bedrock | «LLM-сервис AWS» | Маркетплейс моделей, включающий Claude, Llama, Titan, Mistral, Cohere |
| Azure OpenAI | «ChatGPT от Azure» | Эксклюзивные модели OpenAI в дата-центрах Azure с корпоративным контролем |
| Vertex AI | «LLM от Google» | Платформа с приоритетом на Gemini и Model Garden для сторонних моделей |
| PTU | «выделенная мощность» | Provisioned Throughput Unit — зарезервированные GPU для инференса, тарификация почасовая |
| Application Inference Profile | «тегирование в Bedrock» | Профиль стоимости/использования для конкретного продукта с тегами, нативно интегрированный с CloudWatch |
| Model Garden | «каталог Vertex» | Раздел сторонних моделей в Vertex AI, отдельный от Gemini |
| Two-provider minimum | «избыточность LLM» | Политика запуска каждого критичного пути LLM на ≥2 гиперскейлерах |
| BAA | «бумажки по HIPAA» | Business Associate Agreement; требуется для PHI; предоставляется всеми тремя платформами |
| Abuse monitoring | «наблюдатель за логами» | Проверка безопасности на стороне провайдера для промптов/выводов; отключается в корпоративных тарифах |
