# Инференс на edge-устройствах — Apple Neural Engine, Qualcomm Hexagon, WebGPU/WebLLM, Jetson

> Главное ограничение edge-устройств — пропускная способность памяти, а не вычисления. Мобильная DRAM работает на скорости 50-90 ГБ/с; дата-центровая HBM3 выдаёт 2-3 ТБ/с — разрыв в 30-50 раз. Декодирование ограничено памятью, поэтому разрыв имеет решающее значение. В 2026 году ландшафт делится на четыре направления. Apple M4/A18 Neural Engine достигает пика в 38 TOPS с унифицированной памятью (без копирования между CPU и NPU). Qualcomm Snapdragon X Elite / 8 Gen 4 Hexagon даёт 45 TOPS. WebGPU + WebLLM запускает Llama 3.1 8B (Q4) со скоростью ~41 ток/с на M3 Max (примерно 70-80% от нативной производительности); 17,6 тыс. звёзд на GitHub, API, совместимый с OpenAI, покрытие мобильных устройств ~70-75%. NVIDIA Jetson Orin Nano Super (8 ГБ) вмещает Llama 3.2 3B / Phi-3; AGX Orin запускает gpt-oss-20b через vLLM со скоростью ~40 ток/с; Jetson T4000 (JetPack 7.1) вдвое быстрее AGX Orin. TensorRT Edge-LLM поддерживает EAGLE-3, NVFP4, chunked prefill — продемонстрировано на CES 2026 компаниями Bosch, ThunderSoft, MediaTek.

## Цели обучения

- Объяснить, почему инференс LLM на мобильных устройствах ограничен пропускной способностью памяти, а вычисления вторичны.
- Перечислить четыре edge-платформы (Apple ANE, Qualcomm Hexagon, WebGPU/WebLLM, NVIDIA Jetson) и сопоставить каждую с конкретным сценарием использования.
- Назвать разрыв в покрытии WebGPU в 2026 году (Firefox Android догоняет) и выход Safari iOS 26.
- Выбрать формат квантования для каждой платформы (Core ML INT4 + FP16 для ANE, QNN INT8/INT4 для Hexagon, WebGPU Q4 для браузера, NVFP4 для Jetson Thor).

## Проблема

Заказчику нужен голосовой чат-бот на устройстве: голосовой ввод по умолчанию, конфиденциальность по умолчанию, работа без подключения к сети. На MacBook Pro M3 Max Llama 3.1 8B Q4 работает со скоростью ~55 ток/с — нормально. На iPhone 16 Pro та же модель работает со скоростью 3 ток/с — уже не нормально. На Android среднего класса со Snapdragon 8 Gen 3 — 7 ток/с. В браузере через WebGPU на Chrome Android v121+ — 4-8 ток/с в зависимости от устройства.

Разброс в производительности — это не проблема переноса. Это разрыв в пропускной способности, умноженный на формат квантования, умноженный на доступность NPU из пользовательского пространства. Инференс на edge-устройствах в 2026 году — это четыре разные задачи с четырьмя разными решениями.

## Концепция

### Пропускная способность — реальный потолок

Декодирование считывает полный набор весов для каждого токена. Одна модель 7B в формате Q4 весит 3,5 ГБ. Чтение 3,5 ГБ на скорости 50 ГБ/с занимает 70 мс — теоретический потолок составляет ~14 ток/с. При 90 ГБ/с (высококлассная мобильная DRAM) потолок сдвигается до ~25 ток/с. Никакие вычислительные мощности не помогут преодолеть этот предел.

Дата-центровая HBM3 на скорости 3 ТБ/с считывает те же 3,5 ГБ за 1,2 мс — потолок составляет 830 ток/с. Та же модель, те же веса. Другая подсистема памяти.

### Apple Neural Engine (M4 / A18)

- До 38 TOPS. Унифицированная память (CPU и ANE используют общий пул) — без накладных расходов на копирование.
- Доступ через Core ML + скомпилированные модели `.mlmodel`, либо через Metal Performance Shaders (MPS) из PyTorch.
- Бэкенд llama.cpp Metal использует MPS, а не ANE напрямую; для нативного доступа к ANE требуется конвертация через Core ML.
- Лучший практический путь для iOS-приложений в 2026 году: Core ML с весами INT4 + активациями FP16.

### Qualcomm Hexagon (Snapdragon X Elite / 8 Gen 4)

- До 45 TOPS. Интегрирован с CPU и GPU в составе SoC, но имеет отдельный домен памяти.
- QNN (Qualcomm Neural Network) SDK и AI Hub обеспечивают конвертацию из PyTorch/ONNX.
- Шаблоны чата, Llama 3.2, Phi-3 — всё поставляется как полноценные артефакты на AI Hub.

### NPU от Intel / AMD (Lunar Lake, Ryzen AI 300)

- 40-50 TOPS. Программная поддержка отстаёт от Apple/Qualcomm; OpenVINO улучшается, но остаётся нишевым решением.
- Лучше всего подходит для Windows ARM copilot-приложений; нативная поддержка на десктопах AMD/Intel для local-first подхода.

### WebGPU + WebLLM

- Запуск моделей в браузере через вычислительные шейдеры WebGPU; без установки.
- Llama 3.1 8B Q4 со скоростью ~41 ток/с на M3 Max — примерно 70-80% от нативной производительности через тот же бэкенд.
- 17,6 тыс. звёзд на GitHub у WebLLM; JS API, совместимый с OpenAI; Apache 2.0.
- Покрытие в 2026 году: Chrome Android v121+, Safari iOS 26 GA, Firefox Android всё ещё догоняет. В целом покрытие мобильных устройств ~70-75%.

### Семейство NVIDIA Jetson

- Orin Nano Super (8 ГБ): вмещает Llama 3.2 3B, Phi-3 с хорошей скоростью в ток/с.
- AGX Orin: запускает gpt-oss-20b через vLLM со скоростью ~40 ток/с.
- Thor / T4000 (JetPack 7.1): производительность вдвое выше AGX Orin, поддерживаются EAGLE-3 и NVFP4.
- TensorRT Edge-LLM (2026) поддерживает спекулятивное декодирование EAGLE-3, веса NVFP4, chunked prefill — оптимизации из дата-центров, перенесённые на edge.

### Выбор квантования для каждой платформы

| Платформа | Формат | Примечания |
|--------|--------|-------|
| Apple ANE | Веса INT4 + активации FP16 | Путь конвертации через Core ML |
| Qualcomm Hexagon | QNN INT8 / INT4 | Конвертеры AI Hub |
| WebGPU / WebLLM | Q4 MLC (q4f16_1) | Используйте `mlc_llm convert_weight` + скомпилированный `.wasm`; GGUF не поддерживается |
| Jetson Orin Nano | Q4 GGUF или TRT-LLM INT4 | Ограничено памятью |
| Jetson AGX / Thor | NVFP4 + FP8 KV | Путь Edge-LLM |

### Ловушка длинного контекста на edge-устройствах

128K-контекст Llama 3.1 — это дата-центровая функция. На телефоне с 8 ГБ ОЗУ: 4 ГБ модель + 2 ГБ KV-кэш для 32K токенов + накладные расходы ОС = переполнение памяти (OOM). Edge-развёртывания ограничивают контекст до 4K-8K токенов, если не применяется агрессивное квантование KV (Q4 KV).

### Голос — убийственное приложение

Голосовые агенты чувствительны к задержкам (первый токен < 500 мс). Локальный инференс полностью устраняет сетевую задержку. В сочетании с распознаванием речи (варианты Whisper Turbo работают на edge-устройствах) инференс на edge превращается в полноценный производственный голосовой цикл.

### Цифры, которые стоит запомнить

- Apple M4 / A18 ANE: 38 TOPS.
- Qualcomm Hexagon SD X Elite: 45 TOPS.
- WebLLM на M3 Max: ~41 ток/с на Llama 3.1 8B Q4.
- AGX Orin: ~40 ток/с на gpt-oss-20b через vLLM.
- Разрыв в пропускной способности между дата-центром и edge: 30-50 раз.
- Покрытие мобильных устройств WebGPU: ~70-75% (Firefox Android отстаёт).

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| ANE | «Apple neural engine» | NPU на устройстве в чипах серии M и A; унифицированная память |
| Hexagon | «Qualcomm NPU» | NPU в Snapdragon; доступ через QNN SDK |
| WebGPU | «browser GPU» | Стандартизированный W3C API для GPU в браузере; Chrome/Safari 2026 |
| WebLLM | «browser LLM runtime» | Проект MLC-LLM; Apache 2.0; JS, совместимый с OpenAI |
| Jetson | «NVIDIA edge» | Семейство Orin Nano / AGX / Thor / T4000 |
| TRT Edge-LLM | «edge TensorRT» | Edge-версия TensorRT-LLM 2026 года; EAGLE-3 + NVFP4 |
| Unified memory | «shared pool» | CPU и NPU видят одну и ту же RAM; без накладных расходов на копирование |
| Bandwidth-bound | «memory limited» | Декодирование ограничено скоростью чтения весов в байтах/сек |
| Core ML | «Apple conversion» | Фреймворк Apple для моделей, нативных для ANE |
| QNN | «Qualcomm stack» | Qualcomm Neural Network SDK |
